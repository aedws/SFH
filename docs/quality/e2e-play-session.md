# 실제 플레이 세션 E2E 검수

## PC·모바일 시작과 양손 조작 {#mobile-entry-e2e}

`mobile_control_entry_contract_test.gd`를 배포 필수 검사에 추가합니다. 정상 마커뿐 아니라 SCRIPT ERROR도 실패로 처리합니다.

| 플레이어 기대 | 자동 판정 |
|---|---|
| 조작 선택 후 로비 | PC·모바일 버튼 실제 클릭, 파일 저장→새 Game 로드, 움직이는 로비·브리핑 미노출 |
| 두 손 조작 | 서로 다른 손가락으로 조이스틱/공격/스킬, 실제 좌표 이동·방향 전환·스킬 에너지 감소 |
| 손을 떼면 멈춤 | 조이스틱 바깥 release, 한 손만 해제해도 다른 공격 유지, 포커스/모달/기기 전환 전체 해제 |
| 화면 버튼으로 준비 | 실제 터치→가방/설정→닫기, 게이트 근처 사용→브리핑→취소→로비 |
| 공격 화면을 가리지 않음 | 4 화면 크기 경계, 좌/우 영역 비중첩, 가로/세로 HP·재화·목표와 양손 영역 비중첩, 미니맵 경계 |
| 모드 변경/제거 | 모바일 쿨타임/EN 표시·PC 중복창 숨김, PC 복귀 HUD 복원, 모바일 기능 OFF에도 로비 유지 |
| 키 배치 변경 | 점멸을 9번 Action으로 옮겨도 첫 터치 스킬 버튼은 점멸 발동, 손을 떼면 실제 배치 Action 해제 |
| 패드 밖 UI도 사용 | 지도·소켓과 동일 CanvasLayer의 GUI 버튼 터치/취소, 터치 down 동안 마우스 공격 상태가 켜지지 않음 |
| 크게 읽고 누르기 | 844×390·390×844·1280×720·640×360·320×568 × 100/125/150%, 실제 버튼 확대·양손 비중첩·44 논리 픽셀 이상·설정 UI 클릭 |
| 첫 안내만 확인 | PC는 이력 미소비, 첫 모바일 팝업, 실제 확인 클릭, 새 인스턴스 재시작 시 미노출, 설정 초기화에도 이력 유지 |
| 안내를 놓치지 않음 | 미확인 종료 시 재노출, 저장 실패 시 팝업/미확인 유지와 재시도, 팝업 4 화면 경계와 고정 확인 버튼 |
| 기존 데이터 유지 | v1 설정 호환·기존 PC 위치 보존·v2 배율/확인 저장 및 재로드·잘못된 배율 거부 |
| 가로 기본으로 시작 | 네이티브 센서 가로 설정·모바일 가로 선호 스냅샷, 세로에서만 시작/안내 전환 버튼, 가로 회전 시 버튼 숨김 |
| 회전 권한 실패에도 진입 | `test_mobile_orientation_policy.mjs`: 가로 잠금 요청·전체화면 명시 클릭만 요청·거절/미지원/동기 예외 처리·PC 복귀 시 잠금 해제 |

팝업 테스트는 창 크기뿐 아니라 논리 해상도도 변경해 실제 세로 배치를 검사합니다. 작은 세로 창에서 크기 버튼까지 스크롤한 뒤 클릭하며 확인 버튼은 고정합니다. 기기 실제 회전/방향 잠금 승인 여부는 Android/iOS 실기에서 별도 확인합니다.

2026-09-03 로컬 Web에서 세로 시작 화면의 ‘모바일·가로 플레이’와 회전 안내/명시적 전체화면 버튼, 가로 전환 시 버튼 숨김을 시각 검수했습니다. 자동 회전 요청 거절이 미처리 예외나 로비 진입 실패로 이어지지 않는 것은 정책 단위 검사로 판정합니다.

2026-09-03 크기/첫 안내 추가 검수: 로컬 브라우저 844×390·390×844에서 팝업 줄바꿈·내부 스크롤·고정 확인 버튼과 150% 선택 피드백을 확인했습니다. 최초 확인 전 저장하지 않고, 확인 완료 후 재실행에서는 팝업을 생략하는 계약을 자동 검사합니다.

2026-09-03 로컬 Web 빌드를 브라우저에서 844×390/390×844로 검수했습니다. 실제 시작 선택→로비와 격리 전투 렌더링을 분리해 확인했으며, 회전 중 화면이 찌그러지는 재진입 시점과 로비 안내·장식 문구·미니맵 겹침을 수정했습니다. Godot 입력/상태 자동 검증과 이 화면 검수는 Android/iOS 실기 멀티터치·노치·성능 인증을 대신하지 않습니다. 기존 전체 플레이 E2E와 중·대형 가상 600초 회귀도 유지합니다.

## P6 로컬 마감 재검증 {#p6-closeout-e2e}

기능 파일 존재 대신 참가 안내→출격→성공/실패→기록→마감→장착→재실행으로 판정합니다.

| 플레이어 기대 | 자동 검증 |
|---|---|
| 참가 조건을 알 수 있음 | 배포 Resource 그대로 지역 3×난이도 3×규모 3×페널티 0/9/10 = 81조합. 대형/10점 9조합만 참가 |
| 소형도 정상 플레이 | 실제 준비 화면의 미참가 이유·기록 버튼 클릭·ESC 복귀·탈출·일반 기록 유지, 시즌 미집계 |
| 대형 성공 뒤 보상 | 대형 결과 제출→앱 오프라인 마감→외형 6종·영수증→칭호/오라 장착·재실행·해제 |
| 업데이트로 기록이 사라지지 않음 | 구 all-size 시즌 저장→새 정책으로 재시작→기존 조건 유지→마감 사본 보존→다음 대형 시즌으로 전환 |
| 순위와 지급이 중복되지 않음 | 3종 정렬, 보스 실제 처치 1회, 봉투 변조/중복, 시간 경계·재시도·저장/손상·선택 모듈 제거 |

`scripts/test-p6.ps1`의 3개 테스트와 전체 `e2e_play_session_test.gd`를 사용합니다. 신규 마커 `shipped_policy_81 legacy_policy_rollover`를 CI 필수 조건에 포함합니다. Godot headless 자동 입력/상태 판정이며 실제 온라인 경쟁 서버 또는 사람의 육안 인증으로 표기하지 않습니다.

## 로비 세팅 → 장착한 그대로 출격 {#hub-preparation-e2e}

`hub_preparation_contract_test.gd`와 기존 상점/작전 조합 테스트를 CI 필수 검사로 실행합니다. 실제 플레이 저장과 격리된 Game에서 자동 입력·공개 상태·Control 경계를 검사합니다.

| 플레이어 기대 | 판정 |
|---|---|
| 상점이 로비에 있음 | 배치 단말 근처 F로 열림, 멀리서는 거부, 구매/닫기 후 이동 가능 |
| 출격 전에 준비 완료 | 준비 단말 F → 요원 클릭 → 장비 버튼 → I 편집. 작전 2단계에서는 요원·상점·무기 선택을 노출하지 않음 |
| 저장 없이 출격하지 않음 | 편집 중 직접 시작 거절·무차감, 게이트 접근 시 저장 확인, 취소는 계속 편집, 저장 후 브리핑 |
| 장착한 그대로 들어감 | 실물 무기 교체·모듈·파츠·강화 단계 저장 → ESC/Q/F → 최종 투입. 주/보조·방어구·활성 슬롯 값 사본과 가방 배치 일치 |
| 세팅을 바꿔도 출격 | 81개 지역/규모/난이도/요원 조합 + 12개 추가 세팅. 구형 카탈로그 선택은 거절하되 실제 장비는 유지 |
| 확장 무기도 안전 | 테스트 슬롯 규칙을 공개 상태 계약으로 확장한 뒤 카탈로그 밖 대검 출격. 기본 게임의 장착 태그 제한을 우회하지 않음 |
| 비용과 스킬이 명확 | 무기 재청구 없음, 미해금 스킬 무차감, 아크 질주 추가 60 C 한 번, 전격 무기에서 발동·권총에서 태그 비활성 |
| 취소/복귀/재실행 보존 | 브리핑 ESC와 정상 복귀 세팅 일치. 기존 실패 장착품 소실 smoke 및 Windows write/read 별도 프로세스 회귀 유지 |
| 작은 화면·선택 제거 | 1280×720, 1920×1080, 640×360, 390×844 준비 패널·고정 버튼 경계. 단말 OFF에도 I/U/E·거점·출격 유지 |

신규 성공 마커: `HUB_PREPARATION_OK`. Godot headless 자동 검증이며 새 배포판의 사람 육안 플레이 인증을 의미하지 않습니다. 상점 품질 실물 흐름은 아래 P7-01A/B 계약이 별도로 판정합니다.

## P7-01A/B·P7-02 · 상점 비교·품질 실물·회전 {#p7-shop-e2e}

`game/tests/shop_browser_contract_test.gd`와 `shop_quality_inventory_contract_test.gd`를 Godot headless로 실행합니다. 신규 Game은 `_ready` 전 저장 경로를 캐시 아래 고유 테스트 폴더로 격리하며 실제 플레이 저장을 사용하지 않습니다.

| 플레이어 인식/실패 상황 | 판정 근거 |
|---|---|
| 기존 거점에서 출발 | 로비 보급 단말로 접근 → 실제 F로 상점 열기, 작전 브리핑 진입 없음 |
| 선택과 구매의 구분 | 열기·세 품질 선택 중 잔액/가방 불변, 구매 버튼 전까지 차감 없음 |
| 비교와 실제 결과 | 동일 품목 수량당 표준 가격 비교, 선택한 품목/가격/수량만 I 가방 실물로 지급, 완료 안내 |
| 품질이 실제 수치에 반영 | 고성능 탄도 모듈의 품질·옵션·소켓 payload 확인→I 편집→U 장착→실제 투사체 피해 +1.25배 |
| 장착 왕복 보존 | 장비에서 해제해 가방으로 돌려보낸 뒤에도 동일 품질 ID·배율·옵션·소켓 유지 |
| 품질 정의 교체 | 테스트 전용 Resource에서 고성능 표시명·소켓을 바꾸면 정책 코드 수정 없이 견적에 반영 |
| 저장 재시작 | 고성능 모듈을 장착·강화해 저장한 뒤 별도 Godot 프로세스로 다시 열어 품질 1.25와 거래 ID 유지 |
| 중복·오래된 견적 | 구매 후 선택 해제, 추가 클릭 무변경, 회전 번호 불일치 구매 거부 |
| 런 복귀 회전 | 런 시작→사망 정산→회전 번호 +1·매물 교체·사유 표시, 중복 거점 갱신은 추가 회전 없음 |
| 조립 취소 보존 | 런 시작 상태를 취소한 뒤 거점 복귀 신호가 와도 매물과 회전 번호 유지 |

| 지급 원복 실패 | 거래 기록과 공급자 원복이 함께 실패해도 아이템 지급 뒤 크레딧까지 환불되는 이중 획득 차단, 명시적 일관성 오류 반환 |
| 불가능한 구매 | 순수 정책에서 잔액 부족·해금·가방 공간·음수/소수 비용·잘못된 수량/품질/지급 유형 거부. 실제 패널에서도 사유·구매 비활성·추가 차감 없음 확인 |
| ESC와 일시정지 | 상점을 닫으면 거점 이동 가능 상태로 복원, 브리핑이 남지 않음 |
| 반응형 | 1280×720, 1920×1080, 640×360, 390×844 패널·닫기·구매 화면 내 배치, 1/3열 전환 |
| 제거성 | UI 토글 OFF에서 P5 도메인·거점 유지, 실물 지급만 OFF에서는 가방 불변·레거시 창고 지급, 자동 구매 폴백 없음 |
| 구매 이후 다음 출격 | 반복 상점 방문·ESC 복귀 뒤 실제 F → 다음 2회 → 투입 버튼 클릭으로 전투 시작 확인 |

성공 마커는 `P5_HUB_PROGRESSION_OK`, `P7_SHOP_BROWSER_OK`, `P7_SHOP_QUALITY_OK`, `P7_SHOP_DELIVERY_MODULE_OK`입니다. 이 검사는 자동 입력·상태·레이아웃 판정이며 브라우저/Windows 육안 검수나 임시 가격·옵션·리롤 정책의 기획 확정을 대신하지 않습니다. 서버 위변조·백업 E2E는 사전 설계에만 등록된 **미실행 계획**입니다.

## P7-03 · 반출 도면 영구 등록 {#p7-blueprint-e2e}

| 플레이어 인식/실패 상황 | 판정 근거 |
|---|---|
| 첫 제작소 상태 | Recipe 3종과 `도면 반출 필요` 0/3 표시 |

| 중복 반출 | 이미 등록한 도면은 다시 늘리지 않는 멱등 처리 |

사이버펑크 표현 계층도 같은 세션에서 검사합니다. 오버레이가 뷰포트 전체를 덮되 입력을 가로채지 않는지, 핵심 신호색이 정확히 `#02e5e1`인지, Feature Manifest에서 끄면 표현 노드만 빠지고 플레이 규칙은 유지되는지를 확인합니다.

## 플레이어 인식 계약

`PlayerPerceptionJudge`는 화면 안에서 실제로 보이는 Label·Button과 아이콘의 접근성 툴팁을 수집해 의미 단서를 검사합니다. 테스트가 내부 값만 보고 통과하지 않도록 입력 전후 키 배지·자원 숫자·월드 이동량뿐 아니라 대시의 표현 강도·궤적 표본·카메라 리드도 함께 증거로 전달합니다.

| 단위 | 체크포인트 예시 | 실패 예시 |
|---|---|---|
| 방향·선택 | 거점 목표, I/U/E/K, 장비·개조 정보 | 기능은 열리지만 무엇을 바꾸는 화면인지 설명 없음 |
| 결정·한눈 정보 | 작전 비용·위험·회수, 전투 HP·에너지·대시 | 투입 버튼은 있으나 비용·결과를 판단할 단서 없음 |
| 행동·자원 피드백 | Q, 점멸, 대시, 자원 회수 | 내부 슬롯·쿨타임·크레딧만 바뀌고 보이는 문구는 그대로 |
| 상태·결말 | 탈출 시작/정지/재개, 성공/실패 | 카운트다운은 멈췄지만 이유가 없거나 성공·실패 손익이 구분되지 않음 |
| 연속성 | 모달 종료·정산 후 복귀 | 창은 닫혔지만 전투 HUD나 거점 방향 안내가 복구되지 않음 |

현재 **31개 체크포인트, 9개 인식 단위와 15개 게임플레이 흐름**을 자동 판정합니다. 전체 기능군의 자동·부분·수동 범위와 다음 검수 순서는 [플레이어 인식 단위 E2E 감사](player-perception-audit.md)에 정리합니다.

## 사람 검수 원칙

- 클릭·키 입력 한 번이 두 화면을 동시에 토글하지 않아야 합니다.
- 모달이 열리면 뒤의 거점·전투 HUD가 시각적으로 경쟁하지 않아야 합니다.
- 숫자는 내부 계산 명칭이 아니라 플레이어가 해석하는 의미로 표시합니다.
- 내부 상태가 변해도 플레이어가 볼 수 있는 문구·수치·움직임 중 하나가 변하지 않으면 실패입니다.
- 같은 동작은 데스크톱과 Web에서 동일한 InputMap Action을 사용합니다.
- 한 판 성공뿐 아니라 사망 후 복귀와 재투입도 연속으로 검사합니다.

## 후속 검수

기본기→드랍, 방 봉쇄→보상, 현장 전리품 비교→보류→획득, 현장 무기·스킬 즉시 교체, 런 세션 소켓, **규모 3×지역 3×난이도 3×요원 3의 81개 실제 작전 조합과 3규모×4세팅 변경 프로필 12개**, 결제 전 실패·무차감·ESC 거점 복귀, 성공/사망 전리품 정산, P5-01~10의 선택→견적→실전→복원, 중·대형 10분 논리 세션, 방·통로 안개 전환은 자동 완료했습니다. Web 전용 회귀는 P5 확정 CSV 6종을 파일 없이 payload만으로 구성해 거점 초기화가 유지되는지도 검사합니다. P6-01~02는 공급자 교체, 익명 신원, 검증 봉투, 멱등 키, 변조 거부, 영구 재시도 저장·복원과 결과 화면 상태를 판정합니다. 다음 우선순위는 P6-03 시즌 경계와 실제 이동 경로로 중·대형 맵을 장시간 주행하는 실기 테스트, 다중 해상도 렌더링과 사운드 인지 계층입니다.
