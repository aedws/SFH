# 실제 플레이 세션 E2E 검수

## 2026-09-03 추가 · 보스 등장과 접근 방향

| 플레이어 기대 | 검증 |
|---|---|
| 새 보스가 나타났음을 즉시 인지 | 50% 회수 실제 생성 뒤 `보스 등장` 배너, 설치 전 보스·일반 보스·중복 신호 구분 |
| 어느 쪽에서 오는지 식별 | 8방향×1280×720/1920×1080/640×360/390×844 투영, 실제 작전 카메라의 우측 화면 밖 보스 화살표 |
| 카메라와 화면 변화에도 방향이 맞음 | 카메라 이동·0.5배 줌·화면 안 진입 시 해당 화살표 숨김 |
| 가방과 경고가 겹치지 않음 | 물리 I로 가방 열기→경고 숨김·수명 정지→ESC로 복귀→표시 복원 |
| 죽은 보스의 잔상이 없음 | 처치 즉시 제거, 복수 중 남은 보스 유지, 마지막 제거 뒤 경고 종료, 종료 시 구독 해제 |
| HUD를 빼도 전투 가능 | Manifest 경고 비활성화 후 작전·생성기·추격 서비스 유지 smoke |

`BOSS_WARNING_OK`, `E2E_BOSS_WARNING_OK`가 CI 필수입니다. 좌표·상태 계약과 실제 입력 자동 E2E이며 사람의 장시간 플레이 평가를 대신하지 않습니다.

가방을 열고 닫는 입력 대기 사이에도 카메라 보간이 진행되므로, 화면 안/밖 보스 테스트 위치는 **각 판정 시점의 카메라 변환**으로 다시 계산합니다. 이전 프레임 좌표로 화면 내부를 가정해 화살표를 오판정하지 않으며, 실제 투영 좌표가 화면 내부인지 먼저 확인합니다.

## 2026-09-03 추가 · P6 보상과 실물 파밍 한 판

| 플레이어 기대 | 검증 |
|---|---|
| 네 종류를 한 판에서 발견 | 실제 네 방 진입→최소 무리 생성→문 봉쇄→적 사망→개방, 무기/방어구/모듈/파츠 순환 |
| 주운 물건을 바로 사용 | 물리 F→실제 가방 인스턴스→I 편집→호환 장착/저장→ESC 전투 재개 |
| 못 쓰는 물건도 보관 | 요원/슬롯 태그 거부 시 아이템 유지. 호환 소총·파츠 고정 후보로 사용 경로도 별도 검사 |
| 가방 부족이 물건을 삭제하지 않음 | 한 칸 남은 가방에 모듈 2개 획득 실패→배치·수량·드랍 유지·안내 표시 |
| 보스도 보상을 줌 | 실제 추격 보스 처치→드랍 2개·중복 등록 무시·방 클리어 수 불변 |
| 반출과 사망 결과가 다름 | 탈출→네 종류 창고 반출·중복 정산 무시·거점 가방 이중 지급 없음; 사망→네 종류 소실·창고 불변 |
| 시즌 명예가 유지 | 마감 후 1회 지급·신원 분리·목록 고정·저장 실패 롤백·재시작·칭호/오라 장착·해제·손상 보존 |

`E2E_LOOT_SESSION_OK` / `E2E_LOOT_DEATH_OK`는 통합 게임 입력 테스트, `P6_REWARD_OK`는 시간 주입을 사용하는 시즌 계약 테스트입니다. 전투 이동은 테스트 위치 이동, 다수 적 섬멸은 실제 피해 API로 가속합니다. 중·대형 600초도 논리 시간 가속이므로 브라우저 10분 수동 플레이·시각/사운드 검수를 완료했다고 의미하지 않습니다.

## 2026-09-03 추가 · 절반 회수 보스와 거점 자유 편집

| 플레이어 기대 | 통과 기준 |

| 생성 실패 때문에 보스가 영영 사라지지 않음 | 첫 생성 실패 후 추가 크레딧 없이 제한 주기로 재시도, 성공 후 재생성 금지 |
| 문이 닫혀도 안전지대가 되지 않음 | 실제 RoomDoorBarrier 충돌체 통과·접촉 HP 감소, 열었다 재봉쇄한 뒤 다시 피해 확인 |
| 방 클리어와 보스 추격은 별개 | 보스 생성 전후 방 적 수·문 수·일반 스폰 예산 불변, 방 섬멸 후 보스 생존·타게팅 유지 |

| 로비에서 창을 자유롭게 오갈 수 있음 | 포커스가 있는 I/U/E 여섯 방향 직접 키 전환, 한 창만 표시, 반복 열기 후 ESC·이동 복구 |
| 다른 창에서도 방금 바꾼 장비가 보임 | U 무기 교체·E 모듈/파츠 장착·해제 후 I 최신 편집본, I→E 저장·취소·계속 편집 |

`PURSUIT_BOSS_OK`는 실제 물리 프레임을 포함한 추격 계약, `E2E_HUB_LOADOUT_OK`는 통합 게임의 키 입력·버튼 동작·상태 전환입니다. 헤드리스 검증이며 브라우저 수동 플레이를 했다는 의미는 아닙니다. 기존 방 전투와 전체 세션 E2E도 함께 실행합니다.

계약 테스트의 가속 시계는 실시간 일주일 운영이나 실제 서버 검증을 대신하지 않습니다. 온라인 실서비스·칭호/오라 지급은 아직 검사 대상에 포함되지 않습니다.

이 문서는 기능이 존재하는지만 확인하지 않고, 플레이어가 실제로 누르는 키와 화면 전환 순서에서 한 판이 끝까지 이어지는지를 검사합니다. 23개 UI 상태, 31개 플레이어 인식 체크포인트와 15개 게임플레이 인과 흐름을 두어 **단서가 읽히는지, 입력이 타격·처치·드랍·런 소켓·정산까지 이어지는지, 성공·실패의 의미가 구분되는지**를 판정합니다.

## 실행

### 2026-09-03 통합 인벤토리 편집 회귀

`E2E_INVENTORY_EDITOR_OK`를 별도 필수 성공 표식으로 사용합니다. 기존 23개 UI 상태·31개 인식 체크포인트는 유지하며 아래 판정을 추가합니다.

| 플레이어가 기대하는 것 | 검증 내용 |
|---|---|
| 칸을 옮겨도 아이템이 사라지지 않음 | 실제 Viewport 클릭 선택→빈 칸 이동, 겹침·음수 좌표 거부, 원본은 저장 전 불변 |
| 드래그도 같은 규칙 적용 | 엔진 드래그 시작·payload 생성 후 로컬 좌표 드롭 계약 검사. 헤드리스/숨김 창은 OS 커서를 이동하지 않으므로 드롭 좌표만 주입하며, 실제 OS 포인터 전체 드래그 검증과 구분 |
| 장착 결과를 미리 보고 결정 | 무기 교체·모듈 장착/해제, 원본 장비 불변, 슬롯 태그 거부, 가방 가득 찼을 때 해제 거부 |
| 실수로 닫아도 세팅 보존 | 실제 ESC→확인→ESC 계속 편집, 탭 이동 저장, U 이동 변경 취소, 외부 K 호출 가드 |
| 저장이 이전 세팅을 덮어쓰지 않음 | 원본 변경 감지 시 저장 거부, 저장 후 재편집·취소가 최근 저장본을 복원 |
| 모든 칸과 탭에 접근 가능 | 1280×720, 1024×720, 768×720, 390×844에서 3탭 경계·가로 잘림 없음·세로 스크롤 마지막 행 접근 |

스모크와 실제 OpenGL 렌더 실행에서도 같은 테스트를 사용합니다. `--capture-inventory`로 엔진 출력만 저장해 한글·아이템 칸·장비/스탯 배치를 확인할 수 있습니다. 확인창은 저장/취소/계속 편집 3개 버튼 안에서 키보드 포커스를 순환시킵니다.

앱 재시작 가방 배치 저장, 회전, 자동 정렬, 미정 방어구 2종은 통과 대상으로 보고하지 않습니다.

실제 입력 순서마다 `UIStateJudge`가 현재 화면을 스냅샷으로 읽습니다. 단순 `visible` 값이 아니라 상위 노드까지 반영한 유효 표시 상태, 일시정지, 열린 모달 수, 장비 탭, 1280×720 기준 화면 경계와 HUD 교차 영역을 함께 판정합니다.

|---|---|---|---:|---|

사이버펑크 표현 계층도 같은 세션에서 검사합니다. 오버레이가 뷰포트 전체를 덮되 입력을 가로채지 않는지, 핵심 신호색이 정확히 `#02e5e1`인지, Feature Manifest에서 끄면 표현 노드만 빠지고 플레이 규칙은 유지되는지를 확인합니다.

## 플레이어 인식 계약

`PlayerPerceptionJudge`는 화면 안에서 실제로 보이는 Label·Button과 아이콘의 접근성 툴팁을 수집해 의미 단서를 검사합니다. 테스트가 내부 값만 보고 통과하지 않도록 입력 전후 키 배지·자원 숫자·월드 이동량뿐 아니라 대시의 표현 강도·궤적 표본·카메라 리드도 함께 증거로 전달합니다.

| 단위 | 체크포인트 예시 | 실패 예시 |
|---|---|---|
| 방향·선택 | 거점 목표, I/U/E/K, 장비·개조 정보 | 기능은 열리지만 무엇을 바꾸는 화면인지 설명 없음 |
| 결정·한눈 정보 | 작전 비용·위험·회수, 전투 HP·에너지·대시 | 투입 버튼은 있으나 비용·결과를 판단할 단서 없음 |
| 행동·자원 피드백 | Q, 점멸, 대시, 자원 회수 | 내부 슬롯·쿨타임·크레딧만 바뀌고 보이는 문구는 그대로 |
| 상태·결말 | 탈출 시작/정지/재개, 성공/실패 | 카운트다운은 멈췄지만 이유가 없거나 성공·실패 손익이 구분되지 않음 |
| 연속성 | 모달 종료·정산 후 복귀 | 창은 닫혔지만 전투 HUD나 거점 방향 안내가 복구되지 않음 |

현재 **31개 체크포인트, 9개 인식 단위와 15개 게임플레이 흐름**을 자동 판정합니다. 전체 기능군의 자동·부분·수동 범위와 다음 검수 순서는 [플레이어 인식 단위 E2E 감사](player-perception-audit.md)에 정리합니다.

## 사람 검수 원칙

- 클릭·키 입력 한 번이 두 화면을 동시에 토글하지 않아야 합니다.
- 모달이 열리면 뒤의 거점·전투 HUD가 시각적으로 경쟁하지 않아야 합니다.
- 숫자는 내부 계산 명칭이 아니라 플레이어가 해석하는 의미로 표시합니다.
- 내부 상태가 변해도 플레이어가 볼 수 있는 문구·수치·움직임 중 하나가 변하지 않으면 실패입니다.
- 같은 동작은 데스크톱과 Web에서 동일한 InputMap Action을 사용합니다.
- 한 판 성공뿐 아니라 사망 후 복귀와 재투입도 연속으로 검사합니다.

## 후속 검수

기본기→드랍, 방 봉쇄→보상, 현장 전리품 비교→보류→획득, 현장 무기·스킬 즉시 교체, 런 세션 소켓, **규모 3×지역 3×난이도 3×요원 3의 81개 실제 작전 조합과 3규모×4세팅 변경 프로필 12개**, 결제 전 실패·무차감·ESC 거점 복귀, 성공/사망 전리품 정산, P5-01~10의 선택→견적→실전→복원, 중·대형 10분 논리 세션, 방·통로 안개 전환은 자동 완료했습니다.
