안개 검사는 단순 상태 전환 외에도 문 안팎을 여섯 번 왕복했을 때 완전 개방이 유지되는지, 180도 입력에서 시야가 즉시 반전되지 않는지, 생성된 벽 충돌체를 맞은 차폐 광선이 실제로 존재하는지 확인합니다. 다른 방으로 빠르게 이동하면 이전 방과 새 방의 별도 혼합값을 함께 관측하며, 재진입 뒤 방문 방 수가 유지되어야 통과합니다.

사이버펑크 표현 계층도 같은 세션에서 검사합니다. 오버레이가 뷰포트 전체를 덮되 입력을 가로채지 않는지, 핵심 신호색이 정확히 `#02e5e1`인지, Feature Manifest에서 끄면 표현 노드만 빠지고 플레이 규칙은 유지되는지를 확인합니다.

## 플레이어 인식 계약

`PlayerPerceptionJudge`는 화면 안에서 실제로 보이는 Label·Button과 아이콘의 접근성 툴팁을 수집해 의미 단서를 검사합니다. 테스트가 내부 값만 보고 통과하지 않도록 입력 전후 키 배지·자원 숫자·월드 이동량뿐 아니라 대시의 표현 강도·궤적 표본·카메라 리드도 함께 증거로 전달합니다.

| 단위 | 체크포인트 예시 | 실패 예시 |
|---|---|---|
| 방향·선택 | 거점 목표, I/U/E/K, 장비·개조 정보 | 기능은 열리지만 무엇을 바꾸는 화면인지 설명 없음 |
| 결정·한눈 정보 | 작전 비용·위험·회수, 전투 HP·에너지·대시 | 투입 버튼은 있으나 비용·결과를 판단할 단서 없음 |
| 행동·자원 피드백 | Q, 점멸, 대시, 자원 회수 | 내부 슬롯·쿨타임·크레딧만 바뀌고 보이는 문구는 그대로 |

## 사람 검수 원칙

- 클릭·키 입력 한 번이 두 화면을 동시에 토글하지 않아야 합니다.
- 모달이 열리면 뒤의 거점·전투 HUD가 시각적으로 경쟁하지 않아야 합니다.
- 숫자는 내부 계산 명칭이 아니라 플레이어가 해석하는 의미로 표시합니다.
- 내부 상태가 변해도 플레이어가 볼 수 있는 문구·수치·움직임 중 하나가 변하지 않으면 실패입니다.
- 같은 동작은 데스크톱과 Web에서 동일한 InputMap Action을 사용합니다.
- 한 판 성공뿐 아니라 사망 후 복귀와 재투입도 연속으로 검사합니다.

## 배포 전체·부분 응답 QA · 2026-09-05 {#deployment-full-response-qa-2026-09-05}

실서비스 외부 요청에서 Range 헤더가 없는 게임 홈과 Windows ZIP이 `206 Partial Content`로 반환되는 현상을 발견했습니다. R2 전체 객체에도 전체 범위 메타데이터가 들어올 수 있는데 Worker가 이를 클라이언트의 부분 요청으로 오판한 것이 원인이었습니다.

| 사용자 요청 | 합격 응답 |
|---|---|
| 게임 홈·게임 자산 전체 `GET` | `200`, `Content-Range` 없음, 전체 `Content-Length`, `Accept-Ranges: bytes` |
| Windows ZIP 전체 `GET`/`HEAD` | `200`, 다운로드 파일명·전체 길이 유지 |
| 명시적 `Range: bytes=0-31` | `206`, 정확한 `Content-Range`, 본문 32바이트 |

로컬 Worker 계약은 실제 R2처럼 전체 객체에도 range descriptor를 제공해 오판 회귀를 재현합니다. main 배포 E2E는 게임 홈과 ZIP의 `200`, Range 자산의 `206`, 체크섬과 배포 커밋을 함께 확인해야 통과합니다. 같은 QA 라운드에서 실제 입력 E2E 31개 인식 체크포인트·15개 인과 흐름, P5/P6 계약, 57개 기능·231개 클래스·순환 0개, 대형 전장 평균 6.88ms 성능 예산을 통과했습니다.
