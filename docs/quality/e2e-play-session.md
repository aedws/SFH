# 실제 플레이 세션 E2E 검수

이 문서는 기능이 존재하는지만 확인하지 않고, 플레이어가 실제로 누르는 키와 화면 전환 순서에서 한 판이 끝까지 이어지는지를 검사합니다. 23개 UI 상태 계약과 별도로 20개 플레이어 인식 체크포인트를 두어 **단서가 읽히는지, 입력 결과가 보이는지, 성공·실패의 의미가 구분되는지**를 판정합니다.

## 실행

PowerShell 실행 정책에 영향받지 않는 명령은 다음과 같습니다.

```powershell
.\scripts\test-e2e.cmd
```

세부 계약 스모크와 성능 예산까지 한 번에 재검사하려면 다음 순서로 실행합니다.

```powershell
.\scripts\test-e2e.cmd
.\scripts\test-game.cmd
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\test-performance.ps1
.\scripts\wiki.cmd build
```

| 실패 정산 | 재투입 후 체력 0 → `Enter` | 피격 반응, 생존·처치·분실을 읽고 거점 안내가 복원 | 통과 |

자동화는 `game/tests/e2e_play_session_test.gd`가 소유합니다. 기능 내부 함수를 순서대로 호출하는 대신 `InputEventKey`와 지속 이동 Action을 전달하여 Web과 데스크톱의 입력 라우팅 차이도 회귀 범위에 포함합니다. 테스트 전용 프로필·랭킹·외부 성장·키 설정 경로를 사용하므로 실제 플레이 저장 데이터는 읽거나 지우지 않습니다.

## UI 상태 판정 계약

실제 입력 순서마다 `UIStateJudge`가 현재 화면을 스냅샷으로 읽습니다. 단순 `visible` 값이 아니라 상위 노드까지 반영한 유효 표시 상태, 일시정지, 열린 모달 수, 장비 탭, 1280×720 기준 화면 경계와 HUD 교차 영역을 함께 판정합니다.

| 상태 | 반드시 표시 | 반드시 숨김 | 정지 | 추가 판정 |
|---|---|---|---:|---|
| 거점 | 거점 HUD | 작전 설정·전투 HUD·결과·모달 | 아니요 | 거점 HUD가 화면 안에 위치 |
| K 키 설정 | 키 설정 | 거점·전투·다른 모달 | 예 | 모달 정확히 1개, 화면 안에 위치 |
| I 가방 | 가방 | 거점·전투·다른 모달 | 예 | 모달 정확히 1개, 화면 안에 위치 |
| U 장비 | 장비 편집 | 거점·전투·다른 모달 | 예 | 장비 탭 0, 모달 정확히 1개 |
| E 모듈·파츠 | 장비 편집 | 거점·전투·다른 모달 | 예 | 개조 탭 1, 모달 정확히 1개 |
| 작전 설정 | 브리핑·계약·투입 확정 | 거점·전투·결과·모달 | 예 | 1180×660 패널과 양쪽 열·투입 버튼이 화면 안에 위치 |
| 전투 | 임무·플레이어 주변 생존/장비/무기·행동 도크·미니맵·스킬·대시 | 거점·설정·결과·모달 | 아니요 | 16개 벡터 아이콘과 8개 현재 키, 모든 HUD 경계·상호 비겹침 |
| 내부 증강 선택 | 세로 카드 3장 | 모든 전투 HUD·다른 모달 | 예 | 3장 모두 화면 안, 첫 카드 포커스, 계열·효과·키 안내 표시 |
| 전투 중 I/U/E | 선택 모달 1개 | 모든 전투 HUD·다른 모달 | 예 | 닫으면 전투 HUD와 진행 상태 복원 |
| 성공·실패 결과 | 결과 화면 | 전투 HUD·미니맵·스킬·대시·상호작용 | 예 | 결과 화면만 화면 안에 위치 |

현재 E2E는 이 계약을 거점 시작부터 성공 복귀, 재투입, 사망 결과와 실패 복귀까지 **23개 전환 지점**에서 판정합니다. 실패 시 `내부 증강 3장 선택/run_buff_choice · 필수 레이어가 보이지 않습니다`처럼 상태·맥락·위반 레이어를 함께 출력합니다.

사이버펑크 표현 계층도 같은 세션에서 검사합니다. 오버레이가 뷰포트 전체를 덮되 입력을 가로채지 않는지, 핵심 신호색이 정확히 `#02e5e1`인지, Feature Manifest에서 끄면 표현 노드만 빠지고 플레이 규칙은 유지되는지를 확인합니다.

## 플레이어 인식 계약

`PlayerPerceptionJudge`는 화면 안에서 실제로 보이는 Label·Button과 아이콘의 접근성 툴팁을 수집해 의미 단서를 검사합니다. 테스트가 내부 값만 보고 통과하지 않도록 입력 전후 키 배지·자원 숫자·월드 이동량뿐 아니라 대시의 표현 강도·궤적 표본·카메라 리드도 함께 증거로 전달합니다.

| 단위 | 체크포인트 예시 | 실패 예시 |
|---|---|---|
| 방향·선택 | 거점 목표, I/U/E/K, 장비·개조 정보 | 기능은 열리지만 무엇을 바꾸는 화면인지 설명 없음 |
| 결정·한눈 정보 | 작전 비용·위험·회수, 전투 HP·에너지·대시 | 투입 버튼은 있으나 비용·결과를 판단할 단서 없음 |
| 행동·자원 피드백 | Q, 점멸, 대시, 자원 회수 | 내부 슬롯·쿨타임·크레딧만 바뀌고 보이는 문구는 그대로 |
| 상태·결말 | 탈출 시작/정지/재개, 성공/실패 | 카운트다운은 멈췄지만 이유가 없거나 성공·실패 손익이 구분되지 않음 |
| 연속성 | 모달 종료·정산 후 복귀 | 창은 닫혔지만 전투 HUD나 거점 방향 안내가 복구되지 않음 |

현재 **20개 체크포인트와 9개 인식 단위**를 자동 판정합니다. 전체 기능군의 자동·부분·수동 범위와 다음 검수 순서는 [플레이어 인식 단위 E2E 감사](player-perception-audit.md)에 정리합니다.

## 브라우저 육안 검수 목록

| 화면 | 사람이 확인할 항목 | 판정 |
|---|---|---|
| 시작 거점 | 한글, 안내 문구, 상단 HUD 겹침, 게이트 식별성 | 통과 |
| I 가방 | 상세 패널·격자·용량 정보가 한 화면에 유지되는지 | 통과 |
| U 장비 | 슬롯·선택 장비·후보 카드와 호환 요약이 오해 없이 읽히는지 | 통과 |
| E 모듈·파츠 | U 화면이 닫히지 않고 탭·제목·키 배지가 함께 바뀌는지 | 수정 후 통과 |
| 작전 브리핑 | 좌측 임무·회수와 우측 조건·위험·투입이 1280×720 안에서 균형 있게 읽히는지 | 통과 |
| 전투 HUD | 좌측 338×108 임무, 플레이어 주변 224×86 생존 코어·장비·무기, 우측 세로 스킬과 모서리 행동 도크의 비겹침 | 자동 통과 |
| 행동 직후 | Q 현재 무기, 점멸 재사용·에너지, 대시 사용 상태가 입력 직후 구분되는지 | 자동 통과 |
| 내부 증강 | 3장 카드의 계열·이름·STACK·효과·선택 키가 같은 순서로 비교되는지 | 자동 통과 |
| 정산 | 성공은 정산, 실패는 분실을 명시하며 같은 복귀 입력을 안내하는지 | 자동 통과 |

브라우저는 키 이벤트의 물리 키 정보가 항상 동일하지 않습니다. 그러므로 화면 탭 선택은 물리 키 값을 다시 해석하지 않고 `toggle_equipment`, `toggle_modification`이라는 독립 InputMap Action을 소비합니다.

## 이번 검수에서 발견하고 바꾼 것

| 오작동처럼 보인 상태 | 원인 | 변경 후 |
|---|---|---|
| U 화면에서 E를 누르면 창이 닫힘 | U와 E가 같은 Action을 공유하고 물리 키 이벤트에 다시 의존 | U·E Action을 분리하고 열린 창에서는 목표 탭 전환 |
| 장비 화면에 `활성 스킬 2/3` 표시 | 실제 발동 슬롯이 아니라 장비 태그 호환 수를 활성 수처럼 표현 | `장비 태그 호환 2/3`으로 의미 명시 |
| 전투 안내가 1·2·3만 암시 | 현재 1~9 슬롯·좌클릭 기본기 계약보다 오래된 Scene 문구 | 런타임 안내를 `LMB 기본기 · 1~9 스킬` 기준으로 통일 |
| 성공·실패 결과 뒤로 전투 HUD가 남음 | 정산 오버레이만 켜고 전투 HUD·미니맵·스킬·대시를 종료하지 않음 | 정산 진입에서 활성 전투 UI를 한 번에 숨기고 결과 화면만 유지 |
| 상단 카드가 전장을 넓게 가림 | 모든 작전·생존·장비 정보를 1040px 상단 카드 한곳에 배치 | 임무는 좌측 상단, 생존·무기·스킬은 하단 중앙으로 나눠 중앙 전장 시야 확보 |
| 거점 Q 교체가 된 것인지 알 수 없음 | 교체 결과가 숨겨진 전투 HUD 상태 문구에만 기록 | 거점 조작 안내 끝에 `현재 무기명`을 표시하고 Q 전후 변화를 E2E로 비교 |
| 대시 HUD에 `SHIFT / SPACE`가 고정 표시 | 자유 키 설정과 무관한 예전 키 이름이 제목에 잔존 | 제목을 키 비종속 `DASH · 회피`로 바꾸고 실제 Space 입력 뒤 상태 변경 판정 |

## 사람 검수 원칙

- 클릭·키 입력 한 번이 두 화면을 동시에 토글하지 않아야 합니다.
- 모달이 열리면 뒤의 거점·전투 HUD가 시각적으로 경쟁하지 않아야 합니다.
- 숫자는 내부 계산 명칭이 아니라 플레이어가 해석하는 의미로 표시합니다.
- 내부 상태가 변해도 플레이어가 볼 수 있는 문구·수치·움직임 중 하나가 변하지 않으면 실패입니다.
- 같은 동작은 데스크톱과 Web에서 동일한 InputMap Action을 사용합니다.
- 한 판 성공뿐 아니라 사망 후 복귀와 재투입도 연속으로 검사합니다.

## 후속 검수

기능 보유와 플레이어 인식 보증 사이에 남은 공백은 [플레이어 인식 단위 E2E 감사](player-perception-audit.md)의 P1·P2 목록을 기준으로 진행합니다. 우선순위는 마우스 기본기→명중→처치→드랍 사슬, 방 진입→봉쇄→보상 사슬, 중·대형 10분 동선, 전장의 안개 실제 렌더링 순서입니다.
