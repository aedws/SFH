## 진행률의 분모

공개 GDD v128·62블록과 트래커 66행을 라이브 재조회했습니다. 해시는 기존과 동일합니다. 연결 Notion 앱은 접근 오류가 있어 공개 원문 수집기로 확인했으며, 원문 편집 시각과 이번 확인 시각을 구분합니다.

| 범위 | 계산과 결과 | 해석 |
|---|---|---|
| 노션 전체 가중 대응도 | `(45×3 + 1×0.5×3) / (52×3 + 14) = 80.3%` | 확정 3, 미정 1 가중치 유지 |
| 노션 미정 14행만 제외 | `136.5/156 = 87.5%` | 확정 요구에도 미구현 6행이 남음 |
| 선행 정책 대기 6행까지 별도 제외한 참고값 | `136.5/138 = 98.9%` | 46행 중 구현 근거45·부분1. 전체 제품 완료율이 아님 |

파우치2·심층3·혈전1은 노션에 요구가 있지만 오너의 상세 정책 선택을 기다리는 **미구현**입니다. 제외한다고 구현 완료로 바꾸지 않습니다. 새로운 훈련장 오류는 노션 66행의 별도 요구가 아니므로 위 분모에 임의로 한 행을 더하지 않습니다. 별도 품질 게이트가 실패했으므로 참고값이 높아도 **전체 완료 판정은 미달**입니다. 신규 스킬·장비·위키 도구 역시 노션 점수에 중복 가산하지 않습니다.

### QA-LIVE-TRAINING 재현 근거 {#qa-live-training}

공개 배포나 Google Sheet의 값을 바꾸지 않고 격리된 서비스 fixture에 라이브 값을 넣었습니다. 플라스마 창의 시험값을 피해123·쿨타임3초로 설정했을 때 결과는 다음과 같습니다.

```text
AUDIT_LIVE_TRAINING training_damage=32.0 operation_damage=123.0 training_cd=8.0 operation_cd=3.0
```

검사 경로: `skill_balance_values`에 시험값 → `get_skill_catalog_resources()`의 같은 ID → `SkillBalanceSnapshot.apply()`의 작전 정의와 비교. `Game`의 `get_skill_catalog_resources` 호출부와 `TrainingGroundService`의 카탈로그 소비도 소스에서 대조했습니다. 기존 회귀에 훈련/작전 라이브 동등성 검사가 없어 green CI만으로 발견되지 않았습니다. 현재 잠금 CSV 모드의 기본값이 모두 깨졌다는 뜻은 아닙니다.
