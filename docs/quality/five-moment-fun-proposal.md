# 한 판의 다섯 순간 — 재미 선명화 제안서

**작성일:** 2026-09-06 · **상태:** 제안 / 오너 판단 대기 · **판단 주체:** 프로젝트 오너(사용자)

이 문서는 구현 명령이나 확정 기획이 아닙니다. 작성 기준은 저장소 `89c9690`의 코드·CSV·기능 문서와 사용자 대화입니다. 신규 인간 플레이테스트나 Notion 재대조를 실시한 결과로 취급하지 않습니다. 기획자는 의도·콘텐츠·수치 초안을 보완하고, 개발자는 구현 경계와 검증 근거를 제공하며, 채택·보류는 오너가 판단합니다.

## 1. 제안 요약 {#summary}

> 적을 시원하게 정리하고, 탐나는 장비를 발견하고, 더 가져갈지 살아서 나갈지 고민하게 만든다.

권장 방향은 **기능 수를 늘리기보다 한 판 안에서 행동과 보상의 관계를 선명하게 만드는 것**입니다. 설명문·전체 화면 효과를 추가하는 방식보다 짧은 단서, 구분되는 반응, 실제 선택 결과를 우선합니다.

| 순간 | 플레이어가 느껴야 할 것 | 핵심 변경 제안 | 전달됐다는 관찰 신호 |
|---|---|---|---|
| 첫 교전 | 내가 움직이고 공격해서 돌파했다 | 발사·명중·처치·방 확보의 반응 구분 | 다음 적을 스스로 찾아가고 회피를 시도 |
| 첫 장비 획득 | 이 장비를 써보고 싶다 | 용도 차이 한 줄과 간결한 비교·장착 동선 | 어떤 상황에 쓸지 말하고 실제로 시험 |
| 첫 강화 | 방금 선택해서 강해졌다 | 기존 런 버프의 원인·결과 비교 | 강화의 변화를 안내 없이 설명 |
| 탈출 판단 | 더 벌고 싶지만 잃기는 싫다 | 반출 예상·위험 원인·탈출 조건 분리 | 계속 탐험하거나 탈출하는 이유를 설명 |
| 정산 이후 | 다음 판에는 이것을 해보고 싶다 | 획득 결과와 다음 행동 연결 | 재도전 권유 없이 다음 목표를 선택 |

관찰 신호는 재미의 **단서**이지 증명은 아닙니다. UI를 이해해도 지루할 수 있고, 다시 출격하지 않아도 시간이 부족한 것일 수 있습니다. 행동·이유·불편을 함께 기록합니다.

### 이번 제안에서 하지 않는 것

- 게임 코드·경제·드랍표·저장 데이터 변경, 신규 에셋 구매, 과금 설정 변경.
- 제안서를 기획 확정·구현 완료·진행률 상승으로 자동 집계.
- 정상 플레이에 강제 튜토리얼, 강제 장비 교체, 강제 재출격 추가.
- 인간 검수를 E2E 성공으로 대체하거나, 미실시 테스트에 점수를 부여.

## 3. FUN-01 — 첫 교전: 입력이 쾌감으로 돌아오는 순간 {#first-combat}

**목표 감정:** “내가 때려서 쓰러뜨렸다. 조금 더 잘 움직이면 더 멋지게 잡겠다.”

**가설:** 발사와 명중이 비슷하게 보이거나 적의 죽음이 드랍·방 확보에 묻히면 공격의 성과를 놓칠 수 있습니다. 강한 흔들림만 더하면 오히려 조준 없는 전투의 상황 파악을 방해할 수 있습니다.

**최소 개선안**

1. 반응을 네 층으로 분리합니다. 발사는 작은 총구 반응, 명중은 대상 중심의 짧은 충격, 처치는 뚜렷한 소멸·드랍, 마지막 적은 짧은 방 확보 신호입니다. 발사만으로 명중 효과를 재생하지 않습니다.
2. 최초 교전에서는 이동 방향과 적 접근이 읽히는 여백을 확보합니다. 밀집감은 적을 겹쳐 놓는 대신 경로와 등장 간격으로 만듭니다. 기존 최소 스폰량·전체 예산은 임의로 낮추지 않습니다.
3. 소리는 기본기·명중·처치·위험 중 구분력이 높은 소수부터 시험합니다. 동시 재생 상한·음량 조절·음소거를 두고 시각 단서도 유지합니다. 사용 에셋은 별도 라이선스 검토 후 도입합니다.
4. 화면 전체 점멸·상시 카메라 흔들림은 피합니다. 기존 효과 상한과 중앙 시야 보호를 유지하고 효과 축소 상태에서도 결과가 읽히게 합니다.

**시험 장면:** 별도 QA 프로필과 고정 seed로 첫 교전 30초를 관찰합니다. 시간은 작전 진입 이후 기준이며, 실제 출격 경로인 로비→게이트 F는 생략하지 않습니다. 적 수를 바꾸는 비교안은 승인 전 테스트용으로만 격리합니다.

**관찰 질문:** 무엇이 맞았는지 알았나? 왜 피해를 받았는지 알았나? 적을 잡은 뒤 다음 행동을 스스로 골랐나? 타격을 구분해도 쾌감이 없었다면 별도로 실패 원인을 적습니다.

## 4. FUN-02 — 첫 장비: 숫자가 아니라 새로운 사용법을 발견 {#first-loot}

**목표 감정:** “이건 지금 무기보다 숫자만 높은 게 아니라, 저 무리에 써보고 싶다.”

**최소 개선안**

1. 획득물은 `이름 / 용도 한 줄 / 현재 장비와 핵심 차이 / 반출 상태` 순으로 보여줍니다. 모든 옵션·태그·파츠 설명은 상세 보기에 둡니다.
2. 예시 문구는 “펄스 소총 · 명중한 적 주변에 전기 피해”입니다. 돌격소총의 ‘세 번 명중마다 단일 전격’과 구분합니다. 설명대로 실제 고유 효과가 발동해야 하며, 더 높은 DPS라는 이유만으로 모든 장비에 ‘추천’을 붙이지 않습니다.
3. 보관·즉시 장착·그대로 두기의 결과를 구분합니다. 가방 부족, 태그 불일치, 미저장 세팅이 있으면 원인을 설명하고 기존 거래·저장 확인을 우회하지 않습니다. 장착 가능한 행동만 제공하고 기존 로비 장비를 덮어쓰지 않습니다.
4. 획득 직후 다음 안전한 교전에서 사용 차이를 확인할 기회를 줍니다. 보라색 광기둥이나 긴 팝업보다 장착 전후 결과가 기억에 남아야 합니다.

**시험 장면:** QA 전용 seed에서 기능 차이가 있는 장비를 첫 획득 후보로 확보해 UI를 비교합니다. 일반 작전의 첫 드랍 보장·희귀도·드랍률 변경은 별도 안이며, 이번 제안 채택만으로 바꾸지 않습니다. 이후 무작위 seed에서 장비가 늦게 나오는 경험도 확인합니다.

**관찰 질문:** 비교창을 닫은 뒤 장비의 특징을 설명하나? 스스로 써보거나 보관을 선택하나? 거절도 합리적 선택이므로 장착률만으로 합격시키지 않습니다.

## 5. FUN-03 — 첫 강화: 선택 직전과 직후가 연결됨 {#first-growth}

**목표 감정:** “내가 고른 강화 때문에 방금과 달라졌다.”

**최소 개선안**

1. 카드의 첫 문장은 결과를 설명합니다. 예: `고속 순환 — 일반 공격이 더 자주 나갑니다`, 아래에 현재→적용 후 발사 간격과 ‘이번 작전 한정’을 표시합니다. 정확한 수치는 기존 공급자가 계산합니다.
2. 강화 후 짧은 아이콘 반응으로 적용 사실을 알리고 바로 전투로 돌아갑니다. 이미 선택한 강화를 재확인할 수 있지만 상시 긴 설명은 표시하지 않습니다.
3. 첫 비교 실험은 기존 `고속 순환` 또는 `화력 과부하`를 사용합니다. 같은 적 종류·방어·난이도·장비 조건에서 강화 전후 결과를 비교하고 시간 경과 난이도 상승을 분리합니다.
4. 현행 공격 간격 -10%가 읽히지 않으면 표현 개선안과 수치 개선안을 별개로 시험합니다. 후자는 **QA 후보로만 -15% / -20%**를 비교하고, 처리량·생존 압박을 보고 채택합니다. 발사 간격 -20%는 공격 횟수 단순 +20%와 같지 않으므로 실제 발사·명중 로그로 확인합니다.

**보호 규칙:** 런 버프가 무기 고유 효과·고정 옵션의 정의나 피해 수치를 바꾸지 않습니다. 발사 빈도 변화로 고유 효과가 더 자주 발생하는 간접 효과는 따로 계측합니다. 중첩 상한과 강화 해제·작전 종료 초기화를 유지합니다. 생존·방어 선택도 첫 카드에서 배제하지 않습니다.

**관찰 질문:** 카드 설명을 다시 보여주지 않았을 때 무엇이 바뀌었는지 말하나? 달라진 것을 알아도 재미가 없다면 선택 폭·전투 요구와의 관계를 추가 조사합니다.

## 6. FUN-04 — 탈출 판단: 회수의 기쁨과 위험의 이유를 연결 {#extraction-choice}

**목표 감정:** “이 정도면 가져가고 싶다. 하지만 다음 방에는 더 탐나는 것이 있다.”

**최소 개선안**

1. `휴대 중 / 탈출 시 예상 / 사망 시 소실`을 구분합니다. 아이템 가치가 아직 정의되지 않았다면 ‘미평가’로 표시하고 크레딧과 임의 합산하지 않습니다. 최종 정산은 기존 정산 서비스가 결정합니다.
2. 크레딧 회수액이 기존 50% 임계에 가까워지면 작은 위협 단서를 제공하고, 생성 순간 “회수 신호 감지 → 추격 보스”를 연결합니다. 임계·생성 시점·방 독립 추격은 그대로 둡니다. 100 C 진입의 50 C 회수는 보스 임계이지 손익분기점이 아님을 혼동하지 않게 합니다.
3. 출격 전에 무료 작전도 첫 1 C에서 추격이 시작되는 현행 규칙을 보여줍니다. 이것이 초보자에게 불공정하게 느껴지면 증거와 함께 별도 변경 안건으로 올립니다. 이번 안에서 몰래 유예하지 않습니다.
4. 탈출이 아직 잠겨 있으면 잠금 이유와 개방 조건을, 이미 가능하면 현재 경로와 방어전 요구를 표시합니다. 완주 조기 탈출과 시간 개방의 기존 조건을 존중하며 연출용 목표 시간 때문에 새로 잠그지 않습니다.
5. 보스 처치의 현재 보상이 충분히 읽히는지 먼저 점검합니다. 고유 보상·추가 선택 보상 신설은 경제를 바꾸므로 별도 승인·목록 검증 대상으로 둡니다.

**시험 장면:** 임계 직전/도달/처치/생존 추격, 유료·무료 작전, 탈출 잠금/시간 개방/완주 조기 개방을 구분합니다. 첫 회수 전에 위험을 예상했는지와 회수 자체를 기피하게 되었는지를 기록합니다.

**관찰 질문:** 왜 보스가 왔는지 설명하나? 지금 나갈 수 있는지 아나? 계속 탐험하거나 탈출하는 이유가 있나? 오래 남았다는 이유만으로 재미에 성공했다고 판단하지 않습니다.

## 7. FUN-05 — 정산 이후: 다음 판의 이유를 남김 {#next-run}

**목표 감정:** “가져온 것이 남았다. 다음에는 이것으로 저 상황을 해결해 보고 싶다.”

**최소 개선안**

1. 정산 첫 화면을 세 줄로 압축합니다. `가져온 것 / 영구적으로 남은 변화 / 잃거나 작전 종료로 사라진 것`입니다. 계산 상세는 펼쳐 봅니다.
2. 실제 반출한 장비·해금이 있다면 하나를 골라 다음 행동에 연결합니다. “로비에서 장착 확인” 또는 “해금 목록 확인”처럼 상태에 맞는 안내를 주고 없는 보상을 꾸며내지 않습니다.
3. 사망 시 손실 규칙을 유지하면서 마지막 피격 원인·회수 실패·해결 가능한 행동을 보여줍니다. 근거를 수집하지 못한 사망 원인은 추정으로 단정하지 않습니다. 패배 보상이나 로드아웃 환급은 이 안에 포함하지 않습니다.
4. 거점 복귀 시 세팅을 보존하고 해당 장비를 찾기 쉽게 합니다. 다음 출격은 항상 로비 게이트에서 사용자가 결정합니다. 결과창의 ‘다음’으로 자동 출격시키지 않습니다.

**시험 장면:** 가치 있는 반출/소액 반출/빈 반출/사망/이미 해금된 중복 획득을 포함합니다. 영구 결과의 중복 지급·재접속 복원도 자동 검사합니다.

**관찰 질문:** 무엇이 남았고 어디서 쓰는지 설명하나? 실제 가능한 다음 목표를 고르나? 시간이 충분하고 종료가 자유로운 상황에서 다시 출격하고 싶어 하는지, 그 이유는 무엇인지 기록합니다.

## 8. 실행 순서와 승인 단위 {#priorities}

먼저 **관찰과 계측 → 표현 개선 → 필요할 때만 수치·보상 변경** 순서로 진행합니다. 다섯 안을 한꺼번에 적용하면 무엇이 좋아졌는지 판별하기 어렵습니다.

| 순서 | 제안 묶음 | 우선하는 이유 | 종료 또는 중단 기준 |
|---|---|---|---|
| 0 | 현행 한 판 관찰·기준 기록 | 느낌과 실제 결함을 분리 | 첫 플레이 기록 없이 개선 성공 선언 금지 |
| 1 | FUN-01 교전 반응 | 반복하는 행동 자체가 즐거워야 함 | 인식은 개선돼도 가림·피로·성능 저하가 생기면 축소 |
| 2 | FUN-03 강화 인과 | 첫 판 안에서 상승을 느끼게 함 | 표현만으로 부족할 때만 수치 실험 승인 요청 |
| 3 | FUN-02 장비 용도·선택 | 획득물을 다음 전투의 이유로 만듦 | 획득 팝업이 전투를 끊거나 보관 실패 시 수정 |
| 4 | FUN-04 위험·탈출 판단 | 파밍이 무조건적인 벌이 되는지 검증 | 임계 설명 후에도 무료 첫 회수 회피가 반복되면 규칙 재검토 |
| 5 | FUN-05 정산·다음 목표 | 판의 성과를 다음 시도로 연결 | 자동 출격·허위 보상·중복 지급은 즉시 실패 |

권장 첫 승인 범위는 **0번 현행 관찰과 1번 표현 중심 프로토타입**입니다. 모든 수치·첫 드랍 보장·추격 임계·보상 변경은 별도 승인 상태를 유지합니다. 일정·공수는 첫 관찰에서 발견한 결함과 필요한 에셋 범위를 확인한 후 산정합니다.

## 9. 모듈화와 데이터 경계 {#module-boundaries}

아래 이름은 새로 구현됐다는 뜻이 아니라 연결 책임에 대한 제안입니다. 기존 공개 계약을 우선 재사용하고, 필요한 관찰 사건이 없을 때만 최소 Signal/스냅샷을 추가합니다.

| 책임 | 기존 기반 또는 확장 지점 | 금지할 결합 |
|---|---|---|
| 타격·소리 표현 | hit_feedback·boss_warning 소비자, 별도 음성/효과음 정책 | 표현기가 피해·처치·보스 생성 규칙 변경 |
| 장비 비교 | 전리품 비교 Presenter와 장비 정체성 스냅샷 | UI가 인벤토리 배열·저장 데이터를 직접 수정 |
| 강화 설명 | run_buffs·growth_balance 제공자의 적용 전후 값 | 설명 문구에 별도 수치 계산식을 하드코딩 |
| 위험·반출 예상 | 작전 계약·회수 원장·추격·정산 공개 스냅샷 | HUD가 보스를 생성하거나 재화를 지급 |
| 정산 요약 | 확정 정산 결과를 읽는 Presenter | 결과창을 열 때마다 지급·해금 재실행 |
| 재미 관찰 | 선택적 로컬 이벤트 기록기 | 게임 진행이 기록 서버나 기록기 활성화에 의존 |

표현·관찰 모듈을 껐을 때 피해·드랍·계약·정산·저장 결과는 같아야 합니다. 전투 규칙을 바꾸는 정책 실험은 별도로 켜고 끄며 동일 seed로 비교합니다. 최상위 Game에는 제안별 예외 분기를 누적하지 않습니다.

현재 제안은 새 게임 목록을 만들지 않으므로 **Google Sheet와 CSV를 수정하지 않습니다.** 승인 후 기존 버프 수치만 조정하면 기존 시트를 사용합니다. 소리 카탈로그·새 보상 목록처럼 실제 목록이 필요해지면 기존 상시 허가 범위에서 시트를 확장하되 1행 변수명·2행 한국어 설명·3행부터 데이터, 실시간 시험→확정 CSV·Web 공급자·버전·검증 계약을 유지합니다.

## 10. 사람 플레이 검수 계획 {#human-test}

### 방법

- 1차는 SFH를 처음 접하는 사람 4~6명의 탐색적 검수입니다. 통계적 재미·리텐션 검증 표본으로 사용하지 않습니다. 기기, 입력 방식, 유사 장르 경험을 기록하며 모바일 결과와 PC 결과를 섞어 해석하지 않습니다.
- 1인당 첫 시도 약 15분을 관찰하고 추가 플레이 시간과 짧은 회고 시간을 둡니다. 참여자가 원하면 언제든 중단합니다. 전체 약 25~35분은 운영용 가안이며 한 판의 강제 제한 시간이 아닙니다.
- 진행자는 조작·메뉴를 먼저 설명하지 않습니다. 막혀 도움을 요청하면 도와주되 도움 전 행동과 시각을 기록합니다. 교전 중 계속 말하게 하기보다는 순간별 사후 질문을 사용합니다.
- 첫 회차는 현행 문제 발견용입니다. 프로토타입 비교는 별도 신규 참여자를 조건별로 배정하고 기기·seed·장비·난이도를 맞춥니다. 같은 사람의 재시험은 숙련 영향이 있으므로 ‘신규 플레이 개선’으로 단정하지 않습니다.
- UI를 보는 고정 seed 시험과 자연스러운 무작위 한 판을 분리합니다. 확률상 첫 장비가 나오지 않았다면 `미관찰`로 남기고 UI 이해 실패와 보상 간격 문제를 구분합니다.

### 기록할 것

| 항목 | 기록 방식 |
|---|---|
| 맥락 | 익명 참여자 ID, 빌드 SHA, 데이터 버전, seed, 기기·해상도·입력, 초기 로드아웃 |
| 순간 | 방 진입, 첫 발사·명중·처치, 첫 장비 확인·결정, 강화 선택·적용, 위협 임계, 탈출 선택·결과 |
| 행동 | 멈춤, 메뉴 왕복, 오입력, 도움 요청, 자발적 시험·회피·재출격 |
| 발화 | 정확한 짧은 인용과 관찰자의 해석을 분리 |
| 재미·이해 | 이해 여부, 즐거웠던/답답했던 장면과 이유, 다시 하고 싶은 이유·하지 않을 이유 |
| 미관찰 | 해당 순간 미도달·확률적 미발생·시간 부족을 실패와 구분 |

녹화는 동의를 받은 경우에만 하고 보관·삭제 시점을 정합니다. 초기에는 관찰표로도 충분하며 계정 정보·입력 키 전체·사용자 파일 경로를 수집할 필요가 없습니다. 이벤트 기록기를 추가한다면 로컬 저장과 비활성화를 기본으로 합니다.

### 판정 기준과 실험용 목표

다음은 **가안**입니다. 기준 기록을 본 뒤 오너가 조정하며 재미 점수로 자동 합산하지 않습니다.

- 첫 교전에서 발사·명중·처치의 차이를 구분하고 첫 장비·강화·정산의 결과를 자기 말로 설명하는지 확인합니다.
- UI 단독 비교 장면에서는 장비의 용도·보관 결과를 약 10초 안에 파악하는지 봅니다. 정상 전투 중에는 시간을 강요하지 않습니다.
- 대상 순간을 경험한 사람 중 2명 이상이 같은 핵심 오해·도움 요청을 반복하면 우선 수정 후보로 삼습니다. 미도달자를 분모에서 조용히 제외하지 않고 별도 표기합니다.
- 자발적 재출격은 횟수와 이유를 함께 기록합니다. 소수 표본의 재출격률을 ‘재미 검증 완료’ 또는 장기 잔존율로 발표하지 않습니다.
- 새로운 입력 차단·저장 손실·중복 지급·화면 가림·기존 성능 예산 초과가 발생하면 재미 평가와 무관하게 수정 또는 되돌립니다.

### 자동 검사와 인간 판단의 분리

E2E에는 이벤트 중복·명중 전 효과 금지·UI 비겹침·음소거/효과 축소 시 의미 유지·버프 전후 값 일치·50% 임계 불변·탈출 조건·정산 멱등성·관찰 모듈 off 시 동일 결과를 추가하는 것을 제안합니다. **이 테스트는 아직 추가하지 않았습니다.**

자동 PASS는 “올바르게 전달될 조건을 만들었다”는 뜻입니다. 시원함, 놀라움, 긴장감, 다음 목표에 대한 욕구는 인간 관찰 결과를 별도 근거로 남겨야 합니다.

## 11. 오너 판단표 {#owner-decision}

| 판단할 것 | 권장안 | 현재 상태 |
|---|---|---|
| 첫 실행 범위 | 현행 관찰 후 FUN-01 표현 프로토타입부터 | 제안 / 미승인 |
| 내부 강화 수치 | 현행으로 먼저 측정, 필요 시 격리된 비교 실험 | 제안 / 미승인 |
| 첫 장비 보장 | QA seed에서만 먼저 노출, 일반 드랍 보장은 보류 | 제안 / 미승인 |
| 추격 보스 | 50%·무료 최소 1 C·방 독립 규칙 유지, 원인 전달부터 | 제안 / 미승인 |
| 새 보상·패배 보상 | 경제 영향 검토 전 추가하지 않음 | 제안 / 미승인 |
| 최종 채택 | 인과·기능 회귀 + 인간 관찰 + 성능 근거로 오너 판단 | 제안 / 미승인 |

판단 기록 예시: `FUN-01 / 표현 프로토타입만 승인 / 피해·스폰 수치 유지 / 관찰에서 첫 처치 원인 혼동 재확인 / 실기 영상과 E2E 결과 제출 후 재판단`. 이 문구는 작성 예시이며 실제 승인이 아닙니다.
