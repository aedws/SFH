# 모바일 위키 반응형 E2E

## 판단 요청 최상단 안내 (2026-09-09)

기획자 작업실의 `decisions-needed`는 도구 바로가기보다 먼저 표시합니다. 파우치·심층·혈전·방탄복 성장의 질문/미승인 예시/수락 기준과 Notion 반영 후 오너 개인 메시지 전달 형식을 제공합니다. 추가 미정14행도 행별 질문과 미승인 예시로 설명하며 여섯 개 네이티브 details는 기본 접힘입니다. 키보드로 펼칠 수 있고 게임 정책·Sheet·기획 승인 상태는 바꾸지 않습니다.

생성 HTML 회귀는 최상단 순서·4개 판단 ID·오너 권한·미승인 표기·메시지 안내·원문 링크·접힘 상태를 검사합니다. 메시지 자동 발송이나 외부 Notion 쓰기는 구현 범위가 아닙니다. 반응형 렌더와 실제 브라우저 확인 결과는 해당 작업의 검증 기록과 구분합니다.

검증: `test_role_workspace.mjs`에서 기획자/개발자 × 320·390·768·1440px 총8조합 통과. 미정14건 보완 후에도 재실행해 기획자 판단 안내가 도구보다 먼저 표시되고 6개 항목의 Enter 열기/닫기·44px 터치 높이·가로 넘침 없음·초안 유지·바로가기 복귀를 확인했습니다. 로컬 인증 대역을 사용한 Chromium 검사이며 공개 로그인 검증과 구분합니다. 390px 실제 렌더 이미지도 읽고 확인했습니다.

## 효과·스탯 명세 툴킷 (2026-09-08)

`test_effect_toolkit.mjs`는 35개 변수·92개 대상별 현행 값과 범위·빈값·Notion 근거·원본 지문·기획/승인 분리·중복·CSV 줄바꿈·전기 광역 반경 조합·새 행동 분류를 통과했습니다. `test_effect_toolkit_ui.mjs`는 기획자/개발자 × 320·390·768·1440px에서 4종 대상 선택, 명세 생성, 빈 숫자 거절, 수정 후 기존 결과 숨김, 개발자 읽기 전용, 가로 넘침·스크립트 오류 0을 확인했습니다. 인증은 로컬 대역입니다. 결과 화면은 `outputs/effect-toolkit/`입니다.

실제 공유 시트의 EffectGuide 94행·10열, EffectSpec 6행·11열을 전수 읽어 쓴 값과 일치함을 확인했습니다. 두 설명 행 고정과 드롭다운을 적용하고 기존 Weapon·Skill·Character·Item의 읽은 범위 값·검증 규칙은 동일했습니다. 실제 `--sheet` 읽기로 4개 초안을 변경 계획으로 변환했습니다. 브라우저에서 탭·저장 상태도 확인했으나 시트 전체 캔버스의 시각 검수는 별도입니다. 게임 데이터는 수정하지 않았으며 새 효과의 플레이 검수 완료를 뜻하지 않습니다.

## 개발자 현행 밸런스 조회 (2026-09-08)

`test_balance_workbench_ui.mjs`를 headless Chromium 320·390·768·1440px에서 통과했습니다. 확정본 없음→현행 CSV 자동 공개, 일부 확정→확정안 우선/나머지 현행 목록 조회, 변수 변경→CSV 원본 값과 수치 표 일치, 새로고침→조회 선택 유지, 확정 API 장애→유무 판단 불가 표시, 카탈로그 장애→재시도 복구를 검사했습니다. 가로 넘침·브라우저 오류·개발자 값 편집기·개발자 확정 POST는 모두 0입니다. 화면 근거는 `outputs/balance-workbench/current-*.png`입니다. 인증과 저장소는 로컬 테스트 대역이며 운영 안건은 수정하지 않았습니다.

## 맵·피스 설계실 (2026-09-08) {#map-workbench}

`test_map_workbench_ui.mjs`로 기획자/개발자 각각 320·390·768·1440px를 실제 headless Chromium에서 검사합니다. 현행 맵 → 시드 비교 → 지역/규모 변경 → 필수 피스 위치 시험 → 잘못된 Notion 주소 거절 → 초안 생성 → 설정 변경 시 낡은 초안 무효화 → 원본 복원 → 잘못된 시드 복구가 범위입니다. 8개 조합에서 가로 넘침 0, 버튼 높이 44px 이상, 브라우저 스크립트 오류 0, 외부 POST 0을 확인했습니다. 지도 클릭과 동일한 공간 선택 목록을 제공하여 작은 지도·키보드에서도 피스를 선택합니다.

지도는 실제 건물·도로 배치까지만 대조합니다. 초안은 자동 제출/저장되지 않으며 사용자가 복사 후 Notion에 공유해야 합니다. 로컬 역할 인증은 mock이고 실서비스 보호는 Worker 비로그인 JSON 차단 및 배포 후 인증 검사로 별도 검증합니다. 화면 캡처는 `outputs/map-workbench/`에 남깁니다. 7개 작업 바로가기는 작은 화면에서 보조 꼬리표를 생략해 첫 화면 접근성을 유지합니다.

SFH 위키는 기획자가 **현재 결정과 진행 상태를 찾는 화면**이자 개발자가 **구현 계약과 검증 근거를 확인하는 화면**입니다. 콘텐츠가 존재하는지만 확인하지 않고, 작은 화면에서도 목적 문서를 발견하고 내용을 읽고 다음 문서로 이동할 수 있어야 통과합니다.

## 브라우저 E2E 계약

### 역할별 작업 블록 · 2026-09-08 {#role-workspace}

상단 6개 블록에서 일을 고르고 해당 설명·도구만 펼칩니다. 기획자는 수치 시험·요청·초안·구현 범위·시트·작성 가이드, 개발자는 판단·확정 그래프·코드·작업선·검증·원칙으로 진입합니다. 작은 화면에서는 보조 설명을 줄이고 제목과 작업 종류를 유지합니다.

- 같은 페이지 바로가기는 접힌 상위 블록을 열고 도착 지점으로 스크롤·키보드 포커스를 함께 이동합니다. 기존 앵커·판단 콘솔의 `view/decision` 직접 링크도 유지합니다.
- 블록을 접는 것은 편집 상태 삭제나 저장이 아닙니다. 초안·계산기 입력은 같은 페이지에서 접었다 펴도 유지되며, 자동 확정·자동 전송하지 않습니다.
- `role-workspace.css`는 역할 문서만 꾸미고, `role-workspace.js`는 공개된 앵커의 탐색만 담당합니다. 권한은 Worker, 계산·확정 저장은 기존 밸런스 모듈, 코드 지도 지연 로딩은 기존 지도 모듈이 소유합니다.
- `wiki_articles.py`가 Markdown 변환 **이후** 역할 컨테이너를 생성해 원시 HTML 요청 목록·폼이 코드 블록으로 잘리는 것을 방지합니다. 제거 시 이 컨테이너와 두 정적 자산만 제거하면 기존 문서·도구 계약이 남습니다.
- `test_role_workspace.mjs`: 320×568·390×844·768×1024·1440×900, 역할별 상단 블록·가로 넘침·키보드·직접 링크·초안 유지·요청 필터 DOM. `test_balance_workbench_ui.mjs`는 실제 서버 계산 모듈을 사용해 확정→읽기 전용 그래프 흐름을 별도 검사합니다. 인증·저장소는 로컬 테스트 더블이며 운영 인증 E2E와 구분합니다.

### 홈에서 작은 문서로 · 2026-09-07

- 공개 홈의 문서 진입은 `/access/login/?return=%2Ffeatures%2F`로 연결하고, 기존 로그인 상태에서도 종합 문서로 돌아와야 합니다. 비밀번호 변경 필수 상태와 역할별 접근 제한은 우선합니다.
- 종합 → 주제 → 세부 → 상위 경로 복귀는 빌드된 링크로 동작합니다. 제목 아래 문서 설명을 읽고 링크를 선택할 수 있습니다.
- 종합/작전/전투/전리품/성장/개발 구조의 구현 집계는 `notion-code-audit.json`에서 생성하며 트래커 해시가 다르면 빌드를 중단합니다. 공개 홈에는 내부 집계와 미구현 목록을 넣지 않습니다.
- 부분·미구현·충돌·미정은 기본 접음의 ‘남은 경계’ 안에서 구분하며, 문서 개선으로 게임 완료 숫자를 올리지 않습니다.
- `test_wiki_articles.py`가 전 문서 상하위 링크·집계·잔여 항목을 검증하고 `test_developer_workspace.mjs`가 네 폭×다섯 문서, 접기/펼치기, 두 역할의 기존 로그인 복귀를 검사합니다. 로컬 역할 응답은 테스트 더블이며 배포 인증 회귀는 실제 Worker 검사를 별도 수행합니다.

### 개발자 운영 작업대 · 2026-09-07

2026-09-08부터 첫 화면은 작업 바로가기이며 판단 콘솔·코드 지도·긴 운영 안내는 접혀 있습니다. ‘작업·오너 판단’에서 작업 개요를 열고 객체 선택→수락 조건→관계·계보→문서 근거로 이동합니다. 읽기 전용 온톨로지와 역할 인증은 유지합니다.

- 320·390·768·1440px에서 개요·검색·검사 패널·계보가 페이지 가로 넘침 없이 표시됩니다.
- 목록은 6개씩 표시하되 전체 등록 객체가 마지막 페이지까지 도달 가능해야 합니다.
- 선택·탭 전환 뒤 검색어·유형·상태·페이지를 유지하며 검색 결과가 없으면 오래된 검사 패널을 남기지 않습니다.
- 탭의 좌우 화살표·Home·End, URL 직접 진입·새로고침, 모바일 선택 뒤 검사 패널 포커스를 확인합니다.
- 코드 지도는 처음 펼칠 때 JSON을 한 번 요청하고 기본 접힘에서는 요청하지 않습니다.
- `scripts/test_developer_workspace.mjs`는 loopback에서 빌드된 HTML을 Chromium으로 검사하고 `outputs/developer-workspace/`에 화면을 저장합니다. 배포 인증 검사는 별도이며 로컬 서버를 인증 대체로 배포하지 않습니다.

재현: `scripts/wiki.ps1 build` → `.venv/Scripts/python.exe -m http.server 8767 --bind 127.0.0.1 --directory .wiki-site` → Playwright가 설치된 Node 환경에서 `node scripts/test_developer_workspace.mjs`. 게임 런타임·Notion 확정·진행률은 이 UI 검사로 변경하지 않습니다.

실측 결과: 네 폭 모두 개요·검사 패널 화면을 저장해 확인했고 전체 244개 객체 순회, 빈 검색, 필터 유지, 키보드 탭, 직접 링크 복원, 지도 지연 요청을 통과했습니다. 브라우저 JavaScript 예외 0건, 페이지 가로 넘침 0건입니다. 위키 strict 빌드·생성 문서 검사와 역할 인증 Worker 회귀도 통과했습니다. 실제 Palantir 연동이나 게임 진행도 증가를 의미하지 않습니다.

### 1. 공개 홈 인지

- 문서 폭이 뷰포트를 넘지 않습니다.
- 핵심 문구, 현재 빌드, 브라우저 플레이, `PLAN · DEV · QA · DOCS`가 소스 순서와 시각 순서 모두 일치합니다.
- 휴대폰에서 핵심 행동은 전체 폭 1개와 보조 행동 2개로 배치됩니다.
- 실행·다운로드는 즉시 보이고, 내부 진행률·기획 요청·제안 도구는 공개 홈에서 제공하지 않습니다.
- 접이식 요약은 44px 이상이며 한 항목을 펼쳐도 페이지 전체 가로 넘침이나 이웃 클릭 범위 교차가 없어야 합니다.
- 홈에는 홍보용 설명, 플레이·다운로드, 로그인, 최신 공개 갱신 한 건만 존재합니다.
- 진행률·기획 요청·제안 도구·문서 맵·내부 작업선은 공개 홈 DOM에서 제거합니다.
- 홈 DOM에는 최신 날짜 하루만 존재하고, 전체 과거 이력은 로그인 뒤 개발 현황 문서에서 확인합니다.

### 2. 인증 검색

- 검색은 돋보기와 `문서 검색`/`검색`, 플레이는 청록색 배경과 삼각형·`게임 플레이`/`플레이`로 구분합니다. 색상이나 툴팁만으로 구분하지 않습니다.
- 플레이 SVG는 버튼의 수직 중앙에 위치하며 폰트 글리프·점멸 가상 요소가 정렬을 바꾸지 않습니다.
- 4개 뷰포트에서 검색·플레이 높이는 44px 이상이고, 클릭 영역 교차·화면 밖 노출이 없어야 합니다.
