# 모바일 위키 반응형 E2E

SFH 위키는 기획자가 **현재 결정과 진행 상태를 찾는 화면**이자 개발자가 **구현 계약과 검증 근거를 확인하는 화면**입니다. 콘텐츠가 존재하는지만 확인하지 않고, 작은 화면에서도 목적 문서를 발견하고 내용을 읽고 다음 문서로 이동할 수 있어야 통과합니다.

## 사용자별 핵심 동선

| 사용자 | 시작점 | 성공 조건 |
|---|---|---|
| 공개 방문자 | 공개 홈 | 짧은 게임 설명 뒤 브라우저 플레이·Windows 다운로드·팀 로그인을 구분 |
| 기획자 | 로그인 뒤 기획자 탭 | 쉬운 게임 설명→완료된 플레이→남은 결정→작성 방법 순으로 이해 |
| 개발자 | 로그인 뒤 개발자 탭 | 완료 기준선·오류·다음 작업·구조와 원칙을 구현 순서로 확인 |
| 인증 사용자 | 검색 또는 문서 맵 | 보호된 검색 허브와 4단계 전체 문서 맵에서 원하는 문서로 이동 |
| 구조 검수자 | 코드 모듈 노드맵 | 실제 코드의 모듈→클래스→상속·참조·검증 관계를 선택하며 양방향 추적 |
| 역할 사용자 | 역할 로그인 | 고정 역할 ID로 자기 탭을 열고 비밀번호만 변경하며 다른 역할은 403으로 차단 |

## 필수 뷰포트

| 등급 | CSS 뷰포트 | 확인 목적 |
|---|---:|---|
| 소형 휴대폰 | 320x568 | 최소 지원 폭, 헤더·버튼·2열 요약의 경계 |
| 일반 휴대폰 | 390x844 | 기본 모바일 읽기와 전체 화면 검색 |
| 태블릿 세로 | 768x1024 | 2열 문서 맵과 표 스크롤 |
| 데스크톱 | 1440x900 | 4열 문서 맵과 홈 대시보드 밀도 |

## 브라우저 E2E 계약

### 1. 공개 홈 인지

- 문서 폭이 뷰포트를 넘지 않습니다.
- 핵심 문구, 현재 빌드, 브라우저 플레이, `PLAN · DEV · QA · DOCS`가 소스 순서와 시각 순서 모두 일치합니다.
- 휴대폰에서 핵심 행동은 전체 폭 1개와 보조 행동 2개로 배치됩니다.
- 실행·다운로드와 진행률은 즉시 보이되, 배포 상세·기획 요청·제안 도구·핵심 루프·당일 상세는 기본 접힘 상태입니다.
- 접이식 요약은 44px 이상이며 한 항목을 펼쳐도 페이지 전체 가로 넘침이나 이웃 클릭 범위 교차가 없어야 합니다.
- 홈에는 홍보용 설명, 플레이·다운로드, 로그인, 최신 공개 갱신 한 건만 존재합니다.
- 진행률·기획 요청·제안 도구·문서 맵·내부 작업선은 공개 홈 DOM에서 제거합니다.
- 홈 DOM에는 최신 날짜 하루만 존재하고, 전체 과거 이력은 로그인 뒤 개발 현황 문서에서 확인합니다.

### 2. 인증 검색

- 모바일 검색 출력은 `100dvh`에서 헤더를 제외한 높이를 사용합니다.
- 비로그인 공개 홈·로그인 화면에서는 검색 진입을 숨기고 검색 색인 요청 자체도 로그인으로 돌려보냅니다.
- 인증 뒤 입력 전 기획 우선순위와 빠른 검색 묶음이 즉시 보이며 내부 스크롤이 가능합니다.
- 입력 후 추천 화면이 사라지고 실시간 문서 결과와 현재 검색어가 표시됩니다.
- 검색 닫기 뒤 본문 스크롤과 링크 입력이 복구됩니다.

### 3. 문서 읽기

- 본문은 16px 수준의 기본 글자와 충분한 행간을 유지합니다.
- 네 열 이상 표는 본문을 찌그러뜨리지 않고 표 컨테이너 안에서만 가로 스크롤합니다.
- 코드 블록과 긴 경로는 페이지 전체가 아니라 해당 블록 내부에서만 스크롤합니다.
- 키보드 포커스와 고대비 모드에서 활성 요소 경계가 사라지지 않습니다.
- 장식 연결선은 클릭·터치를 가로채지 않고, 노드 선택으로 DOM이 갱신돼도 선택한 항목의 포커스가 유지됩니다.

### 4. 전체 문서 맵과 배포 경로

- 데스크톱 4열, 태블릿 2열, 휴대폰 1열로 재배치됩니다.
- 현재 문서의 `YOU` 표시와 대→중→소→세부 경로가 유지됩니다.
- 즉시 페이지 이동 후에도 검색 데이터, 브라우저 플레이, 83개 문서 링크는 현재 호스트의 배포 루트를 유지합니다.
- 홈 대시보드는 검색 색인에서 제외하며, 검색 첫 결과는 홈 회귀 링크가 아니라 실제 상세 문서여야 합니다.
- 모든 노드의 배포 URL이 HTTP 200을 반환해야 합니다.

### 5. 현재 코드 모듈 노드맵

- 생성 JSON의 소스 해시는 `game/**/*.gd` 내용과 일치하고 코드 변경 뒤 미갱신 상태는 빌드에서 차단합니다.
- 데스크톱/태블릿/휴대폰은 선택 노드 중심 방사형 관계를 각각 최대 12/8/6개 표시하고, 초과 관계는 페이지 버튼으로 분할합니다.
- 검색·계약/조립/기능/검증 필터·모듈 선택 뒤 가로 넘침이 없고 모든 노드 터치 범위가 44px 이상입니다.
- 위성 노드를 누르면 중앙·상세·URL이 함께 바뀌고, 화살표 방향으로 사용처·의존처를 구분하며 클래스마다 Godot 엔진 기반과 프로젝트 내부 기반이 구분됩니다.
- 빈 결과, JSON 로드 실패, 키보드 포커스, 고대비와 모션 감소 상태에서도 정보가 소실되지 않습니다.

### 6. 역할 로그인과 계정 변경

- 공개 홈·로그인과 필수 CSS·JavaScript만 로그인 없이 열립니다.
- 기획자·개발자 선택, 고정 아이디, 비밀번호 입력, 오류·잠금 안내가 320px에서도 한 열로 읽힙니다.
- 비로그인 내부 문서, 검색 JSON, 문서 노드 데이터와 사이트맵은 로그인 화면으로 이동하며 본문을 노출하지 않습니다.
- `planner/0000`, `developer/0000`은 각각 자기 역할 탭을 즉시 열며 아이디 변경 요청은 반영되지 않습니다.
- 비밀번호 변경 뒤 초기 비밀번호·다른 역할 경로·CSRF 누락·이전 세션은 실패합니다.
- revision 3 마이그레이션은 workerd 호환 해시로 이전 계정을 한 번 복구하고 실제 로그인까지 확인하며, 이후 배포는 변경 비밀번호를 보존합니다.
- 로그인·계정·역할 탭은 모두 44px 터치 대상, 키보드 포커스와 상태별 `aria-live` 피드백을 유지합니다.

## 자동·실브라우저 검증 분리

`scripts/check-wiki-responsive.ps1`은 다음 회귀를 모든 위키 빌드에서 차단합니다.

- 역할별 빠른 이동과 E2E 문서 누락
- `dvh`, safe-area, coarse pointer, 4·2·1열 반응형 계약 누락
- 모바일 검색 전체 높이와 표·코드 내부 스크롤 누락
- 검색·플레이 링크의 현재 페이지 상대 경로 회귀
- 44px 터치 범위, 비차단 장식, ARIA 제어 관계, 홈 최신 하루 계약 누락
- 공개 홈에 진행률·기획 요청·문서 맵 등 내부 고밀도 블록이 다시 노출되는 회귀
- 코드 모듈 JSON 현행성, 관계 대상 무결성, 페이지·런타임·반응형 스타일 누락
- 역할별 보호 경로·검색 제외·쿠키/CSRF·최초 변경·교차 역할 거부 계약 누락

실제 브라우저 검수는 네 뷰포트에서 공개 홈의 DOM 폭·실행 링크·로그인, 인증 뒤 검색 열기·입력·닫기, 역할 탭과 문서 맵, 콘솔 오류를 확인합니다. CSS 문자열 검사만으로 통과 처리하지 않습니다. 자동 계약에는 `REAL_BROWSER_REQUIRED` 표식을 유지합니다.

## 검증 결과

2026-09-02 공개 범위 재설계에서는 홈을 게임 소개·브라우저 플레이·Windows 다운로드·팀 로그인·공개 갱신 한 건으로 제한했습니다. 기획 요청·제안 도구·진행률·문서 맵은 홈에서 제거했고, 내부 HTML·검색/노드 JSON·사이트맵은 Worker 인증 뒤에만 제공합니다.

2026-09-02 방사형 코드 모듈 노드맵 실브라우저 검수에서 1440x900은 중앙 `core`와 12개 위성·12개 방향선을 표시했고 위성 겹침 0쌍, 페이지 가로 넘침 0px, 최소 조작 높이 44px였습니다. `conditional ranking` 위성을 누르면 중앙·상세·URL 쿼리가 모두 같은 모듈로 전환됐습니다. 390x844와 320x568은 각각 위성 6개, 겹침 0쌍, 가로 넘침 0px이며 최소 높이는 76px·68px, 콘솔 오류 0건이었습니다.

2026-09-01 실제 Chromium 검수 결과입니다. 모든 크기에서 `documentElement.clientWidth`와 `scrollWidth`가 같아 페이지 전체 가로 넘침이 없었습니다.

협업 개선안 전체 적용 뒤 요청 허브의 작업·밸런스 데이터·검증 완료 6개 카드와 결정 ID·원본 리비전·대체/충돌 계보를 확인했습니다. 390x844에서는 같은 콘텐츠와 로컬 제안 초안기가 1열로 재배치되고 입력·선택·복사 버튼 7개가 모두 44px 이상이었습니다. 초안 복사 결과에는 요청 ID·근거·수락 기준·Sheet 대상이 포함됐으며 외부 전송은 발생하지 않았습니다. 가로 넘침과 콘솔 경고·오류는 0건입니다.

접근성 재검수에서는 데스크톱 전체 문서 맵의 상호작용 노드 교차가 0쌍이었고, 닫힌 검색 결과 레이어는 `pointer-events:none`, 검색 활성 시에는 `auto`로 전환됐습니다. 카테고리 선택 뒤 활성 요소가 새로 렌더링된 동일 버튼에 복원됐으며 `aria-controls`로 다음 열을 가리켰습니다. 390x844에서는 가시 상호작용 요소 22개의 최소 높이가 55px, 44px 미만 0개, 가로 넘침 0px, 문서 맵 1열, 홈 일자 카드 1개로 측정됐습니다. 브라우저 경고·오류 로그는 0건입니다.

| 뷰포트 | 실제 판정 | 핵심 측정 |
|---:|---|---|
| 320x568 | 재검증 대상 | 공개 실행·로그인 44px, 기획 루프 1열, 가로 넘침 0 |
| 390x844 | 통과 | 본문 16px, 가로 넘침 0px, 추천 버튼→실시간 색인 결과·첫 결과 이동, 제안 입력·복사 44px+ |
| 768x1024 | 통과 | 문서 맵 2열, 넓은 표가 724px 컨테이너 안에서 992px 콘텐츠만 독립 스크롤 |
| 1440x900 | 재검증 대상 | 공개 히어로 2열, 역할 탭 정보 구조, 보호 검색의 가로 넘침 0 |

추가로 비로그인 `development-status/`·검색 JSON·사이트맵 차단, 각 역할 로그인→자기 탭, 인증 뒤 `모듈 규칙` 검색→결과 클릭, 중첩 문서 경로를 실제 동작시킵니다. 추천 검색은 Material이 요구하는 `keyup`까지 전달해 즉시 결과를 표시해야 하며 브라우저 콘솔 오류는 0건이어야 합니다. 정적 검사는 모든 Markdown·내비게이션·노드 데이터 경로와 네 뷰포트 계약을 strict 빌드 전에 판정합니다.

실패 항목은 배포 전에 수정하며, 일자별 요약은 [개발 현황과 업데이트](../development-status.md)에 압축합니다.
