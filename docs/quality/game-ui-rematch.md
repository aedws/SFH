# 전체 게임 UI 재편

2026-09-08 · 색만 바꾸는 작업이 아니라 **무엇을 선택하고, 무엇을 지불하며, 무엇을 얻는지** 읽히도록 게임 화면을 재편합니다. 청록 `#02e5e1`, 픽셀 한글, 전투 중앙 비우기는 유지합니다. 이 문서의 범위는 게임이며, 별도 웹사이트인 역할 위키는 [위키 검수](wiki-responsive-e2e.md)를 따릅니다.

## 무엇이 달라졌나

### 16:10 장비 화면 재배치 · 2026-09-09 {#equipment-1610}

- **기준 비율:** Windows 기본 창과 PC 모드의 논리 화면은 1280×800(16:10)입니다. 다른 비율에서 늘여 그리지 않고 화면 비율을 유지합니다. 모바일은 기존 가로 우선·기기 비율·터치 크기 정책을 유지하며 PC 복귀 시 16:10으로 복원합니다.
- **가방:** 장착 장비 / 회수품 / 선택한 아이템을 분리합니다. 장비 카드를 줄여 방어구 4부위와 스탯을 함께 보고, 상세 검사는 별도 미리보기로 확인합니다.
- **무기·파츠:** 메인·보조 무기를 큰 거치대에 표시하고 실제 소켓을 선택합니다. 배경 격자를 덜어 실루엣과 장착 상태를 강조합니다. 무기 도식은 종횡비를 유지하며 호환 파츠만 연결합니다.
- **방어구·모듈:** 대상 장비의 실물 미리보기 / 장착·보유 모듈 / 소켓 설정의 3영역입니다. 빈 부위에는 가짜 장비를 표시하지 않습니다. 장비 작업대에도 무기·방어구 미리보기와 보유 장비 카드를 제공합니다.
- **작은 화면:** 내부 세로 스크롤과 열 전환을 사용합니다. 닫기는 상단에 고정하고 미저장 변경의 저장·버림·취소는 유지합니다. 화면을 줄인 뒤 이전 가방 폭이 남는 최소 크기 순환과 제목의 과도한 줄바꿈을 수정했습니다.

`EquipmentScreenLayout`은 열 비율만 반환합니다. 공용 아이템 그림·미리보기·슬롯 버튼은 `presentation_theme`가 소유해 가방과 장비의 순환 의존성을 차단합니다. 장착·교체·소켓·세트·저장 처리는 기존 공개 계약을 그대로 사용하며 이번 변경으로 새 밸런스 목록이나 Sheet 구조는 만들지 않습니다.

**검증:** `equipment_screen_contract_test`는 1280×800, 1440×900, 1920×1200, 1024×640, 640×400, 390×844에서 가방·파츠·모듈·무기/방어구 작업대를 순회하고 원본 불변·경계·PC 해제 버튼 가시성을 검사합니다. 실제 렌더 fixture에서 제목 세로 줄바꿈과 주요 버튼의 스크롤 밀림을 발견해 수정했습니다. 장착/해제 버튼은 긴 설명 위에 두며 입력 E2E는 탭 재배치 완료 후 화면 내 좌표를 클릭합니다. 기존 파츠 테스트는 키보드 선택, 호환 실패, 가방 가득참, 교체·해제, 저장/버림, 미래 소켓 추가를 계속 검증합니다. 렌더링 fixture와 실제 일반 플레이의 미감 수락은 구분합니다.

- **출격 준비실:** 개발 단계·유틸리티 명칭 대신 요원/스킬과 시설 아이콘, 장비 세팅, 로비 복귀를 구분합니다. 실행 위치까지 이동하는 로비 경로는 유지합니다.
- **제작소:** 기본 도면을 바로 실행하지 않습니다. 도면 카드 → 보유/필요 재료·크레딧 비교 → 명시적 제작 → 성공/실패 영수증입니다. 도면 선택은 무료입니다. 결과는 기존 영구 제작 기록에 보관되며 가방 지급을 새로 약속하지 않습니다.
- **회수 도감:** 짧은 수량 안내 대신 수집 대상·지역·회수량·완료 진행 막대를 표시합니다. 미완료 목표와 완료 목표를 구별하며 열람만으로 재화를 변경하지 않습니다.
- **장비·모듈·증강:** 내부 개발 메모 제거, 파츠 소켓 한글 명칭, 선택 카드 대비, 장착/강화 액션, 선택적으로 펼치는 소켓 규칙, 증강 그림문자로 정리합니다. 기존 파츠 도식·모듈 슬롯·가방 회전/이동은 유지합니다.
- **설정·모바일:** Action ID를 감추고 조작명과 실제 키만 배치합니다. 스킬/HUD 탭은 유지합니다. 모바일 첫 안내는 이동/전투/준비 세 단계로 나누며 터치 크기 선택과 확인은 유지합니다.
- **보상·현장:** 시즌 기록은 OS 대화상자 대신 게임 내 보관소, 드랍은 종류별 그림과 근접 시 품명, 비교는 장착·회수·손실 결과를 표시합니다. 전투 중 빈 소켓과 내부 CSV 출처를 상시 강조하지 않습니다.
- **전환 오류:** 처음 여는 준비실·설정창의 과도한 최소 높이, 훈련 결과가 다른 창 위에 남는 겹침, 어두운 선택 카드의 검은 글자, 모바일 첫 작전 안내와 상단 메뉴 겹침을 수정합니다.

표의 ‘유지’는 검토 누락이 아닙니다. 이미 게임의 행동·상태를 표현하는 요소를 꾸밈 목적으로 다시 키우지 않습니다. **코드 점검, 렌더 fixture, 실제 입력 E2E, 사람의 재미 수락은 서로 다른 근거**입니다.

### 누락 방지 장치

`game/tests/support/game_ui_audit_sources.json`에 **UI 생성·표시 소스 47개 + 메인 씬/월드 표시 9개**를 고정 등록합니다. `scripts/check_game_ui_audit.py`는 Control/컨테이너/대화상자/버튼/라벨 상속, UI 생성, 문자열 드로잉을 탐색하여 새 파일 또는 삭제 파일을 실패로 알립니다. 정적 씬과 Node2D 도형은 별도 등록으로 보완합니다. 이 검사는 시각 디자인의 좋고 나쁨을 자동 판정하지 않으므로 새 씬/새 도형만 추가한 경우에도 작성자가 표를 갱신해야 합니다.

CI에서 기존 모듈/파츠 카드 검수가 `MOD`·`PART` 표시 문자열에 의존하던 문제도 확인했습니다. 실제 아이템 종류 메타데이터로 판정하고, 문구를 한글로 바꿔도 카드 수가 유지되는 회귀 검사를 추가했습니다. 문구 번역과 기능 유무 판정을 분리합니다.

## 모듈 경계 · 이후 확장

- `GameUI`: 코드 생성 SVG 아이콘 캐시, 표면, 행동 버튼, 헤더, 접기만 담당합니다. 결제·장비·프로필은 참조하지 않습니다. 폰트의 이모지 지원과 무관하게 렌더됩니다.
- `GameDossier`: 게임 내 모달·스크롤·고정 복귀·이전 일시정지/키보드 초점 복원. 부모 브리핑이 열려 있으면 ESC는 보관소만 닫습니다.
- `HubArchivePanel`: 공개 catalog/quote/command 계약만 소비합니다. `get_workshop_candidates`, `quote_workshop_recipe`, `craft_recipe`, `get_codex_entries`입니다. 도감 반환은 복사본이며 새 목록 행을 자동 표시합니다.
- 제작 재료·가격·고정 옵션·도면 해금·가방·장비 저장은 기존 서비스 책임입니다. 이 UI 작업은 게임 밸런스 목록을 추가하지 않아 **Google Sheet 열/시트를 늘리지 않았습니다.**
- `TrainingHudLayout`: 계측/복원과 분리된 화면 배치·모달 차폐입니다. 결과 자체를 지우지 않고 상위 표면만 숨겨 닫은 뒤 다시 확인할 수 있습니다.
- 일반 소비 화면을 전부 하나의 거대 UI 클래스에 합치지 않습니다. 표시 유틸리티만 공유하고 각 기능의 프레젠터를 유지합니다.

### 아직 구분해서 봐야 하는 것

- headless Chromium에서 **실행 중 PC↔모바일 뷰포트 전환 시 WebGL `INVALID_OPERATION` 경고**가 발생합니다. 이후 화면은 렌더되며 스크립트 오류와 구분하여 `report.json`의 `warnings`에 남깁니다. 모든 GPU/실제 모바일에서 무오류로 검증했다고 주장하지 않습니다.
- 모바일 첫 안내는 상단 메뉴 아래로 이동하고 교차 검사를 추가했습니다. 실제 손가락 가림·장시간 플레이와 작은 훈련 버튼의 터치 선호도는 추가 수락 항목입니다. 기능 존재만으로 사람의 편의/재미 완료를 확정하지 않습니다.
- 공개 브라우저와 Windows는 같은 병합 커밋의 배포 파이프라인을 사용합니다. 로컬 화면 검수와 배포 성공은 별도로 확인합니다.
