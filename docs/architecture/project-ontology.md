# 프로젝트 오너 판단 온톨로지

## 목적

SFH 위키의 문서를 새 원본으로 만들지 않고, 이미 존재하는 기획·코드·데이터·테스트를 **판단 가능한 객체와 관계**로 연결합니다. 최종 판단 주체는 기획자나 AI 개발자가 아니라 프로젝트 오너입니다.

| 역할 | 책임 | 최종 확정 가능 여부 |
|---|---|---|
| 프로젝트 오너 | 범위·우선순위·수락·출시 결정 | 가능 |
| 기획자 | 플레이 의도·수치 후보·기획 근거 제공 | 불가 |
| 개발자 | 구현 상태·위험·테스트·배포 근거 제공 | 불가 |

## 단일 원본 경계

```text
기획 확정·임시 판단  → Notion
밸런스 후보          → Google Sheet
확정 런타임 데이터   → 저장소 CSV
구현·검증 상태       → Git 코드·E2E·CI
판단 화면            → 위 원본을 연결한 읽기 전용 위키 뷰
```

위키 콘솔의 상태를 직접 편집해 실제 구현 상태를 바꾸지 않습니다. `owner-decision-registry.json`은 판단 대상과 관계를 선언하고, `generate_project_ontology.py`가 코드 모듈 지도와 전체 문서 지도를 결합해 배포 데이터를 만듭니다.

## 객체와 관계

- **판단 객체:** 원칙, 결정, 위험, 작업. 반드시 `authority:project-owner`를 판단 주체로 가집니다.
- **근거 객체:** 문서. `knowledge-map.json`에서 자동 수집합니다.
- **구현 객체:** 코드 모듈. `code-module-map.json`에서 자동 수집합니다.
- **관계:** 판단, 구현, 검증, 영향, 차단, 설정, 문서화처럼 방향과 뜻을 가진 연결입니다.
- **상세 화면:** 선택한 판단 객체의 상태·확실성·수락 조건·다음 행동과 직접 관계만 표시합니다.

## 현재 도입 범위

1. 객체 ID와 프로젝트 오너 권한 계약
2. 깨진 객체·문서·모듈 관계를 차단하는 생성 검사
3. 개발자 작업실의 읽기 전용 판단 콘솔
4. 검색·상태 필터·선택 객체 상세와 직접 관계 탐색
5. 데스크톱·모바일·키보드 접근성 및 보호 자산 검사

자동 승인, 위키에서의 코드 수정, 배포 실행, 과금·서버 설정 변경은 포함하지 않습니다. 실제 사용 후 유지 비용과 정보 정확성을 검토하기 전까지 행동 기능은 읽기 전용 링크로 제한합니다.

## 변경 절차

1. 신규 판단 대상은 `docs/assets/owner-decision-registry.json`에 고유 ID, 상태, 확실성, 오너, 근거, 수락 조건과 다음 행동을 기록합니다.
2. 문서와 모듈 연결은 각각 `document:<문서 경로>`와 `module:<기능 폴더>`를 사용합니다.
3. `python scripts/generate_project_ontology.py`로 산출물을 갱신합니다.
4. `scripts/check-project-ontology.ps1`가 중복 ID, 소유권 누락, 깨진 관계, 없는 문서와 개발자 화면 계약을 검사합니다.
5. PR의 위키 빌드·역할 인증·반응형 E2E를 통과한 뒤에만 배포합니다.

## 확장 중단 조건

- 수동 상태가 코드·테스트보다 자주 뒤처짐
- 같은 판단을 Notion과 레지스트리에 중복 작성해야 함
- 그래프 유지 시간이 실제 게임 기능 개발을 침범함
- 원본 근거 없이 `구현·검증됨` 상태가 표시됨
- 역할 인증 밖으로 판단 데이터가 노출됨

하나라도 반복되면 객체 유형 확장을 멈추고 자동 수집과 검증부터 보강합니다.
