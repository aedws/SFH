# 모듈화 점검 기록

## 2026-09-07 · 프레임·타격·속도감 경계 {#frame-feedback}

- 안개 내부 계산·질의 할당만 개선하며 맵 제공자 계약·차폐 정책을 변경하지 않습니다.
- 타격 연출은 기존 Director/Profile과 `damaged` Signal 안에 유지합니다. 대기 시 처리 중지/피격 시 재개, 카메라 변위 상한·0 설정·효과 종료 정리를 검사합니다. 피해 계산과 전역 시간은 그대로입니다.
- 속도감은 `PlayerMovementFeedback`의 export 수치·잔상 관리로 조정합니다. 실제 속도·대시 거리/쿨타임·충돌체는 변경하지 않습니다. 순간 위치 이동 시 잔상을 끊고 비활성화 상태를 복구합니다.
- 새로운 gameplay 목록·Sheet 탭·CSV 스키마·런타임 모듈 의존성은 추가하지 않습니다. 렌더링 계측 옵션과 회귀 검사는 게임 런타임 밖에 유지합니다.

## 2026-09-07 · N26-08B 렌더링 검사 경계 {#n26-rendered}

- 렌더링 장시간 검사는 `game/tests/rendered_soak_test.gd`와 명시적으로 실행하는 `scripts/test-rendered-soak.ps1`에만 추가합니다. 새 FeatureManifest 기능이나 플레이어 이동·피해·저장 규칙을 추가하지 않습니다.
- 기존 저장 격리 제공자를 재사용하고, 맵의 공개 경로·방/시야 스냅샷을 소비합니다. 자동 조향·합성 입력·부하 수집은 검사 전용이며 게임 서비스가 테스트를 참조하지 않습니다.
- 시간 배속이나 위치 필드 덮어쓰기 없이 정상 이동·점멸·충돌을 실행합니다. 경로 이탈 뒤 재탐색과 데드존 보정은 검사기에만 적용합니다. 게임에서 발견한 결함과 검사기 오차를 구분합니다.
- 배포 바이너리의 외부 스크립트 차단을 해제하지 않았습니다. 소스 렌더링·다운로드 일반 실행·Web·사람 수락은 다른 근거로 기록합니다. WSL 자동 기동·과금 변경 없음.
- 정적 검사: 기능 57·클래스 234·의존 26·순환 0·서비스 Scene 탐색 0 유지. 소스 GPU 중·대형 각각 600초 후 Node 잔류 0이며 모든 제거 조합·장기 누수 부재를 보증하지 않습니다.

## 2026-09-07 · N26-08B 선택 제거·재구성 경계 {#n26-08b}

- 훈련 복원 서비스는 활성 세션 중 제공자 교체를 거절합니다. 키 어댑터는 재구성 시 이전 Signal과 목록을 해제하며, UI는 존재하는 스킬 슬롯만 편집 가능하게 표시합니다.
- `Game` 조립부의 선택적 투자 제공자 폴백을 명시적인 `Array[Resource]`로 유지합니다. 기능을 끄더라도 빈 배열 타입 오류로 훈련 설치와 다음 출격이 중단되지 않습니다. 정책과 복원 로직을 Scene으로 옮기지 않았습니다.
- 훈련 스킬 순환은 현재 ID를 건너뛰며 대안이 없으면 실패 값을 반환합니다. UI 재선택만으로 쿨타임/충전을 초기화하지 않습니다.
- 선택 제거 5개 구성, 작전 81개 조합·설정 변경 12개, 전체 게임·E2E, Windows 별도 프로세스 저장/읽기 계약 통과. 정적 감사는 기능 57·클래스 234·의존 26·순환 0·서비스 Scene 탐색 0으로 유지합니다.
- 중·대형 ×2시드 CPU 단기 예산과 해제 후 잔류 Node 0을 확인했습니다. 장시간 메모리 누수·실제 GPU·모든 기능 조합의 보증은 아닙니다. Sheet/CSV·저장 스키마·과금·WSL 기동 설정은 변경하지 않았습니다.

## 2026-09-07 · N26-08A 훈련 세팅 복원 {#n26-08a}

- `TrainingLoadoutService`에 명시적 참여자 등록을 추가했습니다. 장비·가방을 기본 제공자로, 스킬/AP와 공용 소켓을 선택 제공자로 연결합니다. 미래 상태 제공자는 같은 export/validate/restore 계약으로 확장하며 UI에 복원 분기를 추가하지 않습니다.
- `TrainingLoadoutSnapshot`은 전체 사전 검증→값 복원→부분 실패 시 직전 값 롤백을 담당합니다. 실패 시 원본·저장 보호를 해제하지 않고 재시도를 기다립니다. 지속 효과는 안전하게 취소하며 재생 복원은 하지 않습니다.
- `DesktopProgressService`는 훈련을 직접 참조하지 않습니다. 임시 로드아웃 보호 계약으로 시험 전 정상 체크포인트만 보존합니다. `Game`은 종료/작전/상점 이동 전에 복원 순서를 조립합니다. 장비 초안 취소는 훈련을 유지합니다.
- 실전 소켓 서비스와 동일 규칙을 별도 인스턴스에서 재사용합니다. 카탈로그·슬롯 제한·효과 계산의 복제 구현은 없습니다. 훈련 UI는 선택·장착/해제·종료 명령만 보냅니다.
- 반복 훈련 종료가 카탈로그 원본을 비우던 `TrainingService` 참조 공유를 사본으로 수정했습니다. `TrainingSkillBindingAdapter`는 새 스킬을 원래 슬롯 키에 연결하고 영구 설정을 읽기만 합니다. 57개 기능·234개 클래스, 의존 26·순환 0·서비스 Scene 탐색 0입니다.
- 신규 계약 및 전체 로컬 E2E 통과. 새 Sheet 목록·저장 스키마·과금 변경 없음. 장비별 소켓 소유권과 N26-08B 성능/배포 회귀는 별도 수락입니다.

## 2026-09-05 · 가방 아이템 회전과 저장 경계

- `GridInventory`가 인스턴스별 방향, 현재 점유 크기, 충돌·경계 검증과 export/restore를 소유합니다. 아이템 정의의 기본 `grid_size`는 바꾸지 않습니다.
- `InventoryEditSession`은 회전을 이동·장착과 같은 미저장 초안 변경으로 처리합니다. 저장 전에는 실전 가방에 반영하지 않고, 실패·취소·외부 충돌 시 기존 상태를 복구합니다.
- `GridInventoryWindow`와 `InventoryGridView`는 선택·`R` 의도와 현재 크기만 표현합니다. 전투의 기존 `equip_field_loot` 액션을 가방 문맥에서 재사용하므로 K 키 설정으로 바꾼 키가 그대로 표시·동작하며, 가방 밖 현장 장착 행동은 유지됩니다.
- 구 저장에 회전 필드가 없으면 기본 방향으로 복구합니다. 존재하지 않는 아이템·비정상 타입·회전 후 경계/겹침 상태는 저장 검증에서 거부합니다.
- 순수 제공자 회귀, 실제 클릭→R→저장 E2E, 별도 Godot 프로세스 write/read 복원을 각각 검사합니다. 새 아이템이나 밸런스 목록이 없어 Google Sheet·확정 CSV·과금 모델은 변경하지 않습니다.

## 2026-09-03 · P6 로컬 마감·기획 데이터 튜토리얼

- 참가 규격은 `SeasonPolicy` Resource만 수정합니다. Game·전투·정산에 대형 분기를 추가하지 않습니다.
- `SeasonRankingService`가 활성 시즌의 고정 조건과 기록을 보존하며 다음 시즌에 새 정책 ID를 적용합니다. `SeasonPresenter`는 그 사본의 정책 ID/조건을 설명합니다.
- 일반 누적 기록과 시즌 참가를 분리해 소/중형 미참가가 출격 실패나 정산 소실이 되지 않습니다.
- 배포 기본 정책 81조합, 저장된 구 정책 복원·마감·신규 정책 전환, 대형 로컬 보상, 전체 플레이 E2E로 확인합니다. 제출·큐·칭호/오라 기존 분리·선택 제거 계약은 유지합니다.
- 기획 튜토리얼은 시트 공급자와 실제 Resource/카탈로그 연결을 구분합니다. 새 목록은 없어 Sheet·CSV를 변경하지 않습니다. 서버 위변조·다세대 백업은 계획만 유지합니다.
- 이번 판정은 **P6 경계와 수정 영향 범위**이며 전체 저장소에 결합이 전혀 없다고 단정하는 감사가 아닙니다.

## 2026-09-03 · 로비 단말과 실물 장비 출격 원본

- `HubServiceStation`: 배치 위치/반경/서비스 ID와 상호작용 신호만 소유. 프로필·장비·계약 내부 경로 의존 없음.
- `HubPreparationPanel`: 주입된 준비 컨트롤·일시정지·모달 전환·스크롤만 소유. `hub_preparation_enabled`로 독립 제거하며 기본 방 Scene은 신규 기능을 참조하지 않음.
- `OperationSetupPresenter`: 기존 요원·스킬·도구 컨트롤을 로비에 제공하고 작전에는 실제 제공자 스냅샷 확인만 표시. 새 데이터/수치 계산 없음.
- `LoadoutInvestmentService`: 장착 보존 정책을 Game에서 주입, 카탈로그 무기 선택·경로·비용 제외. Game의 무기 교체 루프도 삭제해 미래 구형 계약이 아이템 상태를 덮어쓰지 않음.
- 장비·가방 export/restore 공개 계약을 유지하고 편집 중 직접 시작을 거절합니다. I 저장/취소/계속 편집 가드를 게이트 진입에도 적용합니다.
- 로비 단말 입력·4화면·실물 값 비교·81작전+12세팅·비카탈로그 무기·선택 제거, 기존 한 판/실패 정산/Windows 재실행을 회귀 검사합니다.
- 새 목록이 없어 Sheet 확장 없음. 상점 품질/실물 지급·서버 보안·과금은 별도 범위를 유지합니다.

## 2026-09-03 · P7-01A 상점 비교와 보안 구현 예정 분리

- `ShopQuotePolicy`는 입력 사본으로 견적만 계산하고 `RotatingShopService`가 구매를 수행합니다. `ShopOfferPresenter`는 설정 품질과 현재 창고 수량 지급을 구분해 표현합니다.
- `ShopBrowserPanel`은 P5 공개 façade만 사용하며 프로필/가방 내부 Node 경로를 읽지 않습니다. Game 변경은 선택 UI의 지연 설치·모달 연결·열기뿐입니다.
- `shop_browser_enabled=false`일 때 UI를 로드하지 않고 P5 상점·거점은 남습니다. 자동 첫 매물 구매로 폴백하지 않습니다. P5/회전 상점 제거도 기존 계약으로 유지합니다.
- 가격·수량·미지원 유형 검증, 읽기 전용 사본, 동일 품목 개당 비교, 오래된 견적 차단, 실제 F/마우스/ESC, 4화면 크기, 중복 클릭을 전용 계약 테스트에 추가했습니다.
- 위변조 감지·거래 원장·다세대 백업은 [사전 설계](../design/p7-plus-preimplementation.md#economy-integrity-plan)만 등록합니다. 현재 로컬 환불 처리나 SHA-256을 서버 검증 또는 DB 트랜잭션으로 표기하지 않습니다.
- 새 목록 없이 기존 ShopOffer 6행·확정 CSV·Web payload를 유지합니다. 실제 품질 적용·장비 가방 지급·가격 밸런스는 P7-01B로 남습니다.

## 2026-09-03 · 보스 경고와 외곽 방향 HUD

- `boss_warning`의 추적기·좌표 투영·스타일 Resource·HUD를 분리했습니다. 보스 생성, 피해, 문, 크레딧 로직은 수정하지 않습니다.
- Game은 생성기/플레이어/전투 표시 문맥만 주입하고 작전 종료 때 해제합니다. HUD가 Enemy 내부 배열이나 방 경로를 직접 탐색하지 않습니다.
- 설치 전 생성도 동일 공개 목록으로 복원하고 중복 신호는 한 번만 경고합니다. 개체의 처치·퇴장, 재구성·모듈 해제 시 구독을 정리합니다.
- Manifest 선택 제거 smoke, 8방향×4크기·카메라 줌·복수 보스·처치·일시정지 계약과 실제 작전 I/ESC E2E를 필수 CI에 추가했습니다. 매 프레임 전체 적이 아닌 등록된 보스만 좌표 갱신합니다.

## 2026-09-03 · P6-04와 실물 드랍 한 판

- **데이터/동작/표현:** 시즌 보상 카탈로그·마감 지급·프로필 저장·장착 패널·캐릭터 표현을 5개 모듈로 분리했습니다. 오라는 정적 원 두 개로 그리며 공격 수치를 수정하지 않습니다.
- **공통 파서:** CSV 로딩/파싱은 코어 `CatalogCsvTable`로 옮기고 기존 P5 이름은 호환 파사드로 유지합니다. P6가 P5 기능 폴더 내부 구현에 의존하지 않습니다.
- **실물 획득:** 생성 정책은 Resource, 카테고리 추첨은 LootTableProvider, 가방 트랜잭션/런 복구는 FieldLootInventoryService, 영구 반출은 RunSettlementService가 소유합니다. Game은 적 신호·방 완료·복귀 순서만 연결합니다.
- **의존 순서 수정:** 장비 카탈로그를 정산 서비스보다 먼저 주입하도록 수정했습니다. 없던 장비 정의 때문에 반출물을 소실로 판정하던 경로를 통합 E2E가 검출했습니다.
- **선택 제거:** R 즉시 장착을 꺼도 F 방어구 가방 획득은 유지합니다. 시즌 보상 토글을 꺼도 일반 랭킹·시즌은 유지합니다. 기존 기능 제거 smoke도 함께 실행합니다.
- **무결성:** 묶음 획득은 가방 체크포인트로 전량 성공/실패, 실패한 F는 다른 상호작용으로 전달하지 않음, 동일 방/적 중복 드랍 방지, 크레딧 휴대 원장과 정산 이중 지급 방지.
- **잔여 경계:** 실서버 보상 검증, 창고 실물 전체 인출 UI와 강화된 반출 인스턴스 영구 저장은 완료로 과장하지 않습니다. 정산 멱등은 현재 프로세스 run ID 기준입니다.

## 2026-08-29 랜덤 맵 모듈

결론은 **MVP 단계에서 교체 가능한 선택 모듈로 분리되어 있음**입니다. 맵의 생성 알고리즘과 등급 데이터는 한 기능 폴더 안에 있고, 플레이어·적·무기 모듈은 `MapTierConfig`나 방 배열을 직접 알지 않습니다.

튜토리얼은 플레이 규칙을 호출하지 않는 읽기 전용 표현 모듈입니다. `Game`은 설치와 첫 성공 조립 시점의 표시만 연결하고, Presenter는 계약 서비스를 직접 생성하지 않습니다. 따라서 설정 단계 수나 튜토리얼 보존 정책을 바꿔도 맵 생성과 투자 정산 모듈을 수정할 필요가 없습니다.

## 의도된 결합

- `Game`은 모듈 Scene의 문자열 경로와 조립 순서를 압니다.
- `EnemySpawner`는 기본 적 Scene을 참조합니다. 이는 `spawning → enemies` 선언 의존성입니다.
- `RoomEncounterSystem`은 맵·적 생성·크레딧의 공개 계약만 사용합니다. 이는 Manifest에 선언된 `room_encounters → map_generation, spawning, credits` 의존성입니다.
- `RoomWarpSystem`은 맵·방 진행도 공개 계약만 사용합니다. 이는 `room_warp → room_encounters, minimap` 선언 의존성입니다.
- `Game`은 기본 장비 Scene과 선택된 로드아웃 Resource 경로를 알고, 장비는 플레이어의 스탯 적용 공개 메서드만 압니다.
- `Game`은 인벤토리 카탈로그와 I/U 패널 Scene 경로를 알고, 가방과 장비 시스템은 서로의 내부 Node 경로를 참조하지 않습니다.
- `Game`은 장비, 밸런스, 자동 무기의 조립 순서를 알지만 각 모듈은 서로의 내부 Node 경로를 참조하지 않습니다.
- `Game`은 내부 레벨 → 버프 선택 → 외부 정산 순서와 장비 → 가방·원장 → 강화 서비스 순서를 압니다.
- 플레이어, 적, 투사체는 생성 벽용 충돌 레이어 `16`을 공유합니다.
- 맵 전용 스모크 테스트는 맵 기능 경로를 참조합니다. 맵 기능을 완전히 삭제하면 해당 테스트도 함께 제거하거나 교체해야 합니다.

이 결합은 숨겨진 의존성이 아니라 조립부, Manifest 검사, 문서에 드러난 계약으로 관리합니다.
