# 모듈화 점검 기록

## 2026-08-30 전투 자원·드랍 회복·레벨업 회복 감사

| 점검 대상 | 결과 | 독립성·검증 근거 |
|---|---|---|
| 공용 에너지 | 통과 | 최대량·시작량을 `CombatResourceConfig`가 소유하고 스킬 실행기는 제공자의 조회·소비 계약만 호출 |
| 슬롯별 충전 | 통과 | 최대 충전과 복구 시간은 각 `CombatSkillDefinition`에 남겨 스킬별 독립 교체 가능 |
| 적 처치 드랍 | 통과 | 적은 사망 위치만 Signal로 전달하고 에너지·체력 드랍률·수량·최소 보정은 자원 시스템에 격리 |
| 체력 적용 | 통과 | 결정과 레벨업 모두 플레이어의 `heal()` 계약을 사용하고 HP 계산을 복제하지 않음 |
| 레벨업 회복 | 통과 | `ProgressionSystem`이 레벨당 HP 12를 소유해 임시 버프 UI 활성 여부와 무관하게 정확히 한 번 적용 |
| 선택 비활성화 | 통과 | `combat_resources_enabled=false`에서 결정·에너지 HUD만 제거되고 쿨타임 전용 세 스킬 유지 |
| 자동 검증 | 통과 | 소비·부족 차단·충전 복구·2종 드랍 수집·레벨업 회복·HUD·비활성 폴백 검사 |

전투 자원을 스킬 효과나 적 스크립트에 넣지 않고 `CombatResourceSystem`이라는 정책·상태 제공자로 분리했습니다. 체력 결정과 경험치 결정은 각각 독립 Scene이며, 한 모듈을 끄거나 드랍 표현을 교체해도 적 생성·피해·경험치·스킬 효과가 유지됩니다.

대형 방·적 14명·전기 효과 3개·전투 자원 활성 조건에서 평균 6.889ms, 최대 8.435ms, Node 1,291개로 성능 예산을 통과했습니다.

## 2026-08-30 적 군중 분리·생성 간격 감사

| 점검 대상 | 결과 | 독립성·검증 근거 |
|---|---|---|
| 생성 겹침 방지 | 통과 | 생성기가 기존 적과 40px 이상 떨어진 걸을 수 있는 후보만 승인하며 후보가 없으면 요청을 취소 |
| 이동 중 분리 | 통과 | 적은 주입된 `get_separation_vector()` 계약만 사용하고 생성기 목록이나 SceneTree 그룹을 직접 읽지 않음 |
| 좁은 통로 흐름 | 통과 | 적끼리 강체 충돌을 추가하지 않고 추적 벡터에 분리 조향만 합성해 상호 봉쇄를 피함 |
| 정책 교체·비활성화 | 통과 | 반경·강도·간격·이웃 수·갱신 간격을 `EnemyCrowdConfig`에 격리하고 `enabled=false` 폴백 검증 |
| 계산량 제한 | 통과 | 적별 0.08초 분산 갱신과 가까운 이웃 최대 8명 제한, 대형 방 성능 게이트 유지 |
| 자동 검증 | 통과 | 동일 좌표 2회 생성 간격, 완전 중첩 시 반대 벡터, 실제 이동 분리와 정책 비활성화를 검사 |

적의 체력·피해·길찾기에는 군중 규칙을 추가하지 않고 선택 제공자와 설정 Resource만 주입했습니다. `Game`은 생성기 공개 계약을 확인할 뿐 분리 계산을 수행하지 않으며, 방 전투와 전역 증원은 같은 생성 간격 정책을 공유합니다.

대형 맵·방 적 14명·전기 효과 3개 조건에서 평균 6.894ms, 최대 8.134ms, Node 1,280개로 기존 성능 예산을 통과했습니다.

영구 상태를 중앙 `Game`이나 런타임 `CreditLedger`에 추가하지 않고 전투 세션 밖의 `PersistentProfile`로 옮겼습니다. `Game`은 선택값을 서비스 사이에 전달하고 결과 문자열을 조립할 뿐 가격, 점수, 랜덤 옵션, 적 배율을 다시 계산하지 않습니다.

대형 맵·스마트 타게팅·적 72명 조건의 성능 회귀는 평균 6.890ms, 최대 10.327ms, Node 1,480개로 기존 예산을 통과했습니다.

## 2026-08-30 전기 스킬·엄격 성능 예산 재점검

| 점검 대상 | 결과 | 교체·최적화 근거 |
|---|---|---|
| 전기 표현 교체 | 통과 | 공용 `ElectricArcEffect`가 렌더링만 담당하고 각 스킬은 독립 `ElectricEffectProfile` Resource를 주입 |
| 스킬 규칙 분리 | 통과 | 점멸 이동, 자기장 피해, 가속 스탯 규칙은 전기 프로필의 패턴·색·밀도를 모름 |
| 이펙트 연산 예산 | 통과 | 프로필당 최대 128 선분, 10~20Hz 형상 재생성, 기본 동시 효과 3개로 제한 |
| HUD 부하 | 통과 | 쿨타임 상태 Signal을 10Hz로 제한하고 발동·준비 완료만 즉시 전송 |
| 지속 효과 부하 | 통과 | 가속 해제를 per-frame Node 대신 one-shot `Timer`로 전환 |
| 범위·경로 부하 | 통과 | 자기장 임시 배열 제거, 적 A* 0.7초 분산 갱신과 96px 재탐색 기준 적용 |

| 엄격 자동 검증 | 통과 | 대형 맵·적 72명에서 평균 6.887ms, 최대 10.328ms, Node 1,490개, 전기 효과 3개 |

전기 효과는 스킬 정의가 소유하는 별도 데이터이므로 특정 효과만 비활성화하거나 다른 시각 렌더러로 바꿔도 이동·피해·버프·쿨타임은 유지됩니다. 맵 충돌체 병합과 적 경로 캐시는 각각 맵 생성기와 적 모듈 내부 최적화이며 `Game` 조립부나 다른 기능에 성능 정책을 복제하지 않았습니다.

측정값은 Ryzen AI Z2 Extreme 개발 환경의 헤드리스 CPU 회귀 결과입니다. 실제 최소 사양 인증은 별도 저사양 GPU에서 수행해야 하며, 임시 목표와 출시 전 절차는 [최소·권장 사양과 성능 예산](../performance/minimum-requirements.md)을 따릅니다.

## 2026-08-30 전투 스킬·쿨타임 HUD 점검

| 점검 대상 | 결과 | 근거 |
|---|---|---|
| 효과 교체 가능성 | 통과 | 점멸·자기장·가속을 각각 독립 `CombatSkillEffect` Resource로 구현 |
| 입력·쿨타임 분리 | 통과 | 실행기는 정의의 입력 Action과 재사용 시간만 읽고 효과 세부 동작을 모름 |
| HUD 분리 | 통과 | HUD는 `skill_states_changed`와 `get_skill_states()`만 소비 |
| 기존 스탯 조합 | 통과 | 가속은 플레이어 수정자 출처 계약을 사용해 장비·버프와 곱연산으로 합성 |
| 적 결합 제거 | 통과 | 자기장은 컨테이너에서 `take_damage()` 계약을 제공하는 범위 대상만 호출 |
| 선택 비활성화 | 통과 | Manifest에서 끄면 실행기·HUD가 모두 사라지고 기존 자동 공격은 유지 |
| 자동 검증 | 통과 | 숫자키, 점멸 거리·쿨타임, 자기장 피해, 55% 가속, 3슬롯 HUD와 비활성 폴백 확인 |

장비의 스킬 호환성 정의와 이번 전투 효과 정의는 의도적으로 분리했습니다. 현재는 기본 세 효과를 직접 검증하고, 후속 작업에서 장비 스킬 ID를 전투 정의 ID에 매핑합니다. 이 연결 전에도 장비·자동 무기·내부 성장 기능은 전투 스킬 모듈 없이 독립 실행됩니다.

거점은 장비나 가방 내부 Dictionary를 직접 수정하지 않습니다. Workbench가 장비·가방의 공개 반출입 계약을 조정하고, `Game`은 세션 경계에서 불투명 스냅샷을 전달할 뿐입니다. 따라서 향후 JSON 영구 저장이나 창고 기반 준비 화면을 추가해도 장착 규칙과 격자 배치를 재사용할 수 있습니다.

## 의도된 결합

- `Game`은 모듈 Scene의 문자열 경로와 조립 순서를 압니다.
- `EnemySpawner`는 기본 적 Scene을 참조합니다. 이는 `spawning → enemies` 선언 의존성입니다.
- `RoomEncounterSystem`은 맵·적 생성기의 공개 메서드만 사용합니다. 이는 Manifest에 선언된 `room_encounters → map_generation, spawning` 의존성입니다.
- `Game`은 기본 장비 Scene과 선택된 로드아웃 Resource 경로를 알고, 장비는 플레이어의 스탯 적용 공개 메서드만 압니다.
- `Game`은 인벤토리 카탈로그와 I/U 패널 Scene 경로를 알고, 가방과 장비 시스템은 서로의 내부 Node 경로를 참조하지 않습니다.
- `Game`은 장비, 밸런스, 자동 무기의 조립 순서를 알지만 각 모듈은 서로의 내부 Node 경로를 참조하지 않습니다.
- `Game`은 내부 레벨 → 버프 선택 → 외부 정산 순서와 장비 → 가방·원장 → 강화 서비스 순서를 압니다.
- 플레이어, 적, 투사체는 생성 벽용 충돌 레이어 `16`을 공유합니다.
- 맵 전용 스모크 테스트는 맵 기능 경로를 참조합니다. 맵 기능을 완전히 삭제하면 해당 테스트도 함께 제거하거나 교체해야 합니다.

이 결합은 숨겨진 의존성이 아니라 조립부, Manifest 검사, 문서에 드러난 계약으로 관리합니다.
