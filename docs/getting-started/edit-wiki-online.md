# 위키 수정 요청과 반영

온라인 위키는 [https://sfh-dev-wiki.pages.dev/](https://sfh-dev-wiki.pages.dev/)에서 읽습니다. 공개 페이지는 **읽기 전용**이며 연필 아이콘이나 익명 편집을 제공하지 않습니다.

## 기획자가 수정 또는 추가를 요청할 때

1. 홈의 `기획 요청·완료 안내` 블록에서 역할과 상태를 선택합니다.
2. 요청 ID, 바꿀 내용, 수락 기준, 근거를 입력해 제안 초안을 만듭니다.
3. 초안을 복사해 인증된 SFH Notion 원본에 붙여넣습니다.
4. AI 개발자는 다음 작업 시작 때 공개 Notion 스냅샷을 확인하고 같은 요청 ID로 구현·문서·E2E를 연결합니다.
5. 완료된 변경은 작업 브랜치와 PR 검증을 거쳐 병합되며 Cloudflare 위키에 자동 배포됩니다.

제안 초안은 현재 브라우저에만 임시 저장됩니다. 위키에 입력했다고 원본이나 게임 데이터가 바로 바뀌지는 않습니다.

## 개발자가 문서를 직접 바꿀 때

권한이 있는 개발자는 비공개 원본을 로컬 작업 폴더에서 수정합니다. `main`에 직접 쓰지 않고 `codex/` 작업 브랜치에서 다음 순서를 지킵니다.

1. `docs/**/*.md`, `mkdocs.yml`, 검색 우선순위, 전체 문서 노드맵을 함께 수정합니다.
2. 일일 업데이트는 날짜당 하나의 묶음 안에 추가하고 홈에는 오늘 항목만 최신순으로 둡니다.
3. strict 위키 빌드, 링크·검색·모바일 반응형 E2E를 실행합니다.
4. 커밋·푸시·PR·필수 검사를 통과한 뒤 병합합니다.
5. Cloudflare 배포와 공개 URL을 다시 확인합니다.

## 변경 위치

| 목적 | 원본 |
|---|---|
| 문서 본문 | `docs/**/*.md` |
| 좌측 메뉴 | `mkdocs.yml` |
| 기본 검색 순위 | `docs/assets/search-priorities.json` |
| 전체 문서 노드맵 | `docs/assets/knowledge-map.json` |
| 기획 요청 카드 | `docs/assets/planner-requests.json` |
| 배포 게이트 | `.github/workflows/deploy-wiki.yml` |

게임 수치 목록이 새로 필요하면 Google Sheet의 1행 변수명·2행 설명·3행 이후 데이터 계약을 확장하고, 확정 CSV와 Web 내장 데이터도 같은 PR에서 동기화합니다.

## 배포 확인 기준

- 공개 위키 홈과 수정한 문서가 같은 배포에서 열립니다.
- 검색 결과와 전체 문서 노드맵이 새 문서를 가리키며 404가 없습니다.
- 휴대폰 360px부터 데스크톱까지 가로 넘침과 클릭 범위 교차가 없습니다.
- 브라우저 플레이와 Windows 다운로드는 같은 검증 커밋과 데이터 버전을 사용합니다.
