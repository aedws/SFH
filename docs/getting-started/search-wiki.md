# 위키 실시간 검색 사용법

상단 검색 버튼이나 `/` 키로 검색창을 열면 입력 전에는 **기획자 검색 허브**, 입력 후에는 **실시간 전체 문서 검색**이 표시됩니다.

## 입력 전 검색 허브

검색 허브는 다음 순서로 기획자가 먼저 볼 문서를 정리합니다.

1. `docs/assets/search-priorities.json`의 기획 우선순위
2. 현재 브라우저에서 실제 선택한 검색어 횟수
3. 최근 선택 시점

TOP 10 아래에는 기획·현황, 전투 설계, 작전·맵, 장비·성장, 검증·구조 묶음이 있습니다. 항목을 누르면 해당 검색어가 입력되고 즉시 문서 결과로 전환됩니다.

!!! note "실시간 순위의 범위"
    GitHub Pages는 별도 사용자 추적 서버를 두지 않습니다. 따라서 검색 기록은 현재 브라우저에만 저장되며 다른 사용자에게 전송되지 않습니다. 공동 기본 순서는 JSON의 `priority` 값으로 관리합니다.

## 입력 후 실시간 문서 검색

글자를 입력하는 즉시 문서 제목, 본문, 각 문서의 `검색 별칭`을 함께 검색합니다. 결과를 선택한 검색어는 현재 브라우저의 최근 선택과 탐색 순위에 반영됩니다.

검색 결과가 부족하면 기능명 대신 다음 표현을 함께 시도합니다.

- 입력 키: `Q`, `U`, `I`, `F`
- 기획 상태: `확정 사항`, `앞으로 해야 할 작업`, `미확정`
- 플레이 흐름: `코어 플레이 루프`, `탈출 방어전`, `결과 정산`
- 시스템: `스마트 자동 타게팅`, `장비 모듈`, `작전 맵`
- 검증: `모듈 감사`, `성능 예산`, `버그픽스`

## 모든 문서 하단의 노드맵 HUD

홈의 기존 `자주 찾는 문서` 카드 영역과 위키의 각 문서 최하단에는 현재 위치와 전체 구조를 함께 보여 주는 `전체 문서 노드맵`이 있습니다. 왼쪽에서 오른쪽으로 다음 네 단계가 이어집니다.

```text
L1 대분류 · SFH 개발 위키
  → L2 중분류 · 프로젝트 / 시작 / 설계 / 아키텍처 / 품질 / 기능 / 지원
    → L3 소분류 · 작전·세계 / 전투·조작 / 성장·장비·경제 등
      → L4 세부 · 실제 위키 문서
```

현재 보고 있는 문서는 세부 노드에 `YOU`로 표시됩니다. 중분류를 누르면 소분류와 세부 문서가, 소분류를 누르면 오른쪽 문서 목록이 즉시 바뀝니다. 상단 입력란은 56개 노드의 분류명·문서명·설명을 동시에 검색합니다.

휴대폰에서는 상단 검색이 화면 전체 높이로 열립니다. 입력 전에는 기획 우선순위가, 입력 후에는 실시간 결과가 같은 스크롤 영역에 표시되므로 작은 화면에서도 빈 패널이나 본문과 겹치는 결과가 생기지 않습니다. 자세한 뷰포트 계약은 [모바일 위키 반응형 E2E](../quality/wiki-responsive-e2e.md)에서 확인합니다.

| 입력 | 동작 |
|---|---|
| 클릭·터치 | 분류를 펼치거나 세부 문서로 이동 |
| `Tab` | 다음 노드로 이동 |
| `↑`·`↓` | 같은 열의 이전·다음 노드로 이동 |
| `←`·`→` | 대→중→소→세부 열 사이 이동 |
| 검색 입력 | 전체 노드에서 최대 12개 즉시 결과 표시 |

데스크톱에서는 4열 연결 그래프, 992px 이하 화면에서는 2열, 640px 이하 휴대폰에서는 1열 구조로 바뀝니다. 각 분류의 모든 노드는 공통 연결 레일에 이어지고, 작은 화면에서는 선을 줄여 카드의 읽기 순서만 남깁니다.

분류 원본은 `docs/assets/knowledge-map.json`입니다. 링크는 현재 문서의 깊이가 아니라 배포된 위키 루트 `https://aedws.github.io/SFH/`를 기준으로 생성되므로 홈에서 기능 문서로 이동한 뒤 다시 노드맵을 사용해도 중첩 경로가 생기지 않습니다. 새 문서를 추가할 때 노드맵에서 빠지거나 중복되거나, 경로가 실제 Markdown 출력 주소와 다르면 위키 빌드가 실패합니다.

## 공동 우선순위 수정

`docs/assets/search-priorities.json`에서 다음 필드를 수정합니다.

| 필드 | 역할 |
|---|---|
| `query` | 클릭 시 실제 입력할 검색어 |
| `label` | 순위 목록에 표시할 이름 |
| `description` | 기획자가 결과를 판단할 짧은 설명 |
| `category` | 기획·전투·작전 등 분류 배지 |
| `priority` | 모든 사용자에게 적용되는 기본 순서 |
| `planner_groups` | TOP 10 아래 빠른 검색 묶음 |

위키 빌드는 TOP 10 데이터, 검색어 중복, 우선순위와 검색 스크립트 연결을 자동 검사합니다. 또한 MkDocs 내비게이션의 모든 문서와 노드맵의 세부 문서가 정확히 일치하는지 확인합니다.
