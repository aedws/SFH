# 위키 탐색과 검색 사용법

위키의 기본 탐색은 **큰 문서 → 주제 문서 → 작은 문서**입니다. 나무위키 문서를 읽듯이, 먼저 설명을 읽고 궁금한 항목의 링크를 누르면 됩니다. 문서 노드맵이나 개발 도구를 먼저 배울 필요는 없습니다.

[TOC]

## 1. 처음이라면 여기부터

로그인 후 작업실 상단의 **SFH 종합 문서부터 읽기**를 누르세요.

예를 들어 가방이 궁금하면 [SFH 종합 문서](../features/index.md) → [장비와 인벤토리](../features/equipment.md) → [격자 가방](../features/grid-inventory.md) 순서로 읽습니다. 스킬은 **전투와 조작**, 탈출은 **작전과 맵** 아래에 있습니다.

## 2. 문서 안에서 길 찾기

| 표시 | 용도 |
|---|---|
| 상단의 상위 문서 경로 | 지금 어디를 읽는지 확인하고 큰 문서로 돌아가기 |
| 본문의 목차 | 같은 문서의 원하는 절로 이동 |
| 하위 문서 | 이 주제의 상세 기능 문서로 이동 |
| 본문 속 관련 링크 | 다른 주제의 관련 규칙 확인 |
| 전체 문서 노드맵 펼치기 | 전체 구조가 궁금할 때만 보조 지도로 열기 |

상위·하위 문서 링크는 빌드된 HTML에 들어 있으므로 자바스크립트나 노드맵 로딩이 실패해도 사용할 수 있습니다. 휴대폰에서는 하위 문서가 한 열로 정렬됩니다. 브라우저 뒤로 가기도 그대로 사용할 수 있습니다.

## 3. 이름을 안다면 검색

상단의 **돋보기 + 문서 검색** 입력란(휴대폰에서는 **돋보기 + 검색** 버튼)이나 `/` 키로 검색창을 열면 입력 전에는 **기획자 검색 허브**, 입력 후에는 **실시간 전체 문서 검색**이 표시됩니다.

청록색 **삼각형 + 게임 플레이** 버튼은 검색이 아니라 게임을 **새 탭**에서 실행합니다. 휴대폰에서도 `검색`과 `플레이` 글자는 숨기지 않습니다. 검색은 현재 위키 안에서 열리고 `ESC` 또는 뒤로 화살표로 닫습니다. 공개 홈의 내부 문서 검색 비노출 정책은 유지합니다.

기본 우선순위에서 **SFH 종합 문서**를 먼저 찾을 수 있습니다. 그 아래에는 기획·현황, 전투, 작전, 장비·성장, 검증·구조 검색 묶음이 있습니다. 항목을 누르면 해당 검색어로 결과를 보여 줍니다.

검색어를 모르면 `가방`, `스킬`, `탈출`, `장비 모듈` 같은 게임 용어를 쓰세요. 키 이름이나 `검색 별칭`도 검색 대상입니다.

!!! note "실시간 순위의 범위"
    공동 기본 순서는 `docs/assets/search-priorities.json`의 우선순위이며, 선택 횟수와 최근 선택 시점은 현재 브라우저 안에만 저장됩니다. 다른 사용자의 검색량을 집계하는 실시간 인기 순위는 아닙니다.

## 4. 전체 노드맵은 필요할 때만

공개 홈과 로그인 화면을 제외한 내부 문서 맨 아래에서 **전체 문서 노드맵 펼치기**를 선택합니다. 처음 펼칠 때만 데이터를 불러옵니다. 큰 지도 대신 글을 읽고 싶으면 닫아 두어도 됩니다.

분류 → 묶음 → 세부 문서를 따라가며 현재 문서에는 `YOU`가 표시됩니다. 지도 검색창에서는 전체 문서를 검색합니다. 고정 개수는 안내문에 적지 않고 실제 데이터의 문서 수를 표시합니다.

| 입력 | 동작 |
|---|---|
| 클릭·터치 | 분류 선택 또는 세부 문서 이동 |
| `Tab` | 다음 조작 요소로 이동 |
| `↑`·`↓` | 같은 열의 이전·다음 노드 |
| `←`·`→` | 분류 열 사이 이동 |

## 5. 새 문서를 추가하는 규칙

1. 어느 큰 문서에 속하는지 먼저 정합니다. 게임 규칙이면 5개 게임 주제 중 하나, 구현 방식이면 개발 구조, 시험 기준이면 검증 영역입니다.
2. `mkdocs.yml`의 해당 주제 아래에 문서를 등록합니다. 파일을 옮기지 않고도 탐색 순서를 바꿀 수 있습니다.
3. 주제 문서의 `<!-- sfh:children -->` 위치에는 하위 링크가 자동으로 생성됩니다. 문서마다 상위 링크를 손으로 복사하지 않습니다.
4. `docs/assets/knowledge-map.json`에도 같은 문서를 등록합니다. 필요하면 `search-priorities.json`의 검색 우선순위와 빠른 검색 묶음을 보완합니다.
5. 위키 빌드에서 모든 문서의 상위 경로·하위 링크·고아 문서·기존 주소와 공개/내부 경계를 검사합니다.

같은 수치나 확정 규칙을 큰 문서에 복사하지 마세요. 큰 문서는 짧은 설명과 읽는 순서, 작은 문서는 정확한 규칙과 검증 결과를 담당합니다. 변경 제안 절차는 [웹에서 위키 수정](edit-wiki-online.md)을 따릅니다.
