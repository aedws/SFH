# 프로젝트 실행

## 브라우저에서 바로 플레이

[SFH Web 빌드 바로 실행](https://sfh-game.vstock-market.workers.dev/)을 열면 Godot 설치 없이 현재 `main` 기준 프로토타입을 플레이할 수 있습니다. 데스크톱 Chrome·Edge·Whale 등 최신 Chromium 브라우저를 권장하며, 터치 기기에서는 화면 키패드가 자동 표시됩니다. `K`의 `HUD·모바일` 탭에서 키패드 표시, 플레이어 상태 위치와 키 표기 형식을 바꿀 수 있습니다.

## Windows x86_64

[SFH-Windows-x64-v0.1.0.zip](https://sfh-game.vstock-market.workers.dev/downloads/v0.1.0/SFH-Windows-x64-v0.1.0.zip)을 직접 내려받습니다. ZIP에는 `SFH.exe`, `SFH.pck`, 라이선스 원문과 `BUILD-METADATA.json`이 들어 있으며 [동일 경로의 SHA-256 체크섬](https://sfh-game.vstock-market.workers.dev/downloads/v0.1.0/SFH-Windows-x64-v0.1.0.zip.sha256)으로 무결성을 확인할 수 있습니다.

메타데이터에는 빌드 커밋, Godot 4.7.2, CSV 데이터 버전과 Weapon·런 버프·업그레이드 CSV별 SHA-256이 기록됩니다. 브라우저와 Windows는 같은 CI 실행의 동일 커밋·PCK 입력으로 내보낸 뒤 각각 E2E와 체크섬을 통과한 산출물만 R2에 업로드하므로 파일 배포가 브라우저보다 뒤처지면 운영 전환이 실패합니다.

## 다운로드판 자동 저장 · 다시 켜서 이어가기

**Windows판은 같은 PC·Windows 계정에서 다시 실행하면 거점 세팅과 영구 진행을 불러옵니다.** 별도 저장 버튼은 필요 없습니다. I 편집 확인창의 **저장**을 누른 변경과 U/E에서 실제 적용한 변경만 저장하며, 미확정 편집 초안은 제외합니다.

| 다음 실행에 이어지는 것 | 저장 시점 / 소유 파일 |
|---|---|
| 거점 가방 칸 배치, 무기·방어구·모듈·고유 파츠와 강화, 활성 무기 | 확정 변경 후 짧은 묶음 저장·출격 직전 / `sfh_desktop_progress.json` |
| 영구 크레딧·창고·해금·제작 옵션·도감·소모품 로드아웃 | 기존 거래·탈출 정산 직후 / `sfh_profile.json` |
| 캐릭터·무기·방어구 외부 성장 | 기존 런 종료 정산 / `sfh_meta_progression.json` |
| 로컬 랭킹·시즌·명예 | 기존 랭킹 제공자 파일들 |
| 누적 작전·탈출 횟수와 최근 100회 결과 | 런 종료·중단 복원 / `sfh_desktop_progress.json` |

**저장 위치:** Windows 탐색기 주소창에 `%APPDATA%\Godot\app_userdata\SFH\`를 입력합니다. EXE·ZIP 폴더와 분리되어 새 ZIP을 다른 폴더에 풀어도 유지됩니다. 거점의 작은 저장 상태에 마우스를 올리면 경로와 최근 5회 기록을 확인합니다. ZIP에도 `WINDOWS-README.txt`를 포함합니다.

### 무엇은 이어지지 않나요?

- 전투 도중의 방·적·임시 버프를 그대로 재개하는 기능은 아닙니다. **작전 중 종료는 중단 1회로 기록**하고, 이미 지불한 비용은 환급하지 않으며 장착 장비에는 기존 실패 규칙을 적용합니다. 재실행은 무료 기본 무장의 거점에서 시작합니다.
- 미반출 전리품은 지급하지 않습니다. 성공 반출 장비는 기존 규칙대로 **창고**에 보관하고, 거점 가방에도 다시 넣어 이중 지급하지 않습니다.
- 브라우저 저장 가져오기·PC 간 자동 동기화·클라우드 저장은 제공하지 않습니다. 브라우저판의 기존 저장 방식을 변경하지 않습니다.

### 백업·손상·업데이트

게임을 완전히 종료한 뒤 **SFH 저장 폴더 전체**를 복사하면 수동 백업이나 PC 이전에 사용할 수 있습니다. 같은 저장 경로를 사용하는 여러 버전은 동시에 실행하지 마세요. 프로필·외부 성장·거점 세팅은 임시 파일 검증→직전 `.bak` 보존→본 파일 교체 순서로 저장합니다. 정상 백업이 있으면 손상된 본 파일 대신 읽고, 다음 저장 시 손상 원본을 `.corrupt-*`로 보존합니다. 가장 최근 변경 일부는 이전 백업 시점으로 되돌아갈 수 있습니다.

지원하지 않는 새 형식·복원 불가·디스크 쓰기 실패는 원본을 덮어쓰지 않고 거점에 오류를 표시하며 새 출격을 보류합니다. 폴더를 먼저 백업하고 여유 공간·쓰기 권한을 확인하세요. 기존 평문 프로필·외부 성장은 값을 유지해 새 형식으로 옮깁니다. 파일별 안전 저장이며 **여러 파일의 동시 원자적 정산이나 치트 방지를 보장하는 서버 저장은 아닙니다.**

### 개발자가 확장할 때

`FeatureManifest.desktop_progress_enabled`를 끄면 새 거점 체크포인트·이력 모듈을 제거할 수 있습니다. `desktop_progress_storage_path`로 프로필별 경로를 주입하고, 가방·장비의 `export/validate/restore_runtime_state` 계약으로만 연결합니다. 새 저장 Resource 종류는 `LoadoutValueCodec`의 명시적 형식 등록에 추가합니다. 저장 파일이 지정한 스크립트나 임의 경로는 로드하지 않습니다. 게임 목록을 추가하는 작업이 아니므로 Sheet/CSV 구조와 확정 데이터 버전은 그대로입니다.

검증 범위는 [재실행 E2E](../quality/e2e-play-session.md#desktop-save-e2e), 경계는 [모듈 감사](../architecture/module-audit.md#desktop-save-audit)에서 확인합니다.

## Cloudflare 병렬 배포

공개 위키는 `https://sfh-dev-wiki.pages.dev/`, 게임은 계정 고유 workers.dev 하위의 `https://sfh-game.vstock-market.workers.dev/`를 사용합니다. Windows 다운로드는 같은 게임 게이트웨이의 `/downloads/v0.1.0/` 아래에 둡니다. Cloudflare E2E 통과 뒤 저장소를 Private으로 전환하고 GitHub Pages 폴백은 종료했습니다.

목표 실행 주소는 `https://sfh-game.play-preview.dev/`입니다. 현재 `play-preview.dev`가 등록·DNS 없음 상태이므로 즉시 전환하면 게임이 열리지 않습니다. 저장소는 목표·현행 주소를 분리해 고정했으며, 도메인 등록→Worker custom domain→게임·Range 206·ZIP 해시 E2E가 모두 통과할 때만 링크를 자동 전환합니다. 이 안전장치는 도메인 구매·Cloudflare 플랜·결제를 자동으로 변경하지 않습니다.

| 구분 | 공개 접점 | 저장 책임 | 제공 범위 |
|---|---|---|---|
| 개발 위키 | `sfh-dev-wiki.pages.dev` | Cloudflare Pages `sfh-dev-wiki` | 문서·검색·진행률만 제공 |
| 브라우저 게임 | `sfh-game.vstock-market.workers.dev` | Worker `sfh-game` | Godot Web 런타임과 보안·Range 헤더 제공 |
| Windows 다운로드 | 게임 Worker의 `/downloads/<version>/` | 같은 Worker 게이트웨이 | 검증 ZIP·SHA-256만 제공 |
| 원본 산출물 | 공개 주소 없음 | Private R2 `sfh-game-artifacts` | `game/releases/<commit>/`과 `downloads/releases/<commit>/<version>/`를 분리 저장 |

`vstock-market`은 Cloudflare 계정의 공통 workers.dev 접미사입니다. SFH는 별도 Worker `sfh-game`, 별도 Private R2 `sfh-game-artifacts`를 사용하며 기존 VStock 애플리케이션의 Worker·R2 키를 읽거나 덮어쓰지 않습니다.

GitHub는 소스·PR·검사/복구 기록을 맡고 배포 파일을 보관하지 않습니다. 자체 러너가 같은 main 커밋의 Web·Windows·위키를 생성·검증하며, 배포 작업은 실행/시도별 SHA-256 전달본을 받아 다시 빌드하지 않고 Cloudflare로 직접 보냅니다. Web와 Windows는 R2의 커밋별 경로에 먼저 저장·읽기 검증한 뒤 Worker의 두 활성 경로를 함께 바꿉니다. 공개 `/downloads/<version>/` 주소는 그대로 유지합니다. 위키 Pages에는 게임 WASM·PCK를 결합하지 않습니다. 모든 위키 플레이 버튼은 게임 Worker 절대 주소를 새 탭에서 직접 열며, 기존 `/play/`는 302 호환 경로로만 유지합니다. [전달·실패·복구 계약](source-control-and-cleanup.md#source-only-delivery).

새 Windows ZIP과 체크섬의 공개 검수가 성공한 뒤 R2는 현재·직전 정상 커밋의 파일을 보존하고 나머지 정확한 Windows ZIP/체크섬만 정리합니다. 로컬 `dist` 패키징은 최신 버전만 유지합니다. Web 커밋 릴리스·위키·백업 브랜치·사용자 저장은 이 정리 대상이 아닙니다. 배포 실패 전에 기존 정상 파일을 삭제하지 않습니다.

Web 빌드는 게임 코드와 문서가 `main`에 반영될 때 GitHub Actions가 자동 생성하지만 개발 위키 파일과는 별도 산출물로 유지합니다. 게임 내보내기, 위키 빌드, 필수 `HTML·WASM·PCK` 검증 중 하나라도 실패하면 운영 전환을 중단하므로 플레이 버튼은 마지막으로 검증된 Worker 릴리스를 유지합니다. 한글 UI는 프로젝트에 포함된 OFL 1.1 `Nanum Gothic` 전역 폰트를 사용해 운영체제 폰트에 의존하지 않습니다.

무기, 내부 성장, 장비 강화, 전리품 생명 주기, 지역·난이도 드랍 테이블과 런 세션 소켓 RunAsset의 확정 CSV도 Web PCK에 명시적으로 포함합니다. 브라우저 런타임이 비-Resource CSV 스트림을 제공하지 못하는 환경에서는 원본과 함께 자동 생성한 `EmbeddedCsvPayload`를 읽습니다. 동기화 스크립트와 스모크 테스트가 CSV와 내장 미러의 완전 일치, 원본 경로, 내보내기 포함 계약을 함께 검사하므로 데이터가 빠지거나 어긋나면 작전 조립 전에 빌드를 차단합니다.

위키 홈의 현재 빌드 카드와 모든 문서 상단 고정 헤더의 `브라우저로 플레이` 버튼은 `data-sfh-surface="gameplay"`로 표시되고 게임 Worker를 직접 엽니다. 위키·게임·Private R2의 역할은 홈 카드의 `DOCS · PLAY · ASSETS` 표식과 `deployment-surfaces.json` 계약에서 함께 확인할 수 있습니다.

브라우저 빌드는 개발 프로토타입입니다. 최초 로딩 시간이 필요하고 밸런스와 로컬 저장 데이터 호환성은 개발 중 변경될 수 있습니다.

## Private 저장소 백업과 복구

저장소는 Private 상태를 유지합니다. `main`이 갱신될 때마다 변경 직전 커밋을 `backup/pre-main/<40자리 커밋 SHA>`에 자동 보존하고, 새 커밋이 게임·위키 빌드와 Cloudflare 배포 E2E를 모두 통과하면 `backup/verified-main/<40자리 커밋 SHA>`에도 보존합니다. 전체 SHA를 브랜치 이름에 사용하므로 어느 커밋의 백업인지 모호하지 않으며, 같은 이름이 다른 커밋을 가리키면 워크플로가 실패합니다.

복구는 GitHub Actions의 `Prepare main recovery PR`에서 검증된 전체 백업 브랜치를 입력해 시작합니다. 워크플로는 허용된 두 네임스페이스와 SHA를 다시 검증한 뒤 현재 `main`에서 `recovery/main/...` 브랜치를 만들고, 백업 시점의 파일 트리를 새 커밋으로 복원합니다. 자동 PR 생성 권한이 제한된 경우에는 출력된 compare URL로 같은 PR을 열 수 있습니다. PR에서는 변경 분류에 따른 `export-game`, `e2e`, `build` 판정이 통과해야 병합합니다. 게임이 바뀌는 복구는 병합 후 `package-windows`와 배포 검증까지 성공해야 완료입니다.

이 방식은 강제 푸시·reset·`main` 이력 재작성을 사용하지 않아 현재 상태와 복구 변경을 PR에서 비교할 수 있습니다. GitHub Free Private 저장소의 서버 측 Ruleset 제한을 대체하는 운영 안전망이며, Cloudflare 배포 대상·스토리지·과금 플랜·결제 설정은 변경하지 않습니다.

바탕화면에는 기본 `Newgame` 하나만 상시 유지합니다. 기능별 `Newgame-*` worktree는 PR 병합과 배포 확인 뒤 [작업 폴더 정리와 Git 복구](source-control-and-cleanup.md)의 `status`·`cherry` 검사를 통과한 경우에만 제거합니다. 폴더 복사본은 백업으로 쓰지 않고, 고유한 로컬 변경은 먼저 이름이 분명한 `codex/backup-*` 커밋으로 원격 보존합니다.

## Godot에서 로컬 실행

1. Godot에서 `project.godot`을 가져옵니다.
2. 우측 상단의 프로젝트 실행 버튼을 누르거나 `F5`를 누릅니다.
3. 큰 단일 방의 시작 거점에서 `WASD`로 동쪽 작전 게이트까지 이동하고 `F`를 누릅니다.
4. 세션 구성 화면에서 지역·난이도·페널티, 상점·제작·소모품과 `확정 CSV`/`실시간 테스트`를 확인합니다.
5. 소형·중형·대형을 누르면 표시된 영구 크레딧과 장착 소모품이 실제 차감되고 작전에 진입합니다.
6. 작전에서는 기본 `Space`로 회피하고 `Q`로 무기를 교체하며, `I`로 가방, `U`로 장비·개조 화면을 확인합니다. `K`에서 모든 조작을 바꿀 수 있습니다.
7. 작전 중 `1` 점멸, `2` 원형 자기장, `3` 기동 가속을 사용하고 하단 HUD에서 쿨타임을 확인합니다.
8. 신호가 열린 뒤 탈출 지점에서 `F`를 누르고 15~35초 동안 구역을 지킵니다. 성공 정산과 조건 랭크 확인 후 거점으로 복귀합니다.

## 성공 기준

- 창 크기는 기본적으로 1280×720입니다.
- 데스크톱과 Web 빌드 모두 한글 UI가 네모 글리프 없이 표시됩니다.
- 시작 시 1800×1040px 단일 방의 안전 거점과 동쪽 작전 게이트가 표시됩니다.
- 상단 HUD에 체력, 경험치, 생존 시간, 레벨, 처치 수가 표시됩니다.
- 하단 중앙 HUD에 세 전투 스킬의 키·설명·남은 쿨타임이 표시됩니다.
- 플레이어가 대각선을 포함한 8방향으로 가속·제동하며 Action 기반 회피를 사용하고, K 변경값이 즉시 반영됩니다.
- 터치 브라우저는 방향·공격·대시·스킬·상호작용·메뉴의 화면 패드를 제공하고 키보드와 같은 Action을 사용합니다.
- 플레이어 상태 HUD는 좌하단이 기본이며 K 설정에서 하단 좌·중·우 위치와 키 배지 형식을 바꿀 수 있습니다.
- 카메라가 플레이어를 부드럽게 따라갑니다.
- 적이 플레이어 주변에서 생성되어 추적합니다.
- 무기가 가장 가까운 적에게 자동으로 발사됩니다.
- Q 키로 돌격소총 3점사와 권총 고위력 관통을 교체할 수 있습니다.
- 작전 시작 전에 확정 CSV와 Google Sheet 실시간 테스트 모드를 버튼으로 선택할 수 있습니다.
- 영구 크레딧, 지역·난이도·페널티, 상점·창고·소모품·도면 제작 상태가 작전 화면에 표시됩니다.
- 자동 공격은 거리·남은 체력·우선 등급·밀집도를 합성해 대상을 선택합니다.
- 적 처치 후 경험치 결정이 생성됩니다.
- 32px 타일로 소형 18~24방, 중형 30~40방, 대형 45~60방이 생성되며 가장 작은 방도 화면 한 장보다 큽니다.
- 얇은 벽과 갈색 충돌 방해물이 표시됩니다.
- 방해물이 출입구 있는 긴 실내 칸막이, 넓은 설비 블록과 다중 기둥 형태로 표시됩니다.
- 적 머리 위에 빨간 체력과 파란 방어력 막대가 표시됩니다.
- 방에서는 현재 방 전체를 보고 통로에서는 정면 원뿔 시야만 보이지만, 미니맵은 전체 지형을 유지합니다.
- 벽면 금고·자재함·회수 단말기에서 `F`로 자원을 한 번만 회수할 수 있습니다.
- 획득한 크레딧이 상단 HUD에 표시됩니다.
- 휴대 크레딧이 투입 비용에 도달하면 1~2명의 전역 엘리트가 발생해 방 문과 무관하게 추격합니다.
- I 키로 서로 다른 크기의 아이템 패널이 있는 격자 가방이 열립니다.
- U 키로 전체 화면 장비 관리가 열리고 왼쪽 메인·보조·신체·신발 슬롯을 전환할 수 있습니다.
- 장비 장착 탭에서 가방 장비 카드를 직접 고르고, 모듈·파츠 탭에서 장착 슬롯·코스트 막대·필터·강화 비용을 확인할 수 있습니다.
- 상단 HUD에 맵 등급과 방 수가 표시됩니다.
- 초록 원은 시작점이며 탈출 지점은 잠금 중 회색, 신호 개방 후 주황색입니다.
- 피격 후 4초 동안 피해를 받지 않으면 최대 체력 65%까지 일부 회복합니다.
- 탈출 범위에서 F를 누르면 카운트다운 방어전이 시작되고 구역 유지에 성공하면 영구 결과 정산 화면이 표시됩니다.

## 자동 스모크 테스트

```powershell
.\scripts\test-game.cmd
```

시작 거점, 작전 게이트, 전투 세션 진입·복귀, 화면 크기 방, 전장의 안개, 미니맵, 자원 회수와 기존 전투·장비·성장 기능이 정상이라면 `SMOKE_TEST_OK`가 표시됩니다.

## 자동 성능 예산 테스트

```powershell
.\scripts\test-performance.ps1
```

대형 작전의 프레임 시간, Node 수, 충돌체 압축률과 동시 전기 이펙트 수가 예산 안이면 `PERFORMANCE_BUDGET_OK`가 표시됩니다. 이 테스트는 개발 PC의 CPU 회귀 검사용이며 실제 최소 사양은 [최소·권장 사양과 성능 예산](../performance/minimum-requirements.md)의 실기 절차로 별도 인증합니다.
