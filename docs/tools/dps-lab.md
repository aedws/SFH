# 무기·스킬 DPS 실험실

적을 얼마나 빨리 처치하는지 수치로 비교하는 **기획용 계산기**입니다. DPS는 초당 피해, 처치 시간(TTK)은 적의 체력과 방어막을 모두 소모하는 데 걸리는 시간입니다.

1. 무기와 스킬 원본을 선택합니다. 선택을 바꾸면 시험값이 초기화됩니다.
2. **적과 비교 조건**에서 체력·방어막·목표 처치 시간을 입력합니다.
3. **장착 시뮬레이터**에서 무기 파츠·모듈, 방어구·모듈, 캐릭터·공용 모듈을 선택합니다. 장비/모듈 강화, 품질 배율, 최대 레벨 소켓 태그를 바꿀 수 있습니다.
4. 무기 또는 스킬 시험값을 바꾸고 청록색 피해선과 미장착 기준의 회색 점선을 비교합니다. 스킬을 바꿔도 장착 세팅은 유지하며, 무기를 바꾸면 무기 파츠·모듈만 초기화합니다.
5. **스킬별 피해 · 캐릭터 생존 그래프**를 펼칩니다. 모든 등록 스킬은 독립 AP 조건의 피해선으로 비교하고, 방어구는 HP·방어·이동속도·피격 1회 피해·연속 피격 생존 시간으로 확인합니다.

## 요원 AP와 이동 조건

고급 자원 입력은 **패시브 적용 전 기본값**입니다. 선봉대(뱅가드)의 [전술 적응](../features/character-selection.md#tactical-adaptation-20260922)은 최대/시작 AP ×1.15, ‘지속 이동 가정’을 켠 동안 자연 회복 ×1.20을 적용합니다. 현재 기본100/10이면115/12가 되며, 정지는115/10입니다. ‘패시브 적용 AP’에서 최종 최대량과 초당 회복을 확인하세요.

이동 토글은 관측 시간 전체의 비교 조건이지 실제 이동 경로/벽/워프 시뮬레이터가 아닙니다. 회복 지연과 충전 제한은 그대로이며 드랍은 포함하지 않습니다. 개발자 확정 그래프도 같은 계산식을 사용하고, 이전 근거 해시의 확정안은 최신 소스와 별개로 표시합니다.

## 결과를 읽는 법

| 결과 | 의미 |
| --- | --- |
| 관측 구간 합산 DPS | 선택한 무기 + 스킬의 누적 피해 ÷ 관측 시간. 첫 발사와 첫 스킬이 준비된 0초에서 시작합니다. |
| 예상 처치 시간 | 평균 피해선이 적 체력 + 방어막을 처음 넘는 시점. 첫 타격 처치는 0초, 관측 구간 내 미처치는 별도로 표시합니다. |
| 목표 시간 대비 | 기획자가 입력한 목표와 비교할 뿐, 자동으로 쉬움·어려움을 확정하지 않습니다. |
| 무기 장기 DPS¹ | 점사 사이 간격과 마지막 발사 후 대기를 포함한 반복 주기 기준. 고유 기능의 주 대상 피해를 평균화합니다. 짧은 구간 DPS와 다를 수 있습니다. |
| 적 접촉 DPS | 연속 접촉 시 적 공격력 ÷ 공격 간격. 플레이어 방어·회피를 적용하지 않은 압박 참고값입니다. |

**적 방어막은 피해 감소율이 아닙니다.** 먼저 소모되는 흡수량입니다. 예를 들어 체력 100 + 방어막 50인 적은 총 150 피해가 필요합니다. 적 기본값 선택은 난이도의 기본 배율만 적용하며, 체류 시간 성장·보스·페널티는 포함하지 않습니다.

## 실제 전투와의 차이

- 단일 적, 무기 1개와 스킬 1개를 대상으로 한 준비 완료 상태의 연속 공격 모델입니다. **표적 거리(px)**에 따른 [거리 피해 곡선](../features/weapon-distance.md)과 탐지·탄환 수명 범위를 적용합니다. 탄환 도착 지연·재탐색·이동·회피·재장전·다수 적 분산은 시뮬레이션하지 않습니다.
- 치명타와 명중률은 평균 피해로 계산합니다. 따라서 표시한 TTK는 **평균 피해선의 교차 시점**이지, 무작위 실제 전투의 평균 처치 시간을 보장하는 값이 아닙니다.
- 0.01초 단위 모델, 그래프는 0.1초 간격 표본입니다. 실제 프레임 지연은 포함하지 않습니다. 첫 타격부터 관측 종료 시점까지 포함하므로 짧은 구간에서는 장기 DPS와 차이가 납니다.
- 자기장은 시전 즉시 첫 피해를 준 뒤 지속 시간 끝 **이전까지** 누적합니다. 기본 5초 / 0.5초는 10틱입니다. 무기 태그 제한과 무기별 스킬 피해·지속 시간 보정을 적용합니다.
- AP 회복 지연, 쿨타임, 순차 충전 회복을 함께 적용합니다. 적 처치 AP 드랍과 다른 스킬의 AP 경쟁은 제외합니다. 제한을 끄면 실제 전투가 아닌 이론 상한입니다.
- 고유 기능은 주 대상 1명의 고정 피해만 반영합니다. 주변 적 광역 피해·이동 이득·상태이상 자체는 DPS로 환산하지 않습니다. 기동 가속의 직접 피해 0은 정상입니다.
- 내부 무기 레벨은 기본 탄환 피해에만 반영하며, 고유 기능의 고정 피해는 증폭하지 않습니다. 장착 시뮬레이터는 활성 무기·방어구·캐릭터의 실제 Resource/강화 CSV를 합산합니다. 캐릭터 레벨에는 외부 성장 HP·이동속도도 반영됩니다. 무기/방어구 외부 계정 레벨, 랜덤 부여 옵션·세트·런 버프·소모품·보조 무기 모듈은 자동 합산하지 않습니다. 필요한 무기 추가 보정은 고급 시험값에 직접 입력하고 근거를 함께 기록하세요.
- **파츠와 모듈에 효과를 지어내지 않습니다.** 현행 파츠 강화는 직접 피해에 연결되지 않습니다. `target_range`/`projectile_damage` 같은 플레이어 미사용 통계는 무기 피해로 자동 변환하지 않습니다. 활성 무기에 장착한 모듈의 강화 CSV 무기 보정만 탄환 DPS에 합산합니다. 방어구/캐릭터 모듈은 플레이어 스탯 계약을 따릅니다. 후보 special_feature_id는 DPS 효과가 아닙니다.
- 방어 생존선은 실제 `max(1, 적 피해 − 방어력)`을 사용하고 0초부터 접촉 공격을 받는 통제 조건입니다. 회복·회피·적 공격 중단은 제외합니다. 같은 수식/장착 조건을 재현하지만 실제 전투 난수·프레임·동선의 완전한 재생은 아닙니다.
- ‘매 시전 직전 감전’은 상태를 매번 재부여할 수 있다고 가정한 상한 실험입니다. 실제 상태 연계 시뮬레이션이 아닙니다.

## 원본과 기획 요청

무기는 저장소의 **확정 Weapon CSV + 무기 Resource**, 스킬은 실제 런타임이 사용하는 **스킬 Resource**, 적은 Enemy와 작전 난이도 Resource에서 추출합니다. 실시간 Google Sheets 미확정 값이나 현재 플레이 중인 캐릭터 저장 데이터를 가져오는 화면은 아닙니다.

CSV 행이 없는 무기는 현재 게임이 사용하는 **런타임 대체값**으로 표시합니다. 이를 의도된 근접 무기 밸런스 확정값으로 해석하지 마세요. 데이터 변경 시 원본 지문 검사가 오래된 카탈로그를 차단합니다.

시험값은 메모리에만 존재하며 저장소·Google Sheets·게임·계정 저장을 수정하지 않습니다. 변경 제안은 아래처럼 [기획 요청 절차](../design/planner-request-workflow.md)에 기록합니다.

> [임시] 대상: 돌격소총 / 원형 자기장. 적 HP 100, 방어막 50, 30초, 명중 1, 체류 1, AP 제한 적용. 변경: 탄환 피해 1.6 → 2.0. 목표 처치 5초. 계산기 결과와 실제 플레이 검수를 각각 첨부. 판단 요청: 확정 적용 여부.

관련 안내: [아이템·밸런싱 튜토리얼](../getting-started/planner-item-balance-tutorial.md) · [전투와 조작](../features/combat.md) · [기획자 작업실](../access/planner.md)

기획자 작업실에 내장된 같은 계산기는 [기획 확정본 전달](balance-workbench.md)을 지원합니다. 이 독립 실험실은 메모리 시험용이며, 저장은 기획자 작업실의 명시적 확인에서만 수행합니다.

## 모듈 계약과 검증

`export_dps_catalog.gd`는 읽기 전용 Resource/CSV 어댑터, `dps-catalog.json`은 인증된 데이터, `dps-engine.js`는 순수 계산, `dps-lab.js`는 입력·표·SVG 표시만 담당합니다. 새 효과 종류는 계산 모델 등록 없이 임의 추정하지 않습니다. 새 게임 목록이 필요한 작업이 아니므로 Google Sheets 구조는 확장하지 않았습니다.

`export_dps_loadout.gd`는 실제 강화 제공자·장비 Resource에서 목록과 레벨별 기여를 추출합니다. `dps-loadout.js`는 호환·중복·슬롯·비용·품질을 검증하고 `dps-loadout-ui.js`는 선택만 제공합니다. 새 무기/방어구/모듈/캐릭터와 기존 유형의 새 스킬은 추출 후 자동 나열됩니다. `test_dps_loadout.mjs`는 실제 Godot EquipmentSystem·Player·AutoWeapon으로 만든 104개 조합과 수치·코스트를 대조합니다. 미지원 효과 종류는 추출 실패로 알려야 하며 0 피해로 조용히 대체하지 않습니다.

기획 확정은 계산 모델 v2의 장착 스냅샷·소스 지문·합산/무기/스킬별/생존 그래프를 서버에서 다시 검증해 저장합니다. 개발자 기본 화면은 최신 전투 확정안을 우선하며, 없거나 오래된 원본이면 현재 구현 그래프로 전환하고 이유를 표시합니다. 과거 확정본은 변경하지 않습니다.

검증: 원본 파일 목록·SHA-256 일치, 점사 주기·치명·자기장 틱·태그·방어막·AP·충전·0/잘못된 입력, 전 카탈로그 조합을 자동 검사합니다. 렌더링 E2E는 320/390/768/1440px, 값 변경 → 결과/그래프 동시 갱신, 초기화, 인증 실패 표시, 표와 키보드 입력을 검사합니다. 이는 계산기 검증이며 실제 플레이 난이도/FUN QA의 대체물이 아닙니다.

2026-09-08 확장 검증: 원본 128개 파일 지문, 무기 5종 × (스킬 4종 + 미선택) 25조합과 실제 Godot 장착 계산 104조합을 대조했습니다. 320/390/768/1440px Chromium에서 장착 변경·중복 차단·캐릭터 교체·개별 스킬 그래프·확정 저장·개발자 읽기 전용 기본값·오래된 원본/미확정/조회 실패를 검증했습니다. 모바일 그래프는 반응형 SVG로 제공합니다.

장착 회귀: `node scripts/test_dps_loadout.mjs`, 화면 연결: `node scripts/test_dps_loadout_ui.mjs http://127.0.0.1:8767`, 확정 API: `node scripts/test_balance_workbench.mjs`. 같은 유형의 신규 스킬과 같은 슬롯의 신규 방어구가 추가되어도 목록 확장과 초기 선택을 유지합니다. 신규 효과 유형은 계산 어댑터와 런타임 대조 사례를 함께 추가해야 합니다. 기존 목록만 활용하므로 이번 변경은 Google Sheet 탭을 추가하지 않습니다.

재검증 명령: `node scripts/test_dps_catalog.mjs`, `node scripts/test_dps_engine.mjs`, `node scripts/test_wiki_auth_worker.mjs`. 이 세 검사는 CI 빌드 게이트에 포함됩니다. 렌더링은 MkDocs 결과를 로컬 서버로 연 뒤 Playwright가 설치된 환경에서 `node scripts/test_dps_lab.mjs http://127.0.0.1:8767`로 별도 실행합니다. 데이터 갱신은 Godot headless에서 `--script res://scripts/export_dps_catalog.gd`, 변경 확인만 할 때는 뒤에 `-- --check`를 붙입니다.
