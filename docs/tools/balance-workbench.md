# 수치 실험과 기획 확정 그래프

[기획자 계산기](../access/planner.md#balance-workbench)에서 값을 시험하고, [개발자 확정 그래프](../access/developer.md#confirmed-balance)에서 전달된 결과를 읽습니다. 각 역할 로그인으로 접근합니다.

## 수치를 조정하는 순서

성장률은 먼저 아래 **선택한 대상 하나의 성장 그래프**를 사용합니다. 서로 다른 무기·캐릭터·방어구를 잇는 선은 성장률이 아닙니다.

1. 무기·스킬·적·AP는 DPS 계산기를 사용합니다. 피해와 처치 시간은 [DPS 모델 한계](dps-lab.md)를 함께 읽습니다.
2. 시설은 중심 깊이별 적 수량 범위, 회수는 생환율을 가정한 기대 회수를 비교합니다. 기본 입력은 예시이며 실제 플레이 기록이 아닙니다.
3. 그 외에는 전체 수치 목록에서 CSV와 변수 열을 고릅니다. 성장·모듈·파츠·아이템·상점·제작·드랍 등 **숫자 열 전체**를 행별로 변경하고 원본과 비교합니다. 서로 다른 항목은 연결선 없이 원본 표로 제공합니다. 이름·태그 등 문자열은 기존 Sheet에서 편집합니다.
4. 안건 제목, 기획 사유·목표, Notion 근거 링크를 넣고 검토 확인 후 **기획 확정본 저장**을 누릅니다. 빈값·NaN·범위 초과는 저장되지 않습니다. 목록 비교의 허용 범위는 계산 예산이며 실제 게임 적용 유효성은 해당 CSV 검증기가 별도로 판정합니다.
5. 저장 완료를 확인합니다. 재시도는 같은 제출 ID를 재사용합니다. 수정안은 새 확정본으로 남기며 이전 그래프를 덮어쓰지 않습니다.

## 확정의 의미

<a id="growth"></a>

### 선택한 대상 하나의 성장 그래프

- 무기: 한 무기의 강화 단계별 기대 직격 피해 또는 지속 무기 DPS.
- 캐릭터: 한 캐릭터의 외부 레벨별 HP·방어력·이동속도 중 한 지표.
- 방어구: 한 방어구만 착용했을 때 강화 단계별 방어력·HP·이동속도 중 한 지표.
- 가로축은 단계/레벨, 세로축은 선택한 성능 수치입니다. `성장률 = (해당 단계 값 / 1단계 값 - 1) × 100`이며 기준값 0일 때 비율을 만들지 않습니다. 증가량은 별도로 표시합니다.
- 선택한 대상만 성장시킵니다. 품질 1, 파츠·모듈 없음, 내부 레벨 1, 거리 0을 고정합니다. 캐릭터를 시험할 때 방어구는 없고, 방어구를 시험할 때 캐릭터는 기본 요원 레벨 1입니다. 고유 효과·옵션은 기존 계산과 동일하게 유지합니다.
- 원본의 최대 단계까지만 표시합니다. 현재 캐릭터 40레벨, 무기·방어구는 각 원본의 3~4단계이며 임의로 성장 단계를 늘리지 않습니다. 현행 효과가 없으면 평탄하게, 단계 보정이 줄면 하락으로 표시합니다.
- **원본 확인 필요:** 전술 방탄복 4단계의 성장 보정은 현재 비어 있어 3단계보다 방어력이 내려갑니다. 이 도구는 이를 숨기거나 임의 보간하지 않습니다. 게임 수치 수정은 별도 안건으로 결정합니다.
- 기획자는 단계별 목표값을 시험하고 확정본으로 전달할 수 있습니다. 목표값은 제안이며 성장 수식이나 CSV를 자동 변경하지 않습니다. 개발자는 현행 성장 곡선과 별도로 저장된 확정안을 읽습니다. 대상·지표를 바꾸면 미확정 시험값을 현행값으로 초기화합니다.
- 상세 수치 표와 편집기는 접어 두어 기본 화면에서는 곡선·처음/마지막 값·성장률에 집중합니다.

기획 확정본은 검토 완료한 **제출안**입니다. 오너 승인·배포 상태를 바꾸거나 게임 수치를 즉시 수정하지 않습니다. 기존 Notion 결정과 충돌하면 오너가 판단합니다. 승인 이후 개발자가 Sheet → 실시간 시험 → 확정 CSV → E2E → 배포 순서로 반영합니다.

입력과 원본 지문, 계산 모델 버전, 결과 그래프, 기획 사유, Notion 링크, 서버 저장 시각을 함께 보관합니다. 원본 카탈로그가 바뀐 상태에서 제출하면 재검토를 요청합니다. 이미 확정한 그래프는 나중의 계산식이나 원본 갱신으로 바뀌지 않습니다. 개발자 화면은 저장 당시 결과를 읽습니다.

## 확정값이 없을 때 개발자가 보는 자료

확정본이 없으면 **현행 밸런스 데이터 · CSV 기준값**을 자동으로 펼칩니다. 목록과 변수 열을 선택하면 원본 정밀도의 표를 볼 수 있습니다. 성장 추이는 별도의 단일 대상 그래프에서 확인합니다. CSV 버전·파일 경로·SHA-256 지문으로 근거를 확인합니다. 예시 시나리오를 넣거나 새 확정 기록을 저장하지 않습니다.

일부 안건만 확정되면 확정 그래프를 먼저 보여주고 현행 데이터는 접어 둡니다. 아직 확정하지 않은 항목도 이 패널에서 전체 목록을 조회할 수 있습니다. 개별 안건과 CSV 열의 확정 여부를 자동 판정하거나 확정안을 현행값으로 덮어쓰지는 않습니다. 조회용 선택기는 있지만 값 편집기는 없습니다.

여기서 현행은 **위키와 함께 생성된 저장소 CSV 스냅샷**입니다. 실시간 Sheet 수정·런 버프·세이브 보정·실제 플레이 기록을 뜻하지 않습니다. 기획 확정 및 오너 승인과 구분하며, 실제 배포 게임과 비교할 때는 릴리스 데이터 버전도 확인합니다. 확정 API 연결 실패는 ‘확정 없음’으로 오인하지 않고 상태 확인 불가로 표시합니다. CSV 조회 실패는 재시도하며 임의 수치로 대체하지 않습니다.

## 모듈·보안 경계

- 원본 어댑터: `build_balance_catalog.py`가 기존 CSV 숫자 열을 읽어 보호 카탈로그를 생성합니다. 새 게임 목록이 없으므로 Sheet 탭은 추가하지 않습니다.
- 순수 모델: `dps-engine.js`와 `balance-engine.js`. `growth-engine.js`는 기존 장착 계산기를 단계별로 호출하며 `growth-lab.js`는 선택·시험값·표시만 담당합니다. 브라우저와 서버가 같은 계산식을 사용합니다. 새 목록이나 게임 수치를 만들지 않아 Sheet 확장은 없습니다.
- 표시: `balance-workbench.js`가 입력·반응형 SVG·접근 가능한 수치 표를 담당합니다. `currentBalance`는 기존 카탈로그의 읽기 전용 표시 어댑터이며 확정 API·게임 수치 쓰기와 분리됩니다. 개발자 영역에는 변경 명령이 없습니다.
- 확인 API: 기존 인증된 `/api/auth/balance`에서 planner만 POST, 양 역할은 GET. 세션·CSRF·동일 출처·본문 크기·원본 지문을 검사하며 서버가 다시 계산합니다. 임의 클라이언트 그래프는 저장하지 않습니다. 개발자 응답은 편집용 제출 입력을 제외하고 그래프·근거만 제공합니다. 과도한 자기장 중첩 계산은 예산 초과로 거부하고 조건 축소를 안내합니다.
- 저장: 기존 비공개 위키 R2의 `balance/confirmed/` 접두사에 불변 기록으로 저장합니다. 자격 증명·게임 데이터·새 과금 상품·도메인을 변경하지 않습니다. 페이지당 20개, 이전 확정본 더 보기로 조회합니다.
- 역할 범위: 개발자 **작업실의 수치 영역**은 그래프·현행 수치 조회 전용입니다. 기존 공용 DPS 문서는 모델 검증용으로 양 역할 접근을 유지하되 그 화면에서 개발자가 기획 확정 저장을 할 수는 없습니다.

이 계산기는 실제 10분 플레이·드랍 분포·난이도/FUN QA의 대체물이 아닙니다. 개별 수치의 의미와 수락 기준을 Notion에 함께 작성해 주세요.
