# P7 이후 사전 구현 설계

!!! warning "번호 체계"
    공개 [SFH Master GDD](https://wobbly-pawpaw-1ff.notion.site/SFH-6b45b728004082af8a4a811ef0a1c5e9)의 공식 구현 마일스톤은 **Phase 1~6**입니다. 이 문서의 P7~P10은 기획 원문에 없는 새 Phase를 확정하는 것이 아니라, Phase 1~6 완료 뒤 남는 상세 요구를 추적하기 위한 **저장소 내부 후속 작업 ID**입니다.

## 2026-09-02 갱신 근거

- 공개 원문: root `v1005`, 77블록, SHA-256 `614a0b8ddee4…`
- 새로 구체화된 범위: 런 종료 회전 상점, 손상·표준·고성능 3대 매물, 골드 리롤, 설계도 영구 제작 등록, 맞춤 옵션·소켓 제작, 단일·밀집 훈련 더미, DPS·타격·AP·쿨타임 계측, 무비용 자유 세팅, 도감 해금률·지역 힌트
- 공식 Phase 5 문구도 `창고·상점 리롤·제작소·연습장 + 준비 세션 UI`로 확대됐습니다. 따라서 이 기능들의 최소 연결은 먼저 P5 완료 조건에 포함하고, P7+에서는 경제 깊이·반복성·운영 품질을 완결합니다.
- Notion Phase 체크박스는 0/6입니다. `No` 문자열 오판독을 수정했으며, 체크 여부는 확정도나 코드 완료 증거로 사용하지 않습니다.

## 착수 게이트

`P5 완료 → P6 완료 → P7 로비 경제 → P8 훈련장 → P9 도감·프리셋 → P10 출시 후보 회귀`

P5·P6 로컬 프로토타입 완료를 기준으로 내부 P7을 시작합니다. P6 실서비스 계정·서버 검증은 별도 승인 대기이며, P7 로컬 상점 구현을 서버 검증 완료로 계산하지 않습니다.

## 2026-09-04 · P7-01A~04 진행 결과

공개 원문을 다시 조회한 결과 `v1005 · 77블록 · 614a0b8ddee4`로 기존 스냅샷과 같습니다. 공식 Phase 체크도 0/6이며 변경하지 않았습니다.

- **완료한 하위 흐름:** 거점 상점 → 세 품질 선택/비교 → 명시 구매 → I 가방 개별 실물 → U/E 장착 → 실제 품질 수치 → 해제 뒤 품질 보존.
- **추가 검증:** 열기·선택 무차감, 가방 공간 부족, 중복 클릭, 오래된 견적, 거래 기록 실패 원복, 4개 화면 크기, 기능 제거, 테스트 저장 격리.
- **아직 남음:** 손상품 가격/성능 범위와 고성능 옵션·소켓 규칙의 기획 확정. 로컬 구현과 운영값 승인을 구분합니다.
- **데이터:** 기존 ShopOffer 6행·확정 CSV를 재사용해 Sheet 목록을 늘리지 않았습니다. 현행 배율·옵션·소켓은 임시 정책입니다.
- **상태:** P7-01A/B 구현 완료·기획 확정 대기, P7-02 회전/리롤·P7-03 영구 도면 등록·P7-04 원자적 맞춤 제작 구현 완료, P8~P10은 `planned`입니다. [상점 사용법](../features/hub-economy.md#shop-browser), [도면 제작](../features/blueprint-crafting.md#p7-04), [검증](../quality/e2e-play-session.md#p7-workshop-e2e).

## P10 · 출시 후보 운영 검증

- 신규 프로필에서 무료 복구→유료 출격→정산→상점·제작→훈련→도감까지 끊김 없이 이어집니다.
- Web·Windows는 동일 커밋·PCK·CSV 해시를 사용하고 모바일은 같은 Input Action을 터치로 전달합니다.
- 실패·취소·중복 입력은 자산을 이중 차감·지급하지 않습니다.
- 평균 PC·대형 교전 60 FPS 예산, 모듈 제거, 위키 링크·검색·모바일 접근성 검사를 함께 통과합니다.

- 결제, 유료 재화, Cloudflare 유료 플랜 활성화는 P7+ 범위가 아닙니다.

## 위변조 감지·거래 기록·백업 구현 예정 {#economy-integrity-plan}

!!! warning "계획만 등록 · 미구현 · 착수 보류"
    2026-09-03 사용자 지시에 따라 연구 결과만 보관합니다. 아래 모듈·서버·DB·백업 작업은 **이번에 구현하거나 활성화하지 않습니다**. P7 로컬 상점 작업과 분리하며 기존 저장·배포·과금·도메인을 유지합니다. 문서 작성은 기능 진행률에 가산하지 않습니다.

### 목적과 현재 한계

아이템·크레딧의 생성·소비·이전·복구 근거를 남겨 고의 변조와 저장/통신 오류를 구분합니다. 현행 JSON의 임시 저장·이전본·SHA-256은 손상 대비입니다. 값을 바꾼 뒤 해시를 다시 계산하거나 정상 과거 저장으로 되돌리는 행위까지 검증하지 않습니다. 랭킹 제출 봉투도 클라이언트 형식 검증이며 실제 정상 플레이 증명이 아닙니다.

### 예정 모듈 계약

| 모듈 | 예정 책임 | 금지할 결합 |
|---|---|---|
| EconomyCommand | 구매·획득·제작·강화·정산 요청 형식 | UI에서 잔액/능력치 최종값 직접 지정 |
| EconomyPolicy | 소유권·비용·보상·확정 CSV 버전 검증 | 실시간 시험 시트를 공식 경제에 무검증 반영 |
| EconomyTransaction | 자산 변경·거래 기록·중복 방지를 한 번에 확정 | 재화 차감만 저장하고 지급은 별도 확정 |
| ItemProvenance | 개별 장비 ID·생성 거래·소유·소비 이력 | 동일 아이템 복제 또는 이미 소비한 보상 재청구 |
| SecurityAudit | 의심 요청·거절·충돌·운영자 복구 기록 | 비밀번호·토큰 기록, 클라이언트 로그를 진실로 간주 |
| SaveBackupProvider | 저장 세대·백업·변환·복원 제공자 | 빌드 다운로드 정리와 플레이어 백업 삭제 권한 공유 |

권장 흐름은 `행동 요청 → 인증·규칙 검증 → 자산/원장 동시 확정 → 처리 영수증 → UI 반영`입니다. 같은 요청의 재전송은 기존 결과를 반환하고, 요청 ID를 바꿔도 동일 작전/드랍 보상을 재지급하지 않습니다. 두 기기 동시 소비에는 상태 버전 검사를 사용합니다. 서버 없는 로컬 거래와 서버 검증 거래는 같은 공개 인터페이스 뒤의 다른 제공자로 구성할 예정입니다.

### 기획·운영 결정이 먼저 필요한 항목

- 오프라인 싱글 성장과 온라인 검증 성장의 분리 여부. 기존 로컬 저장은 보존하되 자동으로 공식 거래·랭킹 자산으로 승격하지 않는 안을 권장합니다. **아직 적용된 정책은 아닙니다.**
- 게임 계정 제공자와 계정 복구. 위키 planner/developer 계정은 게임 계정으로 재사용하지 않습니다.
- 비경쟁 협동/공식 거래/랭킹의 신뢰 경계. 클라이언트가 보고한 처치·드랍의 상한 검사만으로 정상 플레이를 증명할 수 없습니다. 공식 경제를 보호하려면 주요 전투·드랍 판정의 신뢰 서버 이전이 필요합니다.
- 허용 데이터 손실 시간·복구 시간, 백업/감사 기록 보관 기간, 열람·복구 권한, 제재 판단 주체.
- 서버 검증 연결이 끊긴 경우 `확정/대기/거절` 표시와 재접속 정책. 단절이나 저장 손상만으로 부정행위 정지하지 않습니다.

### 예정 기록·백업·복구

- 정상 거래 원장과 보안 감사 기록을 분리합니다. 서버 시각·계정·작전/거래 ID·변경량·상태/규칙 버전·판정 사유를 남깁니다.
- 순번·이전 해시·서버 서명 체크포인트와 별도 보관 권한으로 감사 기록 수정·삭제를 탐지합니다. 해시 연결만으로 관리자 수준 조작까지 방지한다고 주장하지 않습니다.
- 로컬은 여러 세대의 검증 저장과 프로필·장비·성장 **동일 세대** 복구, 버전 변환 전 백업을 예정합니다. 테스트는 실제 플레이 저장 경로에서 실행하지 않습니다.
- 서버 후보는 별도 Workers API + D1 거래 DB + 비공개 R2 백업입니다. 기존 배포 Worker/R2는 플레이어 경제 서버가 아니며 재사용 활성화하지 않습니다. 비용/사용량 검토 전 서비스·과금 변경 금지.
- 계정별 복구는 백업/원장을 대조해 새 복구 거래로 기록합니다. 이미 이전·소비한 아이템을 과거 저장 덮어쓰기로 복제하지 않습니다. 개별 계정 복구를 위해 운영 DB 전체를 되돌리지 않습니다.

### 착수 순서와 예정 E2E

`운영 정책 승인 → 로컬 거래 일관성/복구 → 온라인 경제/계정 → 검증 플레이 → 멀티 전투 권한` 순서로 별도 작업 ID를 부여합니다. 현재 모두 미착수입니다.

예정 검증: 잔액 수정+해시 재계산, 과거 저장/아이템 복사, 정산 재전송/요청 ID 변경, 차감 직후 종료, 응답 유실, 두 기기 동시 소비, 잘못된 CSV 버전, 손상/구버전 백업 복원, 정상 지연 오판 방지. 이는 **계획 목록이며 통과 실적이 아닙니다**.

연구 근거: [OWASP 감사 로그](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html), [D1 배치 트랜잭션](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch), [D1 백업·시점 복구](https://developers.cloudflare.com/d1/reference/time-travel/), [Godot 전용 서버](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_dedicated_servers.html). D1 문서상 시점 복구는 Free 7일/Paid 30일이며, 장기 보관이나 추가 사용량의 비용은 별도 산정합니다.

## 기계 검증

`docs/assets/post-p7-roadmap.json`이 원문 버전·블록 근거·패킷 ID·데이터 게이트·모듈·플레이어 결과·E2E 인과를 보관합니다. `scripts/check-p7-roadmap.ps1`은 원문 불일치, 근거 없는 진행 상태, 완료 오표시를 차단합니다. 진행 중 패킷에는 완료 하위 범위·남은 범위·존재하는 검증 파일이 모두 필요합니다.
