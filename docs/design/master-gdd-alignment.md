진행률은 Notion 체크박스가 아니라 저장소 코드·데이터·플레이어 인식 E2E를 근거로 계산합니다. 공개 원문의 Phase 1~6 체크는 기획 범위가 확정됐다는 신호이며 구현 완료를 대신하지 않습니다.

## 2026-09-02 핵심 변경

이전 v797·57블록에서 v1005·77블록으로 확대되며 다음이 구체화됐습니다.

1. **3단계 플레이어 동선:** 로비 허브→출격 준비→인게임 던전의 역할을 분리했습니다.
2. **로비 허브 서비스:** 개인 창고, 런 종료 회전 상점, 설계도 제작소, 훈련 연습장, 도감·랭킹을 명시했습니다.
3. **상점 3대 매물:** 손상 하자품, 표준 순정품, 고성능 꿀매물의 가격·성능 스펙트럼과 골드 리롤을 확정했습니다.
4. **제작소 고점:** 설계도 영구 등록, 맞춤형 옵션·소켓 제작을 상점과 다른 확정 파밍 경로로 분리했습니다.
5. **훈련 연습장:** 단일 보스·밀집 잡몹 더미, DPS·타격·AP·쿨타임 계측, 무비용 자유 세팅을 요구합니다.
6. **도감:** 해금 진행률과 미해금 항목의 드랍 지역 힌트를 로비에서 확인합니다.
7. **공식 Phase 5 확대:** `로비 1단계 허브 + 2단계 준비 세션 UI` 연결까지 완료 조건에 포함됐습니다.

## 확정 요구 대조표

| 기획 묶음 | 가중치 | 구현률 | 저장소 근거와 남은 차이 |
|---|---:|---:|---|
| 기술 스택·모듈 기반 | ×1 | 100% | Godot 4.x, GDScript, CharacterBody2D·Area2D·TileMapLayer·Custom Resource와 선택 기능 Scene 경계 구현 |
| 입력·완전 자유 스킬 바인딩 | ×2 | 100% | 23개 물리 Action과 스킬→Action 배치, K UI·충돌 교환·HUD/발동·저장 연결 |
| 스마트 오토 타게팅 | ×2 | 95% | 최근접·최고 HP·엘리트·밀집 중심·이동 벡터·자기 대상 정책 구현, 콘텐츠별 튜닝 잔여 |
| 로비→준비→인게임 3단계 루프 | ×2 | 70% | 허브→작전→허브, 계약·페널티·정산 구현. 캐릭터·완성형 4대 투자와 허브 서비스 통합은 미완료 |
| 상점 vs 제작소 경제 | ×1 | 40% | 영구 상점 등록·기본 구매·도면 제작·랜덤 옵션 기반 존재. 3대 회전 매물·리롤·전용 제작소 UI 미완료 |
| 훈련 연습장 | ×1 | 0% | 전용 더미 시나리오·DPS/AP/쿨타임 계측·무비용 자유 세팅이 없음 |
| 전리품 2대 분류·현장 파밍 | ×2 | 100% | 생명 주기·지역 테이블·현장 교체·세션 소켓·성공/사망 정산 완료 |
| 가변 태그·등급 확장 | ×1 | 80% | 동적 태그, 1~5 등급, 불일치 스킬 비활성, 등급 변형 구현. 무기별 독립 스킬 프리셋 미완료 |
| 탈출·생환·파산 방지 | ×2 | 95% | F 방어전, 구역 이탈 일시정지·재개, 정산, 무료 기본 진입 구현 |
| 비동기 조건부 랭킹·시즌 보상 | ×1 | 40% | 동일 조건 3대 로컬 랭킹 구현. 서버 제출·검증·신원·부정 방지·칭호/오라 미완료 |

계산식은 `Σ(구현률 × 가중치) ÷ 15`입니다.

`(100×1 + 100×2 + 95×2 + 70×2 + 40×1 + 0×1 + 100×2 + 80×1 + 95×2 + 40×1) ÷ 15 ≈ 79%`

9월 1일의 87%에서 79%로 내려간 것은 코드 퇴행이 아니라 확정 범위가 8개 묶음에서 10개로 확대되고 훈련장·상점/제작소 상세가 새 분모에 들어왔기 때문입니다.

## 다음 개발 순서

1. **P5-01~05:** 캐릭터·무기/스킬·유틸리티·단일 작전 초안·파산 방지를 완결합니다.
2. **P5-06~10:** v1005가 확정한 3대 상점·리롤·제작소·훈련장·도감의 최소 플레이 흐름을 연결합니다.
3. **P6-01~04:** 온라인 랭킹 제공자, 제출 검증, 시즌, 칭호·오라를 별도 계층으로 연결합니다.
4. **내부 P7~P10:** 공식 Phase 1~6 종료 뒤 경제 심화, 훈련 품질, 도감/프리셋, 출시 후보 회귀를 진행합니다. 이 번호는 Notion의 공식 Phase가 아닙니다.

세부 선행 조건과 완료 게이트는 [현행 마일스톤 작업 라인](current-milestone-workline.md), 내부 P7 이후는 [P7 이후 사전 구현 설계](p7-plus-preimplementation.md)에서 관리합니다.
