## 결정 완료 항목 실행 · 2026-09-22 {#decided-20260922}

공개 원본 재조회 결과 GDD101블록/작업표82행과9/21 해시가 동일합니다. 공개 원본을 사용하고 원본 기획 체크박스는 변경하지 않았습니다. 코드 구현과 전용 회귀가 확보된 항목부터 마감합니다.

추가16행의 고유15요구만 보면 **코드 구현5 · 부분5 · 미구현5**입니다(중복1행 제외). 아래9/21의2·8·5는 당시 이력입니다. 최신82행 전체 완료율이나 정상10분 통과율이 아닙니다. [실시간 사용법](../features/grid-inventory.md#realtime-20260922) · [정산](../features/session-sockets.md#settlement-20260922) · [전술 적응과 근거](../features/character-selection.md#tactical-adaptation-20260922). 앞선 두 작업은 데이터 변경이 없었으나 전술 적응은 공유 Character Q/R열·잠금 CSV·Web payload·계산기를 함께 갱신했습니다. 데이터 버전 `2026-09-22.1`.

### 다음 실행 패킷 {#next-20260922}

9/22 후속으로 [런 자산 대상 선택](../features/session-sockets.md#target-selection-20260922)을 구현했습니다. UI에서 첫 스킬만 사용하던 제약을 해소했고 새 목록·Sheet 확장은 없습니다. 해당 고유 요구는 여전히 부분 구현이므로 **구현5·부분5·미구현5**를 유지합니다. 다음은 스킬별 기본1/2소켓 대응과 고급/심층 추가 조건, 룬별 효과 목록·수치의 확정이며, 그 전까지 기존 전역 용량을 임의 변경하지 않습니다.

확정 수치가 명확한 전술 적응을 구현했습니다. 다음 구현 후보는 **스킬별 소켓/4계열 룬→특화 요원→공급처·규격 변경** 순서로 세부 확정값을 대조합니다. 스킬별 소켓 개수/룬 목록, 요원별 업적·중첩 조건, 기존 저장품 이관처럼 비어 있는 결정은 코드 완성을 위해 임의 확정하지 않습니다. 현재 남은5부분/5미구현을 자동으로 ‘즉시 착수 가능’으로 취급하지 않습니다.

별도 품질선은 [기록 사용법·자동 검사·사람 수락](../quality/e2e-play-session.md#run-flow-20260922)을 기준으로 **기본 체력·정상 속도10분/F 실제 플레이→중·대형 안개/후퇴/보상 판단→모바일 FUN QA**입니다. 최신 로컬 보고서와 플레이 행동 근거를 함께 보존하고 느린 구간의 조작/표현 원인부터 수정합니다. 계측 검증을1~2분/3초 목표 수락으로 대신하지 않습니다.

## 9/21 재개·원본 변경 우선 안내

기존 이펙트 전수 수정과 전리품 비교 회귀는 병합·배포까지 마감했습니다. 공개 Notion은 GDD101블록·작업표82행으로 확장됐으며 9/21 재조회 해시도 동일합니다. 아래9/10 순서는 기존 실행 이력이며, 신규30분 마감·가방/파우치·스킬 룬·요원 변경은 [재확인 결과와 적용 판단](master-gdd-alignment.md#source-recheck-20260921)을 먼저 확인합니다. 기존80.3%를 최신82행 완료율로 사용하지 않습니다. 정책 변경 승인 전에는 기존 정상10분 검수 기준을 임의 폐기하지 않습니다.

6. 계약 테스트와 실제 입력 E2E가 F 장착→피해 증가→HUD 해제→원복, 중복 제한, 런 초기화, 선택적 모듈 제거를 판정합니다.

**P4-05 종료 산출물:** [런 전용 룬·코어·유물 소켓](../features/session-sockets.md), RunAsset Sheet/CSV/Web payload, 독립 Service/HUD와 플레이어 인식 28개·게임플레이 흐름 10개 E2E입니다.

### 완료한 P4-06 패킷

1. `RunSettlementService`가 Item 생명 주기 결과를 자동 환전·창고 보관·영구 해금·사망 소실로 분배합니다.
2. 탈출 성공 정산 화면은 자동 환전, 영구 해금, 창고 보관을 분리하고 실패 화면은 소실 종류·수량을 표시합니다.
3. 동일 `run_id`는 한 번만 프로필을 변경해 중복 신호·재시도에도 자산을 다시 지급하지 않습니다.
4. `OperationResultService`의 휴대 크레딧·고철·랭킹과 획득 전리품 정산을 독립 모듈로 유지합니다.
5. 소·중·대형 × 표준·숙련·악몽 9개 UI 투입 조합이 전투를 조립하고 명시적 종료 때만 거점으로 돌아오는지 검증합니다.
6. `run_settlement_enabled=false`에서 생명 주기와 영구 프로필이 남는 선택 모듈 검사를 통과했습니다.

**P4-06 종료 산출물:** [런 전리품 정산](../features/run-settlement.md), 독립 정산 Service, 성공·사망·중복 방지 계약, 실제 UI 9조합과 플레이어 결과 인식 E2E입니다.
