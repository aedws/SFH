# 현행 마일스톤 작업 라인

## 기준과 운영 원칙

- 기준 원문: [게시된 SFH 프로젝트 Master GDD](https://wobbly-pawpaw-1ff.notion.site/SFH-6b45b728004082af8a4a811ef0a1c5e9)
- 기준 판정: [Master GDD 구현 대조](master-gdd-alignment.md)의 **95%**, Phase 1·2·3·4·5 완료, Phase 6 제공자 경계 완료
- 완료 판정: 클래스나 UI가 존재하는지가 아니라 플레이어가 `선택 → 실행 → 결과 → 다음 세션 반영`을 인식할 수 있고 자동 E2E가 같은 인과를 증명해야 합니다.
- 모듈 원칙: 데이터 정의, 도메인 규칙, 화면 표현, 저장·외부 제공자를 분리합니다. 기존 대형 Scene이나 HUD에 새 규칙을 직접 추가하지 않습니다.
- 진행 원칙: 한 작업선의 필수 게이트가 실패하면 다음 작업선으로 넘어가지 않습니다. Phase 2·3 회귀가 발생하면 해당 변경은 완료로 계산하지 않습니다.

## 한눈에 보는 실행선

`기준선 고정 → Phase 1·4 완료 → Phase 5 로비 허브·준비 세션 → Phase 6 비동기 랭킹·시즌 → 내부 P7 경제 → P8 훈련 → P9 도감 → P10 출시 후보`

Phase 2의 무기 교체·태그·AP·쿨타임과 Phase 3의 탈출 방어·정산은 전 구간 공통 회귀선입니다. 성능 예산, 모듈 감사, 위키와 플레이어 인식 E2E는 각 작업선 종료 때 함께 갱신합니다.

## 작업선 1 · Phase 1 완결: 자유 스킬 배치

물리 키를 Action에 연결하는 현재 `K 키 설정`과, 스킬을 Action에 배치하는 새 기능은 별도 모듈로 유지합니다.

| ID | 구현 단위 | 모듈 경계 | 플레이어가 확인할 완료 조건 | E2E 게이트 |
|---|---|---|---|---|
| P1-01 · 완료 | 스킬↔Action 배치 데이터 계약 | `SkillBindingProfile`은 `skill_id → action_id`만 소유 | 장착 스킬마다 현재 입력 위치가 보임 | 저장 전·후 매핑 스냅샷 일치 |
| P1-02 · 완료 | 충돌·교환 정책 | `SkillBindingService`가 중복 교환, 기존 장비 시스템이 태그 적합성을 담당 | 이미 사용 중인 칸에 놓으면 두 스킬 교환 피드백 | 교환·거부·허용 Action 검증 |
| P1-03 · 완료 | K 화면의 두 단계 편집 | UI는 서비스 명령과 읽기 전용 상태만 사용 | `키 배치`와 `스킬 배치`를 구분해 편집 | 실제 K/ESC, 22개 키와 3개 장착 스킬 행 |
| P1-04 · 완료 | 전투·HUD 실시간 반영 | `CombatSkillSystem`과 HUD는 배치 제공자만 조회 | 배치 직후 키 표시와 실제 Action 발동 위치가 동기화 | 배치 Signal→상태 재방출→HUD 갱신 |
| P1-05 · 완료 | 영구 저장·초기화 | JSON 저장을 서비스 내부 어댑터로 격리 | 재시작 뒤 유지되며 기본값 복구 가능 | 저장→재구성→복구→초기화 |

**Phase 1 종료 게이트:** 플레이어가 장착한 임의 스킬을 허용된 입력에 배치하고, 충돌을 이해하고, 재시작 뒤에도 같은 HUD와 발동 결과를 확인합니다.

## 작업선 2 · Phase 4 기반: 전리품 생명주기 계약

현장 교체보다 먼저 아이템의 소유 기간과 정산 결과를 고정합니다. 이 계약은 Phase 5 상점과 Phase 6 보상에서도 재사용합니다.

| ID | 구현 단위 | 모듈 경계 | 플레이어가 확인할 완료 조건 | E2E 게이트 |
|---|---|---|---|---|
| P4-01 · 완료 | 전리품 2대 분류 | 영구 자산형과 세션 증폭·환금형의 획득·장착·탈출·사망 정책을 Resource로 정의 | 아이템 상세 데이터에서 이번 런/영구/환전 결과를 진입 전에 이해 | 15개 정의·두 분류·잘못된 생명주기 조합 거부 |
| P4-02 · 완료 | 지역·난이도별 드랍 테이블 확장 | `LootTableProvider`는 작전 context에 맞는 후보·추첨·브리핑만 제공하고 아이템 생명 주기는 기존 서비스를 조회 | 지역·난이도를 바꾸면 대표 전리품과 최고 등급이 진입 전에 달라짐 | 29행·3지역, 동일 시드 결정성, 고난이도 등급 가중치, Item·Weapon·Skill 교차 검증, 성능 예산 |
| P4-03 · 완료 | 현장 비교·획득 계약 | 비교 서비스는 현재 장비와 후보 수치만 계산, 표시와 입력은 별도 | 드랍 접근 시 교체 이득·손실·보존 결과가 보임 | 드랍→접근→비교 패널→ESC 보류→재접근→F 획득 |

**작업선 2 종료 게이트:** 모든 신규 전리품은 드랍되기 전에 `어디서 나오고, 언제 사라지고, 탈출·사망 때 무엇이 되는지` 자동 검증할 수 있습니다.

### 완료한 P4-01 패킷

1. `LootLifecycleDefinition`에 `영구 자산형`과 `세션 증폭·환금형` 식별자, 획득·장착·탈출·사망 결과를 정의합니다.
2. 기존 장비·스킬·도면과 신규 룬·코어·유물이 같은 정의 인터페이스를 사용하되, 장비 영구 모듈과 런 전용 소켓은 별도 서비스로 둡니다.
3. Google Sheet `Item` 시트의 1행 변수명·2행 설명을 유지하고 J:P에 생명 주기 7열, 3행 이후에 도면 3개와 룬·코어·유물 3개를 추가했습니다.
4. Sheet 시험 공급자와 확정 CSV 공급자가 같은 16열 스키마를 사용하고, 확정 CSV·Web payload·release 해시를 함께 검증합니다.
5. 플레이어에게는 드랍 상세에서 `이번 런 사용`, `탈출 시 영구 해금`, `탈출 시 자동 환전`, `사망 시 소실`을 아이콘과 짧은 문구로 먼저 보여줍니다.
6. 정의 누락·상충 정책·알 수 없는 분류를 빌드에서 차단했습니다. 다음은 P4-02 드랍 테이블입니다.

**P4-01 종료 산출물:** Resource/CSV 스키마, Sheet 열 계약, 정책 검증 테스트, 아이템 상세 Presenter, 모듈 감사와 플레이어 인식 E2E 목록입니다.

### 완료한 P4-02 패킷

1. Google Sheet에 독립 `LootTable` 탭을 만들고 1행 변수명·2행 설명·3행 이후 데이터 규칙으로 세 지역 27행을 정의했습니다.
2. 지역·난이도·맵 크기·적/방 보상/금고/보스 출처를 조합하고, 투자 계약의 고등급 배율을 등급별 유효 가중치에 반영합니다.
3. 모든 `item_id`를 P4-01 `Item` 정의와 지역 태그에 교차 검증해 잘못된 지역 배치를 런타임과 동기화 단계에서 차단합니다.
4. 같은 seed와 작전 context가 같은 아이템·수량을 내도록 결정적 추첨을 구현했습니다.
5. 작전 진입 UI가 상위 3개 대표 전리품·후보 수·최고 등급을 보여 줘 플레이어가 타겟 파밍 결정을 내릴 수 있습니다.
6. 확정 CSV·Web payload·Windows 배포 메타데이터와 실시간 Sheet 공급자를 같은 스키마 뒤에 두고 폴백을 검증했습니다.

**P4-02 종료 산출물:** [지역·난이도 전리품 테이블](../features/loot-tables.md), 27행 확정 CSV, 결정적 Provider, 작전 브리핑, 플레이어 인식 24개·게임플레이 흐름 6개 E2E입니다.

### 완료한 P4-03 패킷

1. 방 클리어 때 `room_reward` 후보를 추첨해 월드 비교 신호를 생성합니다.
2. 순수 비교 서비스가 현재 무기·후보 등급·보유 수량과 생명 주기 결과만 계산합니다.
3. 접근 패널은 영구/이번 런, 탈출 결과, 사망 결과와 `F 획득 / ESC 보류`를 한 시선에 표시합니다.
4. ESC는 드랍을 유지하고 패널만 닫으며 재접근 뒤 F는 런 임시 보관으로 옮깁니다.
5. 즉시 장비 교체는 호출하지 않아 P4-04 경계를 보존합니다.
6. 실제 입력 E2E는 플레이어 인식 25개·게임플레이 흐름 7개로 확대했습니다.

**P4-03 종료 산출물:** [현장 전리품 비교·획득](../features/field-loot-acquisition.md), 비교/드랍/패널/획득 서비스, 계약 테스트, 모듈 제거 검사입니다.

## 작업선 3 · Phase 4 완결: 현장 교체·세션 소켓·자동 환전

| ID | 구현 단위 | 모듈 경계 | 플레이어가 확인할 완료 조건 | E2E 게이트 |
|---|---|---|---|---|
| P4-04A · 완료 | 현장 무기 즉시 교체 | 전리품 명령을 독립 장착 서비스로 전달하고 임시 정책을 Resource로 격리 | R로 새 무기를 즉시 사용하고 기존 무기의 런 임시 보관·복구를 확인 | 드랍→R 교체→활성 무기 변화→거점 복귀 전 복구 |
| P4-04B · 완료 | 현장 스킬 즉시 교체 | `FieldLootSkillEquipService`가 슬롯·태그·자원·키 교체를 무기 장착과 분리 | 아크 질주의 슬롯·키·ENERGY·CD·충전을 보고 R로 교체 | 드랍→태그 검증→R 교체→3번 키 유지→상태 복구 |
| P4-05 · 완료 | 런 전용 룬·코어·유물 소켓 | 영구 장비 모듈과 별도인 `SessionSocketService`가 무기·스킬·플레이어 런 효과만 소유 | F 장착 즉시 전투 수치가 변하고 RUN ONLY HUD에서 해제 | 드랍→F 소켓→피해 변화→HUD 해제→원복 |
| P4-06 · 완료 | 탈출 자동 환전·영구 해금·사망 소실 | `RunSettlementService`가 정책 결과를 만들고 프로필·상점·재화 저장소는 결과만 적용 | 정산 화면에서 해금, 환전액, 창고, 소실 항목이 분리되어 보임 | 성공 시 도면 등록·자동 환전, 사망 시 런 전리품 소실, 중복 정산 방지 |

**Phase 4 종료 게이트:** `처치/탐색 → 장비·스킬 드랍 → 현장 교체 또는 소켓 → 전투 변화 → 탈출 정산`의 전체 인과가 한 실제 플레이 E2E로 연결됩니다.

### 완료한 P4-04B 패킷

1. Google Sheet `Skill` 탭 14열·4행과 `LootTable` 29번째 활성 행을 같은 확정 CSV 스키마로 연결했습니다.
2. `아크 질주`는 전기 태그 무기에서만 슬롯 3의 기동 가속을 교체하며 기존 3번 Action을 유지합니다.
3. 비교 HUD가 기존→후보, 슬롯, 키, ENERGY, CD, 충전을 표시하고 태그 불일치는 장착 전에 거부합니다.
4. 무기와 분리된 교체 서비스가 스킬 정의·쿨다운·충전·런 전용 키 매핑을 보관합니다.
5. 거점 복귀 전에 무기·스킬 스택을 역순 복구하며 런 전용 바인딩은 사용자 설정 파일에 저장하지 않습니다.
6. 계약 테스트와 실제 R 입력 E2E가 표시→교체→키 유지→복구를 판정합니다.
