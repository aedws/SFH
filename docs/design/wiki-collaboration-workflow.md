# AI 개발자·기획자 위키 협업 개선안

## 현재 확인한 문제

| 문제 | 실제 위험 | 이번 조치 |
|---|---|---|
| 요청과 완료 카드 혼합 | 기획자가 지금 답할 항목을 놓침 | 역할 필터와 명시적 상태 추가 |
| 담당자·차단 여부 없음 | 서로 상대가 처리한다고 오인 | 기획·개발 담당과 최종 판단자인 프로젝트 오너를 분리하고 상태 흐름 표시 |
| Notion 최신성 불명 | 변경 전 스냅샷을 최신 기획으로 오인 | 마지막 확인 시각과 `자동 동기화 아님` 경고 |
| 요청의 완료 조건 없음 | 문장 구현만 끝내고 플레이 결과 누락 | 카드별 수락 기준 접기 영역 |
| 완료 근거가 흩어짐 | AI가 같은 기능을 재구현하거나 기획자가 검증 불가 | 위키 내부 구현·E2E·감사 근거 링크 |
| Notion·JSON 이중 원본 | 수정 순서에 따라 상태가 충돌 | Notion=기획 결정, JSON=검증된 작업 스냅샷으로 책임 분리 |
| 데이터 요청 위치 불명 | Sheet 탭·범위가 중복되거나 잘못 확장 | 카드에 `sheet_target` 표시 |
| 변경·폐기 이력 없음 | 오래된 요구가 다시 활성화됨 | `decision_id`·`source_revision`·`supersedes`·`conflicts_with` 적용 |

## 수정 대안

1. **정적 JSON v3 + 역할별 화면 — 적용.** 담당자·상태·차단·수락 기준에 결정 ID와 원본 리비전, 대체·충돌 계보를 더했습니다.
2. **Notion → CI 검증 스냅샷 — 적용.** 공개 읽기 엔드포인트에서 블록 57개의 버전·해시를 결정론적 JSON으로 고정합니다. CI는 스냅샷 무결성을 검증하며, 변경을 자동으로 `확정`처리하지 않습니다.
3. **Markdown 결정 로그 — 적용.** `DEC-P4-04`에 현장 교체 임시 안전 정책과 변경 조건을 고정했습니다.
4. **인증된 협업 입력 — 안전 형태로 적용.** 위키 입력기는 제안을 로컬에서만 정규화·복사하고 인증된 Notion이 실제 작성 권한을 담당합니다. 새 Worker, Access, KV, R2 쓰기를 추가하지 않아 과금·권한 표면을 늘리지 않습니다.
5. **위키 직접 공개 편집 — 제안 초안 표면으로 대체.** 익명 원격 쓰기는 차단하되 44px 터치 대상의 반응형 초안 생성기를 제공합니다. 실제 원본 변경은 Notion 인증·PR 검증을 거칩니다.

## 권장 운영선

현재 1~5안의 핵심 효과를 무료·읽기 중심 구조로 적용했습니다. 실제 쓰기는 Notion과 저장소 PR로만 수행하며 Cloudflare 플랜·결제·새 저장 자원을 추가하지 않습니다.

기획자는 플레이 의도와 수치 후보를, 개발자는 구현·검증 근거를 제공하며 **범위·우선순위·수락·출시의 최종 판단은 프로젝트 오너가 수행합니다.** 상태 흐름은 `needs_decision → blocked/ready → implemented → accepted/deferred`를 사용하고, `accepted`는 오너 근거 없이는 자동 전환하지 않습니다. 기획 결정은 Notion, 구현과 검증은 저장소, [프로젝트 오너 판단 온톨로지](../architecture/project-ontology.md)는 두 원본의 마지막 검증 상태를 읽기 전용으로 연결합니다.
