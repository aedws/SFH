# AI 개발자·기획자 위키 협업 개선안

## 현재 확인한 문제

| 문제 | 실제 위험 | 이번 조치 |
|---|---|---|
| 요청과 완료 카드 혼합 | 기획자가 지금 답할 항목을 놓침 | 역할 필터와 명시적 상태 추가 |
| 담당자·차단 여부 없음 | 서로 상대가 처리한다고 오인 | `owner_role`, `blocking`, 상태 흐름 표시 |
| Notion 최신성 불명 | 변경 전 스냅샷을 최신 기획으로 오인 | 마지막 확인 시각과 `자동 동기화 아님` 경고 |
| 요청의 완료 조건 없음 | 문장 구현만 끝내고 플레이 결과 누락 | 카드별 수락 기준 접기 영역 |
| 완료 근거가 흩어짐 | AI가 같은 기능을 재구현하거나 기획자가 검증 불가 | 위키 내부 구현·E2E·감사 근거 링크 |
| Notion·JSON 이중 원본 | 수정 순서에 따라 상태가 충돌 | Notion=기획 결정, JSON=검증된 작업 스냅샷으로 책임 분리 |
| 데이터 요청 위치 불명 | Sheet 탭·범위가 중복되거나 잘못 확장 | 카드에 `sheet_target` 표시 |
| 변경·폐기 이력 없음 | 오래된 요구가 다시 활성화됨 | 다음 단계에서 `supersedes`·`decision_revision` 추가 예정 |

## 수정 대안

1. **정적 JSON v2 + 역할별 화면 — 현재 적용.** 무료 정적 배포를 유지하면서 담당자·상태·차단·수락 기준·근거·확인 시각을 구조화합니다. 저장소 PR과 E2E가 감사 기록이 됩니다.
2. **Notion → CI 검증 스냅샷 — 다음 권장.** 읽기 전용 토큰이 준비되면 CI가 공개 기획을 가져와 변경 감지만 하고, 사람이 승인한 PR에서 JSON을 갱신합니다. 자동 확정은 하지 않습니다.
3. **Markdown 결정 로그 병행.** 중요한 정책만 `DEC-*` 문서로 고정해 Notion 삭제·권한 문제에도 근거를 보존합니다. 문서량 증가가 단점입니다.
4. **인증된 협업 앱.** 실시간 편집·상태 변경·감사 로그가 필요할 때만 별도 앱을 검토합니다. 인증·보안·운영비가 커 현재 단계에는 과합니다.
5. **위키 직접 공개 편집.** 가장 빠르지만 권한·감사·악성 변경 위험이 커 현재는 채택하지 않습니다.

## 권장 운영선

현재는 1안을 유지하고 3안의 결정 로그를 핵심 정책에만 추가합니다. Notion 토큰이 이미 운영상 안전하게 준비된 뒤에만 2안으로 확장합니다. Cloudflare 유료 기능, Workers 유료 플랜, Notion 유료 자동화는 요구하지 않습니다.

상태 흐름은 `needs_planner → ready_for_dev → in_implementation → implemented_verified → accepted`로 고정합니다. 기획 결정은 Notion, 구현과 검증은 저장소, 첫 화면은 마지막으로 검증된 결합 상태만 보여 줍니다.
