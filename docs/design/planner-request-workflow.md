# 기획 요청·밸런스 데이터 운영

<!-- sfh-standing-sheet-extension: authorized-without-separate-approval -->

위키 홈의 **PLANNER REQUEST LINK**는 기획자가 지금 답해야 하는 항목과 구현 완료 안내를 한곳에서 보여 줍니다. 요청은 코드 주석이나 채팅에만 남기지 않고 요청 ID와 공개 Notion 근거를 연결합니다.

## 상태 태그

| 태그 | 의미 | 기획자 행동 |
|---|---|---|
| `작업 요청` | 규칙·예외·플레이 결과가 미확정 | 같은 요청 ID로 Notion에 확정·보류·수정 근거 작성 |
| `밸런스 데이터` | 수치·목록·확률·비용 표가 필요 | Notion에 정책 근거를 적고 지정 Google Sheet 탭에 시험값 작성 |
| `완료 안내` | 코드·데이터·플레이어 인식 E2E까지 통과 | 의도와 다르면 새 요청 ID로 변경 근거 작성 |

## 역할·상태 계약

첫 화면은 `기획자 할 일`, `AI 개발자 할 일`, `검증 완료`로 필터링합니다. 각 카드는 담당자, 차단 여부, 수락 기준, 검증 근거와 Sheet 대상 범위를 가집니다. Notion은 기획 결정의 원본이고 위키 JSON은 마지막으로 검증한 작업 스냅샷이므로 자동 동기화로 오해하지 않도록 확인 시각을 항상 표시합니다.

기획 요청 상태는 `needs_planner → ready_for_owner`로 근거 준비도를 나타내고, 오너 판단 뒤 개발 상태가 `ready_for_dev → in_implementation → implemented_verified → accepted/deferred`로 이어집니다. `accepted`는 프로젝트 오너만 확정하며 구현 완료와 최종 수락을 같은 상태로 취급하지 않습니다.

## Notion 작성 계약

기획자 작업실 최상단의 [지금 결정해 주세요](../access/planner.md#decisions-needed)는 파우치·심층·혈전·방어구 성장의 질문, 미승인 예시, 결과 확인 기준을 먼저 보여 줍니다. 예시는 게임 적용값이 아니며 프로젝트 오너 승인과 분리합니다. 기획자는 **Notion에 안을 반영한 뒤 오너에게 개인 메시지로 판단 ID·문단 링크·변경 요약·확정/임시/미정 상태를 전달**합니다. 위키에 자동 메시지 발송이나 자동 배포 기능을 추가한 것은 아닙니다.

1. 카드의 `PLAN-*` 또는 `DATA-*` 요청 ID를 Notion 결정 제목에 그대로 포함합니다. 새 아이디어는 `DRAFT-날짜-키워드`로 시작할 수 있고 다음 분류 때 정식 ID와 연결합니다.
2. `확정 / 임시 / 제안 / 보류 / 변경 / 검수 완료` 중 하나를 명시합니다. 섞여 있으면 `부분 확정`으로 쓰고 각 문장을 확정·임시·미정으로 나눕니다.
3. 대상, 플레이어 동작, 적용 시점, 예외·미정, 플레이어가 확인할 수락 기준을 적습니다. 모르는 값은 빈칸이 아니라 `미정`입니다.
4. 수치가 필요하면 단위, 최소·기본·최대, 등급 또는 난이도별 변화 기준을 적습니다.
5. 기존 결정을 바꾸면 이전 문장을 덮어쓰지 않고 새 블록의 `supersedes`에 이전 결정 ID를 기록합니다.
6. 개발자는 공개 Notion 근거와 저장소 구현을 대조한 뒤 카드 상태를 `완료 안내`로 바꿉니다.

| Notion 상태 | 구현 허용 | 기획 완료 계산 | 개발 처리 |
|---|---:|---:|---|
| 확정 | 예 | 예 | 정식 계약·E2E로 반영 |
| 임시 | 예 | 아니오 | 교체 가능한 데이터·정책으로 격리하고 `provisional` 표시 |
| 부분 확정 | 확정 문장만 | 확정 문장만 | 임시·미정 항목을 별도 요청으로 유지 |
| 제안 | 아니오 | 아니오 | 대안과 영향만 보고 |
| 보류 | 아니오 | 아니오 | 재개 조건 전까지 변경 금지 |
| 변경 | 예 | 새 결정 검증 뒤 | 이전 ID·저장 호환·되돌리기를 함께 검사 |
| 검수 완료 | 해당 없음 | 예 | 구현 커밋·빌드·화면 근거와 수락 연결 |

문서가 서로 충돌하면 상태가 더 강한 문장을 임의로 선택하지 않습니다. 같은 결정 계보에서 날짜가 최신이고 이전 ID를 명시적으로 교체한 블록을 근거 후보로 삼으며, 계보가 없거나 범위가 겹치면 `needs_planner` 또는 `needs_decision`으로 되돌립니다. Notion 저장은 자동 승인·배포가 아니며 프로젝트 오너가 `노션 최신 내용 확인 후 [요청 ID] 반영`처럼 작업을 지시한 시점에 스냅샷·구현·검증 절차를 시작합니다.

기획자가 바로 복사할 최소 형식과 부분 확정·수치 확정·변경 예시는 [기획자 작업실의 Notion 작성 가이드](../access/planner.md#notion-authoring)에 있습니다.

권위 있는 원문은 [게시된 SFH Master GDD](https://wobbly-pawpaw-1ff.notion.site/3d35b728004081eba698e9a00f6ec0ed)입니다.

## Google Sheet 상시 확장 허용

사용자는 **앞으로 모든 구현 작업에서 새로운 아이템·무기·방어구·스킬·드랍·강화·경제 등 열거형 목록이 필요하면 별도 재승인 없이 공용 Google Sheet를 확장할 수 있도록 명시적으로 허용**했습니다.

확장 시 다음 규칙은 항상 유지합니다.

- 1행 변수명, 2행 한국어 설명, 3행부터 개별 데이터
- 기존 도메인 탭을 우선 사용하고 책임이 다르면 독립 탭 추가
- `runtime_enabled`로 시험 행과 비활성 행을 구분
- 실시간 테스트 공급자와 확정 CSV 공급자가 같은 스키마 사용
- Web payload·Windows 배포 메타데이터·CSV 해시까지 함께 갱신
- 기획 확정 전 값은 요청 카드와 Sheet 설명에서 `임시`로 명시

목록이 필요하지 않은 로직 변경에는 Sheet를 억지로 확장하지 않습니다.

## 완료 판정

카드를 `완료 안내`로 바꾸려면 Definition/Policy/Service/Presenter 또는 Provider 경계, 실제 플레이 입력, 플레이어가 보는 결과, E2E와 위키 문서가 모두 연결되어야 합니다. 클래스만 존재하거나 Notion에 문장만 추가된 상태는 완료로 계산하지 않습니다.
