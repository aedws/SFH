# 최소·권장 사양과 성능 예산

현재 사양은 **MVP 개발 중인 임시 목표**입니다. Godot 엔진의 실행 가능 하한과 SFH가 1280×720에서 다수 적을 처리할 게임 플레이 하한은 다릅니다. 아래 SFH 사양은 실제 저사양 PC 실기 검증 전까지 인증 사양으로 사용하지 않습니다.

## 임시 목표 사양

| 구분 | 최소 목표 | 권장 목표 |
|---|---|---|
| 운영체제 | Windows 10 64-bit | Windows 11 64-bit |
| CPU | x86_64 SSE4.2, 4스레드급 CPU | 물리 4코어, Intel Core i5-6600K / AMD Ryzen 5 1600급 이상 |
| 메모리 | 4 GB RAM | 8 GB RAM |
| GPU | Direct3D 11 또는 OpenGL 3.3 지원 내장 GPU, Intel HD 4000 / Radeon R5급 이상 | Direct3D 11 또는 OpenGL 4.6 지원 GPU, GeForce GTX 650 / Radeon HD 7750급 이상 또는 동급 최신 내장 GPU |
| 화면 목표 | 1280×720, 낮음, 30 FPS 하한 | 1280×720, 보통, 평균 60 FPS |
| 저장 공간 | 500 MB 여유 공간 | 1 GB 여유 공간 |

Godot 4.7 공식 문서의 내보낸 프로젝트 하한은 Windows 10, SSE4.2 CPU, Compatibility 렌더러용 OpenGL 3.3/D3D11 GPU, 2 GB RAM입니다. 공식 권장은 물리 4코어, 4 GB RAM, OpenGL 4.6급 전용 GPU입니다. 엔진 문서도 프로젝트의 범위·해상도·설정에 따라 요구 사양이 달라지므로 실제 저사양 하드웨어 시험과 그래픽 옵션 제공을 권장합니다. [Godot 4.7 시스템 요구사항](https://docs.godotengine.org/en/4.7/about/system_requirements.html)

## 현재 자동 성능 게이트

`scripts/test-performance.ps1`은 중·대형 × 시드 2개로 총 4개 작전을 실행합니다. 일반 방 하나를 최대 수량으로 봉쇄하고 90프레임 준비 후, 기본 공격 입력·세 스킬 발동과 함께 240프레임을 측정합니다. 조기 사망을 막는 테스트 전용 HP 보정만 사용하며 실전 밸런스는 변경하지 않습니다. 발사체 생성이 없거나 런타임 오류가 있으면 성공 마커가 있어도 실패합니다.

2026-09-07 로컬 측정, AMD Ryzen AI Z2 Extreme / Godot 4.7.2 / `DisplayServer=headless` / 테스트 뷰포트 1280×720:

| 규모·시드 | 평균 ms | p95 ms | 최대 ms | 진입 ms | 최대 Node |
|---|---:|---:|---:|---:|---:|
| 중형 · 8675309 | 6.852 | 7.732 | 10.523 | 1323.834 | 1666 |
| 중형 · 4040600 | 6.869 | 8.080 | 8.962 | 463.012 | 1590 |
| 대형 · 8675309 | 6.858 | 8.192 | 9.789 | 577.899 | 2018 |
| 대형 · 4040600 | 6.870 | 7.885 | 9.052 | 599.013 | 1987 |

예산은 평균·p95 ≤16.667ms, 최대 ≤33.334ms, Node ≤6000, 전기 효과 ≤3, 충돌체/원시 셀 ≤25%입니다. 최초 방 적은 중형 26·대형 34명, 효과 최대 3개, 충돌 비율 약 6.7%, 매 작전 해제 후 잔류 Node 증가는 모두 0입니다. 첫 진입과 이후 진입의 로딩 상태는 다르므로 위 수치를 모든 PC의 로딩 보증으로 사용하지 않습니다.

이 검사는 **헤드리스 CPU·SceneTree 단기 회귀**입니다. 실제 GPU 렌더러/FPS, 10분 실시간 플레이, 장시간 메모리·발열·1% low, 내보낸 Web/Windows의 시각적 동등성은 아직 별도 검증이 필요합니다. 240프레임 결과나 가속된 600초 논리 테스트를 실제 10분 플레이로 표기하지 않습니다. 환경 차이가 있는 CI에서는 정확성·오류 검사를 필수로 하고 이 로컬 시간 예산을 그대로 강제하지 않습니다.

## 적용한 최적화

- 전기 선분은 매 프레임 생성하지 않고 프로필별 10~20Hz에서만 재생성해 캐시합니다.
- 스킬 HUD 상태 전송을 10Hz로 제한하고 발동·준비 완료 시에만 즉시 갱신합니다.
- 지속 이동 버프는 매 프레임 감소 Node 대신 one-shot `Timer`로 해제합니다.
- 지속 자기장은 매 프레임이 아니라 0.5초 피해 틱에서만 대상을 순회하며 임시 자식 배열 생성을 제거했습니다.
- 적 A* 경로는 0.7초 간격으로 분산 갱신하고 대상이 96px 이상 이동했을 때 다시 계산합니다.
- 적 군중 분리는 0.08초 간격으로 분산 갱신하고 가까운 이웃 8명까지만 조향에 합성합니다. 생성 시 40px 간격도 한 번만 검사합니다.
- 연속 벽·설비 셀을 직사각형 충돌체로 병합해 대형 맵의 CollisionShape2D 폭증을 막습니다.
- 방 전투는 필요한 방에만 적을 만들고 전역 증원을 정지합니다. 적 생성기는 종료 Signal로 목록을 정리하며 매 프레임 전체 목록을 재검사하지 않습니다.
- 스마트 타게팅은 매 프레임이 아니라 새 발사 묶음에서만 최대 72개 대상의 가중 점수를 계산합니다.
- 전투 자원은 적 처치 순간에만 결정을 만들고, 슬롯 3개의 충전 타이머만 갱신합니다. 회수 완료 즉시 Pickup을 제거해 상시 Node를 누적하지 않습니다.
- 플레이어 이동의 정지 스냅·횡그립·반전 처리는 플레이어 한 명의 벡터 연산으로 끝나며 별도 Node나 매 프레임 대상 탐색을 추가하지 않습니다.
- 타격 충격은 공격마다 Node를 만들지 않고 Director 하나가 최대 32개 짧은 기록을 코드로 그립니다. 카메라 흔들림도 Camera2D 하나의 offset만 갱신합니다.
- 사이버펑크 노이즈·스캔라인은 화면 크기 변경 시에만 정적으로 다시 그리고, 매 프레임은 2px 스캔 바와 5px 상태 점만 이동·점멸합니다. 효과 계층은 6개 Node이며 Manifest에서 통째로 제거할 수 있습니다.
- 이동 체감 피드백은 Line2D 하나와 최대 10개 위치 표본을 재사용하며 출발·정지·선회 신호도 코드 드로잉으로 처리합니다. 속도·충돌 계산이나 새 텍스처·대시별 Node를 추가하지 않습니다.
- 전리품 테이블은 작전 조건 변경·드랍 추첨 때만 28개 데이터 행을 필터링하며 매 프레임 순회하지 않습니다. 브리핑은 최대 3개 표시용 정의만 생명 주기·장비 카탈로그 제공자에 조회합니다.
- 현장 장착은 플레이어가 R을 누를 때만 장비 상태 두 개와 복구 기록 하나를 변경하며 매 프레임 장비 목록을 순회하지 않습니다.
- 전장의 안개는 문턱 공간 히스테리시스·안심 외곽·탐색 기억을 기존 단일 Shader에서 합성합니다. 벽 차폐 48광선은 0.07초 간격 또는 8px 이동 때만 갱신하며 추가 Viewport나 Light2D를 만들지 않습니다.
- 런 정산은 탈출·사망 순간에만 획득 Dictionary를 한 번 순회하며 전투 프레임 중 작업이나 추가 월드 Node를 만들지 않습니다.

## 출시 전 실기 인증 절차

1. 최소 목표 PC와 권장 목표 PC에서 내보낸 Windows 빌드를 각각 실행합니다.
2. 대형 맵의 연속 방 교전, 방당 적 34명, 문 봉쇄, 전장의 안개와 세 전기 스킬을 동시에 사용하는 조건을 10분 유지합니다. 방 전투 비활성 폴백은 별도로 적 72명까지 시험합니다.
3. 평균 FPS, 1% low, 최대 프레임 시간, 메모리, GPU 사용률과 온도를 기록합니다.
4. 최소 PC는 720p 낮음에서 30 FPS 하한, 권장 PC는 720p 보통에서 평균 60 FPS를 통과해야 합니다.
5. 실패하면 적 표시 거리·전기 이펙트 밀도·안개 품질 옵션을 먼저 낮추고 사양표를 실측 결과로 교정합니다.

## 실행 방법

```powershell
.\scripts\test-performance.ps1
```

성공하면 `PERFORMANCE_BUDGET_RESULT` JSON과 `PERFORMANCE_BUDGET_OK`가 출력됩니다.
