# 도면 제작과 랜덤 옵션

정책은 **완제품 직접 드랍보다 도면 반출 후 거점 제작을 주 획득 경로로 사용**하는 것입니다. P7-03부터 성공 정산으로 반출한 도면은 소비 수량과 별개인 영구 제작 등록으로 전환됩니다. 이후 게임을 다시 실행해도 제작 후보의 `재제작 가능` 상태가 유지됩니다.

| 도면 | 결과 | 고철 | 크레딧 | 옵션 |
|---|---|---:|---:|---:|
| 돌격소총 | 제작 돌격소총 | 2 | 80 C | 1~2개 |
| 전술 조끼 | 제작 전술 조끼 | 2 | 70 C | 1~2개 |
| 원형 자기장 | 제작 원형 자기장 | 3 | 95 C | 1~3개 |

현재 표의 비용·옵션·소켓은 `Recipe` Sheet의 `provisional` 값입니다. 옵션 풀·Roll 보장과 환불 규칙은 P7-04에서 기획 확정값으로 교체합니다. P7-03은 값 자체가 아니라 **도면 반출→영구 등록→재접속→제작 후보 유지**를 완결합니다.

## P7-03 모듈 경계

- `BlueprintRegistry`: 프로필의 영구 등록 ID만 읽고 쓰며 중복 등록을 멱등 처리합니다.
- `WorkshopRecipeProvider`: `Recipe` CSV를 제작법 ID·도면 ID로 조회합니다. 저장과 UI를 모릅니다.
- `WorkshopUnlockService`: 반출 수량을 검사하고, 존재하는 제작법의 도면만 등록하며 `재제작 가능/도면 반출 필요` 후보를 만듭니다.
- `WorkshopService`: 위 세 모듈과 기존 제작 거래를 조립합니다. P7-04의 옵션 Roll·차감 정책은 이후 별도 서비스로 분리합니다.
- `P5HubProgressionService`: `register_extracted_blueprints / get_workshop_candidates / craft_recipe` 공개 계약만 제공합니다.

거점 제작소 버튼에는 `도면 1/3`처럼 영구 등록 수가 표시되고, 마우스를 올리면 각 제작 후보의 상태를 확인할 수 있습니다. 제작 결과는 정의 ID, 고유 인스턴스 ID와 옵션·소켓 수를 영구 프로필에 저장합니다.

## Google Sheet 확인 · 2026-09-04

`Recipe!A1:M5`의 3개 제작법은 현재 확정 CSV와 같습니다. 새 레시피 목록은 추가하지 않았습니다. 전체 시트 대조 중 `Item!A18:P21`에 Utility 전용 4행이 중복된 것은 발견했지만, Item 생명주기 스키마와 맞지 않아 자동 반영하지 않았습니다. 해당 행은 `Utility` 탭에서만 관리하도록 기획 데이터 정리가 필요합니다.

## 자동 검증

`P7_BLUEPRINT_REGISTRY_OK`는 미등록 표시, 알 수 없는 도면 거부, 반출 1회 등록, 중복 멱등, 재접속 후 제작 후보 유지와 façade 조회를 판정합니다.
