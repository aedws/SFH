# 격자 가방 인벤토리

## 2026-09-08 · 아이템 중심 게임 화면 {#item-presentation}

단색 블록과 설명 중심 가방을 **장착 카드 → 회수품 격자 → 선택 아이템 검사**의 세 영역으로 바꿨습니다. [PUBG 장비별 슬롯 화면](https://pubg.com/es-mx/news/2197)과 [퍼스트 디센던트 UI 개발 노트](https://tfd.nexon.com/en/news/2538364)의 정보 배치를 참고했으며, 타 게임 이미지·상표 에셋을 배포물에 넣지 않았습니다.

- 무기·칼·방어구·신발·파츠·모듈·구급품을 SFH 코드 기반 도형으로 식별합니다. 모듈은 기존 태그에 따라 조준점/십자/방패/기동 기호로 구분합니다. 새 무기 소분류는 기본 무기 도형, 알 수 없는 아이템은 중립 상자로 표시하며 장착 규칙을 추측하지 않습니다.
- 패널 전체를 등급색으로 채우는 대신 어두운 바탕과 상단 색 띠를 사용합니다. 색은 기존 아이템 분류 색이며 **새 등급·드랍 확률을 뜻하지 않습니다**. 선택은 청록 테두리와 점으로 구분합니다.
- 작은 칸에 이름 일부만 잘라 넣지 않습니다. 이름 전체·실제 점유 크기는 마우스 툴팁과 선택 검사 영역에서 확인합니다. 격자에 포커스를 두고 방향키로 아이템을 선택할 수도 있습니다.
- 오른쪽에는 선택한 실물의 도형과 설명, 회전·장착·해제 버튼을 둡니다. 회전 시 점유 크기와 그림 방향이 함께 변합니다. 드래그 미리보기도 같은 도형을 사용합니다.
- 장착 칸은 실제 등록된 슬롯만 노출합니다. 작동하지 않는 ‘확장 예정’ 칸은 제거했으며, 새 슬롯 규칙을 등록하면 자동으로 늘어납니다.
- 1000px 미만은 가방을 먼저 보여주고 장비·검사 영역을 세로로 배치합니다. 세로 스크롤과 기존 가용 너비 맞춤은 유지합니다. 작은 1칸 아이템은 선택 후 검사 영역에서 식별하는 것이 권장됩니다.

`InventoryItemArt`는 읽기 전용 그림 제공자, `InventoryItemPreview`는 검사·드래그 표시, `InventorySlotButton`은 네이티브 클릭/포커스/드롭, `InventoryGridView`는 격자 표현과 선택만 담당합니다. 이동·회전·장착·태그·모듈 코스트·저장 확인은 기존 `InventoryEditSession` 계약을 유지합니다. 선택 사본을 별도로 보관해 탭 이탈 시 가방 표시 원본 Dictionary가 비워지는 참조 공유도 차단했습니다. 게임 데이터 목록 추가가 아니므로 Google Sheets 구조는 변경하지 않았습니다.

[화면·실제 입력·저장 보호 검수](../quality/e2e-play-session.md#inventory-presentation)

현재 탭은 **작전 가방 / 무기 · 파츠 / 모듈 설정**입니다. E도 마지막 모듈 설정으로 바로 연결됩니다. 무기·방어구·캐릭터 대상 선택, 칩 카드, 최대 레벨 슬롯 소켓과 저장 확인은 [통합 모듈 화면](equipment-customization.md#module-sockets)을 참고하세요. 아래 파츠 설명의 모듈 관리는 이 공통 탭으로 분리했습니다.

## 무기 카드형 파츠 편집 {#weapon-attachment-rack}

I → **무기 · 파츠** 탭은 메인·보조 무기를 위아래 카드로 표시합니다. 무기 그림 위에 광학 소켓, 아래에 총구·탄창 등 실제 정의에 존재하는 소켓만 배치합니다. 배그의 시선 흐름을 참고하되 외부 이미지·상표 에셋을 복사하지 않은 SFH 코드 도식입니다.

1. 무기 카드나 파츠 슬롯을 클릭합니다. 슬롯은 Tab 이동 후 Enter로도 선택할 수 있습니다.
2. 오른쪽 **호환 파츠 · 보유 목록**에서 원하는 인스턴스를 선택해 장착/교체합니다. 무기 소분류·고유 소켓이 맞지 않는 파츠는 후보에서 제외됩니다.
3. 장착된 파츠는 같은 슬롯에서 **파츠 해제 → 가방**으로 돌려놓습니다. 교체 시 이전 파츠와 강화 단계도 가방으로 반환하며, 반환 실패 시 장비·가방을 함께 복원합니다.
4. 탭 이동·ESC 닫기 시 저장/변경 취소/계속 편집을 선택합니다. 저장 전에는 실제 캐릭터 장비가 바뀌지 않습니다.

빈 슬롯은 회색 아이콘, 장착 슬롯은 청록 아이콘과 점, 선택 슬롯은 밝은 테두리로 구분합니다. 이름 전체는 슬롯 툴팁과 상세 영역에서 확인합니다. 모듈 코스트·장착·해제는 공통 모듈 설정에서 관리하고, U 고급 작업대의 강화 기능은 유지합니다. 좁은 화면에서는 본문을 세로 스크롤합니다.

`WeaponAttachmentRack`/`WeaponPartsBoard`는 표시와 선택 신호만 담당합니다. 실제 교체는 `InventoryEditSession.replace_part()`가 검증된 초안과 체크포인트로 처리합니다. 새 무기·파츠 목록이나 밸런스 변경은 없으므로 Sheet/CSV 구조는 그대로입니다.

## 런 소켓 아이템 재사용

작전 또는 활성 훈련에서 보유 룬·코어·유물을 선택하면 **런 소켓에 즉시 장착** 버튼이 표시됩니다. 미저장 배치가 있으면 저장/버리기/계속 편집을 먼저 확인합니다. 계속 편집은 적용을 취소합니다. 효과는 기본적으로 현재 무기/첫 장착 스킬에 귀속하고 해제 시 1×1 가방 아이템으로 반환합니다. 가방 부족 시 장착을 유지합니다. 일반 거점에서는 훈련을 시작하기 전 런 효과를 적용하지 않습니다.

가방은 `supports_inventory_item`/`perform_inventory_item_action` 제공자만 호출합니다. 소유권·대상·효과·훈련 복원은 [런 소켓](session-sockets.md)과 [훈련장](training-ground.md)이 담당하며 일반 장비 저장 흐름은 유지합니다.

## 현재 구현 범위

거점과 작전에서 I 키로 12×8 가방을 열고 닫습니다. 아이템은 종류와 정의에 따라 서로 다른 격자 크기를 점유하며, 같은 칸에 겹치거나 가방 경계를 벗어날 수 없습니다. 가방 안 아이템을 한 번 클릭한 뒤 `R`을 누르면 현재 칸을 기준으로 90도 회전합니다. 예를 들어 3×2는 2×3으로, 다시 누르면 3×2로 돌아갑니다.

| 예시 | 점유 크기 |
|---|---:|
| 돌격소총·대검 | 4×2 ↔ 2×4 |
| 전술 조끼 | 3×3 |
| 전용 파츠 | 2×1 ↔ 1×2 또는 3×1 ↔ 1×3 |
| 구급품 | 2×2 |
| 모든 장비 모듈 | **1×1 고정** |

가로·세로가 같은 아이템은 회전할 필요가 없어 입력이 거부됩니다. 회전한 크기가 가방 밖으로 나가거나 다른 아이템과 겹치면 방향을 바꾸지 않고 기존 배치를 유지합니다.

가방을 열면 게임이 일시정지됩니다. 변경이 없으면 `ESC`로 바로 닫고, 이동·장착 변경이 있으면 **저장 후 이동 / 변경 취소 후 이동 / 계속 편집**을 선택합니다. U/E/K/M 전환도 같은 확인을 거칩니다. 확인창에서 ESC는 계속 편집이며, Tab·방향키 포커스는 확인창 안에 머뭅니다.

거점의 I 화면은 출격 준비 가방입니다. 전투 세션과 동일한 `GridInventoryWindow`를 재사용하며, U/E 화면에서 장비·모듈·파츠를 장착하거나 해제하면 아이템이 이 격자로 이동합니다. 거점을 떠날 때 런타임 스냅샷을 보관하고 작전용 인스턴스에 복구합니다.

다운로드판에서는 이 거점 스냅샷을 디스크에도 자동 저장하므로 종료 후 재실행해도 확정한 가방 위치·장착·모듈·파츠 강화가 유지됩니다. 전투 중 임시 전리품은 성공 반출 시 창고로 정산하며, 편집 초안과 전투 중 이어하기는 저장 범위가 아닙니다. [저장 위치·백업·중단 규칙](../getting-started/run-project.md#desktop-save)을 확인하세요.

## 거점에서 자유롭게 전환하기

- `I`는 가방 편집, `U`는 장비 장착, `E`는 모듈·고유 파츠입니다. 먼저 ESC로 닫지 않아도 세 창 사이 여섯 방향으로 직접 전환합니다.
- I의 미저장 변경은 목적 창을 열기 전에 **저장 / 변경 취소 / 계속 편집**으로 보호합니다. 취소하면 기존 창과 편집 내용이 유지됩니다.
- U 고급 작업대의 장착·교체·강화는 즉시 적용 방식입니다. E/I 모듈 설정은 저장 확인을 거치는 초안 방식입니다. 다시 열면 최신 장비·가방으로 편집본을 새로 만듭니다. 출격 전까지 가방 칸 배치도 바꿀 수 있습니다.
- 이미 열린 U/E에 다른 탭 열기 명령을 보내도 최초 일시정지 상태를 덮어쓰지 않습니다. ESC 종료 후 거점 이동이 정상 복구되며, 작전 준비 중 열었던 경우에는 준비 화면의 일시정지를 유지합니다.

2026-09-03에는 열린 장비 창을 재진입하면 ESC 후 거점이 멈추던 오류를 수정했습니다. E2E는 버튼에 키보드 포커스가 있는 여섯 방향 전환, 반복 열기, 실제 장착 버튼, I↔E 저장·취소와 최신 편집본을 검증합니다.

## I 화면 정보 밀도

상단 **작전 가방**, **무기 · 파츠**, **모듈 설정**의 세 탭으로 편집합니다. 가운데는 무기 카드형 파츠 편집, 마지막은 무기·방어구·캐릭터 공통 모듈 화면입니다. 가방 셀은 가용 너비에 맞춰 20~52px로 조정하며 세로 스크롤합니다. 가방은 1000px 미만에서 열을 세로로 쌓고, 모듈 보드는 가용 너비900px 미만에서 세로 배치합니다.

- 왼쪽: 메인·보조 무기 카드와 실제 신체·신발 슬롯. 아래에 최대 체력·방어력·이동속도와 활성 스킬의 **장착 후 미리보기**를 압축합니다. 저장 전에는 실제 캐릭터에 적용하지 않습니다.
- 가운데 가방: 아이템을 드래그하거나 선택 후 빈 칸을 클릭하여 이동. 아이템을 한 번 선택하고 `R` 또는 상세 영역의 회전 버튼으로 방향을 바꿉니다. 장비 슬롯으로 드래그하거나 슬롯 선택→아이템 선택→장착 버튼으로 교체합니다.
- 최우측: 선택 아이템 설명과 장착·해제. 모듈 탭에서는 코스트·점유 수와 장착 모듈/고유 파츠 해제 버튼을 보여줍니다.
- 하단: 공간 사용과 미저장·거부 이유. 호환 태그, 가방 공간, 모듈 코스트, 중복·고유 소켓 규칙은 기존 장비 정의를 따릅니다.

이 레이아웃은 `GridInventoryWindow`와 `InventoryGridView`에만 있으며 가방 배치·충돌 규칙에는 관여하지 않습니다. 따라서 화면 밀도와 셀 표현을 바꿔도 `GridInventory`의 상태 계약은 그대로 유지됩니다.

## 데이터 블록

`InventoryItemDefinition`은 다음 정보만 소유합니다.

- 고유 `item_id`, 표시 이름, `item_type`
- 기본 방향의 `grid_size`와 패널 색상
- 장비·파츠·모듈을 가리키는 선택적 `linked_resource`
- 검색과 UI에 표시할 설명

초기 가방 구성과 전체 격자 크기는 `InventoryCatalog` Resource에 있습니다. 새로운 아이템은 기존 `.tres`를 복제해 카탈로그 배열에 추가합니다.

회전은 아이템 정의를 복제하지 않고 인스턴스별 `rotations` 상태로 저장합니다. 스냅샷의 `grid_size`는 현재 점유 크기, `base_grid_size`는 정의의 원래 크기입니다. 기존 저장 데이터에 `rotations`가 없으면 모든 아이템을 기본 방향으로 읽으므로 이전 다운로드판 저장과 호환됩니다.

## 배치 규칙

`GridInventory`는 UI와 분리된 런타임 제공자입니다.

- 초기 아이템은 좌상단부터 첫 빈 공간에 자동 배치
- `can_place(size, position, ignore_id)`로 경계와 충돌 검사
- `move_item(instance_id, position)`으로 검증된 위치 이동
- `can_rotate_item(instance_id)` / `rotate_item(instance_id)`으로 현재 위치에서 방향 전환과 충돌·경계 검증
- `take_item(instance_id)`으로 장착·소비 시스템에 아이템 전달
- `add_linked_resource()`로 해제된 장비·모듈·파츠와 강화 상태 반환
- `can_add_linked_resource()`로 교체 전 반환 공간 검사
- `export/restore_runtime_state()`로 거점·작전 Scene 교체 사이 배치와 아이템 상태 보존
- `get_items_by_type(type)`으로 장비 UI가 후보 검색
- `get_snapshot()`으로 UI가 내부 Dictionary를 직접 소유하지 않고 복사된 상태 소비

모듈 타입이 1×1이 아니면 `InventoryItemDefinition.is_valid()` 단계에서 카탈로그 등록이 거부됩니다.

## 장비 화면 연결

가방은 장비 규칙을 알지 않습니다. U/E 화면이 아이템의 `linked_resource`와 선택적 런타임 상태를 장비 시스템에 전달하고, 장착이 성공한 경우에만 가방에서 제거합니다. 해제 시에는 장비 제공자가 돌려준 Resource와 강화 상태를 다시 격자에 배치합니다.

따라서 가방 배치 로직은 무기 태그, 파츠 소켓, 모듈 코스트와 독립적으로 교체할 수 있습니다.

## 활성화와 제거

- `inventory_enabled`: 가방 런타임과 I 화면 설치
- `inventory_catalog_path`: 초기 가방 카탈로그
- `equipment_customization_enabled`: 가방 아이템을 장비에 연결하는 U 화면

장비 개조는 가방에 의존하지만 가방은 장비에 의존하지 않습니다. 순수 수집·소비 아이템 전용 게임에서도 같은 격자 제공자를 재사용할 수 있습니다.

## U 장비 화면의 카드 선택

U 화면은 가방 스냅샷에서 장비·모듈·파츠만 카드로 투영합니다. 사용자는 아이템을 직접 선택한 뒤 장착하며, 카드에는 분류·태그·소켓·코스트와 현재 슬롯 호환 여부가 표시됩니다. 장착이 거부되면 원본 아이템은 가방에 남습니다.

I 화면의 이동·장착·모듈 탭은 `InventoryEditSession`이 소유한 복제 가방·장비를 편집합니다. 저장은 두 상태의 사전검증→적용 순서로 처리하고, 실패 시 기존 상태로 복구합니다. 편집 도중 다른 제공자가 원본을 변경했다면 덮어쓰지 않고 다시 열도록 안내합니다.

**저장의 범위:** 현재 실행의 거점↔작전 전달 상태입니다. 전투 중 편집은 해당 런 소유이며 사망/정산 정책을 우회하지 않습니다. 다운로드판은 확정한 위치·회전 상태를 재시작 후 복구합니다. 브라우저 새로고침 영속화, 여러 가방, 자동 정렬은 별도 작업입니다. U 고급 작업대의 강화·개조는 즉시 적용 방식이며 I/E 편집본을 저장/취소한 뒤 진입합니다.

## 모듈 계약과 검증

### 첫 열기 레이아웃 안정화

I 창을 처음 표시하는 프레임에는 `ScrollContainer`의 실제 폭이 아직 정렬되지 않을 수 있습니다. 이전 구현은 이 0에 가까운 값을 최소 240px로 해석해 아이템이 좌측에 겹친 것처럼 보였고, 첫 드래그 뒤에야 정상 폭으로 다시 계산했습니다. 이제 컨테이너 `resized` 이후 지연 레이아웃을 한 번 더 적용하며, `open_layout_ready`, 실제 가방 폭, 최소 480px 격자 폭을 자동 검사합니다.

- `GridInventory`: 칸 배치·아이템 소유권·런타임 스냅샷.
- `InventoryEditSession`: 원본과 분리된 편집본, 이동·회전·장착·모듈 거래, 저장·충돌·롤백.
- `InventoryGridView` / `InventorySlotButton`: 클릭·드래그 의도 전달과 격자/장착 슬롯 표현.
- `GridInventoryWindow`: 반응형 구성, 탭, 상세 정보, 이탈 확인. Game은 제공자와 저장/전환 신호만 연결합니다.
- 장비 비활성 시 가방 이동은 유지됩니다. 새 장비 슬롯은 `get_slot_descriptors()`로 발견하며 UI에 새 조건문을 추가하지 않습니다.
- 기존 Sheet/확정 CSV 아이템 목록을 재사용하므로 이번 작업에 새 시트·아이템·밸런스 수치는 추가하지 않았습니다.

회귀 검사는 실제 마우스 클릭→`R` 입력→저장→탭 이동 뒤 방향 유지, 경계/충돌 시 무변경, 다운로드판 별도 프로세스 재실행 복원을 판정합니다. 근거는 [실제 플레이 E2E](../quality/e2e-play-session.md)의 인벤토리 편집 계약에서 확인합니다.
