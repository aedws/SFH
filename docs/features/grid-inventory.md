# 격자 가방 인벤토리

## 현재 구현 범위

거점과 작전에서 I 키로 12×8 가방을 열고 닫습니다. 아이템은 종류와 정의에 따라 서로 다른 격자 크기를 점유하며, 같은 칸에 겹치거나 가방 경계를 벗어날 수 없습니다.

| 예시 | 점유 크기 |
|---|---:|
| 돌격소총·대검 | 4×2 |
| 전술 조끼 | 3×3 |
| 전용 파츠 | 2×1 또는 3×1 |
| 구급품 | 2×2 |
| 모든 장비 모듈 | **1×1 고정** |

가방을 열면 게임이 일시정지됩니다. 변경이 없으면 `ESC`로 바로 닫고, 이동·장착 변경이 있으면 **저장 후 이동 / 변경 취소 후 이동 / 계속 편집**을 선택합니다. U/E/K/M 전환도 같은 확인을 거칩니다. 확인창에서 ESC는 계속 편집이며, Tab·방향키 포커스는 확인창 안에 머뭅니다.

거점의 I 화면은 출격 준비 가방입니다. 전투 세션과 동일한 `GridInventoryWindow`를 재사용하며, U/E 화면에서 장비·모듈·파츠를 장착하거나 해제하면 아이템이 이 격자로 이동합니다. 거점을 떠날 때 런타임 스냅샷을 보관하고 작전용 인스턴스에 복구합니다.

다운로드판에서는 이 거점 스냅샷을 디스크에도 자동 저장하므로 종료 후 재실행해도 확정한 가방 위치·장착·모듈·파츠 강화가 유지됩니다. 전투 중 임시 전리품은 성공 반출 시 창고로 정산하며, 편집 초안과 전투 중 이어하기는 저장 범위가 아닙니다. [저장 위치·백업·중단 규칙](../getting-started/run-project.md#desktop-save)을 확인하세요.

## 거점에서 자유롭게 전환하기

- `I`는 가방 편집, `U`는 장비 장착, `E`는 모듈·고유 파츠입니다. 먼저 ESC로 닫지 않아도 세 창 사이 여섯 방향으로 직접 전환합니다.
- I의 미저장 변경은 목적 창을 열기 전에 **저장 / 변경 취소 / 계속 편집**으로 보호합니다. 취소하면 기존 창과 편집 내용이 유지됩니다.
- U/E의 장착·교체·해제는 기존 즉시 적용 방식입니다. I를 다시 열면 최신 장비·가방으로 편집본을 새로 만듭니다. 출격 전까지 가방 칸 배치도 바꿀 수 있습니다.
- 이미 열린 U/E에 다른 탭 열기 명령을 보내도 최초 일시정지 상태를 덮어쓰지 않습니다. ESC 종료 후 거점 이동이 정상 복구되며, 작전 준비 중 열었던 경우에는 준비 화면의 일시정지를 유지합니다.

2026-09-03에는 열린 장비 창을 재진입하면 ESC 후 거점이 멈추던 오류를 수정했습니다. E2E는 버튼에 키보드 포커스가 있는 여섯 방향 전환, 반복 열기, 실제 장착 버튼, I↔E 저장·취소와 최신 편집본을 검증합니다.

## I 화면 정보 밀도

2026-09-03부터 한 화면에서 장비·스탯·가방을 확인하고, 상단 **작전 가방 / 무기 모듈 / 방어구 모듈** 탭으로 편집합니다. 가방 셀은 가용 너비에 맞춰 20~52px로 조정하며 가로 잘림 없이 세로 스크롤합니다. 1000px 미만에서는 열을 세로로 쌓고 본문도 스크롤합니다.

- 왼쪽: 메인·보조 무기 2칸과 방어구 2×2 영역. 현재 신체·신발만 활성화되어 있으며 나머지 2칸은 확장 예정으로 명시합니다. 새 슬롯 규칙을 추가하면 실제 슬롯으로 표시됩니다.
- 가운데: 최대 체력·방어력·이동속도와 활성 스킬의 **장착 후 미리보기**. 저장 전에는 실제 캐릭터에 적용하지 않습니다.
- 오른쪽 가방: 아이템을 드래그하거나 선택 후 빈 칸을 클릭하여 이동. 장비 슬롯으로 드래그하거나 슬롯 선택→아이템 선택→장착 버튼으로 교체합니다.
- 최우측: 선택 아이템 설명과 장착·해제. 모듈 탭에서는 코스트·점유 수와 장착 모듈/고유 파츠 해제 버튼을 보여줍니다.
- 하단: 공간 사용과 미저장·거부 이유. 호환 태그, 가방 공간, 모듈 코스트, 중복·고유 소켓 규칙은 기존 장비 정의를 따릅니다.

이 레이아웃은 `GridInventoryWindow`와 `InventoryGridView`에만 있으며 가방 배치·충돌 규칙에는 관여하지 않습니다. 따라서 화면 밀도와 셀 표현을 바꿔도 `GridInventory`의 상태 계약은 그대로 유지됩니다.

## 데이터 블록

`InventoryItemDefinition`은 다음 정보만 소유합니다.

- 고유 `item_id`, 표시 이름, `item_type`
- `grid_size`와 패널 색상
- 장비·파츠·모듈을 가리키는 선택적 `linked_resource`
- 검색과 UI에 표시할 설명

초기 가방 구성과 전체 격자 크기는 `InventoryCatalog` Resource에 있습니다. 새로운 아이템은 기존 `.tres`를 복제해 카탈로그 배열에 추가합니다.

## 배치 규칙

`GridInventory`는 UI와 분리된 런타임 제공자입니다.

- 초기 아이템은 좌상단부터 첫 빈 공간에 자동 배치
- `can_place(size, position, ignore_id)`로 경계와 충돌 검사
- `move_item(instance_id, position)`으로 검증된 위치 이동
- `take_item(instance_id)`으로 장착·소비 시스템에 아이템 전달
- `add_linked_resource()`로 해제된 장비·모듈·파츠와 강화 상태 반환
- `can_add_linked_resource()`로 교체 전 반환 공간 검사
- `export/restore_runtime_state()`로 거점·작전 Scene 교체 사이 배치와 아이템 상태 보존
- `get_items_by_type(type)`으로 장비 UI가 후보 검색
- `get_snapshot()`으로 UI가 내부 Dictionary를 직접 소유하지 않고 복사된 상태 소비

모듈 타입이 1×1이 아니면 `InventoryItemDefinition.is_valid()` 단계에서 카탈로그 등록이 거부됩니다.

## 장비 화면 연결

가방은 장비 규칙을 알지 않습니다. U/E 화면이 아이템의 `linked_resource`와 선택적 런타임 상태를 장비 시스템에 전달하고, 장착이 성공한 경우에만 가방에서 제거합니다. 해제 시에는 장비 제공자가 돌려준 Resource와 강화 상태를 다시 격자에 배치합니다.

따라서 가방 배치 로직은 무기 태그, 파츠 소켓, 모듈 코스트와 독립적으로 교체할 수 있습니다.

## 활성화와 제거

- `inventory_enabled`: 가방 런타임과 I 화면 설치
- `inventory_catalog_path`: 초기 가방 카탈로그
- `equipment_customization_enabled`: 가방 아이템을 장비에 연결하는 U 화면

장비 개조는 가방에 의존하지만 가방은 장비에 의존하지 않습니다. 순수 수집·소비 아이템 전용 게임에서도 같은 격자 제공자를 재사용할 수 있습니다.

## U 장비 화면의 카드 선택

U 화면은 가방 스냅샷에서 장비·모듈·파츠만 카드로 투영합니다. 사용자는 아이템을 직접 선택한 뒤 장착하며, 카드에는 분류·태그·소켓·코스트와 현재 슬롯 호환 여부가 표시됩니다. 장착이 거부되면 원본 아이템은 가방에 남습니다.

I 화면의 이동·장착·모듈 탭은 `InventoryEditSession`이 소유한 복제 가방·장비를 편집합니다. 저장은 두 상태의 사전검증→적용 순서로 처리하고, 실패 시 기존 상태로 복구합니다. 편집 도중 다른 제공자가 원본을 변경했다면 덮어쓰지 않고 다시 열도록 안내합니다.

**저장의 범위:** 현재 실행의 거점↔작전 전달 상태입니다. 전투 중 편집은 해당 런 소유이며 사망/정산 정책을 우회하지 않습니다. 앱 종료·브라우저 새로고침 후 가방 배치 영속 저장, 회전, 여러 가방, 자동 정렬은 아직 별도 작업입니다. 기존 U/E 고급 작업대의 강화·개조는 기존 즉시 적용 방식이며 I 편집본을 저장/취소한 뒤 진입합니다.

## 모듈 계약과 검증

- `GridInventory`: 칸 배치·아이템 소유권·런타임 스냅샷.
- `InventoryEditSession`: 원본과 분리된 편집본, 이동·장착·모듈 거래, 저장·충돌·롤백.
- `InventoryGridView` / `InventorySlotButton`: 클릭·드래그 의도 전달과 격자/장착 슬롯 표현.
- `GridInventoryWindow`: 반응형 구성, 탭, 상세 정보, 이탈 확인. Game은 제공자와 저장/전환 신호만 연결합니다.
- 장비 비활성 시 가방 이동은 유지됩니다. 새 장비 슬롯은 `get_slot_descriptors()`로 발견하며 UI에 새 조건문을 추가하지 않습니다.
- 기존 Sheet/확정 CSV 아이템 목록을 재사용하므로 이번 작업에 새 시트·아이템·밸런스 수치는 추가하지 않았습니다.

회귀 근거는 [실제 플레이 E2E](../quality/e2e-play-session.md)의 인벤토리 편집 계약에서 확인합니다.
