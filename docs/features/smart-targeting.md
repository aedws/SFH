# 스마트 자동 타게팅

## 실제 후보 수집 · 2026-09-07

무기와 스킬은 `TargetCandidateArea`의 원형 `Area2D` 겹침 후보를 공통으로 사용합니다. 제공자가 소유하지 않는 적은 제외하고 최종 중심 거리·정렬·HP/등급/밀집 정책을 유지합니다. 생성 직후·반경 변경·큰 위치 이동에는 물리 목록이 갱신되기 전 제공자 폴백을 사용해 첫 입력이 사라지지 않게 합니다. 비물리 훈련 더미도 지원하고 재구성/종료 때 센서를 해제합니다. [검증 계약](../architecture/module-audit.md#partial-adapters).

에임이 없는 SFH는 하나의 가중치 공식으로 모든 행동을 처리하지 않습니다. 무기와 스킬 정의가 목적에 맞는 정책 ID를 선택하고 `SmartTargetingPolicy.resolve()`가 동일한 후보 스냅샷에서 결과를 반환합니다.

| 정책 | 결과 | 기본 사용처 |
|---|---|---|
| `nearest` | 사거리 안 가장 가까운 적 | 소총·단일 기본기 |
| `highest_health` | 최대 HP가 가장 높은 적 | 고체력 우선 단일 스킬 |
| `elite` | 우선 등급이 가장 높은 적, 동률은 HP | 보조 무기·정예 대응 |
| `densest` | 실제 원형 반경에 가장 많은 후보가 포함되는 지점 | 범위·지점 스킬 |
| `direction` | 현재 이동 입력 벡터 | 점멸·돌진 |
| `self` | 플레이어 위치 | 자기장·자기 버프 |

각 `CombatSkillDefinition`은 타게팅 모드와 사거리를, 무기는 밸런스 데이터의 `smart_targeting_mode`를 소유합니다. `smart_targeting_enabled`를 끄거나 제공자를 제거하면 무기는 최근접 폴백, 자기 대상 스킬은 기존 효과 폴백을 유지합니다.

적은 `get_targeting_snapshot()`으로 위치·체력·장갑·우선 등급·상태 태그만 공개합니다. 타게팅 정책은 적의 HealthComponent 경로나 생성기 내부 배열을 읽지 않습니다.

## N26-03A · 중심점·반경 계약

- 지점형 스킬의 `target_point`는 선택한 공격 중심이며 대표 적 `target`의 좌표로 덮어쓰지 않습니다. 두 값은 용도가 다릅니다. 평균 중심은 피격 수를 유지할 때만 사용합니다.
- `CombatSkillDefinition.get_targeting_radius()`가 효과의 기존 `get_parameters().radius`와 최종 `radius_multiplier`를 읽습니다. 별도 밸런스 목록은 만들지 않습니다.
- `CombatSkillSystem`은 배율 합성 후 `resolve_for_skill(..., effect_radius)`로 전달합니다. 반경을 제공하지 않는 효과는 정책의 기존 기본값을 사용합니다.
- 기존 5인자 `resolve()`만 제공하는 사용자 정책은 이전 호출 경로로 동작합니다. 자기장 `self`와 점멸 `direction` 모드는 바꾸지 않습니다.
- 삭제 예정·무효·중복·사거리 밖 후보는 군집과 대표 적 선택에서 제외하며, 동률은 가까운 기준 적 → 좌표 순으로 고정합니다. 같은 좌표의 서로 다른 적은 각각 1명으로 셉니다.

N26-03A에서는 평균 이웃 군집을 유지했으나, N26-03B(`add3a33`)에서 아래 최대 피격 계산으로 교체했습니다. 기본 3종 스킬에 신규 광역 공격을 추가한 작업이 아닙니다.

검증: `smart_targeting_center_contract_test.gd`는 3기 중심과 실제 실행 효과, 반경/배율 변경, 동률·순서·중복·무효·사거리, 기존 정책·기능 제거 폴백을 검사합니다. 게임 스모크와 기존 실제 입력 E2E도 통과했습니다.

## N26-03B · 원형 최대 피격 계산 {#n26-03b}

**플레이 차이:** 서로 18만큼 떨어진 적 2명에게 반경 10의 공격을 놓는다면, 한 적을 기준으로 이웃만 찾는 대신 두 적 사이에 놓아 모두 맞춥니다. 적이 한쪽에 쏠렸을 때 평균 중심으로 이동하면서 반대편 적이 빠지는 현상도 방지합니다.

1. 정책은 기존과 동일하게 **사거리 안 적의 중심 좌표**만 선택합니다. 적 충돌체 크기·시야 차단·사거리 밖 적 추가 타격은 이번 변경의 계산 대상이 아닙니다.
2. `CircularCoverageSolver`가 각 적을 원의 경계에 둔 상태로 중심의 각도 구간을 훑어 최대 포함 수를 찾습니다. 원 경계의 접점도 포함합니다.
3. 시전 중심이 사거리를 벗어나면 사거리 원으로 투영합니다. 모든 후보가 그 원 안에 있어 후보까지의 거리가 늘어나지 않습니다.
4. 선택 집합의 평균 중심이 같은 후보를 모두 포함할 때만 평균을 사용합니다. 그렇지 않으면 피격을 보존하는 계산 중심을 유지합니다.
5. 부동소수점 경계 오차만 제곱 거리의 상대 0.000001로 처리합니다. 공격 효과의 실제 반경·피해 수치·갱신 주기는 변경하지 않습니다.

**모듈 경계:** 정책은 후보·모드·대표 적을, 순수 계산기는 좌표·반경·시전 거리만 다룹니다. 계산기는 Scene·적 Node·장비·저장소에 접근하지 않습니다. 효과 실행기와 UI에 계산을 중복하지 않으며 기존 5인자 정책 교체와 기능 제거 폴백을 유지합니다.

**자동 수락 근거:** `circular_coverage_contract_test.gd`가 적 사이 배치·지름 접점·불안전한 평균·사거리 경계·동일 좌표·36개 회전 배치를 검사하고, 240개 고정 난수 배치의 피격 수를 독립 O(n³) 원 교차점 전수 계산과 대조합니다. 실제 `CombatSkillSystem` → 검사 효과 실행에서도 이전 방식이 놓친 2명과 평균 이동 시 누락되던 5명 모두 적중을 확인합니다. 이는 자동 계약·실제 입력 회귀이며 사람의 재미 수락을 대신하지 않습니다.

## 성능

대상 선택은 탄환 매 프레임이 아니라 새 발사 묶음이 시작될 때만 수행합니다. 대형 최대 72명 조건을 성능 예산 테스트에 포함했습니다.

원형 계산은 O(n² log n), 기준 적당 임시 메모리 O(n)입니다. 2026-09-07 로컬 Windows Godot 4.7.2 headless에서 밀집·분산·원형 72명 배치, 총 72회 요청의 p95는 약 **3.1ms**였습니다. 자동 게이트는 **단일 계산 p95 < 16.67ms**이며 전체 프레임·모바일/Web FPS 보장이 아닙니다. 첫 구현의 약 19.7ms를 숫자 배열의 네이티브 정렬·불필요 할당 제거로 줄였습니다. 향후 동시 시전량이 늘면 별도로 합산 예산을 검증해야 합니다.
