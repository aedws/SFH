# 스마트 자동 타게팅

에임이 없는 SFH는 하나의 가중치 공식으로 모든 행동을 처리하지 않습니다. 무기와 스킬 정의가 목적에 맞는 정책 ID를 선택하고 `SmartTargetingPolicy.resolve()`가 동일한 후보 스냅샷에서 결과를 반환합니다.

| 정책 | 결과 | 기본 사용처 |
|---|---|---|
| `nearest` | 사거리 안 가장 가까운 적 | 소총·단일 기본기 |
| `highest_health` | 최대 HP가 가장 높은 적 | 고체력 우선 단일 스킬 |
| `elite` | 우선 등급이 가장 높은 적, 동률은 HP | 보조 무기·정예 대응 |
| `densest` | 반경 안 이웃이 가장 많은 군집의 중심점 | 범위·지점 스킬 |
| `direction` | 현재 이동 입력 벡터 | 점멸·돌진 |
| `self` | 플레이어 위치 | 자기장·자기 버프 |

각 `CombatSkillDefinition`은 타게팅 모드와 사거리를, 무기는 밸런스 데이터의 `smart_targeting_mode`를 소유합니다. `smart_targeting_enabled`를 끄거나 제공자를 제거하면 무기는 최근접 폴백, 자기 대상 스킬은 기존 효과 폴백을 유지합니다.

적은 `get_targeting_snapshot()`으로 위치·체력·장갑·우선 등급·상태 태그만 공개합니다. 타게팅 정책은 적의 HealthComponent 경로나 생성기 내부 배열을 읽지 않습니다.

## N26-03A · 중심점·반경 계약

- 지점형 스킬의 `target_point`는 선택한 군집의 평균 중심이며 대표 적 `target`의 좌표로 덮어쓰지 않습니다. 두 값은 용도가 다릅니다.
- `CombatSkillDefinition.get_targeting_radius()`가 효과의 기존 `get_parameters().radius`와 최종 `radius_multiplier`를 읽습니다. 별도 밸런스 목록은 만들지 않습니다.
- `CombatSkillSystem`은 배율 합성 후 `resolve_for_skill(..., effect_radius)`로 전달합니다. 반경을 제공하지 않는 효과는 정책의 기존 기본값을 사용합니다.
- 기존 5인자 `resolve()`만 제공하는 사용자 정책은 이전 호출 경로로 동작합니다. 자기장 `self`와 점멸 `direction` 모드는 바꾸지 않습니다.
- 삭제 예정·무효·중복·사거리 밖 후보는 군집과 대표 적 선택에서 제외하며, 동률은 가까운 군집 → 좌표 순으로 고정합니다.

이번에는 기존 O(n²) 이웃 군집 알고리즘을 유지합니다. 평균 중심이 원형 범위의 전역 최적 피격 지점이라는 보장은 없으므로, 해당 요구 전체는 **부분 대응**으로 유지하고 N26-03B에서 경계 배치·최대 피격 수·성능을 함께 보완합니다. 기본 3종 스킬에 신규 광역 공격을 추가한 작업이 아닙니다.

검증: `smart_targeting_center_contract_test.gd`는 3기 중심과 실제 실행 효과, 반경/배율 변경, 동률·순서·중복·무효·사거리, 기존 정책·기능 제거 폴백을 검사합니다. 게임 스모크와 기존 실제 입력 E2E도 통과했습니다.

## 성능

대상 선택은 탄환 매 프레임이 아니라 새 발사 묶음이 시작될 때만 수행합니다. 대형 최대 72명 조건을 성능 예산 테스트에 포함했습니다.
