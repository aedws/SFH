# 탈출 방어전과 작전 결과 정산

## 권장 생환·오염·붕괴 · 2026-09-23 {#pressure-20260923}

오너의 9/23 정책 승인으로 이전 약10분 목표를 **15~20분 권장 생환·30분 강제 실패**로 대체합니다. 추천 시간은 탈출 잠금이 아닙니다. 현행 복합 구역의 두 출구는 이전처럼 일찍 F 방어를 시작할 수 있습니다.

| 작전 시각 | 플레이어에게 달라지는 것 |
|---|---|
| 출격 전 / 시작 | 브리핑에서 권장 생환·20분 오염·30분 붕괴 안내. 임무 HUD에는 붕괴 잔여 시간과 탈출 상태 표시 |
| 15~20분 | 규모별 권장 목표: 소형15분·중형17분30초·대형20분. 오래 머물지 회수할지 선택 |
| 20분 | 기존/신규 일반 적 공격력×1.35·이동×1.15, Hunter 한 번 생성. 기존 회수액50% 추격 보스와 별개이며 두 보스가 함께 존재 가능 |
| 29분 이후 | 붕괴 임박 경고색. 가방을 열고 있어도 런 시간 진행 |
| 30분 | 탈출 미완료 런은 ‘구역 붕괴’ 실패로 종료. 기존 사망 손실·정산 경로 적용. 늦은 탈출/사망 신호로 결과나 지급을 바꿀 수 없음 |

Hunter는 문 개폐·방 클리어·일반 적 생성 한도와 무관하게 추적합니다. 처치한 Hunter를 다시 만들지 않습니다. 생성 실패만 작전 시간1초 간격으로 재시도하며 붕괴·탈출 이후에는 생성하지 않습니다. 외곽 보스 방향 표시와 등장 경고를 재사용합니다.

**임시 수치:** 일반 적×1.35/×1.15, Hunter는 등장 시 플레이어 이동속도×1.08·출격 기준 공격력×1.12·HP120·방어20입니다. 시간/병존 규칙은 승인 사항이고 강화 수치는 밸런스 수락 전 교체 가능합니다. 기존 보스 스펙을 오염 배율로 다시 곱하지 않고 현재 적 HP도 회복시키지 않습니다. 30분은 HP 피해량 비교가 아닌 강제 런 실패이므로 무적/방어로 피할 수 없습니다.

### 모듈 계약

- `RunPressurePolicy` / `configs/default_run_pressure.tres`: 시간·배율 검증과 순수 표시 스냅샷. 출격마다 복제하므로 라이브 원본 변경이 진행 중 런을 바꾸지 않습니다.
- `RunPressureService`: 수락된 작전 시계 입력과 오염/생성/붕괴 사건만 소유. 실제 벽시계 타이머·저장·재화 지급 없음. 뒤로 간 시간·NaN/Inf·종료 후 입력은 무시합니다.
- `EnemySpawner.set_run_pressure` / Enemy 공개 계약: 일반 적 현재/미래 배율 적용. 같은 배율 재호출은 중복 곱셈이 아니며, 추격자는 독립 스펙을 유지합니다.
- Game: 생성·신호 조립과 기존 단일 실패 정산 연결. `FeatureManifest.run_pressure_enabled=false`는 압박 기능만 제거하며 `run_pressure_policy_path`로 정책을 교체합니다. 적 공급자가 없으면 시계/붕괴만 작동합니다.

새 품목 목록은 없으므로 Sheet 구조·잠금 CSV 버전은 바꾸지 않았습니다. [자동 검증과 실제 플레이 미수락 범위](../quality/e2e-play-session.md#pressure-20260923) · [다음 구현](../design/current-milestone-workline.md#approved-20260923).

**현행 구역 정책:** 두 출구 모두 투입 직후부터 현장에서 F 방어를 시작할 수 있습니다. 시간/모든 방 완료 대기는 제거했고 방어 시간·성공/실패 정산은 유지합니다. 이탈 무기한 보존은 아래9/21 유예/역행 정책으로 변경했습니다. `MultiExtractionZone`이 한 출구를 선택하면 다른 출구를 잠그고 중복 완료를 막습니다. [구역 변경 사유와 계약](extraction-district.md).

탈출 신호가 열린 뒤 탈출 지점에서 `F`를 누르면 즉시 끝나지 않고 방어 카운트다운이 시작됩니다. 구역 밖으로 나가면 **2초간 잔여 시간 보존**, 이후에는 **초당1초씩 잔여 시간이 늘어납니다.** 캐릭터 중심이 다시 구역 안으로 들어오면 자동으로 카운트다운을 재개합니다. 밖에서 F를 눌러 유예를 초기화할 수 없습니다.

## 2초 유예·타이머 역행 · 2026-09-21 {#decay-20260921}

새 Notion [확정 작업](https://wobbly-pawpaw-1ff.notion.site/3d85b7280040816da6bbf7d7be82e8b6) 반영의 첫 패킷입니다. 오래된 Pause/Resume 설명은 유예 구간과 복귀 재개의 의미로 유지하고, 무기한 시간 보존은 최신 명시 규칙으로 대체했습니다. 30분 런/가방/파우치/요원 변경은 이번 패킷에 포함하지 않습니다.

예: 방어20초 중8초를 진행해12초가 남았다면, 원 밖2초까지12초 유지 → 밖에서 추가1.5초 체류하면13.5초 → 재진입하면13.5초부터 감소합니다. 잔여 시간은 최초 방어20초를 초과하지 않습니다. 프레임 하나가 유예 경계를 넘더라도 초과분만 계산합니다.

- 상시 임무 HUD: `유예 …초` → `역행 …초` → `방어 …초`. 복귀 지시는 별도 상태/상호작용 안내로 표시해 시간 행이 길어지지 않게 합니다.
- 바닥 원: 완료 진행 호가 줄어들고 역행 중 붉은 경고색으로 전환. 새로운 대형 팝업은 없음.
- 재진입 시 유예 누적을 초기화합니다. 반복해서 짧게 이탈하는 경우에도 원 밖에서는 탈출 완료 시간이 줄지 않습니다.
- 방어 비활성화 시 즉시 탈출, 실패/취소/장면 종료 시 세션 상태 제거, 다른 출구 잠금과 단일 정산은 유지합니다.

`ExtractionExitPolicy`는 유예·역행 속도와 순수 시간 계산만 소유합니다. `ExtractionDefenseConfig.exit_policy`에서 바꾸며 Zone은 시작 전 복제본으로 고정합니다. 역행 속도0이면 명시적 레거시 Pause 정책으로 되돌릴 수 있습니다. 새 아이템/밸런스 목록은 없으므로 Sheet 구조를 추가하지 않았습니다.

## 구역 경계와 입력 안내

바깥 원은 실제 `interaction_radius`(기본 72px)를 표시합니다. 캐릭터 중심이 이 원 안에 있어야 방어전을 시작하거나 유지할 수 있습니다. 몸의 충돌체만 원에 걸친 상태에서는 **“탈출 구역 안으로 더 이동하세요”**를 표시하며, 실행할 수 없는 F 시작 안내를 띄우지 않습니다. 몸이 계속 겹친 채 안으로 이동해도 안내가 갱신됩니다.

구역 잠금·방어 시간·정산 배율은 변경하지 않았습니다. `ExtractionZone`의 단일 중심 거리 판정을 입력·유지·재개·안내에서 공유하며, `configure()`는 물리 원도 같은 반경으로 갱신합니다. [경계 회귀 검사](../quality/e2e-play-session.md#fun-qa-affordance)는 실제 충돌체와 F 입력을 사용합니다.

| 맵 | 표준 | 베테랑 | 악몽 |
|---|---:|---:|---:|
| 소형 | 15초 | 18초 | 21초 |
| 중형 | 20초 | 24초 | 28초 |
| 대형 | 25초 | 30초 | 35초 |

카운트다운 동안 기존 적 생성·증원 예산은 계속 동작합니다. `extraction_defense_enabled`를 끄면 기존 즉시 탈출 방식으로 복귀합니다.
시간표는 `ExtractionDefenseConfig` Resource라서 맵 규모별 기본 시간과 난이도 배율을 코드 수정 없이 바꿀 수 있습니다.

## 성공 정산

- 휴대 크레딧 × 지역·난이도·페널티 회수 배율을 영구 크레딧으로 저장
- 처치 12명당 고철 1개, 최소 1개를 창고로 반입
- 지역별 도면 확률 적용: 폐허 도시 1.0배, 산업 지구 1.3배, 연구 단지 1.7배
- 성공 도면을 대응 영구 상점 항목으로 등록
- 동일 지역·난이도·맵·최소 페널티 조건의 회수 가치·최단 시간·처치 수 랭킹에 각각 제출
- 내부 버프 수량 기반 외부 경험치 정산은 기존 성장 모듈에서 별도로 유지
- 현장 획득품은 Item 생명 주기에 따라 자동 환전·창고 보관·영구 해금하고 결과 화면에 각 종류를 분리 표시

실패 시 휴대 크레딧과 작전 중 획득품, 작전에 착용하고 들어간 준비 로드아웃을 잃고 투입 비용은 반환하지 않습니다. 거점 복귀 시 파산 방지용 기본 무장이 다시 제공됩니다. 성공·실패 모두 결과 화면을 거쳐 시작 거점으로 돌아갑니다.

## 모듈 계약

`ExtractionZone`은 카운트다운, 이탈 유예·역행·재개와 구역 유지 판정만 담당합니다. `OperationResultService`는 휴대 크레딧·고철·랭킹을, [RunSettlementService](run-settlement.md)는 획득 전리품의 자동 환전·창고·해금·소실과 `run_id` 중복 방지를 담당합니다. 두 서비스는 영구 프로필의 공개 메서드만 호출하며 맵, 적, UI 내부 상태를 읽지 않습니다. 장착품 소실은 세션 조립부가 장비의 준비 상태 공개 계약을 비우는 방식이라 인벤토리 내부 배열을 직접 수정하지 않습니다.

2026-09-08 결과 UI는 `OperationResultPresenter`로 분리했습니다. `install(overlay, title, summary, action)`은 표시와 기존 복귀 버튼만 조립하고, `render(result, title, transcript)`는 정산된 결과 사본을 받습니다. 성공/실패·생존/처치·정산/분실 카드가 먼저 보이고, **정산 상세**를 펼치면 랭킹·외부 성장·전체 전리품 기록을 확인합니다. 스크롤과 관계없이 거점 복귀 버튼은 하단에 유지합니다. 초기화 실패는 보상을 꾸며내지 않고 복구 설명을 펼칩니다. 제거 시 Game의 install/render 호출을 제외하면 기존 Scene의 제목/요약/복귀 컨트롤과 정산 도메인은 남습니다. [UI 검토와 잔여 작업](../quality/player-perception-audit.md#game-ui-audit).
도면 기본 확률, 지역별 도면, 처치당 고철과 최소 고철은 `OperationResultConfig`에 분리되어 있습니다.
