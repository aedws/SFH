# 런 전용 룬·코어·유물 소켓

## 2026-09-22 · 장착분까지 환전 확인 {#settlement-20260922}

**획득한 룬은 가방에 있든 소켓에 꽂혀 있든 탈출하면 같은 기준으로 환전됩니다.** 가방에서 빠졌다고 정산에서 사라지지 않습니다. 해제·재장착은 새 획득이 아니며 두 번 환전하지 않습니다. 사망 시에는 두 위치 모두 소실됩니다.

기존 `FieldLootAcquisitionService`의 획득 장부와 `RunSettlementService`의 런 ID별 정산이 이미 담당하므로 별도 환전 경로를 복제하지 않았습니다. 실제 F 드랍 획득→장착/가방 혼재→해제/재장착→게임 정산을 검증했습니다. 잠금 데이터 예시인 전도 룬3개(각60C)·축전 코어1개(110C)·위상 유물1개(220C)는 탈출510C, 사망0C이며 반복 정산도 추가 지급0C입니다. 정산 요약의 자동 환전 금액에도 포함됩니다.

가격은 Item 생명 주기 데이터가 소유하며 위 예시는 새 밸런스 확정이 아닙니다. 스킬별1~3소켓/4계열 룬 전체 구현과도 구분합니다. [전용 회귀 근거](../quality/e2e-play-session.md#decided-20260922).

## 무엇이 변했나

작전에서 룬·코어·유물을 발견하면 비교 패널에 `F 런 소켓 장착`이 표시됩니다. F를 누르면 장비 영구 모듈과 분리된 작전 한정 슬롯에 들어가고 전투 수치가 즉시 변합니다. 빈 소켓은 전투 시야를 위해 표시하지 않으며, 실제 장착 뒤에만 하단 중앙의 `SESSION SOCKETS / RUN ONLY` 패널에서 점유 상태를 확인하고 버튼으로 효과를 해제할 수 있습니다.

기획 데이터가 아직 없으므로 아래 값은 **임시 기본값**입니다. 최종값은 코드가 아니라 Google Sheet `RunAsset` 탭이나 확정 CSV만 바꾸면 교체됩니다.

| 종류 | 임시 슬롯 | 중복 | 임시 효과 |
|---|---:|---:|---|
| 룬 | 2 | 같은 아이템 1개 | 전도 룬: 무기 피해 ×1.15 |
| 코어 | 1 | 같은 아이템 1개 | 축전 코어: 스킬 쿨타임 ×0.85 |
| 유물 | 1 | 같은 아이템 1개 | 위상 유물: 이동 속도 ×1.12 |

슬롯이 가득 찬 상태의 기본 정책은 `오래된 항목부터 교체`입니다. 환전 가격과 탈출·사망 결과는 기존 Item 생명 주기 데이터가 소유하며, P4-06 정산이 실제 프로필·재화 반영을 담당합니다.

## 데이터 계약

### 2026-09-07 · 오너 승인 임시 귀속 정책

- 룬 2·코어 1·유물 1의 **총 용량은 유지**합니다. 무기 효과는 장착 순간의 `무기 슬롯/정의 ID`, 스킬 효과는 스킬 ID, 유물은 플레이어에 귀속합니다. Q로 다른 무기를 들면 이전 무기 룬 효과는 따라가지 않고 되돌리면 다시 적용됩니다.
- 기본 선택은 현재 무기·첫 장착 스킬입니다. `socket_item`/`socket_owned_item`의 `requested_targets`로 특정 스킬 ID를 지정할 수 있습니다. 일반 UI는 대상 선택기가 아니라 기본 대상을 사용하며 툴팁에 귀속 대상을 표시합니다.
- **물리 아이템 인스턴스 귀속은 아닙니다.** 같은 정의의 무기를 다른 슬롯으로 이동하면 기존 귀속이 따라가지 않습니다. 차후 인스턴스 귀속은 대상 공급자와 `SessionSocketBindingPolicy`에서 바꾸며 UI/정산에 계산을 복제하지 않습니다.
- 해제·오래된 슬롯 교체 시 자산을 1×1 가방 아이템으로 반환합니다. 가방 부족 시 기존 장착과 효과를 유지하고 실패합니다. 중복 드랍은 가능하면 가방에 보관하며, 여러 개 획득 중 실패하면 가방·소켓을 함께 원복하고 현장 드랍을 남깁니다.
- 가방에서 선택 후 **런 소켓에 즉시 장착**으로 재사용합니다. 미저장 편집이 있으면 먼저 저장/버리기/계속 편집을 확인하며 계속 편집은 장착을 실행하지 않습니다.
- 탈출 환전은 기존 획득 원장이 한 번 처리합니다. 해제/재장착은 새 획득으로 세지 않으며 영구 장비 모듈이나 성장 수치로 저장하지 않습니다.
- 훈련에서는 **현재 보유한 가방·장착 자산만** 무료로 시험하며 종료 시 진입 전 상태를 복원합니다. 탈출한 룬의 영구 보유 목록을 새로 만든 것은 아닙니다.

효과·용량은 기존 RunAsset CSV, 귀속 선택은 정책 Resource, 입출금은 가방 어댑터가 소유합니다. 실시간 변경이 장착 자산 삭제·용량/중복 제한 축소·효과 대상 변경으로 자산을 잃게 하면 거부하고 마지막 유효 데이터를 유지합니다. 기획 최종 확정은 별도이며 Sheet 열/행은 추가하지 않았습니다.

`RunAsset`은 1행 변수명, 2행 기획자 설명, 3행 이후 개별 규칙 형식입니다. `rule_id`, `item_id`, `socket_type`, `slot_capacity`, `duplicate_limit`, `replacement_policy`, `effect_target`, `modifier_id`, `modifier_operation`, `modifier_value` 등을 독립 열로 둡니다.

- 실시간 테스트: Google Sheet `RunAsset`
- 확정 모드: `session_socket_rules.csv`
- Web 폴백: 같은 CSV로 생성한 `EmbeddedCsvPayload`
- 배포 추적: Web PCK와 Windows 빌드 데이터 목록에 같은 CSV 포함

동기화 검사는 ID 중복, 허용 소켓·효과 대상·연산, 용량, 중복 수, 아이템 생명 주기 연결을 확인합니다. 잘못된 실시간 응답은 현재 유효한 확정 데이터를 덮어쓰지 않습니다.

## 모듈 경계

| 모듈 | 책임 | 하지 않는 일 |
|---|---|---|
| `SessionSocketRule/Table` | CSV 파싱·행 검증 | 전투 수치 직접 변경 |
| `SessionSocketConfig` | 확정/실시간 공급자 선택 | 소켓 장착 판단 |
| `SessionSocketBindingPolicy` | 대상 ID 선택·공용/개별 정책 교체 | 인벤토리나 전투 노드 탐색 |
| `SessionSocketInventoryAdapter` | 공개 가방 계약으로 보유 조회·반환 | 효과 수치 계산 |
| `TargetedModifierStore` | source·target별 값 보관 | 무기/스킬/Scene 참조 |
| `SessionSocketService` | 용량·중복·교체·효과 집계 | 영구 장비 개조·프로필 정산 |
| `FieldLootAcquisitionService` | F 획득을 소켓 명령으로 전달 | 효과 계산 |
| `SessionSocketHUD` | 읽기 전용 점유 표시·해제 명령 | 규칙 보관 |

Manifest의 `session_sockets_enabled`만 끄면 현장 전리품 비교·획득과 영구 장비 모듈은 유지된 채 서비스와 HUD만 제거됩니다. 런 종료 시 서비스가 제거되면서 모든 소켓과 런타임 modifier source가 함께 초기화됩니다.

## 플레이어 인식 E2E

`PROVISIONAL_POLICY_OK`: Q 교체 시 효과 누출 방지, 특정 스킬에만 코어 적용, 가방 부족 원자성, I 편집 확인 취소, 보유 훈련·종료 원복, 잘못된 실시간 데이터 거부. `E2E_PLAY_SESSION_OK`의 F 획득→효과→해제 및 탈출 정산도 재실행했습니다. 자동 검증이 모든 기기/사람의 플레이 수락을 뜻하지는 않습니다.

자동 E2E는 `드랍 생성 → 접근 → F 런 소켓 → HUD 점유 → 실제 무기 피해 증가 → HUD 버튼 해제 → 피해 원복`을 실제 입력과 화면 문구로 판정합니다. 별도 계약 테스트는 룬 2·코어 1·유물 1 용량, 동일 아이템 1개 제한, 무기·스킬·이동 효과, 전체 런 초기화와 선택적 모듈 제거를 검증합니다.

P4-06 탈출 정산 연결은 완료됐습니다. 기획자는 `DATA-P4-05-01`로 슬롯·중복·효과·환전 후보를 남기고 프로젝트 오너가 확정합니다. 개발자는 승인된 값으로 `RunAsset`과 Item 값만 교체한 뒤 같은 E2E를 재실행합니다.
