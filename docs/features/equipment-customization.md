# 장비 파츠·모듈 개조

## 무기·방어구·캐릭터 모듈 화면 {#module-sockets}

**E 또는 I → 모듈 설정**에서 같은 편집 화면을 엽니다. 왼쪽은 대상/레벨/모듈 합산 수치, 중앙 위는 장착 슬롯, 아래는 보유 모듈 카드, 오른쪽은 코스트/장착·해제/소켓 설정입니다. 좁은 화면은 세로 배치와 스크롤로 전환합니다. 실제 보유 모듈과 장비의 슬롯 수만 표시하며 참조 이미지의 10칸을 임의로 지급하지 않습니다.

1. 상단에서 메인·보조 무기, 신체·신발 방어구, 캐릭터 공용 모듈을 선택합니다.
2. 빈 슬롯 → 보유 카드 → **선택 모듈 장착**을 누릅니다. 검색·비용/이름 정렬·장착 가능 필터를 사용할 수 있습니다.
3. 대상이 최대 레벨이면 슬롯 → 소켓 타입 → **선택 슬롯에 소켓 부여**를 누릅니다. 장착 모듈이 있으면 변경 전후 비용을 확인합니다.
4. 탭 이동/ESC 이탈 때 **저장 / 변경 취소 / 계속 편집**을 선택합니다. 저장 전에는 실제 장비·캐릭터 능력치가 바뀌지 않습니다.

### 소켓은 모듈 아이템이 아닌 장착 슬롯에 부여

| 대상 | 현재 소켓 해금 조건 | 소유 범위 |
|---|---|---|
| 무기 | 해당 정의/업그레이드 데이터의 최대 레벨 | 개별 무기 인스턴스 |
| 방어구 | 해당 정의/업그레이드 데이터의 최대 레벨 | 개별 방어구 인스턴스 |
| 캐릭터 | 외부 캐릭터 레벨40 도달 **임시 정책** | 공용 외부 성장에 연결된 모듈4칸/코스트12 |

각 대상이 자기 조건을 충족하면 개별 해금합니다. 세 종류를 동시에 최대 레벨로 만들 필요는 없습니다. 캐릭터 외부 성장 자체에 40 상한을 추가하지 않으며 내부 런 레벨은 해금에 영향을 주지 않습니다. 캐릭터를 방어구/드랍 아이템으로 위장하지 않고 `CharacterModuleDefinition`으로 구성합니다.

- 일치 태그: **강화 후 기본 비용 × 0.5, 소수점 올림**. 예: 5→3, 강화 후3→2.
- 미지정/불일치: 기본 비용 유지. 불일치 페널티·촉매 소모·레벨 초기화·무료 레벨업은 추가하지 않았습니다.
- 모듈 해제 후에도 슬롯 소켓과 다른 슬롯의 위치는 유지됩니다. 소켓 변경으로 용량이 초과되면 변경하지 않습니다.
- 이전 저장의 장비 전체 `granted_module_tags` 할인은 유지합니다. 명시적 슬롯 소켓을 우선하며 중복 할인하지 않습니다.
- 강화 재료/크레딧 작업은 **장비 레벨 · 모듈 강화 작업대**로 이동합니다. 미저장 초안을 먼저 확인합니다.

### 참조와 SFH 적용 범위

퍼스트 디센던트의 [공식 모듈 가이드](https://tfd.nexon.com/en/guide/2591949)와 [공식 소켓 가이드](https://tfd.nexon.com/en/guide/2594452)를 2026-09-07 확인했습니다. 원작의 최대 레벨/숙련도·촉매·레벨 초기화와 SFH 정책은 다릅니다. 이번에는 **카드형 편집 흐름, 최대 레벨 해금, 타입 일치 비용 최적화**를 적용했습니다. 이미지 에셋은 복사하지 않은 SFH 코드 카드입니다.

경제 정책은 `ModuleSocketPolicy`, 검증/저장은 `EquipmentItemState`와 `InventoryEditSession`, 화면은 `ModuleWorkspace`/`ModuleChipCard`로 분리합니다. 기존 태그와 업그레이드 CSV를 재사용하므로 새 아이템 목록·Sheet 열은 추가하지 않았습니다. 캐릭터 조건과 촉매/초기화 여부는 향후 별도 기획 결정 대상으로 남깁니다.

**I 무기 파츠:** [무기 카드형 파츠 편집](grid-inventory.md#weapon-attachment-rack)에서 그림 주변 소켓에 호환 파츠를 장착합니다.

## U 화면

**U는 장비 장착·고급 강화 작업대**, **E는 위의 통합 모듈 편집 화면**입니다. U의 기존 모듈·파츠 고급 탭은 유지하지만 E 기본 진입은 새 화면으로 변경했습니다. [가방 편집과 저장 범위](grid-inventory.md)를 확인하세요.

거점과 작전 중 U 또는 E 키로 전체 화면형 장비·개조 화면을 엽니다. 열린 동안 게임은 일시정지되고 현재 탭의 키 또는 `ESC`를 누르면 닫힙니다. 미니맵을 포함한 작전 HUD보다 앞에 표시되어 정보가 겹치지 않습니다.

I/U/E 전환은 하나의 창만 유지하며 미저장 변경이 있으면 먼저 확인합니다. 같은 화면 키 또는 ESC로 닫습니다. 아래는 U 고급 작업대의 상세 기능입니다.

화면 왼쪽의 슬롯 레일에는 메인 무기, 보조 무기, 신체 방어구, 신발 방어구가 항상 표시됩니다. 슬롯을 선택하면 오른쪽의 두 탭이 같은 대상을 관리합니다.

- **장비 장착**: 현재 장비의 레벨·태그·모듈 용량·파츠 소켓을 확인하고, 가방의 장비 카드를 직접 선택해 장착
- **모듈 · 파츠**: 선택 장비의 장착 슬롯·코스트 막대·합산 적용 수치, 고유 파츠와 보유 모듈·파츠 카드를 표시
- 호환되는 카드는 색상 테두리와 `장착 가능` 상태로, 태그·소켓·코스트가 맞지 않는 카드는 흐리게 표시
- 장착된 모듈 또는 파츠 카드를 선택하면 현재/최대 레벨과 동일 아이템·크레딧 강화 비용을 표시

참조 UI의 `선택 장비 → 장착 세팅 → 보유 목록` 시선 흐름을 SFH 규칙에 맞게 재구성했습니다. 좁은 슬롯 레일 옆에 선택 장비의 코스트·레벨·태그를 담은 장착 카드와 합산 적용 수치를 두고, 보유 목록은 138×92px 4열 카드로 유지합니다. 각 카드는 `MOD/PART`, 기본 코스트 또는 소켓, 태그·호환 상태를 클릭 전에 표시합니다.

필터는 전체·모듈·고유 파츠를 유지하며 정렬은 다음 두 방식을 제공합니다.

- **추천**: 현재 장비에 바로 장착 가능한 후보를 우선하고 그 안에서 낮은 코스트 순으로 정렬
- **코스트**: 모듈의 기본 코스트를 먼저 비교한 뒤 호환 상태와 이름으로 정렬

`EquipmentModuleUIPresenter`는 장비 상태와 가방 항목을 카드 문자열·적용 수치·정렬 키로 변환하는 표현 전용 어댑터입니다. 호환과 유효 코스트의 진실은 여전히 `EquipmentItemState`가 소유하며 UI가 별도 공식을 복제하지 않습니다.

장착 동작은 더 이상 첫 번째 호환 아이템을 자동 소비하지 않습니다. 카드에서 원하는 아이템 인스턴스를 고르고 버튼을 눌러야 하며, 장비 시스템이 장착을 승인한 경우에만 가방에서 제거합니다.

## 거점 장착·교체·해제

- 빈 슬롯에 장비를 장착하거나 현재 장비를 가방의 다른 장비로 즉시 교체할 수 있습니다.
- 교체·해제된 장비는 레벨, 개조 태그, 장착 모듈·파츠 상태를 포함한 채 가방으로 돌아갑니다.
- 장착된 모듈 또는 파츠와 가방 후보를 함께 선택하면 교체하고, `선택 모듈 / 파츠 해제`로 가방에 반환합니다.
- 강화된 모듈·파츠는 해제 후에도 강화 단계를 보존합니다.
- 반환할 가방 공간이 없으면 먼저 장착 상태를 바꾸지 않고 요청을 거부합니다.
- 준비 로드아웃과 가방은 전투 세션 진입·귀환 때 보존되며 Windows 다운로드판은 로컬 저장 제공자를 통해 재시작 복원을 지원합니다. 훈련 시험 세팅은 원본과 분리해 저장을 보호합니다. 브라우저 저장과 같은 보장으로 취급하지 않습니다. [거점 저장 계약](hub-economy.md)을 확인하세요.

## 장비 슬롯 태그

`EquipmentSlotRule`이 장착 가능 여부를 판정합니다.

| 슬롯 | 현재 허용 규칙 |
|---|---|
| 메인 | 원거리 > 화기 > 소총 |
| 보조 | 원거리 > 화기 > 권총 |
| 신체 | `body` 방어구 |
| 신발 | `feet` 방어구 |

아이템이 가방에서 차지하는 크기는 장착 판정에 관여하지 않습니다. 장착 탭은 무기 3단계 태그 또는 방어구 슬롯 태그만 검사합니다.

## 무기 고유 파츠

파츠는 `socket_id`와 호환 무기 소분류 목록을 가집니다.

- 소총 조준경: `rifle + optic`
- 권총 컴펜세이터: `pistol + muzzle`
- 대검 강화 날: `greatsword + blade`

무기 정의에도 사용할 수 있는 소켓 목록이 있습니다. 소분류가 다르거나 무기에 없는 소켓이면 장착할 수 없으며, 같은 소켓에는 파츠 하나만 허용합니다. 방어구는 파츠 장착 API를 항상 거부합니다.

### 총기 파츠 보드

E 화면에서 무기를 선택하면 장착 모듈 아래에 코드 기반 무기 도식과 실제 소켓 지도가 나타납니다. 외부 총기 이미지를 복제하지 않고 `minor_tag`에 따라 소총·권총·단검·대검 실루엣을 그리므로 상업 라이선스 자산을 추가로 요구하지 않습니다.

- 소총 기본 정의는 `optic`, `muzzle`, `magazine` 세 소켓을 도식 주변에 표시합니다.
- 장착된 파츠는 청록색, 빈 소켓은 회색, 현재 선택 소켓은 밝은 테두리로 구분합니다.
- 장착된 소켓을 클릭하면 해당 파츠가 기존 강화·교체·해제 대상으로 선택됩니다.
- 빈 소켓을 클릭하면 보유 목록을 고유 파츠로 필터링하고 호환 후보 선택을 안내합니다.
- 방어구 선택 시 총기 도식을 숨기지 않고 `고유 파츠 미지원` 상태를 명시해 빈 화면으로 오해하지 않게 합니다.

`WeaponPartsBoard`는 `EquipmentItemState`의 무기 정의·소켓·장착 파츠를 읽고 `socket_selected` Signal만 방출합니다. 실제 장착 가능 판정, 소켓 중복, 가방 소비와 상태 변경은 기존 Workbench·EquipmentSystem 계약이 계속 담당합니다.

## 모듈과 장착 코스트

무기와 방어구는 각각 다음 두 제한을 가집니다.

1. `module_slot_limit`: 장착 가능한 모듈 개수
2. `module_cost_limit`: 장착 모듈의 유효 코스트 합계

같은 모듈 ID는 한 장비에 중복 장착할 수 없습니다. 모듈은 범용 `stat_modifiers`와 아직 실행하지 않는 `special_feature_ids`를 함께 가질 수 있습니다.

## 모듈 강화

`cost_by_upgrade_level` 배열이 강화 단계별 코스트를 정의합니다. 예를 들어 `[4, 3, 2]`는 기본 코스트 4, 1강 3, 2강 2를 뜻합니다.

장비 자체의 `upgrade_module()`은 규칙 적용만 담당합니다. 별도 `EquipmentUpgradeService`가 동일 모듈 아이템과 휴대 크레딧을 확인·소비한 뒤 이 API를 호출합니다. 고유 파츠도 같은 방식으로 최대 3레벨까지 강화합니다. 현재 비용은 [모듈·고유 파츠 강화 경제](equipment-upgrade-economy.md)에서 확인합니다.

## 장비 레벨과 최고 레벨 개조

무기·방어구는 정의별 최고 레벨을 가집니다. 최고 레벨에 도달하면 `grant_module_tag()`로 개조 태그를 하나 이상 부여할 수 있습니다.

장착 모듈의 태그 중 하나가 장비 개조 태그와 맞으면 해당 모듈의 유효 코스트는 다음처럼 계산합니다.

```text
유효 코스트 = ceil(강화 단계 코스트 × 0.5)
```

태그가 여러 개 맞아도 반감은 한 번만 적용됩니다. 장비가 최고 레벨이 아니거나 빈 태그·중복 태그를 요청하면 개조를 거부합니다.

## 확장 경계

- 파츠·모듈의 능력치는 `EquipmentStatModifier`로 집계
- 특수 기능은 ID만 선언하고 향후 별도 실행기가 소비
- 레벨 경험치는 외부 성장 모듈, 강화 재료·비용은 강화 경제 모듈에서 승인
- 장비 변경 때 스킬 태그 호환성과 플레이어 스탯을 다시 계산
- 모든 상태는 슬롯별 `EquipmentItemState`에 격리

## 기능 토글과 의존성

거점에서는 `U=장비 장착`, `E=모듈·파츠`라는 독립 InputMap Action이 같은 Workbench의 각 탭을 엽니다. 물리 키를 UI가 다시 해석하지 않으므로 Web에서도 U 화면이 E 입력으로 닫히지 않습니다. 장착·교체·해제·레벨업·강화·개조 계약은 작전 화면과 공유합니다. `read_only` 주입은 향후 관전·미리보기 화면을 위해 남아 있지만 시작 거점에서는 사용하지 않습니다.

`equipment_customization_enabled`는 `equipment_enabled`와 `inventory_enabled`가 모두 필요합니다. 유료 강화는 별도 `equipment_upgrade_economy_enabled`로 끌 수 있습니다. 장비 개조를 끄면 U 화면만 설치되지 않고 기존 기본 로드아웃과 I 가방은 독립적으로 유지할 수 있습니다.

U 화면은 `get_snapshot()`, `get_items_by_type()`, `can_equip_definition()`, `take_equipment_state()`, `install/uninstall_module()` 같은 공개 계약만 사용합니다. 가방 배치 Dictionary나 장비 시스템 내부 슬롯 Dictionary에 직접 접근하지 않으므로 UI Scene을 제거하거나 다른 디자인으로 교체해도 상태 모듈은 유지됩니다.
