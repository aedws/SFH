# 모바일 키패드와 HUD 표시 설정

게임을 실행하면 **PC / 모바일**을 먼저 선택합니다. PC는 키보드·마우스, 모바일은 좌하단 조이스틱과 우하단 공격·스킬 버튼을 사용합니다. 선택 후 로비가 열리며 장비를 준비하고 작전 게이트에서 **F 또는 ‘사용’**을 누릅니다. 바로 전투로 진입하지 않습니다.

매 실행마다 선택할 수 있고 마지막 선택을 설정에 저장합니다. 모드를 바꿔도 장비·재화·작전 설정은 바뀌지 않습니다. 모바일에서도 화면 상단 **설정**으로 변경할 수 있습니다.

스킬을 다른 키/Action으로 재배치해도 화면의 스킬 버튼은 현재 스킬 배치를 따라갑니다. 손을 뗄 때에는 누를 당시의 Action을 해제하여 입력이 남지 않도록 합니다.

## 모바일은 가로 기본

모바일 선택과 터치 모드 활성화 시 **가로 방향 잠금**을 요청합니다. 네이티브 모바일 프로젝트 기본값은 좌·우 가로 센서 방향입니다. PC 모드와 Windows 창 크기는 바꾸지 않습니다.

세로로 열었으면 시작 화면과 첫 안내에서 **기기를 가로로 돌려 주세요**를 표시하고 **전체화면·가로 전환 요청** 버튼을 제공합니다. 전체화면은 이 버튼을 직접 눌렀을 때만 요청합니다. 이미 가로이면 버튼을 숨깁니다. 안내 확인 이력은 그대로 유지되므로 회전했다고 1회성 팝업이 다시 나타나지 않습니다.

방향 잠금 지원/권한은 브라우저마다 다르고 보통 전체화면 조건이 필요합니다. 지원하지 않거나 거절한 경우에는 기기의 자동 회전 잠금을 해제하고 직접 돌립니다. 실패를 무한 대기하거나 시작 실패로 처리하지 않으며, 기존 세로 배치는 호환성 폴백으로 유지합니다. 세로 플레이 중에는 에너지 영역에 ‘가로 권장’을 표시합니다. [브라우저 방향 잠금 규격](https://developer.mozilla.org/en-US/docs/Web/API/ScreenOrientation/lock), [Godot 방향 설정](https://docs.godotengine.org/en/stable/classes/class_displayserver.html#class-displayserver-method-screen-set-orientation).

## 플레이어가 바꿀 수 있는 항목

### 첫 모바일 안내와 크기

첫 모바일 선택에서 **팝업 안내 → 확인하고 로비로 이동** 순서로 진행합니다. 왼쪽 이동, 오른쪽 공격·스킬·대시, 상단 메뉴와 게이트의 ‘사용’을 설명하고 버튼 크기를 먼저 고를 수 있습니다. 내용이 길면 팝업 안만 세로 스크롤되며 확인 버튼은 항상 보입니다.

확인 완료를 저장한 브라우저·기기에서는 다시 표시하지 않습니다. 확인 전에 닫거나 저장에 실패하면 다음 실행에 다시 안내합니다. 표시 설정 초기화는 확인 이력을 지우지 않습니다. 브라우저 사이트 데이터 삭제·새 기기에서는 다시 안내됩니다. PC 선택은 모바일 안내 이력을 소비하지 않습니다.

**설정 → HUD·모바일 → 모바일 버튼·글자 크기**에서 100% / 125% / 150%를 선택합니다. 기본 125%이며 조이스틱·공격·스킬·에너지 글자를 함께 조절합니다. 상단 메뉴 글자도 확대했습니다. 화면이 좁으면 양손 영역·상단 상태 HUD가 겹치지 않는 최대 크기로 제한하므로 세로 화면의 실효 배율은 선택값보다 작을 수 있습니다. PC UI 크기에는 영향을 주지 않습니다.

`K` 입력 설정의 `HUD·모바일` 탭에서 다음 항목을 순환 선택합니다.

| 설정 | 값 | 기본값 |
|---|---|---|
| 플레이어 상태 HUD 위치 | 좌하단·하단 중앙·우하단 | 좌하단 |
| HUD 키 표시 형식 | 간결·대괄호·숨김 | 간결 |
| 모바일 키패드 | 터치 자동·항상 표시·항상 숨김 | 터치 자동 |
| 모바일 버튼·글자 크기 | 100%·125%·150% (안전 영역 자동 제한) | 125% |

PC에서는 저장한 HUD 위치를 사용합니다. 모바일에서는 양손 영역을 우선 확보하고 HP·XP·재화를 좌측 상단 아래에 고정합니다. PC로 돌아오면 저장한 위치를 복원합니다. 에너지·스킬/대시 쿨타임은 터치 패드에 표시하고 중복 PC 스킬창과 단축키 띠를 숨깁니다. 가로는 높이 480, 세로는 너비 480 기준 논리 해상도로 계산해 작은 브라우저에서도 패드가 지나치게 축소되지 않게 합니다.

## 터치 표면

- 좌하단: 원형 조이스틱. 끌어서 방향·속도 조절, 손을 떼면 정지
- 오른쪽: 기본 공격, 대시, 스킬 1·2·3, 상호작용
- 상단: 무기 교체, 전술 지도, 가방, 장비, 모듈·파츠, 설정

이동+공격+스킬을 서로 다른 손가락으로 동시에 입력할 수 있습니다. 조이스틱은 최초 손가락만 추적하고 범위 밖에서 손을 떼도 정지합니다. 모달·작전 설정·결과 화면에서는 패드를 숨기고 입력을 해제합니다. 백그라운드 이동·화면 회전·PC 전환도 입력을 해제합니다. 전투 중에는 터치를 마우스 공격으로 이중 변환하지 않고, 창에서는 일반 버튼 터치 동작을 복원합니다.

## 모듈 경계

| 모듈 | 책임 | 알지 못하는 것 |
|---|---|---|
| `PresentationSettingsService` | JSON 저장, HUD 위치·키 형식·모바일 모드 | 전투 규칙, 실제 UI 노드 |
| `MobileControlPad` | 터치를 semantic Action으로 변환 | 키보드 물리 키, 피해·이동 계산 |
| `VirtualJoystick` | 손가락 소유권·데드존·방향 벡터 | Action·플레이어 속도 |
| `TouchGuiBridge` | 패드 밖의 지도·소켓 등 GUI 터치/드래그 전달 | 마우스 공격 Action 상태 |
| `MobileViewportPolicy` | 가로/세로 논리 해상도 | 게임 세계·장비·경제 |
| `MobileOrientationPolicy` | 가로 요청·명시적 전체화면·미지원/거절 처리 | 로비 진입·저장·전투·기기 회전 강제 보장 |
| `MobilePadLayout` (배치 정책) | 배율·버튼/조이스틱 크기·양손 안전 영역 | 설정 저장·입력·전투 |
| `MobileTutorialPopup` (안내 UI) | 스크롤 안내·크기 요청·확인 Signal | 저장 경로·전투·Scene 전환 |
| `ControlModeEntry` | PC/모바일 선택·설정 저장·로비로 전달 | 작전 진입 조건·투입비 |
| `CombatHudPresenter` | 설정 스냅샷을 배치·표기에 반영 | 설정 저장, 터치 입력 |
| `KeyMappingPanel` | 세 설정의 선택 UI | 저장 형식, 전투 처리 |

`application.tscn`은 선택형 시작 화면만 조립합니다. `FeatureManifest`에서 `mobile_controls_enabled`를 끄면 선택 화면을 로드하지 않고 기존 키보드 로비로 이동합니다. 패드는 `presentation_settings`에만 필수 의존합니다. 런타임 스킬/이동 제공자는 선택형이며 공개 상태만 읽어 에너지·쿨타임을 표시합니다. Action 목록을 늘릴 때도 전투 코드는 변경하지 않습니다.

## 검증

저장 v1 파일은 기존 값 보존 + 기본 배율 125% + 안내 미확인으로 호환됩니다. v2의 배율/확인 이력은 `PresentationSettingsService`가 저장합니다. 안내 UI는 완료를 직접 저장하지 않으며 `ControlModeEntry`가 저장 성공 뒤 로비로 전달합니다. 계정 서버나 Sheet 목록 변경은 없습니다.

새 `mobile_control_entry_contract_test.gd`는 선택 버튼 클릭→설정 재로드→로비→실제 터치→게이트→작전과 모듈 OFF를 검증합니다. 844×390·390×844·1280×720·640×360의 양손 영역/44 논리 픽셀 이상 버튼, 3손가락 실제 이동·공격 입력·스킬 에너지 감소, 창/포커스 전환 해제를 검사합니다. 기존 16 Action·설정 저장·전체 플레이 E2E도 유지합니다. [자세한 판정 기준](../quality/e2e-play-session.md#mobile-entry-e2e). 실제 Android/iOS 기기의 브라우저별 터치/노치·성능 검수는 별도 실기 QA입니다.
