# 익스트랙션 구역 · 공간 공개

## 현행: B 복합 구역 + A 공간 + C 위험 단계 {#compound-20260909}

**2026-09-09 오너의 명시적 채택안**입니다. 아래 이전 기록의 ‘시설마다 반대편 문 2개·모든 마당 통행’은 이 절로 대체합니다. Notion 체크박스와 오너 승인·코드 검증은 별개로 보관합니다.

도로 → 제한된 구역 입구 → 내부 시설·연결 통로 → 더 안쪽 자원 또는 후퇴 → 두 출구 중 하나에서 방어·정산.

| 계층 | 구현 | 교체 경계 |
|---|---|---|
| B 기본 진행 | 최대 2×2 건물 구획을 복합 구역으로 묶고 내부 도로·전방위 서비스 마당 제거. 대표 입구와 내부 연결/다른 접근로 제공. 시작·탈출 외부 접근 보존 | `CompoundDistrictLayout` |
| A 공간 | L/T/U·중정형 실제 바닥. 사각형은 검색 경계일 뿐 방 판정이 아님 | `CompoundSpaceShape` |
| C 난이도 변형 | 위험 단계에 따라 다각형 시설 비율 0→60%. 셀 기반 사선 외곽, 최대 비율 제한. 도로와 필수 시설 위치 유지 | 계약 `map_geometry` |
| 깊이 보정 | 도로 입구에서 연결 그래프의 최소 깊이에 따라 시설 위험·자원 배치 가중치 보정 | `route_depth` |
| 유지 | 일반 교전 후퇴·남아 추격하는 적·금고 F만 선택 봉쇄·두 출구·단일 정산·안전 단말 워프. 모든 방 클리어/10분 대기 강제 없음 | 기존 교전·탈출 모듈 |

필수 시설의 위치·크기·기본 모양은 같은 지역·규모에서 기억할 수 있고 보조 시설 형태는 시드에 따라 달라집니다. C는 **셀에 맞춘 다각형**이며 곡선 벽·자유 메시·다층 도시는 아닙니다. 잠긴 지름길 해제·은신 시스템도 이번 범위가 아닙니다.

### 난이도 1~10과 투자

같은 지역·규모에서 단계를 올리면 기본 투입비가 증가합니다. 장비/요원/소모품 추가 비용은 별도이므로 장비를 교체했다고 위험 단계가 몰래 바뀌지 않습니다. **다른 지역·규모의 총액만 비교해 단계를 역산하지 않습니다.**

`기본 투입비 = ceil(규모 기본비 × 지역 배수 × 단계 배수)`; 결제 = 기본 투입비 + 로드아웃 추가비. 파산 보호 무료 작전은 1단계에 유지됩니다.

| 단계 | 투입비 배수 | 적 HP / 공격 / 이동 | C 비율 |
|---|---|---|---|
| 1 | 1.00 | 1.00 / 1.00 / 1.00 | 0% |
| 5 | 1.50 | 1.35 / 1.20 / 1.08 | 26.7% |
| 10 | 2.00 | 1.80 / 1.50 / 1.16 | 60% |

중간 단계도 독립 행이며 **임시 밸런스**입니다. 기존 ID `standard/veteran/nightmare`는 1/5/10, 중간 단계는 `level_02` 등입니다. 기존 드랍은 표준(1~4)·베테랑(5~9)·악몽(10) 밴드로 호환하고 랭킹은 개별 단계 ID를 구분합니다.

[공유 시트 Difficulty](https://docs.google.com/spreadsheets/d/1dtQKVZiMf7VRFWrVnaL3BqzR0g4ZgEG6ueH9RIN3xqM/edit#gid=1888798825): 1행 변수명, 2행 한국어 설명, 3~12행 10단계. 투입비는 엄격히 증가, 적/보상 배수는 감소 금지, 속도 최대 1.5, C 최대 0.6. 오류 시 마지막 정상 목록 유지. 실시간 시험은 다음 계약에 반영하며 진행 중 지형·적 계약은 불변입니다. `sync_difficulty.py --verify-live` → CSV+Web payload 확정 → 테스트·동일 버전 Web/Windows 배포. 릴리스 메타데이터에 CSV 해시를 포함합니다.

## 탐험과 위험 선택

### 도시형 도로·건물 배치 1차 {#urban-20260909}

2026-09-09 오너 요청으로 **좁은 통로로 연결한 사각 미로보다, 도로를 따라 건물이 들어선 도시 블록**으로 기본 배치를 바꿨습니다. 직교형 저층 도시의 게임용 표현이며 곡선 도로·실제 도시 GIS·다층 건축까지 구현한 것은 아닙니다.

- 대로 14셀 / 이면도로 10셀, 서로 다른 블록 폭·깊이로 구성합니다. 큰길과 필수 건물은 같은 지역·규모에서 기억할 수 있고 보조 건물 크기·용도·출입 방향·가구는 시드로 달라집니다.
- 건물 정면을 도로 쪽으로 당기고 남은 부지는 보도·서비스 마당으로 연결합니다. 건물 외벽은 실제 충돌이고 반대편 두 출입구는 5셀 폭입니다. 실내를 가로지르거나 바깥을 돌아갈 수 있습니다.
- 아스팔트·차선·방향 화살표·횡단 표시, 포장 마당·주차선, 시설별 실내 바닥·외벽 패널·창·선반·침상 형태로 공간을 구분합니다. 모두 직접 그린 절차형 그래픽이며 외부 유료 에셋을 사용하지 않았습니다. 도로 표식·주차선은 바닥 장식이고 장애물이 아닙니다.
- 실내 가구 배치 목표는 방 면적의 4.5%(규모 설정이 더 크면 해당 값, 상한 12%)입니다. 중앙 출입 축·벽 여유·가구 간격이 우선이므로 실제 점유율은 낮을 수 있습니다. 시작·탈출 시설은 비웁니다.
- 보도·마당도 시야 공간이며 건물 안을 밖에서 전부 공개하지 않습니다. 지형 기억·선택 금고 봉쇄·일반 후퇴·드랍·두 출구 정책을 유지합니다.
- 미니맵과 M 확장 지도는 도로·마당·건물 색을 나눠 넓어진 바닥이 한 덩어리로 보이지 않게 합니다. 전체 뷰와 기존 워프·출구 표시를 유지합니다.

`UrbanBlockLayout` Resource의 도로·보도·출입 폭과 provider의 `urban_fixture_density`가 조정점입니다. `urban_city_enabled=false`로 도시 지형·장식을 해제하고 기존 지역 기준점 배치로 돌아갑니다. 시설 목록은 늘리지 않아 Sheet 구조를 추가하지 않았고 기존 Facility 실시간→확정 CSV 계약을 유지합니다. 위키 맵 설계실은 같은 골격을 표시하지만 가구·적·드랍은 시뮬레이션하지 않습니다.

**후속 사람 플레이 수락:** 도로 이동 시간이 지루하지 않은가, 가구를 엄폐물로 즉시 인식하는가, 건물→보도→교차로 시야를 이해하는가. 자동 경로 통과만으로 10분 재미·현실감을 완료 판정하지 않습니다. [검증 근거](../quality/e2e-play-session.md#urban-20260909).

## 교전·탈출 규칙 (현행)

도로에서 제한된 구역 입구를 통해 내부 시설로 진입하고 연결로와 다른 접근로를 선택합니다. 시설 위험 보정은 사각 중심 거리 대신 도로 입구로부터의 최소 연결 깊이를 사용합니다. 지형·시설 선택·전리품 배치 난수는 같은 시드와 계약으로 재현하지만, 실행 중 전투 RNG까지 동일한 리플레이를 보장하지는 않습니다.

- 일반 시설: 소/중/대형 최소 **12/18/24명**. 동시 개체 상한과 총 생성 예산이 부족하면 적은 수로 쪼개 소환하지 않습니다. 재입장 무한 파밍은 불가합니다.
- 보안 금고: 들어가는 것만으로 잠기지 않습니다. 중앙 단말 110px 내에서 **F로 시작할지 선택**합니다. 시작하면 실제 바닥 경계의 출입 포털을 봉쇄하고, 해당 무리를 전멸시키면 포털과 추가 크레딧 박스를 엽니다. 포털 수를 2개로 고정하지 않으며 금고 최소 무리만큼 생성 예산을 예약합니다.
- 출구: 시작과 다른 두 시설에 배치합니다. 출구까지 직접 이동해 방어전을 완료해야 합니다. 방어 중 이탈하면 남은 시간은 멈추고 재진입 시 이어집니다. 한 출구에서 시작한 뒤 다른 출구로 이중 정산할 수 없습니다.
- 워프: 시작과 확보한 정비 시설의 `RELAY / M` 단말 110px 내, 주변 1200px에 적 없음, 금고 봉쇄 없음이 조건입니다. 탈출 시설은 워프 목적지가 아닙니다.

목표 시간 9~10분은 **밸런스 목표이지 강제 대기 시간**이 아닙니다. 방어전·추격자·지참 장비·손실과 영구 보관 정책은 그대로입니다. 시설별 고유 적 종족·의료품 전용 드랍·은신 소음·다층 실내는 이번 구현에 포함하지 않았습니다.

## 공간 단위 공개

건물에 들어가면 해당 건물 전체를 읽을 수 있습니다. 밖으로 나오면 이미 본 건물은 어두운 **지형 기억만** 남고 적·아이템은 숨습니다. 도로는 교차점 사이 구간, 출입 통로는 별도 공간입니다. 다른 방은 문이 열려 있어도 자동 공개하지 않습니다. 전체 지형은 M 지도에 계속 표시합니다.

마스크 셀 소유권으로 공간을 전환하고 새 공간은 0.22초 동안 밝아집니다. 14px 사각형 왕복 여유는 마스크 없는 이전 provider에만 적용합니다. 출입구에서 현재 발 위치 셀은 항상 공개합니다. 공간 모드의 시야 페널티는 반경 축소 대신 공간 밝기에 적용합니다(최저 45%, 임시 해석). [세부 시야 계약](fog-of-war.md).

## 기획자가 조절할 데이터

공유 밸런스 시트의 **Facility** 탭을 사용합니다. 1행 변수명, 2행 한국어 설명, 3행부터 시설입니다. 물류 창고·정비 공장·의료 구역·보안 금고·환승 광장 5종의 수치는 임시값이며 기획 확정을 뜻하지 않습니다.

| 변수 | 의미와 제한 |
|---|---|
| `facility_id` | 중복 없는 안정 ID. `workshop`은 현재 안전 워프 시설 역할도 가짐 |
| `display_name` | 화면 이름 |
| `encounter` | `patrol` 일반 교전 / `objective` 선택 봉쇄. 목표 유형은 정확히 1행 |
| `risk_bonus` | 구역 최소 연결 깊이에 따른 적 수 증가 계수 0~2. 전체 개체 상한은 넘지 않음 |
| `cache_weight` | 일반 현장 자원 배치의 상대 가중치, 0 초과~10. 확정 보상 배율이 아님 |
| `planner_note` | 사유·임시/확정·수락 기준. 런타임 전투 계산에는 사용하지 않음 |

실시간 모드는 30초마다 읽고 검증한 뒤 **다음 작전 생성부터** 사용합니다. 플레이 중 맵을 바꾸지 않습니다. 오류 시 마지막 정상 데이터를 유지하고 브리핑에 표시합니다. 확정은 `scripts/sync_facilities.py`로 CSV와 Web payload를 함께 잠그며, `--verify-live`는 읽기 검증, `--check`는 저장소 일치 검사입니다. Windows 릴리스 CSV 메타데이터에도 포함합니다. [기획자 입력 안내](../getting-started/planner-item-balance-tutorial.md#facility).

## 모듈 경계와 검증

### 지역 기준점 + 랜덤 보조 시설 {#regional-map}

2026-09-08의 지역 기준점을 유지하며 9/9에 B+A+C를 결합했습니다. **같은 지역·규모에서 구획 도로 골격과 필수 시설 위치·외곽 크기·A 기본 모양은 유지하고, 보조 시설 종류·크기·형태·장애물은 시드로 바꿉니다.** 소/중/대 건물 수는 21/35/52개입니다. 난이도는 골격/위치를 다시 추첨하지 않지만 C 다각형 적용 비율을 바꾸므로 같은 시드라도 위험 단계가 다르면 실제 윤곽이 달라질 수 있습니다. 실제 출입 포털은 B 연결과 바닥 경계에서 계산합니다.

| 지역 | 반드시 나오는 기준점 | 공통 필수 요소 |
|---|---|---|
| 폐허 도시 | 남쪽 환승 광장 | 서쪽 정비 공장, 중앙 선택 금고, 시작 1곳, 출구 2곳, 순환 도로 |
| 산업 지구 | 동쪽 물류 창고 | 위와 같음 |
| 연구 단지 | 북쪽 의료 구역 | 위와 같음 |

‘서쪽/중앙’은 사용 가능한 건물 구획 중 가장 가까운 위치입니다. 시작·출구와 다른 필수 피스가 우선 점유한 구획은 피합니다. 같은 시드·원본·계약은 재현되고 CSV 행 순서만 바꿔도 배치는 변하지 않습니다. 시작/출구 **구획**은 고정이지만 시설 세부 크기는 보조 추첨이며 외부 접근은 별도 보장합니다. 의료 구역의 치료·환승 광장의 상점 기능을 새로 만든 것은 아닙니다.

Facility의 G~L열을 확장했습니다. `required_regions`는 `*` 전체, 지역 ID를 `|`로 연결, 또는 `none`. `anchor_zone`은 west/east/north/south/center입니다. `shape_x/y` 0~1은 규모별 최소~최대 건물 크기를 보간합니다. `entrance_axis`는 horizontal/vertical로 기반 건물 정면 배치에 쓰이며, 현행 B 구역의 실제 포털 방향·개수를 강제하지는 않습니다. 실제 포털은 구역 연결에서 결정합니다. `random_weight` 0~10은 보조 추첨 가중치로 자원 가중치 `cache_weight`와 다릅니다. 금고 행은 `*`와 `random_weight=0`으로 정확히 한 곳을 보장합니다. 최대 12종이며 보조 추첨 후보가 하나 이상 필요합니다.

[기획자 맵 설계실](../access/planner.md#map-workbench) · [개발자 맵 설계실](../access/developer.md#map-workbench)에서 시드·지역·규모를 비교하고 선택한 종류의 필수 여부·위치·크기·출입 방향을 시험합니다. **현행 CSV와 시험 변경** 상태를 구분하며 Notion용 초안에는 원본 버전·시드·변경 피스·의도·수락 기준을 담습니다. 자동 제출/저장/게임 적용은 없습니다. 복사한 초안을 Notion에 공유 → 오너 판단 → Sheet 후보/CSV 확정 → 검증·배포 순서입니다.

`RegionalDistrictPlan`은 엔진 장면 없이 JSON-safe 배치만 계산합니다. 게임 provider는 실제 바닥·충돌·시야 공간으로 변환합니다. `export_map_catalog.gd`는 CSV·실제 규모 설정과 27개 Godot 기준 맵을 내보내며 `map-model.js`는 그 결과와 동등성을 검사합니다. `map-workbench.js`는 표시·시험·초안만 담당합니다. 고정 골격도 임시 정책이며 `regional_landmarks_enabled=false`로 이전 구역 랜덤 배치를 비교할 수 있습니다. 행만 추가해 새 전투 행동을 실행하지 않습니다.

검증 범위: 3지역×3규모×10단계 실제 시설/출구 도달·바닥/스폰/보상, 실제 포털·금고 1개·출구 2개, 27개 Web/Godot 기준 맵, 891개 시드의 기준점 유지·보조 변화·행 재정렬, 30개 UI 출격/복귀입니다. 27개 기준 맵은 기본 C 비율의 배치 동등성 검사이며 90개 생성 검사를 JS 모든 난이도 픽셀 동등성으로 부르지 않습니다. 기존 9개 지형 시드/3개 전투·탈출 회귀도 유지합니다. 미리보기는 적·장애물·드랍 위치나 10분 재미를 보증하지 않습니다. **두 번째 출격에서 길을 더 잘 기억하는지**는 사람 수락 항목입니다.

`CompoundDistrictLayout`은 연결, `CompoundSpaceShape`는 실제 바닥, 시설/난이도 Catalog는 표 검증을 맡습니다. `ValidatedCsvCatalogService`가 공통 네트워크/원본 상태를 처리하고 Facility/Difficulty 어댑터는 타입·URL만 제공합니다. `DistrictMapGenerator`는 공간·교전·탈출·워프 스냅샷을 제공합니다. `DistrictEncounterSystem`은 일반 교전과 목표 봉쇄를 분리하며 `MultiExtractionZone`은 두 위치를 단일 방어·정산 흐름으로 묶습니다. `ExtractionDistrictLayout`은 기초 메타데이터와 비교 폴백에 남습니다.

기존 생성기·반경 FOV는 폴백으로 남습니다. `district_layout_enabled=false`와 `space_visibility_enabled=false`를 함께 설정하면 이전 지형·시야를 비교할 수 있습니다. 시설 행 수정이 곧 코드 플러그인 등록은 아닙니다. 새로운 워프 역할·목표 종류를 추가하려면 별도 계약과 테스트가 필요합니다.
