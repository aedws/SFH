# 현장 전리품 비교·획득

**ESC 보류:** 2026-09-08부터 보류한 전리품의 접근 범위를 벗어날 때까지 인접 드랍도 비교창을 자동으로 다시 열지 않습니다. 전리품은 삭제되지 않고 다시 접근하면 비교·획득할 수 있습니다. 밀집 드랍 2개로 즉시 재개 문제를 재현한 회귀 검사를 추가했습니다.

방을 확보하면 보상 박스와 별도로 장비 전리품이 생성됩니다. 이제 획득 기록만 남기는 것이 아니라 **무기·방어구·모듈·파츠가 실제 I 가방에 들어가며 이번 판에서 장착할 수 있습니다.**

## 한 판 테스트 순서

거점에서 I/U/E로 준비 → 작전 게이트 F → 지역·요원·규모 선택 → 방 네 곳 클리어 → F로 전리품 획득 → I에서 장비·모듈·파츠 편집·저장 → M으로 탈출 위치 확인 → 탈출 방어 → 정산 → 거점 복귀.

| 출처 | 현재 임시 정책 |
|---|---|
| 방 클리어 | 완료 순서대로 무기 → 방어구 → 모듈 → 파츠 1개씩, 이후 반복. 종류 안에서는 지역 테이블로 추첨 |
| 일반 적 처치 | 12% 확률로 `enemy` 테이블 추첨. 바닥 전리품 48개 이상이면 일반 적 추가 드랍 중지 |
| 보스 처치 | `boss` 테이블에서 2회 추첨. 방 문·클리어 수와 독립 |
| 크레딧 박스 | 기존 크기 보정 1~5개 보상을 그대로 유지 |

방·보스 보장 보상은 일반 적의 48개 제한 때문에 사라지지 않습니다. 방 번호·적 인스턴스별 생성은 한 번만 처리합니다. 카테고리 후보를 기획에서 모두 끄면 일반 방 보상으로 폴백하므로 해당 카테고리 보장은 없어집니다. 요원 태그에 맞지 않는 장비도 보관은 가능하지만 장착은 거부됩니다.

## 플레이 흐름

1. 방 전투를 끝내 문 봉쇄를 해제합니다.
2. 보상 박스와 별도로 `LOOT · G등급` 신호가 생성됩니다.
3. 가까이 가면 현재 무기, 후보 등급, 보유 수량, 이번 런 사용 방식, 탈출·사망 결과가 표시됩니다.
4. `ESC`는 패널만 닫고 전리품을 월드에 유지합니다.
5. 다시 접근해 `F`를 누르면 실물 장비는 가방, 룬 등은 기존 세션 소켓/임시 보관으로 이동합니다.
6. 가방 공간이 부족하면 설명을 표시하고 바닥에 그대로 둡니다. 여러 개 묶음은 전량 수용 가능한 경우에만 획득합니다.
7. I 편집은 저장 확인, U/E는 기존 즉시 적용 방식입니다. R은 호환 무기·방어구/스킬의 빠른 장착입니다.

**반출 규칙:** 성공하면 획득한 실물은 영구 창고에 수량으로 보관됩니다. 사망하면 이번 런 획득물은 소실됩니다. 양쪽 모두 런 가방·임시 장비 상태는 출격 전 기준으로 복구한 후 기존 로드아웃 소실/대여 정책을 적용합니다. 가방과 창고에 같은 물건을 이중 지급하지 않습니다. 반출품의 이번 런 강화 상태까지 영구 직렬화하거나 창고에서 모든 실물을 꺼내는 새 UI는 이번 범위가 아닙니다.

## 모듈 경계

| 모듈 | 소유 책임 | 알지 못하는 것 |
|---|---|---|
| `LootTableProvider` | 작전 문맥 후보와 결정적 추첨 | 월드 노드·UI·획득 상태 |
| `LootLifecycleService` | 아이템 의미와 탈출·사망 결과 | 거리·입력·장비 교체 |
| `FieldLootComparisonService` | 후보와 현재 장비·보유 수량의 읽기 전용 비교 | 월드 생성·입력·장착 명령 |
| `FieldLootDrop` | 위치·접근 거리·신호 표현 | 생명 주기·인벤토리 변경 |
| `FieldLootComparisonPanel` | 비교 결과와 F/ESC 단서 표시 | 추첨·획득 규칙 |
| `FieldLootAcquisitionService` | 접근 초점·출처 연결·획득 명령 중계 | 장착·영구 정산의 내부 규칙 |
| `FieldLootSpawnPolicy` | 카테고리 순환·일반 적 확률·드랍 제한·보스 수량 | UI·가방·정산 |
| `FieldLootInventoryService` | 가방 수용 트랜잭션·런 기준 상태 복구 | 추첨·영구 창고 |
| `RunSettlementService` | 생명 주기 기반 반출·소실·중복 방지 | 월드·입력·가방 배치 |

Manifest에서 `field_loot_acquisition_enabled`만 끄면 생명 주기와 지역 드랍 브리핑은 유지되고 월드 비교·획득만 빠집니다.

## 자동 검증

- 계약 테스트: 생성→접근→비교→ESC 보류→월드 유지→재접근→선택→런 보관
- 플레이어 인식: 이름·등급·보유 수량·현재 무기·탈출·사망·F/ESC 단서
- 실제 입력 E2E: 방 확보 뒤 물리 ESC와 F를 사용해 25개 체크포인트·7개 인과 흐름 연속 판정
- 모듈 제거: 현장 획득을 꺼도 `LootTableProvider`와 `LootLifecycleService`가 유지되는지 확인

2026-09-03에 공용 `LootTable`을 29→77개 데이터 행으로 확장했습니다. 3지역마다 방 실물 12종·보스 4종을 추가했습니다. 무기·방어구 정의는 기존 Weapon/Armor, 모듈·파츠는 Item을 그대로 사용합니다. Sheet 1행 변수·2행 설명·3행 이후 데이터 및 실시간→확정 CSV→Web payload 계약을 유지합니다. 수치는 콘텐츠 확정 전 임시 정책입니다.

`E2E_LOOT_SESSION_OK`는 실제 네 방의 봉쇄·최소 무리·처치·드랍과 물리 F/I, 정확한 획득 인스턴스 장착, 가방 부족, 보스 2개, 반출·중복 방지를 검사합니다. 랜덤 보상과 함께 호환 소총/파츠 후보를 고정 주입해 양쪽 태그 경로를 검사합니다. `E2E_LOOT_DEATH_OK`는 네 종류의 사망 소실을 검사합니다. 헤드리스 자동 실행이며 장시간 수동 플레이 검수를 대신하지 않습니다.
