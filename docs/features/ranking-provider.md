# P6 검증형 랭킹 제출과 오프라인 보존

P6-01은 가치·시간·처치 3종 로컬 랭킹과 교체 가능한 온라인 제공자 경계를 만들었습니다. P6-02는 실제 한 판의 `run_id`를 익명 기기 신원과 묶고, 같은 결과가 두 번 집계되지 않도록 검증 봉투와 영구 재시도 큐를 추가합니다.

## P6 마감 범위 · 2026-09-03 재검증 {#p6-closeout}

**P6-01~04는 로컬 프로토타입 마감입니다. 온라인 경쟁 서비스 완료가 아닙니다.** 공개 Notion v1005·77블록·해시 `614a0b8ddee4`를 재조회해 같은 원문임을 확인했습니다. 별도 서버·계정·과금 변경은 하지 않았습니다.

| 단계 | 완료한 것 | 이번 마감 검증 |
|---|---|---|
| P6-01 | 3종 로컬 기록·교체 가능한 공급자·오프라인 폴백 | 종목별 정렬·기록 보존·공급자 상태 |
| P6-02 | 익명 신원·검증 봉투·멱등 키·재시도/거부 | 중복·변경된 수치·단절·재시작. 해시는 서버 권위 증명이 아님 |
| P6-03 | 기간·참가·출격 컨텍스트·읽기 전용 마감 | 배포 정책 81조합, 소형 일반 탈출은 가능/시즌 미집계, 구 정책 저장 복원·차기 시즌 전환 |
| P6-04 | 6개 외형 보상·마감 1회 지급·보유/장착 저장 | 대형 성공 기록→오프라인 마감→칭호/오라→재실행·해제 |

**수정한 누락:** Notion의 대형 참가 조건과 달리 배포 정책이 소·중·대 모두 허용했습니다. 신규 정책 `prototype-weekly-large-v2`는 **대형 + 최소 페널티 10점**만 시즌 참가시킵니다. 규모·임계는 설정으로 확장할 수 있습니다. 기존 진행 시즌은 당초 규칙과 보상을 유지하고 마감한 다음 새 정책으로 넘어갑니다. 브리핑에 정책 ID와 유지 이유를 표시하므로 업데이트 직후 소형이 아직 참가 가능하면 현재 정책부터 확인하세요.

일반 누적 기록은 기존 지역·난이도·규모별 비교용으로 남습니다. 소/중형 시즌 미참가는 출격·파밍·탈출·정산 실패가 아닙니다. 기존 기록을 지우거나 새로운 대형 시즌으로 옮기지 않습니다.

남은 실서비스 작업은 로그인 계정/신원, 서버 시간·기록 승인·부정행위 검증, 운영 순위와 서버 확정 지급입니다. 기간·최소 점수·동점·상위 인원 수의 임시값은 기획 확정이 필요합니다. P7-02 회전·리롤은 완료됐고 다음 구현 큐는 [P7-03 설계도 영구 제작 등록](../design/current-milestone-workline.md)입니다. 이를 P6 서버 구현으로 오인해 자동 착수하지 않습니다.

## 공급자 상태 표시

| 상태 | 결과 화면 | 기록 처리 |
|---|---|---|
| 로컬 모드 | `로컬 랭킹 · 기기에 보존` | 로컬 JSON에만 확정 |
| 온라인 준비 | `연결됨 · 제출 준비` | 검증 봉투를 전송할 수 있고 로컬 기록 유지 |
| 동기화 성공 | `서버 검증 완료 · 로컬 보존` | 멱등 키 기준 한 번만 온라인 확정 |
| 공급자 없음·장애 | `오프라인 · 로컬 보존 · 재시도 N건` | 런 결과와 제출 봉투를 디스크에 먼저 보존 |
| 일시 실패 | `온라인 재시도 N건 · 로컬 보존` | 시간초과 응답을 큐에 남기고 다시 전송 |
| 영구 거부 | `온라인 검증 거부 · 이유 · 로컬 보존` | 변조·규칙 위반 사유를 표시하고 재전송 중단 |

온라인 장애나 거부가 작전 정산 자체를 실패시키지 않습니다. 외부 로그인 제공자가 정해지지 않았으므로 현재 신원은 기기에 보존하는 익명 ID이며, 실제 서비스 계정 연동은 동일 `RankingIdentity` 계약의 교체 구현으로 남깁니다.

## 제출 봉투

`RunSubmissionEnvelope` v2는 `run_id`, 조건 키, 시간, 총 처치·보스 격파, 회수 가치, 보상 배율, 페널티와 출격 시 시즌 ID·시작/종료 시각·정책 ID를 SHA-256 다이제스트로 묶습니다. 기존 v1 대기열은 기존 해시 규칙으로 검증하되 새 보스·시즌 수치를 주입할 수 없습니다. 구형 로컬 기록의 보스 수는 0입니다. 클라이언트 다이제스트는 비밀 서명이나 부정행위 방지 증명이 아니며 실서비스는 서버 승인·서버 시간이 필요합니다.

- `idempotency_key`: 익명 신원 + run ID + 조건 키의 안정 해시
- `payload_digest`: 런 수치가 전송 중 바뀌었는지 확인하는 무결성 해시
- `submission_id`: 로그와 UI에서 찾는 짧은 제출 식별자
- `build_id`: 어떤 검증 빌드가 결과를 만들었는지 구분

## P6-03 · 플레이어가 보는 시즌

작전 준비의 **3단계 검토·투입**에 시즌 종료 시각(UTC), 허용 규모, 최소 페널티와 참가 가능 여부가 표시됩니다. 조건 미달이어도 일반 작전은 그대로 진행할 수 있습니다. `시즌 기록 · 읽기 전용` 버튼은 현재 시즌과 최근 마감 기록을 스크롤로 보여주며, 결과 화면에는 보스 격파 수와 시즌 집계 여부를 함께 표시합니다.

| 상황 | 시즌 처리 | 일반 기록 |
|---|---|---|
| 시작 시각 이상·종료 시각 미만에 출격하고 성공 정산 | 같은 시즌·같은 지역/난이도/규모끼리 집계 | 유지 |
| 페널티/규모 미달 또는 사망 | 미집계, 이유 표시 | 일반 참여 기준은 별도, 사망은 양쪽 미집계 |
| 출격 뒤 시즌 종료 시각을 넘겨 생환 | 이전 시즌 변경 금지·신규 시즌으로 이동시키지 않음 | 성공 기록 유지 |
| 앱을 닫은 사이 종료 | 다음 조회/시작 때 한 번만 마감·영구 저장 | 유지 |
| 마감 기록 조회 | 복사본만 반환, 수정·재제출 API 없음 | 유지 |
| 로컬 시즌 파일 오류 | 덮어쓰지 않고 시즌 미집계 안내 | 일반 랭킹·정산 유지 |

**현재 기본 정책:** `prototype-weekly-large-v2`, 2026-08-31 00:00 UTC 기준 7일 반복, 대형만 허용, 최소 페널티 10, 최근 12시즌 보관. 대형 제한은 Notion 요구이며 나머지 수치와 학살자 총 처치 우선·동점 보스 격파 우선은 임시 운영 정책입니다. 기존 `prototype-weekly-v1` 활성 시즌은 마감까지 소/중/대를 유지합니다. 최대 보관 수를 넘긴 가장 오래된 로컬 시즌은 순환 제거됩니다.

`SeasonPolicy`는 기간·참가 조건, `SeasonRankingService`는 시계·마감·저장, `SeasonPresenter`는 안내와 읽기 전용 이력을 소유합니다. 서비스는 별도의 `LocalRankingProvider` 공개 계약을 재사용해 일반 누적 랭킹을 건드리지 않습니다. 출격 시 컨텍스트를 고정하고 같은 시즌 안에서는 보관된 규칙을 사용합니다. 정책을 바꿀 때는 새 `policy_id`를 부여합니다.

시즌 정책 Resource를 `null`로 바꾸면 시즌 기능만 제거됩니다. 실제 서버·계정은 아직 연결하지 않았으며 게임 진입이나 정산에 새 온라인 의존성을 추가하지 않습니다.

## P6-04 · 시즌 칭호와 오라

**P6-01~04의 로컬 프로토타입은 완료했습니다. 실제 온라인 경쟁 서비스가 완료됐다는 뜻은 아닙니다.** 기기 시간·익명 기기 신원을 사용하는 테스트이며 계정 통합·서버 시간·부정행위 검증·운영 승인·서버 확정 지급은 별도입니다.

작전 준비 3단계의 `시즌 보상 · 칭호 / 오라`에서 보유 목록, 순위·시즌·조건별 지급 근거를 보고 장착하거나 해제합니다. 칭호는 거점 캐릭터 위에, 오라는 거점과 전투 캐릭터 둘레에 표시합니다. 전투에서는 칭호 텍스트를 숨기며 능력치·피해·재화에는 영향을 주지 않습니다.

- 임시 보상: 회수 가치·탈출 시간·처치의 조건별 상위 3명 칭호, 1명 오라. 현재 로컬 기록만 있으므로 전 세계 순위가 아닙니다.
- 시즌 개시 시 보상 목록을 고정합니다. 실시간 시트 변경은 다음 시즌부터 적용합니다.
- 종료 시각을 지난 읽기 전용 마감 이력에만 지급합니다. 앱을 닫은 사이 끝났다면 다음 실행/조회 때 지급합니다.
- 시즌·조건·보상 ID별 영수증으로 중복 지급을 막고, 익명 신원에 맞는 기록만 사용합니다.
- 칭호 프로필은 별도 원자적 파일 저장입니다. 저장 실패는 지급을 취소하고, 손상 파일은 덮어쓰지 않습니다. 보상 오류가 일반 작전 진입을 막지 않습니다.
- `season_rewards_enabled=false`는 보상·장착 UI만 제거하고 기존 시즌·랭킹을 유지합니다.

### 기획 데이터

공용 Google Sheet에 **SeasonReward 6행**을 추가했습니다. 1행 변수명, 2행 한국어 의미, 3행부터 보상이며 `reward_id / ranking_id / max_rank / kind / display_name / color / runtime_enabled / description`을 사용합니다. `kind`는 title/aura만 허용해 전투 수치를 주입할 수 없습니다.

`python scripts/sync_season_rewards.py`로 확정 CSV와 Web payload를 동기화하고 `--check`로 검증합니다. 화면의 실시간 테스트/확정 CSV 선택도 연결됩니다. 이번 데이터 버전은 `2026-09-03.1`이며 Windows 메타데이터에도 CSV 해시를 포함합니다.

`SeasonRewardCatalog`(데이터) → `SeasonRewardService`(마감 근거·지급 요청) → `SeasonHonorProfile`(보유·영수증·장착·저장) → `SeasonHonorPanel / SeasonHonorPresentation`(UI·캐릭터 표현)로 분리했습니다. Game은 버튼·캐릭터·소스 선택만 연결합니다.

`P6_REWARD_OK`: 종료 전 미지급, 오프라인 마감, 1회 지급, 다른 신원 거부, 시즌 목록 고정, 잘못된 실시간 데이터 거부, 저장 실패 롤백, 재시작·장착/해제·표현, 손상 파일 보존을 검사합니다.

## 모듈 경계

```text
OperationResultService
  → ConditionalRankingSystem (façade)
      → LocalRankingProvider (항상 보존)
      → OnlineRankingProviderAdapter (주입된 gateway만 사용)
      → RankingIdentity (익명 신원, 교체 가능)
      → RunSubmissionEnvelope (정규화·무결성·멱등 키)
      → RankingSubmissionQueue (저장·재시도·영구 거부)
      → RankingProviderConfig (local / auto / online)
      → SeasonPolicy → SeasonRankingService → SeasonPresenter (optional)
```

- 공통 계약: `submit_run`, `retry_pending_submissions`, `get_entries`, `get_snapshot`, `get_provider_status`
- 로컬 구현: 점수·정렬·멱등 처리·구형 JSON 마이그레이션을 소유합니다.
- 온라인 어댑터: 특정 서버 URL이나 SDK를 소유하지 않고 `submit_envelope` gateway 계약만 호출합니다.
- 제출 큐: 최대 보관·시도·회당 처리 수를 설정으로 받고 성공 ID와 영구 거부 이유를 별도 보존합니다.
- 조립부: 설정 Resource와 공급자 주입만 담당합니다.
- 서버·계정 제공자가 확정되기 전에는 실제 외부 주소를 하드코딩하거나 유료 서비스를 활성화하지 않습니다.

## 설정과 제거

`default_ranking_provider.tres`에서 `provider_mode`, 빌드 ID, 최대 대기 64건, 최대 시도 5회, 회당 재시도 8건을 교체합니다. 온라인 어댑터를 제거해도 로컬 기록은 독립적으로 유지되며, 공급자를 주입하지 않은 `auto`는 안전한 로컬+영구 대기 모드로 동작합니다.
