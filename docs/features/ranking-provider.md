# P6 검증형 랭킹 제출과 오프라인 보존

P6-01은 가치·시간·처치 3종 로컬 랭킹과 교체 가능한 온라인 제공자 경계를 만들었습니다. P6-02는 실제 한 판의 `run_id`를 익명 기기 신원과 묶고, 같은 결과가 두 번 집계되지 않도록 검증 봉투와 영구 재시도 큐를 추가합니다.

## 플레이어가 보는 상태

| 상태 | 결과 화면 | 기록 처리 |
|---|---|---|
| 로컬 모드 | `로컬 랭킹 · 기기에 보존` | 로컬 JSON에만 확정 |
| 온라인 준비 | `연결됨 · 제출 준비` | 검증 봉투를 전송할 수 있고 로컬 기록 유지 |
| 동기화 성공 | `서버 검증 완료 · 로컬 보존` | 멱등 키 기준 한 번만 온라인 확정 |
| 공급자 없음·장애 | `오프라인 · 로컬 보존 · 재시도 N건` | 런 결과와 제출 봉투를 디스크에 먼저 보존 |
| 일시 실패 | `온라인 재시도 N건 · 로컬 보존` | 시간초과 응답을 큐에 남기고 다시 전송 |
| 영구 거부 | `온라인 검증 거부 · 이유 · 로컬 보존` | 변조·규칙 위반 사유를 표시하고 재전송 중단 |

온라인 장애나 거부가 작전 정산 자체를 실패시키지 않습니다. 외부 로그인 제공자가 정해지지 않았으므로 현재 신원은 기기에 보존하는 익명 ID이며, 실제 서비스 계정 연동은 동일 `RankingIdentity` 계약의 교체 구현으로 남깁니다.

## 제출 봉투

`RunSubmissionEnvelope` v2는 `run_id`, 조건 키, 시간, 총 처치·보스 격파, 회수 가치, 보상 배율, 페널티와 출격 시 시즌 ID·시작/종료 시각·정책 ID를 SHA-256 다이제스트로 묶습니다. 기존 v1 대기열은 기존 해시 규칙으로 검증하되 새 보스·시즌 수치를 주입할 수 없습니다. 구형 로컬 기록의 보스 수는 0입니다. 클라이언트 다이제스트는 비밀 서명이나 부정행위 방지 증명이 아니며 실서비스는 서버 승인·서버 시간이 필요합니다.

- `idempotency_key`: 익명 신원 + run ID + 조건 키의 안정 해시
- `payload_digest`: 런 수치가 전송 중 바뀌었는지 확인하는 무결성 해시
- `submission_id`: 로그와 UI에서 찾는 짧은 제출 식별자
- `build_id`: 어떤 검증 빌드가 결과를 만들었는지 구분

## P6-03 · 플레이어가 보는 시즌

작전 준비의 **3단계 검토·투입**에 시즌 종료 시각(UTC), 허용 규모, 최소 페널티와 참가 가능 여부가 표시됩니다. 조건 미달이어도 일반 작전은 그대로 진행할 수 있습니다. `시즌 기록 · 읽기 전용` 버튼은 현재 시즌과 최근 마감 기록을 스크롤로 보여주며, 결과 화면에는 보스 격파 수와 시즌 집계 여부를 함께 표시합니다.

| 상황 | 시즌 처리 | 일반 기록 |
|---|---|---|
| 시작 시각 이상·종료 시각 미만에 출격하고 성공 정산 | 같은 시즌·같은 지역/난이도/규모끼리 집계 | 유지 |
| 페널티/규모 미달 또는 사망 | 미집계, 이유 표시 | 일반 참여 기준은 별도, 사망은 양쪽 미집계 |
| 출격 뒤 시즌 종료 시각을 넘겨 생환 | 이전 시즌 변경 금지·신규 시즌으로 이동시키지 않음 | 성공 기록 유지 |
| 앱을 닫은 사이 종료 | 다음 조회/시작 때 한 번만 마감·영구 저장 | 유지 |
| 마감 기록 조회 | 복사본만 반환, 수정·재제출 API 없음 | 유지 |
| 로컬 시즌 파일 오류 | 덮어쓰지 않고 시즌 미집계 안내 | 일반 랭킹·정산 유지 |

**임시 정책:** `prototype-weekly-v1`, 2026-08-31 00:00 UTC 기준 7일 반복, 소/중/대 허용, 최소 페널티 10, 최근 12시즌 보관. 학살자는 총 처치 우선·동점 보스 격파 우선입니다. 이는 테스트 기본값이며 기획자의 운영 승인이 아닙니다. 최대 보관 수를 넘긴 가장 오래된 로컬 시즌은 순환 제거됩니다.

`SeasonPolicy`는 기간·참가 조건, `SeasonRankingService`는 시계·마감·저장, `SeasonPresenter`는 안내와 읽기 전용 이력을 소유합니다. 서비스는 별도의 `LocalRankingProvider` 공개 계약을 재사용해 일반 누적 랭킹을 건드리지 않습니다. 출격 시 컨텍스트를 고정하고 같은 시즌 안에서는 보관된 규칙을 사용합니다. 정책을 바꿀 때는 새 `policy_id`를 부여합니다.

시즌 정책 Resource를 `null`로 바꾸면 시즌 기능만 제거됩니다. 실제 서버·계정·시즌 보상(P6-04)은 미구현이며 게임 진입이나 정산에 새 온라인 의존성을 추가하지 않습니다. 항목 카탈로그가 아닌 정책 Resource 추가이므로 Google Sheet 목록은 늘리지 않았습니다.

## 모듈 경계

```text
OperationResultService
  → ConditionalRankingSystem (façade)
      → LocalRankingProvider (항상 보존)
      → OnlineRankingProviderAdapter (주입된 gateway만 사용)
      → RankingIdentity (익명 신원, 교체 가능)
      → RunSubmissionEnvelope (정규화·무결성·멱등 키)
      → RankingSubmissionQueue (저장·재시도·영구 거부)
      → RankingProviderConfig (local / auto / online)
      → SeasonPolicy → SeasonRankingService → SeasonPresenter (optional)
```

- 공통 계약: `submit_run`, `retry_pending_submissions`, `get_entries`, `get_snapshot`, `get_provider_status`
- 로컬 구현: 점수·정렬·멱등 처리·구형 JSON 마이그레이션을 소유합니다.
- 온라인 어댑터: 특정 서버 URL이나 SDK를 소유하지 않고 `submit_envelope` gateway 계약만 호출합니다.
- 제출 큐: 최대 보관·시도·회당 처리 수를 설정으로 받고 성공 ID와 영구 거부 이유를 별도 보존합니다.
- 조립부: 설정 Resource와 공급자 주입만 담당합니다.
- 서버·계정 제공자가 확정되기 전에는 실제 외부 주소를 하드코딩하거나 유료 서비스를 활성화하지 않습니다.

## 설정과 제거

`default_ranking_provider.tres`에서 `provider_mode`, 빌드 ID, 최대 대기 64건, 최대 시도 5회, 회당 재시도 8건을 교체합니다. 온라인 어댑터를 제거해도 로컬 기록은 독립적으로 유지되며, 공급자를 주입하지 않은 `auto`는 안전한 로컬+영구 대기 모드로 동작합니다.
