# 작전 진입 마법사와 첫 투입 안내

기본 플레이 동선은 **거점 이동 → 작전 게이트에서 `F` → 작전 설정 → 투입**입니다. 개발·자동 시험처럼 거점을 생략하는 실행도 지원하지만, 플레이어가 빈 화면이나 절반만 생성된 작전에 남는 상태는 허용하지 않습니다.

## 세 단계 결정

| 단계 | 플레이어 결정 | 표시 내용 |
|---|---|---|
| 1. 지역·작전 | 지역, 난이도, 페널티, 맵 규모 | 타겟 파밍과 기본 보상 |
| 2. 요원·장비 | 캐릭터, 주·보조 무기, 스킬, 소모품 | 추가 비용과 출격 가능 여부 |
| 3. 검토·투입 | 최종 계약 확인 | 총비용, 위험·보상, 데이터 모드, 투입 버튼 |

화면에는 한 단계만 보입니다. 좌·우 화살표 키 또는 높이 44px 이상의 `이전`·`다음` 버튼으로 이동하며, 실제 `작전 투입` 버튼은 마지막 단계에서만 나타납니다. 설정 화면을 닫았다 다시 열면 1단계부터 시작하되 선택 데이터는 유지합니다.

### 화면 너비 계약

작전 브리핑은 브라우저 캔버스보다 커지는 고정 폭을 사용하지 않습니다. 패널은 좌우 안전 여백을 뺀 너비 안에서 최대 1160px로 제한하며, 전술 프리뷰는 500×238 기준 좌표를 현재 Control 크기에 비례해 그립니다. 긴 단일행은 말줄임, 실제 설명 문단만 최소 280px 폭을 확보한 뒤 줄바꿈합니다.

| 화면 폭 | 배치 | 보존 정보 |
|---:|---|---|
| 1120px 이상 | 좌측 브리핑 + 우측 단계 | 전술 프리뷰와 모든 계약 정보 |
| 840~1119px | 축소 2열 | 좌측 340px, 나머지는 계약 단계 |
| 839px 이하 | 단일 계약 열 | 장식성 프리뷰를 접고 선택·이전/다음·투입 유지 |

`OperationSetupPresenter`가 화면 폭과 표시만 소유하고 계약 비용·맵·장비 데이터는 다시 계산하지 않습니다. 1280·1024·768·480px 폭 예산과 현재 1280×720의 실제 Control 경계를 E2E에서 함께 검사합니다.

## 초기 실행 경로

| 거점 모듈 | 설정 모듈 | 초기 결과 |
|---|---|---|
| 켬 | 켬 | 기본 거점. 게이트에서 설정을 연다. |
| 끔 | 켬 | 작전 설정 1단계로 직행한다. |
| 켬 | 끔 | 설정된 기본 계약으로 작전을 조립한다. 실패하면 거점으로 복구한다. |
| 끔 | 끔 | 작전을 직접 조립한다. 실패하면 설정 화면을 열어 복구 선택을 제공한다. |

요원·무기·스킬·유틸리티·파츠·모듈·가방·전리품 전제는 [작전 투입 사전검증과 불변 계획](operation-launch-preflight.md)이 결제 전에 확인합니다. 검증이 성공한 계획과 실제 투자 계약이 같을 때만 맵을 조립합니다. 예측할 수 없는 Scene 조립 실패에는 승인 비용과 P5 런 상태를 원자적으로 되돌리고 생성 중이던 노드를 제거한 뒤 위 표의 복구 위치로 돌아갑니다. 정산 모듈을 끈 시험 구성에서도 런 ID는 반드시 종료되어 다음 투입을 막지 않습니다.

Web export에서는 P5의 6개 확정 CSV를 동기화된 내장 payload로 함께 제공합니다. 원본 CSV가 패키지에서 직접 열리지 않아도 같은 해시의 payload를 읽으며, 둘이 어긋나면 CI가 배포 전에 차단합니다. P5만 구성에 실패할 때도 코어 거점은 제한 모드로 살아 있고, 핵심 초기화까지 실패하면 빈 전장 대신 이유와 재시도 동작이 있는 복구 화면을 표시합니다.

작전 중 `ESC`는 해당 런을 실패 정산한 뒤 시작 거점으로 돌아갑니다. 브리핑의 `ESC`는 비용 차감 없이 설정을 닫고 거점으로 복귀합니다.

## 첫 투입 현장 가이드

한 실행 세션의 첫 작전에서만 화면 상단 중앙에 작은 비차단형 가이드가 나타납니다.

1. 이동과 점멸: 이동 키, 대시 키, 점멸 경로 피해
2. 전투와 자원: 기본 공격, 1·2·3 스킬, 에너지와 쿨타임
3. 방 확보: 진입 스폰, 문 봉쇄, 전멸 뒤 `F` 보상 회수
4. 탈출: 전투 방 전체 확보, `M` 전술 지도, 출구의 `F`

가이드는 플레이를 정지하지 않으며 언제든 건너뛸 수 있습니다. 현재 “첫 투입” 판정은 저장 파일이 아닌 프로세스 세션 기준입니다. 계정별 영구 튜토리얼 기록이 필요해질 때 별도 저장 공급자를 연결할 수 있도록 오버레이 모듈을 분리했습니다.

## 모듈 경계

- `OperationSetupStepFlow`: 단계 ID·이동 가능 여부만 소유합니다.
- `OperationSetupPresenter`: 단계별 표시와 입력 컨트롤만 소유합니다.
- `OperationTutorialOverlay`: 현장 가이드 내용과 탐색만 소유합니다.
- `OperationLaunchPreflightService`: 모든 설정 기여와 검증기를 모아 결제 전 불변 계획을 만듭니다.
- `Game`: 기능 플래그에 따라 모듈을 조립하고 진입·실패 복구를 연결합니다.
- 맵 생성, 계약 비용, 장비 선택, 튜토리얼은 서로의 내부 상태를 직접 수정하지 않습니다.

새 아이템·무기·방어구 목록은 필요하지 않아 Google Sheet는 확장하지 않았습니다. 이후 목록형 데이터가 필요한 작업은 기존 실시간 Sheet → 확정 CSV 계약을 그대로 사용합니다.

## 자동 검증

- 소형·중형·대형 × 지역 3종 × 난이도 3종 × 요원 3종, 총 81개 조합을 실제 게이트와 최종 투입 버튼으로 실행
- 거점/설정 기능 플래그 조합 4개 초기 경로 확인
- 물리 좌·우 키로 3단계 이동, 마지막 단계 전 투입 버튼 비노출 확인
- 1280·1024·768·480px에서 패널 너비가 뷰포트를 넘지 않고 840px 미만에서 단일열로 전환되는지 확인
- 실제 1280×720의 세 단계마다 표시 Control이 패널 경계를 벗어나지 않는지 확인
- 첫 투입 가이드 4단계, 44px 조작 범위, 비차단 상태 확인
- 작전 조립 후 플레이어·맵·계약 일치와 `ESC` 중단 뒤 거점 복귀 확인
- 장비·파츠·모듈·유틸리티·페널티를 바꾼 12개 추가 프로필과 실패 무차감 확인
