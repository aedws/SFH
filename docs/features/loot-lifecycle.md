# 전리품 생명 주기

## 무엇이 변했나

전리품을 단순히 “줍는 아이템”으로 보지 않고, 획득한 순간부터 탈출 또는 사망까지 어떤 결과가 되는지 하나의 데이터 계약으로 판정합니다. P4-01에서는 실제 드랍 확률을 늘리기 전에 다음 두 분류와 결과 표현을 먼저 고정했습니다.

| 분류 | 작전 중 | 탈출 성공 | 사망 |
|---|---|---|---|
| `◆ 영구 자산` | 창고 아이템·휴대 크레딧·영구 해금 후보 | 창고 보관·지갑 정산·영구 해금 | 해당 런 획득분 소실 |
| `◇ 이번 런 자산` | 별도 세션 소켓에 장착하는 룬·코어·유물 | 지정 크레딧으로 자동 환전 | 소실 |

아이템 상세 Presenter는 긴 설명보다 `이번 런`, `탈출 시 영구 해금`, `탈출 시 60 C 자동 환전`, `사망 시 소실`처럼 결과를 먼저 제공합니다. 브라우저에서 깨질 수 있는 컬러 이모지 대신 폰트에 포함된 단색 기호를 사용합니다.

## 데이터 공급선

[SFH_item_Balance Google Sheet](https://docs.google.com/spreadsheets/d/1dtQKVZiMf7VRFWrVnaL3BqzR0g4ZgEG6ueH9RIN3xqM/edit?usp=sharing)의 `Item` 탭이 시험 데이터 원본입니다.

- 1행: 변수명
- 2행: 기획자가 읽는 설명과 입력 예시
- 3행 이후: 개별 아이템
- `실시간 테스트`: 공개 CSV를 기본 3초마다 다시 읽고 오류 시 마지막 정상값 또는 확정 CSV 유지
- `확정 CSV`: 저장소의 검증된 15개 항목을 Web 내장 Resource와 함께 사용

기존 A:I 열은 유지하고 J:P에 다음 열을 추가했습니다.

| 열 | 의미 |
|---|---|
| `loot_family` | `persistent_asset` 또는 `session_convertible` |
| `session_behavior` | 작전 중 보관·재화·해금·세션 소켓 정책 |
| `extract_result` | 창고·지갑·영구 해금·자동 환전 결과 |
| `death_result` | 현재는 획득분 `lost` |
| `convert_value` | 자동 환전 크레딧. 영구 자산은 0 |
| `region_tags` | `|`로 구분한 지역 후보. 확률은 P4-02에서 정의 |
| `runtime_enabled` | 런타임 사용 여부 |

현재 확정 목록은 기존 파츠·모듈·소모품·크레딧 9개, 도면 3개, 세션 룬·코어·유물 3개로 총 15개입니다.

## 모듈 경계

- `LootLifecycleDefinition`: 한 아이템의 허용된 정책 조합과 검증
- `LootLifecycleTable`: Sheet/CSV 행을 Definition으로 변환
- `LootLifecycleService`: 확정/실시간 공급자 전환, 지역 필터, 탈출·사망 결과 계산
- `LootLifecyclePresenter`: 플레이어가 읽는 짧은 상태 문구 생성
- `FeatureManifest`: 한 토글과 Config 경로로 모듈 설치·제거

서비스의 `resolve_outcome()`은 결과 사본만 반환하며 인벤토리, 프로필, 크레딧을 직접 변경하지 않습니다. 실제 획득 적용과 정산 트랜잭션은 P4-03과 P4-06이 이 결과를 소비하도록 분리합니다.

## 잘못된 데이터 차단

- 중복·빈 `item_id`, 누락된 지역 태그 거부
- 영구 자산에 양수 자동 환전값을 넣는 조합 거부
- 룬·코어·유물이 아닌 세션 증폭형 거부
- 세션 증폭형의 `session_socket → auto_convert → lost` 규칙 누락 거부
- 잘못된 실시간 CSV가 들어오면 마지막 정상 카탈로그 보존
- 확정 CSV와 Web 내장 payload 불일치 시 빌드 실패

로컬 확인은 `powershell -ExecutionPolicy Bypass -File .\scripts\item-lifecycle.ps1 check`로 실행합니다.

## 플레이어 인식 E2E

1. 도면 상세에서 `◆ 영구 자산`, `탈출 시 영구 해금`, `사망 시 소실`을 확인합니다.
2. 룬 상세에서 `◇ 이번 런 자산`, `런 소켓 장착`, `탈출 시 자동 환전`을 확인합니다.
3. 같은 아이템의 성공·사망 결과가 서로 다른 결과 ID를 반환하는지 확인합니다.
4. 실시간 Sheet의 잘못된 조합이 화면 상태를 깨뜨리지 않고 마지막 정상값을 유지하는지 확인합니다.

P4-01은 데이터·표현 계약까지 완료했습니다. 지역별 실제 드랍 종류·가중치·난이도 표본 분포는 다음 **P4-02** 범위입니다.
