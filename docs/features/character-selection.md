# P5-01 캐릭터 선택·패시브·투입 가격

작전 브리핑의 `요원` 버튼을 누르면 선봉대·질주자·방벽병을 순환합니다. 버튼에는 캐릭터 이름과 추가 투입 비용, 바로 아래에는 패시브 이름과 실제 효과가 표시됩니다. 작전 투입 시 총비용은 맵·지역·난이도 비용에 캐릭터 가격을 한 번만 더하며, 선택 패시브는 작전 중 플레이어 능력치에 적용됩니다.

선봉대(`vanguard`, GDD의 뱅가드)는 확정된 전술 적응 패시브를 사용합니다. 질주자·방벽병과 기본 AP 정책값은 임시 비교값입니다. 기존 요원 ID·무료 시작·저장 호환은 유지합니다.

| 캐릭터 | 추가 비용 | 패시브 | 런타임 효과 |
|---|---:|---|---|
| 선봉대(뱅가드) | 0 C | 전술 적응 | 기본 AP +15%, 이동 중 AP 자연 회복 +20% |
| 질주자 | 120 C | 과충전 보폭 | 이동 +10%, 기동·자기 강화 쿨타임·충전 회복 시간 -20% |
| 방벽병 | 160 C | 강화 프레임 | HP +35, 방어 +2, 이동 -8%, 원형·고리 반경 +15% |

앱 시작에서도 요원과 초기 무기를 선택합니다. 패시브는 요원 고정이고 교체형 액티브와 분리합니다. [초기 선택·40종 카탈로그·Sheet 확장](tactical-skill-catalog.md).

## 전술 적응 · 2026-09-22 {#tactical-adaptation-20260922}

[GDD §13](https://wobbly-pawpaw-1ff.notion.site/3d35b728004081eba698e9a00f6ec0ed)와 [확정 요구](https://wobbly-pawpaw-1ff.notion.site/3e25b728004081d19163e2104c652b7c)를 적용했습니다. 이전 임시 직선·부채꼴 피해 +20%는 제거했습니다. Notion의 기획 체크박스는 코드 검증 결과와 별개로 유지합니다.

| 조건 | 현재 적용값 | 근거 |
|---|---:|---|
| 최대/새 작전 시작 AP | 115 | 임시 기본 100 × 확정 배율 1.15 |
| 정지 중 자연 회복 | 초당 10 | 임시 기본 정책 |
| 이동 중 자연 회복 | 초당 12 | 기본 10 × 확정 배율 1.20 |
| 사용 후 회복 지연·드랍·스킬 충전 | 기존 유지 | AP 자연 회복 배율과 별개 |

이동은 입력 키가 아니라 충돌 처리 후 실제 속도로 판단합니다(1px/s 초과). 벽에 막혀 제자리에서 키만 누르거나 정지 상태에서 좌표만 워프한 경우는 이동 보너스가 아닙니다. 대시는 실제 이동인 동안 적용합니다. 요원 변경으로 최대량이 바뀌어도 현재 AP를 공짜로 채우지 않으며, 새 작전 시작 때만 시작량을 설정합니다. 훈련장은 현재 선택, 진행 중 작전은 투입 계약에 고정된 패시브를 사용합니다.

공유 Sheet `Character` Q/R열은 `energy_capacity_multiplier` / `moving_energy_regeneration_multiplier`입니다. 1행 변수명·2행 설명·3행 이후 데이터, 허용 범위는 0 초과~5입니다. 다른 요원 기본 배율은1입니다. 확정 CSV와 Web payload를 함께 잠갔으며 데이터 버전은 `2026-09-22.1`입니다. 구형 라이브 CSV에 열이 없으면1로 처리하고 잘못된 숫자·NaN·범위 초과는 마지막 정상 카탈로그를 대체하지 못합니다.

[DPS 실험실](../tools/dps-lab.md)의 자원 입력은 패시브 적용 전 기본값입니다. ‘지속 이동 가정’을 켜면 회복 보너스를 반영합니다. 실제 이동 경로·벽 충돌을 그래프가 자동 시뮬레이션하는 것은 아닙니다. [전용 검증](../quality/e2e-play-session.md#vanguard-20260922).

## 데이터와 공급자

- Google Sheet `Character`: 1행 변수명, 2행 설명, 3행 이후 개별 캐릭터입니다.
- 확정 배포: `character_catalog.csv`와 Web 내장 payload를 사용합니다.
- 실시간 시험: 작전 준비의 실시간 모드가 공개 Sheet CSV를 3초 주기로 읽습니다.
- 잘못된 열, 중복 ID, 음수 비용, 0 이하 속도 배율은 카탈로그 교체 전에 거부합니다.
- `source_status=temporary|confirmed`로 기획 확정 여부를 데이터 자체에 남깁니다.

## 모듈 경계

`CharacterDefinition`은 한 캐릭터의 데이터와 유효성만, `CharacterTable`은 CSV 파싱만, `CharacterSelectionService`는 목록 공급·선택·작전 투자 context만 소유합니다. 기존 `OperationContractService`는 캐릭터 종류를 모르며 전달받은 `additional_entry_cost`만 총비용에 합칩니다. 플레이어는 캐릭터 ID를 모르고 `selected_character` 런타임 수정자만 받습니다. 브리핑 Presenter는 스냅샷을 표시할 뿐 비용이나 패시브를 계산하지 않습니다.

FeatureManifest에서 `character_selection_enabled=false`로 끄면 기존 맵·난이도·페널티 계약과 무료 기본 작전은 유지됩니다. 캐릭터 모듈은 작전 계약과 준비 UI가 활성일 때만 허용됩니다.

## 플레이어 인식 E2E

`캐릭터 변경 → 버튼의 이름·추가 비용 확인 → 총 견적 +120 C 확인 → 작전 투입 → 기본 이동에 외부 성장과 선택 배율이 함께 적용되는지 확인`을 한 테스트가 검증합니다. 소·중·대형×지역 3종×난이도 3종×요원 3종의 81조합 회귀도 별도로 유지합니다. 후속 [P5-02 주·보조무기·스킬 투자](loadout-investment.md)와 비용이 같은 작전 견적에 한 번씩 합산됩니다.

기획자는 위키 홈의 `DATA-P5-01-01` 요청에 Notion 근거를 남기고 Sheet의 임시 행을 교체합니다. 캐릭터 수, 가격, 패시브 수치가 바뀌어도 서비스·계약·브리핑 코드는 수정하지 않는 것이 목표입니다.
