# 무기 거리 피해와 기획 확정 곡선

가까이 붙을 무기와 거리를 유지할 무기를 구분합니다. **현재 수치는 임시 정책**이며 기획·Notion 확정값이 아닙니다.

## 현재 게임에서 달라지는 점

| 무기 | 가까운 거리 | 중간 거리 | 사거리 끝 |
| --- | --- | --- | --- |
| 돌격소총 | 100% | 사거리 60%까지 100% | 70% |
| 제식 권총 | 사거리 25%까지 100% | 이후 선형 감소 | 45% |
| 전격 펄스 소총 | 100% | 사거리 50%에서 125% | 60% |

단검·대검의 기존 런타임 대체 데이터는 중립 100%를 유지합니다. 이번 작업에서 새 무기는 추가하지 않았습니다.

발사 순간의 **보정된 자동 탐지 사거리**를 100%로 삼습니다. 발사 위치부터 탄환 충돌 위치까지의 거리에 따라 제어점 사이를 선형 보간합니다. 이동·Q 교체·실시간 시트 갱신은 이미 발사된 탄의 기준을 바꾸지 않습니다. 관통 후속 타격은 관통 유지율과 그 타격의 거리 배율을 각각 적용하며, 앞선 거리 감쇠를 중복 곱하지 않습니다.

직격 최종 피해 = (장비·모듈 보정 피해 + 내부 레벨 가산) × 치명 배율 × 관통 유지율 누적 × 거리 배율.

고유 전격 폭발 등 **고정 피해와 스킬 피해는 거리 배율에서 제외**합니다. 탄환 수명이나 탐지 범위가 늘어나는 기능은 아닙니다. 이미 날아간 탄은 탐지 범위 밖에서도 충돌할 수 있고, 곡선 끝의 배율을 유지합니다.

## 기획자 사용 순서

1. [기획자 수치 실험실](../access/planner.md#balance-workbench)의 **무기 거리별 DPS**를 엽니다.
2. 무기를 선택하고 `거리:배율` 제어점을 변경합니다. 파츠·모듈도 동일 조건으로 시험합니다.
3. 회색 현재 곡선과 청록 시험 곡선을 비교하고 수치 표로 확인합니다.
4. Notion 사유·제목·검토 확인을 입력하고 **기획 확정본 저장**을 누릅니다.
5. **확정 곡선 JSON**을 내려받아 오너에게 전달합니다. 이후 입력을 바꿔도 파일은 저장 당시 그대로입니다.

단순 입력 변경은 확정이 아닙니다. 기획 확정 → 오너 검토 → Sheet/CSV 반영 → 테스트·배포를 거칩니다. 개발자의 **거리 그래프는 현행 게임 값만** 표시합니다. 기존 전투 시뮬레이터의 확정안 이력은 별도로 유지합니다.

### 수치와 그래프의 의미

Weapon 시트 `AR` 열은 `distance_damage_curve`입니다. 1행 변수명, 2행 한글 설명, 3행부터 무기별 데이터입니다. 기존 열은 유지합니다.

예: `0:1;0.5:1.25;1:0.6` = 거리 0%에서 100%, 50%에서 125%, 100%에서 60% 피해. 거리 비율은 0~1 오름차순이며 양 끝 0과 1을 포함하고, 2~16점을 지정합니다. 피해 배율은 0~3입니다. 중립은 `0:1;1:1`입니다. 명시적으로 빈 칸을 넣으면 오류이며, 열 자체가 없는 구형 CSV만 중립값으로 호환합니다.

거리 그래프는 같은 장착·명중률 조건의 **지속 무기 DPS**입니다. 치명은 기대값, 고유 효과는 장기 평균입니다. 실제 플레이 시간축·탄환 도착 지연·적 이동·관통 후속 적·스킬 합계는 아닙니다. 자동 탐지/탄환 수명 범위 밖의 정지 표적은 0으로 표시합니다. [시간축 DPS 계산기](../tools/dps-lab.md)의 표적 거리 입력은 같은 곡선을 사용합니다.

## 개발자 적용 계약

- `WeaponDistancePolicy`: 파싱·검증·선형 보간. 무기 ID별 조건문 없이 CSV로 확장합니다.
- `WeaponBalanceTable`: 잘못된 곡선은 실시간 갱신을 거부하고 이전 값을 유지합니다.
- `AutoWeapon`: 발사 당시 곡선·보정 사거리를 전달합니다.
- `WeaponProjectile`: 타격 시 배율을 적용하고 거리·배율·실제 피해를 이벤트에 남깁니다.
- 위키/확정 API: 같은 제어점 규격을 사용하며 Godot 40개 비교값으로 보간 일치를 검사합니다.

확정 파일은 위키에서 직접 내려받은 것을 오너가 검토해야 합니다. 파일의 상태 문자열만으로 권한 승인을 간주하지 않습니다.

```powershell
python scripts/apply_weapon_distance.py <확정본.json>
# 오너가 해당 안건을 승인한 뒤에만 실행
python scripts/apply_weapon_distance.py <확정본.json> --approve-and-apply
```

기본 실행은 쓰지 않는 미리보기입니다. 적용은 기존 무기의 **곡선 열만** 바꾸며 비교용 장착·명중률·기본 피해는 덮어쓰지 않습니다. 원본 지문이 바뀐 확정안은 차단합니다. 같은 곡선을 Weapon 시트에 반영하고 실시간→CSV 경로·Web payload·릴리스 메타데이터를 유지합니다. 카탈로그 재생성·E2E·PR·배포 후 개발자 현행 그래프가 바뀝니다.

## 신규 무기 Notion 작성 양식 {#notion-template}

사전 고지: **아래는 복사 가능한 제안 양식이며 신규 무기 구현·기획 확정이 아닙니다.** 연결된 Notion 앱에서 제공받은 SFH 페이지가 404를 반환하여 아직 직접 게시하지 못했습니다. 페이지를 연결에 공유하면 별도 하위 가이드로 옮길 수 있습니다.

```text
[임시/확정/보류] 신규 무기 제안
고유 ID: 기존 ID와 중복하지 않는 영문 snake_case
표시 이름 / 무기군 / 태그:
플레이 의도: 어떤 거리에서 어떤 적에게 사용할 무기인가?
기본 피해 / 발사 간격(초) / 탄속(px/초) / 탐지 사거리(px):
발사체 수 / 점사 수 / 점사 간격(초):
치명 확률(0~1) / 치명 배율:
관통 횟수 / 관통 유지율(0~1) / 탄환 수명(초):
distance_damage_curve:
고유 효과: 기존 효과 ID 또는 신규 효과 요청·발동 조건·범위·고정 피해
파츠 소켓 / 모듈 슬롯 / 코스트 / 요구 태그:
아이템 크기 / 희귀도 / 획득 경로(상점·드랍·도면):
비교 무기 / 시험 거리 / 적 HP·방어막 / 장착 조건:
확정 그래프 ID / 기대 DPS와 허용 범위:
기획 사유 / 남은 질문 / 판단 요청 대상 / 확정일:
```

### 예시 — 원거리 집중 소총 (미구현 제안)

```text
[임시] 신규 무기 제안
ID: marksman_rifle_example / 이름: 집중 소총 / 무기군: 소총 / 태그: 원거리·화기
의도: 가까운 적에 약하고 시야를 확보한 원거리 교전에 강함
기본 피해 4 / 발사 간격 1초 / 탄속 1000px/초 / 탐지 사거리 900px
발사체 1 / 점사 1 / 점사 간격 0초
치명 확률 0.1 / 배율 2 / 관통 0 / 유지율 1 / 탄환 수명 1.2초
distance_damage_curve: 0:0.7;0.6:1;1:1.3
고유 효과: 없음 (추가 시 별도 효과 명세)
파츠: optic / 모듈 슬롯 2 / 코스트 6 (임시)
가방 크기: 4x2 / 등급·가격·드랍 지역: 기획 판단 필요
비교: 돌격소총, 거리 90·450·810px, 적 HP 100·방어막 0, 무장착
위 거리별 기본 기대 DPS: 3.30·4.18·5.39 (성장·장착 없음)
확정 그래프: 미작성 / 판단 대상: 오너 / 상태: 제안
```

새 ID 한 행만으로 완성되지 않습니다. Weapon 수치, Equipment 정의·태그·아이템 등록·획득 경로, 고유 효과 구현과 시험 데이터를 함께 연결합니다. 미지원 효과는 구현 요청으로 분류합니다.

## 검증 범위

- Godot: 제어점 범위·보간·발사 스냅샷·중복 타격·관통 비중복·CSV 오류 거부.
- JS: Godot 40개 비교점, 기존 장착 104개 비교, 사거리 밖 DPS 0, 고유 고정 피해 유지.
- 위키 E2E: 320/390/768/1440 너비, 곡선 변경·오류 차단·확정 API·파일 불변·개발자 현행 읽기 전용.
