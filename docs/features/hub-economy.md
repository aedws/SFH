# 영구 해금·상점·창고·소모품 로드아웃

`PersistentProfile`은 전투 Scene과 별도로 생존하며 영구 크레딧, 해금 ID, 창고 수량, 소모품 로드아웃, 도면과 제작 장비를 JSON에 저장합니다.

## P7-01A/B · 상점 비교·품질 실물 지급 {#shop-browser}

1. 거점의 **좌측 위 보급 상점 단말**로 이동해 **F**를 누릅니다. 작전 게이트에 들어갈 필요가 없습니다.
2. 상점 비교 화면이 열립니다. 열기만 해서는 구매하지 않습니다. 좌측 아래 **로드아웃 단말**에서도 회전 상점에 접근할 수 있습니다.
3. 손상·표준·고성능 매물을 눌러 총가격, 수량당 가격, 동일 품목의 표준 단가 대비 비율, 구매 후 잔액과 **가방 보유 수량**을 비교합니다.
4. 아래 **선택 상품 구매**를 눌러야 크레딧이 차감되고 해당 품목·수량이 I 가방의 개별 실물로 지급됩니다. 구매 뒤에는 선택을 해제하므로 연속 클릭으로 추가 구매되지 않습니다.
5. **ESC**로 닫으면 움직일 수 있는 거점으로 돌아갑니다. 장비는 **I/U/E**, 요원·스킬·소모품은 **로드아웃 단말**에서 설정하고, 마지막에 동쪽 작전 게이트로 이동합니다.

## 로비에서 세팅하고 장착한 그대로 출격 {#hub-preparation}

- **보급 상점**과 **로드아웃 단말**은 로비의 실제 상호작용 단말입니다. `hub_preparation/hub_stations.tscn`에서 위치·이름·반경을 조정할 수 있습니다. 로드아웃 모달의 닫기는 `세팅 완료 · 로비로 돌아가기 (ESC)`로 표시해 취소나 막다른 화면으로 오인하지 않게 합니다.
- I에서 아이템을 이동·장착하고 나갈 때 저장/취소/계속 편집을 선택합니다. U/E의 장비·모듈·파츠 편집은 기존 즉시 적용 방식입니다.
- 작전 브리핑은 `지역·작전 → 세팅 확인 → 검토·투입`입니다. 두 번째 화면은 **현재 장착한 무기·방어구·활성 무기·요원·소모품 확인 전용**이며, 수정하려면 로비로 돌아갑니다.
- 무기 카탈로그가 실제 장착 아이템을 덮어쓰지 않습니다. 강화·모듈·파츠·가방 배치와 Q 활성 슬롯을 출격에 넘기며 **이미 장착한 무기를 다시 청구하지 않습니다.** 스킬·소모품·요원·지역 등 기존 투자 비용은 유지합니다.
- 스킬 태그가 장착 무기와 다르면 해당 스킬만 비활성화합니다. 미해금 유료 스킬은 기존대로 차감 전에 출격을 거부합니다.
- 브리핑 취소·정상 복귀는 세팅을 보존합니다. **사망/실패의 장착 로드아웃 소실 규칙은 변경하지 않습니다.** Windows 재실행 보존은 기존 [로컬 저장](../getting-started/run-project.md#desktop-save) 계약을 사용합니다.
- `hub_preparation_enabled=false`는 단말/준비 패널만 제거합니다. 거점·I/U/E·게이트·상점 도메인은 유지하고 개발용 기존 준비 컨트롤을 사용합니다. 이 경우에도 카탈로그 무기 덮어쓰기/재청구는 재활성화되지 않습니다.

!!! info "품질은 개별 아이템에 보존됩니다"
    P7-01B부터 구매한 각 실물은 품질 ID·표시명·성능 배율·임시 옵션·소켓 수를 가집니다. I에서 U/E 장비로 옮기면 모듈·방어구·무기의 실제 능력치 계산에 배율이 적용되고, 다시 가방으로 빼거나 Windows 게임을 종료했다 다시 열어도 같은 품질이 유지됩니다. 현행 ShopOffer 6행의 가격·수량·배율과 품질 Resource의 옵션/소켓 규칙은 `provisional`이므로 기획 확정 수치로 해석하지 않습니다.

### 견적·실패 계약

- `ShopQuotePolicy`: 프로필과 매물·가방 공급자의 복사된 데이터만 읽는 순수 견적. 가격/수량 형식, 품질, 지급 유형, 해금, 잔액과 가방 수용 가능 여부를 검사합니다. 같은 `target_id`·지급 유형의 표준 **개당 가격**과 비교합니다.
- `ItemQualityCatalog`: 손상·표준·고성능의 표시명·옵션 ID·소켓 수를 가진 교체 가능한 Resource입니다. 새 품질은 코드 분기 대신 정의를 추가합니다.
- `ItemQualityDescriptor / ShopItemQualityPolicy`: 공용 payload 키와 배율 연산을 한곳에서 검증하고, 매물 배율과 카탈로그 정의를 개별 인스턴스 payload로 만듭니다.
- `ShopInventoryDeliveryService`: 상점과 그리드 가방 사이의 어댑터입니다. 전체 수량을 먼저 배치할 수 있는지 검사하고 실물 지급 또는 실패 원복만 담당합니다.
- `RotatingShopService`: 구매 때 조건을 다시 검증하며 이전 회전 번호의 견적은 차감 전에 거부합니다. 차감→실물 지급→거래 기록 중 하나라도 실패하면 지급 인스턴스와 크레딧을 함께 원복합니다. 교체 공급자의 원복까지 실패하면 환불을 보류하고 명시적 일관성 오류를 반환해 이중 획득을 막습니다.
- `P5HubProgressionService`: `get_shop_snapshot / quote_shop_offer / purchase_shop_offer` 공개 계약을 제공합니다. UI는 프로필·창고를 직접 수정하지 않습니다.
- `ShopOfferPresenter / ShopBrowserPanel`: 문구와 선택·명시 구매·모달·반응형 배치를 담당합니다. 740px 미만 패널 폭에서는 한 열, 넓은 화면에서는 세 열입니다. 내용은 세로 스크롤, 구매·닫기는 화면 안에 고정합니다.
- `shop_browser_enabled=false`: UI만 제거하고 상점 도메인은 보존합니다. `shop_item_delivery_enabled=false`는 실물 품질 어댑터만 제거해 레거시 창고 지급 계약으로 되돌립니다. P5 또는 회전 상점을 끄면 UI도 설치하지 않습니다.

이는 로컬 상점의 읽기·구매 UX 개선입니다. DB 원자성·서버 위변조 탐지는 [구현 예정안](../design/p7-plus-preimplementation.md#economy-integrity-plan)에만 기록했고 구현하지 않았습니다.

## 기존 영구 해금 서비스의 매물

| 항목 | 가격 | 결과 |
|---|---:|---|
| 현장 응급키트 | 120 C | 창고 +1 |
| 제작용 고철 3개 | 180 C | 창고 +3 |
| 산업 지구 접근권 | 600 C | 지역 영구 해금 |
| 연구 단지 접근권 | 1,200 C | 산업 지구 해금 후 구매 가능 |
| 돌격소총·전술 조끼 | 개별 가격 | 대응 도면을 성공 반출한 뒤 상점 등록 |
| 원형 자기장 | 개별 가격 | 대응 스킬 도면을 성공 반출한 뒤 영구 스킬 등록 |

위 표는 `HubEconomySystem`의 기존 해금·구매 카탈로그입니다. 기본 P5 활성 빌드의 상점 버튼은 위의 회전 매물 비교 화면을 사용합니다. P5를 끈 기존 경로에서만 지역 해금·응급키트 구매가 남아 있습니다.

영구 해금과 구매는 분리됩니다. 도면 반출은 `unlocked_shop_offer_ids`에 판매 항목을 등록하고, 실제 구매가 장비·스킬 보유 상태를 변경합니다. 등록되지 않은 항목은 견적 단계에서 잠금 이유를 반환합니다.

## 창고와 소모품

- 동일 아이템은 ID별 수량으로 창고에 누적합니다.
- 소모품 로드아웃은 최대 3개이며 보유 수량보다 많이 장착할 수 없습니다.
- 출격 성공 시가 아니라 **작전 진입 시** 창고에서 차감합니다.
- 현재 응급키트는 해당 작전 최대 체력 +15를 제공합니다.
- 조립 실패에는 자동 반환하고 정상 출격 뒤 사망에는 반환하지 않습니다.
- 사망 시 해당 런에 착용한 무기·방어구 준비 상태도 소실되며 무료 기본 무장이 복구됩니다.

## 저장 경계

프로필 저장소는 가격·제작식·전투 효과를 모릅니다. 등록된 상점 항목·해금 스킬 ID만 JSON으로 보존합니다. `HubEconomyConfig`가 가격·등록 조건·구매 결과를, 제작 설정이 재료를 소유하고 작전 조립부는 계산된 수정자만 플레이어에 전달합니다.

P7-01A/B에서 비교·선택 구매→I 가방 실물→U/E 장착→실제 수치→해제 후 품질 보존을 연결했습니다. P7-01은 기획자가 손상품 가격·성능 범위와 고성능 옵션/소켓 후보를 제출하고 프로젝트 오너가 확정한 뒤 닫습니다.

## P7-02 회전·리롤

- 작전을 정상 종료해 거점으로 복귀하면 매물이 정확히 한 번 자동 갱신됩니다. 탈출 성공과 사망 모두 다음 준비 회차로 취급합니다.
- 작전 조립 실패·결제 롤백은 완료한 런이 아니므로 매물을 바꾸지 않습니다. 정산과 거점 복귀 신호가 중복돼도 두 번 회전하지 않습니다.
- 상점의 `매물 리롤 · 25 C` 버튼은 비용·현재 잔액·가능 여부를 먼저 보여주며, 누르기 전에는 차감하지 않습니다. 성공하면 선택을 해제하고 교체 수와 잔액을 영수증으로 표시합니다.
- 동일 거래 ID는 한 번만 차감되고 매물 회전 번호도 한 번만 증가합니다. 오래된 매물 견적은 새 회전에서 구매할 수 없습니다.
- 현행 25 C, 3슬롯, 품질별 최소 1개, 이전 매물 우선 회피는 임시 Resource 정책입니다. 기획 확정 시 서비스나 UI를 고치지 않고 정책 Resource만 교체합니다.

회전 계산은 `ShopRotationPolicy`, 런/회전 번호는 `ShopRotationState`, 유료 차감·중복 방지는 `ShopRerollTransactionService`, 조립은 `RotatingShopService`가 담당합니다.

## P7-03 설계도 영구 제작 등록

- 성공 반출한 도면 중 `Recipe`에 연결된 ID만 영구 등록됩니다. 모르는 ID와 수량 0은 프로필을 바꾸지 않습니다.
- 같은 도면을 다시 반출해도 등록 수가 중복 증가하지 않습니다.
- 거점 제작소 버튼은 `도면 등록/전체 후보`를 보여주며, 각 후보는 `재제작 가능` 또는 `도면 반출 필요`로 구분됩니다.
- 게임을 종료하고 다시 열어도 영구 등록과 제작 후보 상태가 유지됩니다.
- `BlueprintRegistry`, `WorkshopRecipeProvider`, `WorkshopUnlockService`를 분리해 프로필 저장, 목록 공급, 반출 판정을 서로 교체할 수 있습니다.

## P7-04 원자적 맞춤 제작

- 후보 선택 전 크레딧 비용·잔액, 재료 보유/필요, 옵션·소켓 최소~최대가 표시됩니다.
- 제작은 크레딧·재료·실제 옵션/소켓 완제품·거래 ID를 프로필에 한 번에 저장합니다. 실패나 중복 요청은 일부만 차감하지 않습니다.
- 옵션 Roll은 `WorkshopRollPolicy` Resource로 교체하고, 거래는 `WorkshopCraftTransactionService`로 격리해 UI·Recipe 공급자·저장소를 독립 교체할 수 있습니다.
- 현행 4개 옵션 풀과 Recipe 비용·재료·범위는 임시값입니다. 새 목록이 필요하지 않아 Sheet를 늘리지 않았고 과금 구성도 변경하지 않았습니다.
