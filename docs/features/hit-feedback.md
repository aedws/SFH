# 타격감과 피격 피드백

## 발동·명중·처치 구분 · 2026-09-10 {#combat-audio-20260910}

총기 발사, 근접 에너지 스윙, 성공한 스킬 발동, 체력 명중, 장갑 명중, 처치를 서로 다른 **CC0 효과음 6종**으로 구분합니다. 신규 36종도 공통 스킬 발동 Signal에 연결되어 스킬 ID별 Game 분기가 필요 없습니다. 훈련 더미도 실전과 같은 타격 피드백을 받습니다. 파일은 총107,640바이트이며 [출처·상업 이용 근거](../architecture/third-party-assets.md)에 원문과 SHA-256을 보존합니다.

`CombatAudioProfile`은 교체 가능한 소리·음량·거리·재생 예산만 소유합니다. `CombatFeedbackAudio`는 미리 만든 8개 2D 음성만 재사용합니다. 기본 -24dB, 같은 이벤트 최소70ms, 발동/명중 각각 최소25ms, 거리900px 제한입니다. 같은 프레임의 근접 발동과 명중은 서로 막지 않지만 군집 명중은 예산 안에서 생략합니다. 무음은 `enabled=false`/`set_enabled(false)`, 전체 표현 제거는 기존 `hit_feedback_enabled=false`입니다. 아직 사용자용 음량 슬라이더는 추가하지 않았습니다.

직선은 폭, 부채꼴은 양쪽 경계, 원/링은 고정 외곽과 맥동, 연쇄는 실제 연결점, 단일은 원점→대상으로 표시합니다. 접촉에는 기존 CC0 스파크와 짧은 흰 코어, 처치에는 확산 링을 겹칩니다. 다중 펄스의 카메라 배율은0.65로 줄이고 기존6px 상한을 유지합니다. 피해·속도·전역 시간을 바꾸지 않습니다. 범위 경계는 기하 범위이며 벽 차폐로 실제 피해가 제외되는 부분의 시각 표현은 후속 실제 플레이 수락 대상입니다.

`COMBAT_AUDIO_OK`: 6개 스트림·같은 프레임 명중·1000회 군집 요청 제한·무음·거리·실제 피해 Signal·중복 연결·해제 회귀. `TACTICAL_FEEDBACK_RENDER_OK`: AMD Radeon890M/Compatibility에서7개 기하 표현과 접촉 렌더, 6종 모두 오디오 믹서의 비영 신호 확인. 출력 최대값0.022~0.030. **자동 믹서 확인은 사람이 듣고 평가한 음질/재미 판정이 아니며**, Headless 검사는 실제 재생 없이 계약만 검사합니다. 정상10분 플레이 수락은 별도입니다.

## 속도감·발사 FX 보강 · 2026-09-08 {#speed-shot-fx}

달릴 때 진행 방향을 먼저 보여주고, 대시에는 최대 69.3px 선행과 기본 대비 최대 8% 줌아웃을 적용합니다. 보통 이동의 줌 변화는 약 2.4%이며 정지하면 부드럽게 원복됩니다. `PlayerMovementFeedback`의 `camera_reference_speed`, `camera_lead_pixels`, `speed_zoom_out`, `zoom_response`로 조정합니다. `speed_zoom_out=0`은 줌 보정만 끄고, 피드백 모듈 비활성화는 카메라 위치·줌을 즉시 원복합니다. 이동 속도·피해·전역 시간은 바꾸지 않습니다.

발사 성공 Signal `projectile_fired(position, direction, color)`을 독립 `WeaponShotFX`가 받아 방향성 총구 섬광·흰 코어·짧은 전기 잔광을 그립니다. 발사 실패/사거리 밖에서는 섬광을 만들지 않습니다. 동시 16개, 기본 수명 0.12초로 제한하며 다중 탄환도 상한을 넘지 않습니다. 더 이상 남은 섬광이 없으면 처리와 다시 그리기를 중지합니다. 카메라 `position/zoom`은 이동 표현, `offset`은 기존 피격 Director가 소유하여 서로 덮어쓰지 않습니다.

상업 이용 가능한 기존 [Kenney Particle Pack](https://kenney.nl/assets/particle-pack)의 CC0 텍스처 2개를 재사용합니다. 2026-09-08 공식 CC0 표기와 반입 라이선스를 재확인했습니다. 추가 다운로드·유료 에셋·실시간 광원·전체 화면 블룸은 추가하지 않았습니다. 출처·라이선스는 `game/assets/vfx/kenney_particle_pack/`에 보존합니다.

`combat_fx_contract_test.gd`는 줌 상한, 정지/비활성화 복원, 피격 offset 소유권, 발사 Signal, 100회 발사의 16개 상한과 종료, 스킬 표시 수명·취소를 검사합니다. 연출 강도는 Resource/export에서 조정하는 표현값이므로 새 게임 목록이나 Google Sheet 열은 추가하지 않습니다.

로컬 렌더 검수: AMD Radeon 890M / Compatibility에서 계측용 45초 세션 평균 16.75ms·P95 17.68ms·최대 56.71ms, 2,687프레임·21발·2개 공간 이동·종료 후 잔류 노드 0을 확인했습니다. 스크린샷 저장 비용도 포함된 값이며 밀집 전투 카운터는 0이므로 고부하/최소사양/10분 일반 플레이 인증이 아닙니다. `combat_fx_render_test.gd`의 고정 GPU 장면에서 발사·점멸·자기장 수명 80%·가속 표시도 확인합니다. 근거는 `outputs/combat-fx-soak/`와 `outputs/combat-fx/overview.png`입니다.

기존 E2E의 워프 안전 검사가 보스를 제거한 다음 전리품을 검사하던 순서를 **보스 전리품 → 워프**로 바꿨습니다. 실패를 무시하거나 보스를 가짜로 재생성하지 않으며 실제 게임의 위협 차단 정책은 그대로 검증합니다.

피해가 숫자만 감소시키지 않고 즉시 읽히도록 1차 타격 피드백을 적용했습니다. 전역 게임 시간을 멈추는 방식은 사용하지 않습니다. 맞은 액터만 짧게 경직되므로 다수 적 전투와 입력 응답을 유지합니다.

## 한 번의 타격에서 일어나는 일

2026-09-07 개선: 충격 초반 약 0.05초에는 작은 흰색 접촉점을, 처치에는 추가 확산 링을 표시합니다. 단발에도 방향성 카메라 충격이 기본 1.8px 발생하고 처치 시 1.8배로 구분됩니다. 연속 타격 충격은 무한 누적하지 않으며 기존 흔들림과 합산해 **최대 6px**로 제한합니다. `HitFeedbackProfile.directional_kick_pixels`와 `directional_kick_decay`로 조정하며 `maximum_camera_offset=0`은 모든 카메라 충격을 끕니다. 공격의 `camera_trauma_multiplier=0`도 존중합니다.

피격이 없는 동안 Director는 처리와 다시 그리기를 중지하고 다음 `damaged` Signal에서 깨어납니다. 액터 섬광 색은 상태가 바뀔 때만 갱신합니다. 게임 전체 시간·피해량·경직·넉백 규칙은 변경하지 않았습니다.

| 순서 | 반응 | 기본값 | 담당 모듈 |
|---:|---|---:|---|
| 1 | 피해·방어력 적용 | 기존 전투 수치 유지 | Player 또는 Enemy |
| 2 | 흰색 피격 섬광 | 0.07~0.08초 | `HitReaction2D` |
| 3 | 맞은 액터 국소 경직 | 0.045~0.055초 | `HitReaction2D` |
| 4 | 타격 방향 넉백 | 적 72, 플레이어 46 초기 충격 | `HitReaction2D` |
| 5 | 충격 링·방사선 | 0.18초, 반경 26px | `HitFeedbackDirector` |
| 6 | 카메라 미세 흔들림 | 적 0.13, 플레이어 0.34 Trauma | `HitFeedbackDirector` |

기본기 투사체는 진행 방향, 점멸은 이동 경로, 자기장은 플레이어에서 대상 바깥쪽, 적 접촉은 적에서 플레이어 방향을 `hit_context`로 전달합니다. 방어력에 막힌 타격은 파란색, 체력 타격은 황색, 전기 스킬은 청록색, 플레이어 피격은 적색으로 구분합니다.

무기 기본기는 발사 순간 총구 섬광과 투사체 광원을 표시하고, 무기 정체성에 따라 충격 색·반경·방사선 수·카메라 Trauma가 달라집니다. 명중 누적 고유 스킬은 별도 `weapon_innate_skill` 출처로 표시되어 기본 타격과 구분됩니다.

## 피해 계약

기존 `take_damage(amount)` 호출은 그대로 유효합니다. 타격 방향이나 표현 강도가 있는 공격만 선택적으로 두 번째 인자를 전달합니다.

```gdscript
target.take_damage(damage, {
    &"source_kind": &"weapon_projectile",
    &"source_position": projectile.global_position,
    &"impact_direction": projectile.direction,
    &"impact_strength": 1.0,
})
```

`hit_context`는 피해량을 바꾸지 않습니다. 액터는 실제 체력·방어력 감소량과 치명 여부를 `damaged` Signal로 방출하고 피드백 모듈이 이를 읽습니다.

## 모듈 구조

```text
공격 모듈
  └─ take_damage(amount, hit_context)
       ├─ Player / Enemy                 # 피해 계산
       ├─ HitReaction2D                  # 해당 액터 섬광·경직·넉백
       └─ damaged Signal
            └─ HitFeedbackDirector       # 충격 링·카메라 Trauma
                 └─ HitFeedbackProfile   # 표현 수치와 동시 표시 상한
```

- Director는 액터의 체력, 방어력 또는 공격 구현 내부를 읽지 않습니다.
- 액터가 사라지면 등록 정보도 `tree_exited`에서 제거됩니다.
- 충격 표시는 타격마다 Node를 만들지 않고 Director 하나가 최대 32개 기록을 그립니다.
- `hit_feedback_enabled`를 끄면 Director가 설치되지 않고 액터의 섬광·경직·넉백도 비활성화됩니다.
- 프로필만 교체해 카메라 강도, 수명, 반경, 방사선 수와 동시 표시 상한을 바꿀 수 있습니다.

## 현재 범위와 다음 단계

이번 단계에는 무기·스킬·적 접촉의 시각·움직임 반응과6종 공통 역할별 음향이 포함됩니다. 무기/스킬마다 고유한 개별 사운드, 처치 전용 파편, 게임패드 진동, 강공격 전용 전역 히트스톱은 아직 적용하지 않았습니다. 전역 히트스톱은 다수 적과 Web 입력 지연을 실제 플레이로 검증한 뒤 별도 정책으로 추가합니다.

## 검증

- 적 타격이 섬광·경직·넉백·충격 링·카메라 Trauma를 동시에 생성하는지 검사합니다.
- 플레이어 피격과 치명타가 별도 강도로 집계되는지 검사합니다.
- 충격 기록이 32개 상한을 넘지 않는지 검사합니다.
- 기능을 끈 구성에서 Director와 액터 반응이 모두 사라지는지 검사합니다.
- 대형 작전 성능 게이트에서 전체 Node와 프레임 예산을 다시 측정합니다.
